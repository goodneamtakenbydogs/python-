# 第 5 章复习卡：迭代器、生成器与惰性计算

这份复习卡用于学完后的快速回忆，不替代完整讲义。

## 1. 可迭代对象、迭代器与 `for` 循环的关系

```text
source
  │
  │ iter(source)
  ▼
iterator
  │
  │ next(iterator)
  ├────────→ 下一项，同时推进状态
  │
  └────────→ 无下一项时发出 StopIteration

for 循环 = 自动执行上面的过程
生成器 = Python 帮助创建迭代器的一种方式
```

## 2. 四个核心概念

### 可迭代对象

能够交给 `iter()` 并提供迭代器的对象。

它不保证有下标、长度、倒序能力、重复遍历能力或完整内存数据。

### 迭代器

能通过 `next()` 给出下一项，并保存一次遍历状态的对象。没有下一项时发出 `StopIteration`。

### 生成器

自动实现迭代器协议的对象，通常由包含 `yield` 的生成器函数或生成器表达式创建。

### 惰性计算

把计算推迟到结果真正被请求时执行。

## 3. 最容易混淆的对比

| 对比 | 左侧 | 右侧 |
|---|---|---|
| 可迭代对象 / 迭代器 | 提供遍历入口 | 保存并推进一次遍历 |
| 列表 / 列表迭代器 | 可重复建立新迭代器 | 当前对象会耗尽 |
| `yield` / `return` | 产出并暂停 | 结束生成器 |
| 列表推导式 / 生成器表达式 | 立即建立完整列表 | 按需计算 |
| `yield group` / `yield from group` | 把整个 `group` 作为一项 | 依次产出 `group` 内部各项 |
| 消费全部 / 保存全部 | `sum()` 可消费全部但只留累计状态 | `list()` 消费并保存全部结果 |

## 4. 迭代协议与结束信号

```text
iter(obj)
→ 请求 obj 的迭代入口

next(iterator)
→ 请求下一项并推进状态

StopIteration
→ 表示自然耗尽
```

迭代器协议：

```text
迭代器的 __iter__() 返回自身
__next__() 返回下一项，结束时抛出 StopIteration
```

兼容补充：对象没有 `__iter__()` 时，`iter()` 还可能从 `obj[0]` 开始使用 `__getitem__()` 序列协议；新代码通常直接实现 `__iter__()`。

迭代器必须满足：

```python
iter(iterator) is iterator
```

## 5. `for` 循环的近似展开

```python
iterator = iter(source)

while True:
    try:
        value = next(iterator)
    except StopIteration:
        break

    # 循环体
```

所以 `for` 不要求对象有下标。

## 6. 生成器时间线

```text
调用生成器函数
→ 创建生成器对象，函数体尚未开始

第一次 next()
→ 从函数开头运行到第一个 yield
→ 产出值并暂停

再次 next()
→ 从上次 yield 后继续
→ 保留局部状态

运行到 return 或末尾
→ 生成器结束
→ 后续继续表示耗尽
```

`return value` 中的 `value` 进入最终 `StopIteration.value`，不会成为普通 `for` 的下一项。

## 7. 哪些操作会消费迭代器

- `next(iterator)`。
- `for value in iterator`。
- `list(iterator)`、`tuple(iterator)`、`set(iterator)`。
- `sum(iterator)`、`min(iterator)`、`max(iterator)`。
- `value in iterator`。
- 消费 `zip()`、`map()`、`filter()` 等下游迭代器。

创建这些下游对象通常不立即推进上游；对下游执行 `next()`、`for` 或 `list()` 时才会发生连锁消费。

分析代码时要逐次记录位置，不能只看底层数据是否改变。

## 8. 惰性计算的选择规则

适合生成器：

- 数据量很大。
- 只需顺序处理一次。
- 可能提前停止。
- 数据持续到达或理论上无限。
- 多个转换阶段可以逐项传递。

适合列表：

- 需要下标和长度。
- 需要多次遍历。
- 需要稳定快照。
- 全部结果规模可接受。
- 后续算法本来就要求完整数据。

## 9. 高频陷阱

1. 把列表叫作迭代器。
2. 认为 `iter()` 会复制全部数据。
3. 认为调用生成器函数已经执行函数体。
4. 两个名字指向同一生成器，却误以为有两份状态。
5. 用成员判断、`list()` 或 `sum()` 后忘记迭代器已经推进或耗尽。
6. 把 `None` 当作迭代结束标记。
7. 对无限迭代器执行无界 `list()`。
8. 以为生成器一定更快、一定占用很少内存。
9. 忘记惰性转换中的异常会延后到消费时。
10. 生成器暂停期间长期持有打开的文件或连接。

## 10. `yield from` 与生成器控制方法

```text
yield from iterable
→ 委托另一个可迭代对象逐项产出

generator.send(value)
→ 把 value 送入暂停的 yield 表达式并恢复

generator.throw(error)
→ 在暂停位置注入异常

generator.close()
→ 请求结束并触发清理路径
```

新生成器通常先用 `next(generator)` 或 `generator.send(None)` 启动。

## 11. `itertools` 速记

- `chain(a, b)`：先消费 `a`，再消费 `b`。
- `islice(source, ...)`：按位置截取迭代流。
- `count(start, step)`：无限等差计数流。
- `repeat(value, times)`：重复产生对象。
- `takewhile(predicate, source)`：条件首次为假时停止。
- `dropwhile(predicate, source)`：丢弃开头连续满足条件的部分。
- `tee(source, n)`：建立逻辑上的多路迭代器，但可能缓存进度差。

无限流必须有 `islice()`、条件、`break`、超时或取消机制。

## 12. 面试回答模板

### 可迭代对象与迭代器

> 可迭代对象能通过 `iter()` 提供迭代器；迭代器保存一次遍历状态，通过 `next()` 返回下一项，结束时发出 `StopIteration`。列表可迭代但不是迭代器，同一个列表可以建立多个独立迭代器。

### 生成器

> 生成器是实现迭代器的一种方式。生成器函数调用时先创建对象，第一次消费才执行；每次 `yield` 产出并暂停，同时保存局部状态和继续位置，之后从暂停点恢复。

### 惰性计算

> 惰性计算把工作推迟到结果被请求时，能减少未使用计算和完整中间结果内存，也能处理无限流；代价是单向消费、耗尽、错误延后和资源生命周期更难观察。
