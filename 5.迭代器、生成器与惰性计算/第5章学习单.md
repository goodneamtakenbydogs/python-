# 第 5 章学习单：迭代器、生成器与惰性计算

## 1. 本章为什么要学

你已经经常写 `for value in values`，也用过列表推导式、`map()` 和 `filter()`。这些写法表面不同，背后都依赖同一套“逐个取得下一项”的规则。

本章要回答四个核心问题：

1. 为什么列表、字符串、字典和文件都能放进 `for` 循环？
2. 遍历进行到哪里，由谁记录？
3. 生成器为什么能暂停，下次又从原位置继续？
4. 为什么按需产生数据能节省内存，却也会带来耗尽、单次消费和资源生命周期问题？

本章主线是：

```text
可迭代对象提供遍历入口
→ iter() 取得迭代器
→ next() 逐项消费
→ StopIteration 表示结束
→ yield 帮助函数自动创建生成器
→ 惰性流水线按需处理数据
```

## 2. 学习目标

完成本章后，应当能够：

- 用自己的话区分可迭代对象和迭代器。
- 解释 `iter()`、`next()` 和 `StopIteration` 的关系。
- 把一个简单 `for` 循环展开成等价的手动迭代过程。
- 说明为什么同一个列表可以建立多个互不干扰的迭代器。
- 说明为什么迭代器通常只能向前消费，耗尽后不会自动回到开头。
- 识别迭代协议中的 `__iter__()` 与 `__next__()`。
- 编写简单生成器函数，并解释调用函数时为什么不会立刻执行函数体。
- 区分 `yield` 暂停与 `return` 结束。
- 解释生成器如何保存局部状态和继续执行位置。
- 比较列表推导式与生成器表达式的计算时机和内存特点。
- 判断惰性计算何时有收益，何时会造成重复消费或资源未及时释放。
- 使用 `yield from` 委托子迭代对象。
- 说清 `send()`、`throw()` 和 `close()` 的基本作用及使用边界。
- 使用 `itertools.chain()`、`islice()`、`count()` 等常见工具。
- 设计逐行处理文件或数据流的流程，而不是一次性加载全部数据。
- 面对无限迭代器时，主动设置终止条件或消费上限。

## 4. 本章知识点清单

### 4.1 遍历、迭代与消费的含义

- 遍历和逐项消费的含义。
- 容器、可迭代对象与迭代器不是同一个分类。
- 列表、字符串、字典、集合、文件和生成器为何都可用于 `for`。

### 4.2 可迭代对象与迭代器

- `iterable`：能够提供迭代器的对象。
- `iterator`：记录当前位置并能给出下一项的对象。
- `iter(obj)` 的作用。
- `next(iterator)` 的作用。
- 迭代器的 `__iter__()` 返回自身，因此 `iter(iterator) is iterator`。
- 一个可迭代对象可以创建多个独立迭代器。

### 4.3 结束信号与 `for` 循环

- `StopIteration` 表示没有下一项。
- `next(iterator, default)` 的默认值形式。
- `for` 循环如何取得迭代器、反复调用 `next()` 并在结束时停止。
- `break` 是调用方主动停止，`StopIteration` 是数据源自然耗尽。

### 4.4 迭代器协议

- 协议是对象为了参与某种语言行为而遵守的方法约定。
- `__iter__()` 提供迭代入口。
- `__next__()` 给出下一项或抛出 `StopIteration`。
- `iter()` 在缺少 `__iter__()` 时还可能使用基于 `__getitem__()` 的序列协议回退；新代码通常直接实现 `__iter__()`。
- 手写迭代器类的最低限度结构。
- 可迭代对象与迭代器分成两个对象的设计价值。

### 4.5 生成器函数

- 函数体中出现 `yield` 后，调用得到生成器对象。
- 第一次 `next()` 才开始执行函数体。
- `yield` 产出一个值并暂停。
- 再次恢复时从上次暂停位置继续。
- 局部名字和继续执行位置都会保留。
- `return` 结束生成器，返回值保存在结束信号中。

### 4.6 生成器表达式与惰性计算

- `[expression for ...]` 立即建立完整列表。
- `(expression for ...)` 建立按需计算的生成器。
- 惰性计算只在消费者索取下一项时做必要工作。
- 首项延迟、峰值内存和提前停止的收益。
- 耗尽、重复遍历、异常延后和调试难度等限制。

### 4.7 组合生成器

- `yield from iterable` 逐项委托。
- 多层数据的扁平化。
- 多个生成器组成处理流水线。
- 中间阶段保持惰性需要避免无意调用 `list()`、`sorted()` 等整体物化操作。

### 4.8 `send()`、`throw()` 与 `close()`

- `send(value)`：恢复生成器并把值送回暂停的 `yield` 表达式。
- 启动生成器时为什么通常先调用 `next()` 或 `send(None)`。
- `throw(error)`：在暂停位置注入异常。
- `close()`：请求生成器结束，并触发清理路径。
- 这些接口不是普通遍历的默认选择。

### 4.9 `itertools`

- `chain()` 串联多个可迭代对象。
- `islice()` 对迭代流按位置截取。
- `count()` 创建无限计数流。
- `repeat()` 重复产生对象。
- `takewhile()` 与 `dropwhile()` 按条件截取。
- `takewhile()` 在首次不满足条件时停止，`dropwhile()` 在首次不满足后产出全部剩余项。
- `tee()` 创建逻辑上独立的迭代器时可能缓存数据。
- 创建 `zip()`、`map()`、`filter()` 等下游对象不等于立即消费；消费下游时才推进上游。
- 无限流必须由上限、条件或外部取消机制约束。

### 4.10 文件与数据流

- 文件对象逐行迭代。
- 一次性 `read()` 与逐行处理的内存差异。
- 生成器流水线中的过滤、转换和汇总。
- 生成器持有文件等外部资源时的生命周期风险。
- 无限数据流、网络数据流和批处理的共同思路。

## 5. 推荐学习顺序

### 第一步：理解 `for` 的迭代过程

用列表练习 `iter()` 和 `next()`，再手动捕获结束信号。先看清“数据”和“遍历位置”由不同对象负责。

### 第二步：比较列表、列表迭代器与生成器

分别观察列表、列表迭代器和生成器：谁能再次从头遍历，谁会保留当前位置，谁耗尽后无法自动恢复。

### 第三步：跟踪生成器的暂停与恢复

在 `yield` 前后加入事件记录，不要只看最终列表。每调用一次 `next()`，明确函数体执行到哪一行、哪些局部状态被保留。

### 第四步：建立惰性流水线

比较列表推导式和生成器表达式，再让多个生成器串起来。重点观察何时真正执行、提前停止时做了多少工作。

### 第五步：学习生成器控制方法与 `itertools`

先掌握普通 `for` 与 `yield`，再学习 `yield from`、`send()`、`throw()`、`close()` 和 `itertools`。高级接口应建立在消费过程已经清楚的基础上。
