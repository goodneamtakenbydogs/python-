# 第 5 章参考回答：迭代器、生成器与惰性计算

这些回答用于检查概念和组织方式，不需要逐字背诵。面试时先给结论，再用最小例子或状态变化解释。

## 一、基础概念题

### 第 1 题：遍历、迭代与消费

**一句话结论：** 遍历强调依次访问全部或部分数据的目标，迭代强调不断取得下一项的过程，消费强调取得下一项会推进迭代状态。

分析迭代器时，“消费”最关键，因为一次 `next()`、一次成员测试或一次 `list()` 都可能让当前位置前进。后续代码看到的不是原位置。普通列表内容可以不变，但引用该列表的迭代器状态已经变化。

常见错误是把“遍历过数据”说成“删除了数据”。改变的是迭代位置，不一定是底层容器。

追问时可以举例：`2 in iterator` 找到 `2` 前会消费前面的项。

### 第 2 题：可迭代对象

**一句话结论：** 可迭代对象是能够交给 `iter()` 并提供迭代器的对象。

列表、字符串、字典都是常见可迭代对象，文件和生成器也可迭代。可迭代只承诺可以开始逐项访问，不承诺支持整数下标、已知长度、倒序、重复遍历或把全部数据预先保存在内存。

常见错误是说“可迭代对象就是容器”。很多容器可迭代，但文件和按需计算对象说明两个概念并不相同。

回答到“能被 `iter()` 处理，并给出不保证下标和重复遍历”通常已经足够。

### 第 3 题：迭代器

**一句话结论：** 迭代器是能通过 `next()` 给出下一项，并保存一次具体遍历状态的对象。

它至少需要知道怎样产生下一项，以及当前消费到了哪里。没有下一项时发出 `StopIteration`。状态不一定真的是整数下标；生成器会保存局部状态和继续执行位置，文件迭代器会保存读取进度。

常见错误是只说“迭代器能循环”，没有说明状态和结束规则。

### 第 4 题：可迭代对象与迭代器

**一句话结论：** 可迭代对象提供遍历入口，迭代器执行并记录某一次遍历。

`iter(list_object)` 会创建列表迭代器，而 `next(list_object)` 不成立，因此列表可迭代但不是迭代器。迭代器自己也必须能用于需要可迭代对象的地方，协议要求其 `__iter__()` 返回自身。

```text
列表 → 可以建立多个独立迭代器
迭代器 → 每次 next() 推进自己的位置
```

常见错误是把二者当成互斥类别。迭代器同时也是可迭代对象。

### 第 5 题：`iter()` 与 `next()`

**一句话结论：** `iter(obj)` 请求迭代器，`next(iterator)` 请求下一项。

`iter()` 让 `for` 不必了解对象的内部存储；`next()` 统一推进一次遍历。迭代器的 `__iter__()` 返回同一对象，所以不会复制当前位置，也不会自动重置。

还可以补充 `next(iterator, default)`：耗尽时返回默认值，而不是传播 `StopIteration`。

### 第 6 题：`StopIteration`

**一句话结论：** `StopIteration` 是迭代器自然结束的专用信号。

不能用 `None` 统一表示结束，因为 `None` 可以是合法数据，例如 `[1, None, 2]`。`for` 循环捕获这个信号并正常结束；手动调用 `next()` 时若不提供默认值，信号会表现为异常。

常见错误是把 `StopIteration` 说成程序故障。对协议而言，它是正常结束机制。

### 第 7 题：`for` 循环的内部过程

**一句话结论：** `for` 先取得迭代器，再反复取下一项，直到收到结束信号。

近似过程是：

```python
source = [1, 2, 3]
iterator = iter(source)
while True:
    try:
        value = next(iterator)
    except StopIteration:
        break
    # 执行循环体
```

因此 `for` 不要求输入支持下标。生成器、集合和文件都能使用同一协议。

### 第 8 题：迭代器协议

**一句话结论：** `__iter__()` 返回迭代器，`__next__()` 返回下一项或抛出 `StopIteration`。

迭代器自己的 `__iter__()` 必须返回 `self`。`__next__()` 每次调用推进状态，结束后应持续表示耗尽，不应悄悄重头开始。

常见错误是让 `__next__()` 在结束时返回 `None`，或让 `__iter__()` 每次把同一个迭代器重置。

完整类和特殊方法机制属于第 6 章，面试首轮不必深入属性查找。

补充追问时可以说明：若对象没有 `__iter__()`，`iter()` 还可能尝试旧的序列协议，从下标 `0` 开始调用 `__getitem__()`，直到收到越界结束信号。新自定义可迭代对象通常直接实现 `__iter__()`。

### 第 9 题：生成器函数

**一句话结论：** 函数体中包含 `yield` 的函数是生成器函数，调用它先创建生成器对象，不会立刻从第一行执行函数体。

第一次 `next()` 或由 `for` 发起的第一次消费才开始执行。这样才能把工作推迟到真正需要数据时。

常见错误是认为执行 `generator = produce()` 后，函数中的打印和文件读取已经发生。

### 第 10 题：`yield` 与状态保存

**一句话结论：** `yield value` 产出值并暂停本次函数执行，同时保存局部状态和继续位置。

下一次 `next()` 从该 `yield` 之后恢复，而不是从函数开头重来。局部名字仍保留上次暂停时的绑定，因此循环计数、累计值等状态可以自然延续。

回答到“产出、暂停、保存、恢复”四个动作已经足够完整。

### 第 11 题：`yield` 与 `return`

**一句话结论：** `yield` 产出并暂停，`return` 结束生成器。

生成器中的 `return value` 会成为最终 `StopIteration.value`，不会成为普通 `for` 循环的下一项。`for` 只把这个异常视为结束。`yield from` 可以接收子生成器的返回值。

常见错误是说“`yield` 等于可以执行很多次的 `return`”。二者的控制流语义不同。

### 第 12 题：生成器也是迭代器

**一句话结论：** 生成器对象自动实现迭代器协议，所以能用于 `for`、`next()` 和 `iter()`。

它保存一份正在进行的函数执行状态。对它调用 `iter()` 得到自身，同一个对象耗尽后不会重置。若要重新执行，通常再次调用生成器函数，创建新的生成器对象。

### 第 13 题：生成器表达式与列表推导式

**一句话结论：** 列表推导式立即计算并保存全部结果，生成器表达式按需计算并只保存迭代状态。

列表适合需要长度、下标、重复遍历或稳定快照的场景。生成器适合数据量大、只遍历一次、可以逐项处理或可能提前停止的场景。

生成器通常降低中间结果的峰值内存，但会耗尽，错误可能延后，也不支持普通列表式随机访问。

边界是最外层 `for` 后面的数据来源表达式会在创建生成器时求值；每项的转换和筛选仍推迟到消费时。

### 第 14 题：惰性计算

**一句话结论：** 惰性计算把工作推迟到结果被请求时才执行。

收益包括降低峰值内存、减少未使用计算、允许提前停止和表达无限序列。限制包括单向消费、不能自动重用、异常延后、资源生命周期更隐蔽，以及某些消费者仍会把全部结果物化。

常见错误是说“生成器一定更快”。它主要改变计算时机与存储策略，实际速度取决于任务。

### 第 15 题：`yield from`

**一句话结论：** `yield from iterable` 把逐项产出的工作委托给另一个可迭代对象。

`yield group` 会把整个 `group` 当作一项产出；`yield from group` 会依次产出其内部各项。对子生成器，`yield from` 还能接收其 `return` 值，并转发部分双向控制。

首轮回答说清逐项委托和与普通 `yield` 的区别即可。

### 第 16 题：`send()`、`throw()` 与 `close()`

**一句话结论：** `send()` 送值并恢复，`throw()` 在暂停点注入异常，`close()` 请求生成器结束。

刚创建的生成器尚未运行到 `yield`，没有能接收普通值的暂停表达式，因此通常先 `next(generator)` 或 `generator.send(None)` 启动。

常见错误是把这些接口当作所有生成器都应使用的标准写法。普通数据遍历通常只需要 `for` 和 `yield`。

### 第 17 题：`itertools`

**一句话结论：** `chain()` 串联输入，`islice()` 按位置消费切片，`count()` 持续产生等差数值。

三者都返回惰性迭代对象。`count()` 没有自然末尾，必须配合 `islice()`、条件、`break`、超时或取消机制。绝不能无界地把它转换成列表。

`takewhile()` 在条件第一次为假时停止，后面的元素不再检查；`dropwhile()` 只丢弃开头连续满足条件的元素，首次为假后产出包括该项在内的全部剩余项。`tee()` 提供逻辑上的多路迭代，但为了弥补各路消费进度差可能不断缓存数据，因此不是固定空间的免费复制。

### 第 18 题：文件逐行处理

**一句话结论：** 逐行迭代只需保留当前行和少量处理状态，适合大文件。

一次性 `read()` 会把剩余内容放入一个大字符串。返回文件生成器时要明确文件从何时打开、何时关闭；如果调用方只消费一部分，文件可能在生成器存活期间持续打开。应使用上下文管理，并约定调用方负责耗尽或关闭。

## 二、代码理解题

### 第 19 题：列表与列表迭代器

输出依次是：

```text
True
10
[20]
[]
```

`iter(iterator)` 返回同一迭代器。第一次 `next()` 消费 `10`，第一次 `list()` 从当前位置消费剩余的 `20`，之后迭代器已经耗尽。

错误回答通常把最后一次也写成 `[10, 20]`，这忽略了同一个迭代器的状态。

### 第 20 题：两个独立迭代器

输出是：

```text
1
2
1
[3]
[2, 3]
```

`first` 已消费两项，`second` 只消费一项。它们引用同一列表，但位置互不干扰。列表内容并未改变。

### 第 21 题：`break` 后的状态

循环先显示 `1`，随后 `next(iterator)` 显示 `2`。

`break` 只让消费者停止循环，不会自动把数据源消费到末尾。迭代器在取出 `1` 后仍保留后续状态。

### 第 22 题：生成器何时执行

依次是：

```text
[]
1 ['start']
2 ['start', 'middle']
```

创建生成器时函数体不执行。第一次消费执行到第一个 `yield`，第二次从该位置继续到第二个 `yield`。此时生成器刚在 `yield 2` 暂停，`"end"` 还没有执行；需要再次恢复，函数越过第二个 `yield` 后才加入。

### 第 23 题：生成器的 `return` 值

输出：

```text
A
done
```

第一次 `next()` 在 `yield "A"` 暂停。第二次恢复后执行 `return "done"`，生成器结束，字符串被放入最终 `StopIteration.value`。

### 第 24 题：共享同一个生成器

输出：

```text
0
1
[2, 3]
[]
```

`alias = source` 只增加一个指向同一生成器对象的名字，没有复制生成器状态。两个名字进行的消费共同推进同一个位置。

### 第 25 题：成员判断会消费

输出：

```text
True
[40]
```

成员判断依次消费 `10、20、30`，找到目标后停止，所以只剩 `40`。若查找 `99`，它会检查到末尾并返回 `False`，后续迭代器已经耗尽。

### 第 26 题：生成器表达式的求值时机

输出对应状态为：

```text
[]
0
[0]
[10, 20]
[0, 1, 2]
```

建立生成器表达式不调用 `transform()`。第一次 `next()` 只处理 `0`。之后 `list(values)` 消费剩余两项，因此事件记录补入 `1、2`。

### 第 27 题：`yield from` 与 `yield`

结果是：

```python
[[1, 2], [3]]
[1, 2, 3]
```

第一个函数每次把完整子列表当作一项；第二个函数把每个子列表的逐项产出委托出去。

### 第 28 题：`send()` 的暂停位置

输出依次是 `0、5、7`。

第一次 `next()` 运行到 `amount = yield total`，向外产出初始 `total`，此时 `amount` 尚未绑定。`send(5)` 使暂停的 `yield` 表达式结果为 `5`，所以 `amount = 5`；更新后再次产出 `5`。随后 `send(2)` 同理得到累计值 `7`。

### 第 29 题：无限迭代器与截取

输出是：

```python
[2, 5, 8, 11]
14
```

`count(2, 3)` 无限地产生公差为 `3` 的数。`islice(source, 4)` 只消费前四项，因此转换为列表能够结束；同一个 `source` 的下一项是 `14`。

### 第 30 题：惰性异常

先显示：

```text
created
10
20
```

随后消费到 `"bad"` 时，`int("bad")` 才抛出 `ValueError`，循环终止，`40` 不会被处理。创建生成器表达式时并未执行这些转换。

## 三、实现、找错与场景题

### 第 31 题：实现有限倒计时

一种清楚写法是：

```python
def countdown(start):
    current = start
    while current > 0:
        yield current
        current -= 1
```

它只保存当前整数，额外空间不随产出数量线性增长。`start <= 0` 时循环一次也不进入，生成器自然结束。

常见错误是先返回 `list(range(...))`，这满足数值结果，却没有按题意实现生成器。

### 第 32 题：实现逐层扁平化

```python
def flatten_once(groups):
    for group in groups:
        yield from group
```

也可以使用两层 `for`。题目只要求展开一层；若元素本身还包含更深嵌套，不应擅自递归展开。

### 第 33 题：修复重复消费错误

问题是 `values` 可能是一次性迭代器。第一个 `sum()` 消费完后，第二个 `sum(values)` 看不到数据。

若允许一次遍历，可以同时累计：

```python
def summarize(values):
    count = 0
    total = 0
    for value in values:
        count += 1
        total += value
    return count, total
```

这只用固定的累计状态。另一种修复是先 `values = list(values)`，但需要 `O(n)` 额外空间。面试中应优先说明单遍累计更符合当前需求。

### 第 34 题：逐行过滤数据

```python
def matching_lines(lines, keyword):
    for line in lines:
        if keyword in line:
            yield line.rstrip("\r\n")
```

使用 `rstrip("\r\n")` 只去掉行尾换行符；无参 `rstrip()` 还会删除其他尾部空白，可能改变原始数据语义。

### 第 35 题：选择列表还是生成器

1. 需要反复遍历和下标访问：列表更适合，因为结果已物化并支持随机访问。
2. 十 GB 日志找第一条错误：生成器或文件逐行迭代更适合，可以提前停止并控制内存。
3. 返回不可变化的时刻快照：物化结果更合适，可根据接口选择元组或列表副本；生成器可能看到延后的外部变化。
4. 单次汇总的多阶段流水线：生成器更适合，各阶段逐项传递，避免完整中间列表。

重点不是二选一口号，而是根据访问方式、数据规模、生命周期和是否需要快照选择。

### 第 36 题：生成器持有文件资源

生成器在第一次消费时打开文件后，可能暂停在第一个 `yield`，文件也随之保持打开。长期保存未关闭的生成器可能占用文件描述符，并让其他操作受到影响。

生成器内部应使用 `with open(...)` 确保退出时清理，调用方也应明确负责耗尽或调用 `close()`。更严格的接口可以由上下文管理器统一生成器和文件的生命周期，完整设计在第 7 章展开。

## 四、连续追问题

### 第 37 题：迭代协议连续追问

1. 列表只保存数据，不保存某一次遍历的唯一位置，也不实现供 `next(list)` 使用的接口，所以不是迭代器。
2. 每次创建新迭代器，可以支持嵌套循环和多个独立消费者。
3. 迭代器本身已经代表当前遍历，协议要求它的 `__iter__()` 返回自身，便于 `for` 统一处理输入。
4. 不一定。`break` 只是消费者停止，后续项通常仍保留在当前迭代器中。

回答时要持续围绕“数据对象”和“遍历状态对象”的职责分离。

### 第 38 题：生成器状态连续追问

1. 生成器保存局部名字的绑定、当前执行位置和运行状态等完成恢复所需的信息。
2. 没有。两个名字若指向同一生成器，就共享同一份状态。
3. 耗尽后不能通过 `iter()` 重置。
4. 通常再次调用生成器函数，获得新的生成器对象；若需要反复随机访问，可能应物化为列表。

常见错误是把重新绑定一个别名当作复制。

### 第 39 题：惰性计算连续追问

1. 它不预先保存全部中间结果，通常只保留当前项和必要状态。
2. 上游数据、内部缓存、闭包和外部资源仍可能很大；最终物化也会占用完整结果空间。
3. 转换逻辑到消费时才执行，因此错误也到相应项被请求时才出现。
4. `sum()`、`min()`、`max()` 通常消费到结束，但只保留累计状态或当前极值；它们与 `list()` 的完整物化不同。

### 第 40 题：数据流水线设计

可以把流程拆为“读取 → 清理 → 过滤 → 解析 → 分批”几个生成器阶段，每层接收上游可迭代对象并逐项产出。下游批量写入数据库，只有批次列表需要有界物化。

避免在中间无意调用 `list()` 或 `sorted()`。对持续流设置停止信号、超时或取消机制；批次达到大小或时间阈值时提交。解析错误应在靠近解析层记录或转换，数据库错误则在写入边界处理重试和事务。

文件、连接和事务应放入清楚的上下文管理边界。调用方提前停止时也必须能触发关闭。面试中继续追问时，应讨论背压、幂等重试和监控，但这些属于并发、异常与工程章节的深入内容。

创建 `map()`、`filter()` 或 `zip()` 对象通常只建立下游迭代关系；当 `next()`、`for`、`list()` 等消费者向下游请求数据时，请求才逐层传到上游。
