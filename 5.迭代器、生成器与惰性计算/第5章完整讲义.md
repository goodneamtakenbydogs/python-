# 第 5 章完整讲义：迭代器、生成器与惰性计算

## 1. `for` 循环与迭代协议

你已经写过这样的代码：

```python
names = ["Ada", "Lin", "Ming"]

for name in names:
    print(name)
```

表面上看，`for` 只是依次取出列表中的元素。但 `for` 不只支持列表：

```python
for character in "Python":
    print(character)

for key in {"theme": "dark", "size": 14}:
    print(key)

for number in range(3):
    print(number)
```

字符串、字典和 `range` 的内部结构并不相同，`for` 却能用同一种方式处理它们。这说明 `for` 并不是只认识列表，它依赖的是一套共同规则。

这套共同规则称为**迭代协议**。这里的“协议”不是网络协议，而是一组方法约定：对象只要按约定提供方法，就能参与相应的 Python 语言行为。

本章先不背特殊方法名，而是从 `for` 真正需要解决的问题出发：

1. 从哪个对象取得数据？
2. 当前已经走到哪里？
3. 怎样取得下一项？
4. 怎样知道已经没有下一项？

## 2. 遍历、迭代与消费

### 2.1 遍历、迭代与消费的含义

**遍历**强调目标：依次访问一组数据中的各项。

**迭代**强调过程：按照某种规则不断取得下一项，直到结束。

**消费**强调状态变化：每取得一项，迭代位置就向前推进；已经经过的数据通常不会自动重新出现。

例如：

```python
numbers = [10, 20, 30]
```

列表 `numbers` 保存三个值。真正遍历它时，还需要一个“当前位置”。第一次取 `10` 后，下一次应取 `20`。这个位置不适合直接保存在列表本身中，否则两个同时进行的循环就会互相干扰。

因此 Python 通常把职责分开：

```text
可迭代对象：提供数据的遍历入口
迭代器：保存一次具体遍历的当前位置
```

### 2.2 容器与可迭代对象的区别

容器是能够持有其他对象的对象，例如列表、元组、字典和集合。很多容器都可迭代，但“容器”和“可迭代”是两个不同角度：

- 容器回答“是否保存其他对象”。
- 可迭代回答“能否提供逐项遍历的入口”。

`range(1_000_000)` 可以逐项产生整数，却不需要像列表那样预先保存一百万个独立整数引用。文件对象也能逐行迭代，但它不是普通的内存容器。

所以不要把“可迭代对象”简单定义成“能装很多元素的东西”。

## 3. 可迭代对象是什么

### 3.1 可迭代对象的定义

**可迭代对象**（iterable）是能够交给 `iter()`，并由此取得迭代器的对象。

```python
numbers = [10, 20, 30]
iterator = iter(numbers)
```

这里：

- `numbers` 是可迭代对象。
- `iter(numbers)` 请求一次遍历所需的迭代器。
- `iterator` 记录这一次遍历走到哪里。

可以用 `iter()` 是否成功来判断一个具体对象能否按迭代协议使用：

```python
iter([1, 2])
iter("ab")
iter({"name": "Ada"})
```

整数本身没有“逐项遍历”的含义：

```python
# iter(42)  # TypeError
```

`TypeError` 表示当前操作不适用于这个类型。异常的完整体系将在第 7 章学习；此处只需要知道 `iter(42)` 无法建立迭代过程。

### 3.2 常见可迭代对象

常见例子包括：

- `list`、`tuple`、`str`、`range`。
- `dict`、`set`、`frozenset`。
- 文件对象。
- 生成器对象。
- `map`、`filter` 和许多 `itertools` 对象。
- 按迭代协议实现的自定义对象。

可迭代只承诺“能开始一次逐项访问”，不承诺：

- 一定有下标。
- 一定能取得长度。
- 一定能倒序访问。
- 一定能重复遍历。
- 一定把所有数据预先放在内存中。

## 4. 迭代器是什么

### 4.1 迭代器保存一次遍历的状态

**迭代器**（iterator）是能够通过 `next()` 给出下一项，并在内部保存当前遍历状态的对象。

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(next(iterator))  # 10
print(next(iterator))  # 20
print(next(iterator))  # 30
```

每次调用 `next(iterator)`，迭代器都完成两件事：

1. 返回当前位置对应的下一项。
2. 把内部状态推进到后面。

列表本身仍然是 `[10, 20, 30]`。变化的是 `iterator` 记录的位置，不是列表内容。

### 4.2 数据与游标的关系

可以把迭代器中的位置理解为“游标”。游标不是必须真实保存为一个整数，这是帮助理解的模型。

```text
numbers ─────────────→ [10, 20, 30]
                         ↑
iterator 第一次 next() 后 └── 下一项将是 20
```

再调用一次：

```text
numbers ─────────────→ [10, 20, 30]
                             ↑
iterator 第二次 next() 后 ──┘ 下一项将是 30
```

### 4.3 一个对象可以建立多个独立迭代器

```python
numbers = [10, 20, 30]
first_iterator = iter(numbers)
second_iterator = iter(numbers)

print(next(first_iterator))   # 10
print(next(first_iterator))   # 20
print(next(second_iterator))  # 10
```

两个迭代器都引用同一个列表，但各自保存自己的位置：

```text
numbers ─────→ [10, 20, 30]
                    ↑
first_iterator ─────┘ 下一项是 30

numbers ─────→ [10, 20, 30]
                ↑
second_iterator ┘ 下一项是 20
```

这就是列表不直接保存单一遍历位置的价值。嵌套循环和多个消费者可以分别进行。

## 5. `StopIteration`：怎样表示已经结束

### 5.1 没有下一项时不能返回普通数据

前三次 `next()` 已经取完 `[10, 20, 30]`。第四次没有值可以返回：

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

next(iterator)
next(iterator)
next(iterator)

# next(iterator)  # StopIteration
```

`StopIteration` 是一种异常，用来表示迭代器自然耗尽。这里不能用 `None` 表示结束，因为 `None` 本身完全可以是合法数据：

```python
values = [1, None, 2]
```

如果把 `None` 同时当作数据和结束标记，调用方就无法区分两种情况。

### 5.2 `next(iterator, default)`

内置函数 `next()` 可以接收第二个实参作为默认值：

```python
iterator = iter([10])

print(next(iterator, "结束"))  # 10
print(next(iterator, "结束"))  # 结束
```

提供默认值后，迭代器耗尽时返回该默认值，而不是把 `StopIteration` 传播给当前代码。

这与字典的 `get()` 类似：默认值改变的是调用方处理“没有结果”的方式，并没有给迭代器增加新数据。

### 5.3 耗尽后不会自动重置

```python
iterator = iter([1, 2])

print(list(iterator))  # [1, 2]
print(list(iterator))  # []
```

`list(iterator)` 会持续消费迭代器直到结束。第一次调用后，位置已经到达末尾；第二次不会自动回到开头。

如果原始对象可以重复迭代，可以重新请求一个新迭代器：

```python
numbers = [1, 2]

print(list(iter(numbers)))  # [1, 2]
print(list(iter(numbers)))  # [1, 2]
```

这里两次 `iter(numbers)` 得到了两次独立遍历。

## 6. 可迭代对象与迭代器的准确区别

### 6.1 可迭代对象与迭代器的包含关系

判断一个对象时，可以分别问：

1. 它能否提供迭代器？
2. 它自己能否通过 `next()` 给出下一项？

列表的回答是：

- 能提供迭代器，所以列表是可迭代对象。
- 列表自身不能直接传给 `next()`，所以列表不是迭代器。

列表迭代器的回答是：

- 能通过 `next()` 给出下一项，所以它是迭代器。
- 迭代器自身也能交给 `iter()`，所以它同时也是可迭代对象。

也就是说，迭代器也是可迭代对象，但可迭代对象不一定是迭代器。

### 6.2 为什么 `iter(iterator) is iterator`

```python
iterator = iter([1, 2, 3])

print(iter(iterator) is iterator)  # True
```

一个迭代器已经代表正在进行的一次遍历。迭代器协议要求它的 `__iter__()` 返回自身，所以 `iter(iterator) is iterator`；不会自动复制当前位置或重新开始。

这条规则让 `for` 可以统一接收两种输入：

- 如果输入是列表，`iter()` 建立新迭代器。
- 如果输入已经是迭代器，`iter()` 就使用当前这个迭代器。

因此，把已经消费一部分的迭代器交给 `for`，循环会从当前位置继续，而不是回到开头。

## 7. `for` 循环背后发生了什么

### 7.1 使用 `iter()` 与 `next()` 展开 `for`

这段代码：

```python
for value in [10, 20, 30]:
    print(value)
```

可以用下面的过程理解：

```python
iterator = iter([10, 20, 30])

while True:
    try:
        value = next(iterator)
    except StopIteration:
        break

    print(value)
```

`try` 表示尝试执行一段可能出现异常的代码；`except StopIteration` 表示只在收到这一结束信号时执行对应分支。完整异常语法在第 7 章展开。

`for` 的关键步骤是：

```text
对目标调用 iter()
→ 对得到的迭代器反复调用 next()
→ 把结果绑定给循环变量
→ 执行循环体
→ 遇到 StopIteration 时正常结束
```

### 7.2 `break` 与自然耗尽不同

```python
iterator = iter([10, 20, 30])

for value in iterator:
    print(value)
    break

print(next(iterator))  # 20
```

`break` 是消费者主动停止循环，并不表示数据源已经耗尽。当前迭代器仍保留在取出 `10` 之后的位置，所以再次调用 `next()` 得到 `20`。

### 7.3 `for` 不要求下标

`for` 循环不是不断执行 `values[index]`。很多可迭代对象没有整数下标，例如集合、生成器和普通文件迭代器。

这种设计让所有对象只需遵守“给出下一项”的约定，无须拥有同一种内部存储结构。

## 8. 迭代器协议的两个特殊方法

### 8.1 特殊方法是什么

`__iter__()` 和 `__next__()` 两侧都有双下划线，属于 Python 的**特殊方法**。特殊方法让对象参与内置语法和函数所定义的行为。

通常代码调用 `iter(obj)` 和 `next(iterator)`，由 Python 在背后寻找相应特殊方法，而不是到处手动写 `obj.__iter__()`。

完整的类和特殊方法机制在第 6 章学习。本章只掌握迭代协议所需的最低结构。

### 8.2 协议约定

一个迭代器需要：

- `__iter__()` 返回当前迭代器自身，即 `self`。
- `__next__()` 返回下一项；没有下一项时抛出 `StopIteration`。

这是本章采用的主要协议。为了兼容较早的序列写法，`iter(obj)` 在找不到 `__iter__()` 时，还可能尝试从 `obj[0]` 开始不断按整数下标取值，也就是使用 `__getitem__()` 的序列协议回退。新代码通常直接实现 `__iter__()`；`__getitem__()` 和完整数据模型在第 6 章学习。

下面的 `class CountdownIterator` 定义一类对象；调用 `CountdownIterator(3)` 会创建其中一个对象，称为实例。`__init__()` 在创建实例时接收起点并保存初始状态。方法中的 `self` 指向正在被使用的那个实例，`self.current` 是它保存当前位置的属性。`raise StopIteration` 则发出“没有下一项”的结束信号。第 6 章会系统解释类、实例和方法绑定；这里先用这几个含义读懂迭代器。

### 8.3 手写一个倒计时迭代器

```python
class CountdownIterator:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration

        value = self.current
        self.current -= 1
        return value
```

使用方式：

```python
class CountdownIterator:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value


countdown = CountdownIterator(3)

print(next(countdown))  # 3
print(next(countdown))  # 2
print(list(countdown))  # [1]
```

状态变化是：

```text
初始 current = 3
next() 返回 3，然后 current = 2
next() 返回 2，然后 current = 1
list() 继续取得 1，然后收到 StopIteration
```

### 8.4 为什么经常把可迭代对象与迭代器拆开

假设希望一个倒计时对象能够重复遍历，可以让它只保存起点，每次 `iter()` 都创建新迭代器：

```python
class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        return CountdownIterator(self.start)
```

于是：

```python
class CountdownIterator:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value


class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        return CountdownIterator(self.start)


values = Countdown(3)

print(list(values))  # [3, 2, 1]
print(list(values))  # [3, 2, 1]
```

`Countdown` 是可重复遍历的可迭代对象；每个 `CountdownIterator` 是一次会耗尽的遍历。

## 9. 为什么需要生成器

### 9.1 手写迭代器需要管理的状态与方法

刚才为了产生 `3、2、1`，写了类、状态属性、`__iter__()`、`__next__()` 和结束判断。逻辑本身很简单，管理暂停位置的代码却不少。

Python 提供**生成器**（generator）来自动管理这类状态。生成器仍然遵守迭代器协议，但通常可以用更接近普通函数流程的方式编写。

### 9.2 最小生成器函数

```python
def countdown(start):
    current = start
    while current > 0:
        yield current
        current -= 1
```

只要当前函数自己的代码块中包含 `yield`，这个函数就是生成器函数，调用它会得到生成器对象。嵌套在其中的另一个函数即使包含 `yield`，也不会自动让外层函数变成生成器函数。

```python
def countdown(start):
    current = start
    while current > 0:
        yield current
        current -= 1


generator = countdown(3)

print(next(generator))  # 3
print(next(generator))  # 2
print(list(generator))  # [1]
```

这个生成器与手写迭代器表达了相同的消费过程，但 Python 自动保存：

- 局部名字 `current` 的当前绑定。
- 下一次恢复时应继续执行的位置。
- 当前是否已经结束。

## 10. 调用生成器函数时发生什么

### 10.1 调用不会立刻执行函数体

观察下面的事件顺序：

```python
def produce():
    print("函数体开始")
    yield 10
    print("函数体继续")
    yield 20


generator = produce()
print("已经得到生成器")
```

此时只会先显示：

```text
已经得到生成器
```

`produce()` 创建并返回生成器对象，但函数体尚未从第一行开始运行。

### 10.2 第一次 `next()` 才开始

```python
def produce():
    print("函数体开始")
    yield 10
    print("函数体继续")
    yield 20


generator = produce()
first = next(generator)
```

现在函数体从开头执行：

```text
打印“函数体开始”
→ 遇到 yield 10
→ 把 10 交给调用方
→ 暂停在这里
```

第二次：

```python
def produce():
    print("函数体开始")
    yield 10
    print("函数体继续")
    yield 20


generator = produce()
next(generator)
second = next(generator)
```

执行过程是：

```text
从上次 yield 后恢复
→ 打印“函数体继续”
→ 遇到 yield 20
→ 把 20 交给调用方
→ 再次暂停
```

第三次 `next()` 从第二个 `yield` 后恢复。函数运行到末尾，于是生成器结束并发出 `StopIteration`。

### 10.3 创建生成器与消费生成器的执行时机

这是常见面试考点：

```text
调用普通函数：开始执行函数体，直到 return 或末尾
调用生成器函数：创建生成器对象
消费生成器：函数体才分段执行
```

如果生成器函数第一行会读取文件或打印日志，这些动作也通常要到第一次消费才发生。

## 11. `yield` 到底做了什么

### 11.1 `yield` 产出值、暂停执行并保存状态

执行到：

```text
yield current
```

生成器会：

1. 计算 `current` 对应的对象。
2. 把该对象作为本次 `next()` 的结果交给调用方。
3. 暂停函数体。
4. 保存局部状态和继续位置。

下次恢复时，从 `yield` 后面继续，而不是从函数第一行重新开始。

### 11.2 生成器循环在多次 `next()` 之间的执行过程

```python
def count_up(limit):
    current = 1
    while current <= limit:
        yield current
        current += 1
```

对 `count_up(3)` 的消费过程：

```text
创建生成器：函数体未开始
next()：current = 1，产出 1，暂停
next()：current 变为 2，产出 2，暂停
next()：current 变为 3，产出 3，暂停
next()：current 变为 4，循环结束，生成器结束
```

这不是每次调用都重新执行 `current = 1`。同一个生成器对象保存着同一次函数执行的状态。

## 12. `yield` 与 `return` 的区别

### 12.1 `yield` 的暂停与 `return` 的结束

在普通函数中，`return value` 把结果交给调用方并结束本次函数调用。

在生成器中：

- `yield value` 交出一个值并暂停，之后可以恢复。
- `return value` 结束生成器，之后不能继续产出普通项。

```python
def sample():
    yield "first"
    return "finished"
    yield "unreachable"
```

第三行之后的 `yield` 不会执行，因为 `return` 已经结束生成器。

### 12.2 生成器的返回值去了哪里

生成器中的 `return "finished"` 不会成为 `for` 循环中的下一项。它作为最终 `StopIteration` 的 `value` 属性传递：

```python
def sample():
    yield "first"
    return "finished"


generator = sample()

print(next(generator))  # first

try:
    next(generator)
except StopIteration as error:
    print(error.value)  # finished
```

普通 `for` 循环会把 `StopIteration` 当作结束信号，不会自动展示其中的返回值。`yield from` 可以接收子生成器的这个返回值，稍后会看到。

### 12.3 生成器的多次产出与最终结束

“生成器可以返回很多次”是一种不够准确的简写。准确说法是：生成器可以多次产出值并暂停，最终只能结束一次。`yield` 与 `return` 对控制流的影响不同。

## 13. 生成器对象也是迭代器

```python
def produce():
    yield 1
    yield 2


generator = produce()

print(iter(generator) is generator)  # True
print(next(generator))               # 1
print(list(generator))               # [2]
print(list(generator))               # []
```

生成器对象实现了迭代器协议，所以它：

- 可以交给 `iter()`。
- 可以交给 `next()`。
- 可以直接用于 `for`。
- 会保存当前位置。
- 会耗尽。

“生成器”和“迭代器”不是互斥身份。生成器是 Python 帮助我们创建迭代器的一种方式。

## 14. 生成器表达式与列表推导式

### 14.1 列表推导式的立即计算与生成器表达式的按需计算

列表推导式：

```python
squares_list = [number * number for number in range(5)]
```

生成器表达式：

```python
squares_generator = (number * number for number in range(5))
```

列表推导式立即完成全部计算，并建立完整列表。生成器表达式建立一个按需计算的生成器对象，只有消费时才逐项计算。

### 14.2 用事件观察计算时机

```python
def square(number):
    print("计算", number)
    return number * number


lazy_values = (square(number) for number in range(3))
print("表达式已经建立")

first = next(lazy_values)
```

建立 `lazy_values` 时不会立刻调用三次 `square()`。第一次 `next()` 只计算第一项。

需要区分“准备数据来源”和“计算每一项”：生成器表达式最外层 `for` 后面的可迭代对象表达式会在创建生成器时求值，产出表达式和逐项循环则等到消费时才执行。例如：

```python
def make_source():
    print("准备数据来源")
    return [1, 2]


values = (number * number for number in make_source())
print("生成器已创建")
```

此时先打印“准备数据来源”，再打印“生成器已创建”；平方运算仍要等到消费 `values` 时才发生。

### 14.3 生成器自身与上游数据的内存占用

比较内存时，重点不是简单打印一次 `sys.getsizeof()`，而是理解数据规模增长方式：

- 列表需要保存全部结果的引用，结果数量为 `n` 时额外存储通常随 `n` 增长。
- 生成器主要保存执行状态和当前位置，不保存全部历史结果，因此自身额外空间通常不随结果总数线性增长。

但生成器引用的上游对象、缓冲区和外部资源仍可能占用大量内存。不能把“用了生成器”直接等同于“整个程序内存一定很小”。

## 15. 惰性计算是什么

### 15.1 定义

**惰性计算**（lazy evaluation）是把计算推迟到结果真正被需要时再进行。

对应地，一次性计算并保存全部结果常被称为立即计算或急切计算。这里的“惰性”不是速度慢，而是“不提前做未被请求的工作”。

### 15.2 降低峰值内存、提前停止与生成无限序列

第一，降低峰值内存：

```python
total = sum(number * number for number in range(10_000_000))
```

`sum()` 逐项消费，不要求先保存一千万个平方值的列表。

第二，允许提前停止：

```python
first_large = next(
    number for number in range(1_000_000) if number * number > 10_000
)

print(first_large)  # 101
```

找到第一项后就停止，不计算后续所有候选。

第三，可以描述无限序列：

```python
def natural_numbers():
    current = 1
    while True:
        yield current
        current += 1
```

无限序列无法完整放入列表，但可以按需取有限部分。

### 15.3 惰性计算的代价

惰性计算也带来限制：

- 结果通常只能按顺序消费，不能随意按下标访问。
- 迭代器耗尽后不能自动重复使用。
- 错误可能延后到消费时才发生。
- 调试时创建位置和报错位置可能相隔较远。
- 如果最终确实需要随机访问全部结果，仍可能需要物化为列表。
- 某些工具为了支持多个消费者会在内部缓存，内存优势可能减弱。

选择规则不是“生成器永远比列表好”，而是：

```text
需要重复遍历、长度、下标或完整快照 → 列表往往更合适
数据很大、可逐项处理、可能提前停止 → 生成器往往更合适
```

## 16. 单次消费与共享迭代器陷阱

### 16.1 判断成员也可能消费

```python
iterator = iter([1, 2, 3, 4])

print(2 in iterator)  # True
print(list(iterator)) # [3, 4]
```

`2 in iterator` 为了寻找 `2`，依次消费了 `1` 和 `2`。后续从 `3` 开始。

如果查找的值不存在，成员测试可能把整个迭代器耗尽。

### 16.2 `zip()` 也会消费输入

```python
numbers = iter([1, 2, 3])
pairs = zip(numbers, ["A", "B"])

print(list(pairs))
print(list(numbers))
```

创建 `pairs` 时还没有逐项取值。`list(pairs)` 开始消费后，前两次配成 `(1, "A")`、`(2, "B")`。第三次先从左侧 `numbers` 取出 `3`，再发现右侧已经耗尽，因此这一项不能组成配对。两行分别显示 `[(1, 'A'), (2, 'B')]` 和 `[]`。

所以 `zip()` 提前结束时，某一路迭代器可能已经多前进了一项。分析这类代码要同时看各路迭代器的取值顺序，而不能只数最终配成了几对。

### 16.3 同一个迭代器不能当作两份独立数据

```python
values = (number for number in range(3))

first_use = list(values)
second_use = list(values)
```

第二次得到空列表不是因为数据被删除，而是同一个生成器的遍历状态已经到达末尾。

若确实需要多次使用，可以：

- 保存可重复迭代的原始数据，每次重新建立迭代器。
- 在规模可接受时一次性物化为列表。
- 在特定场景使用 `itertools.tee()`，但理解它可能缓存两路消费进度之间的数据。

## 17. `yield from`：把产出工作委托出去

### 17.1 用嵌套循环逐项产出内部元素

```python
def flatten(groups):
    for group in groups:
        for value in group:
            yield value
```

内层循环只是把 `group` 中的每一项原样产出，可以写成：

```python
def flatten(groups):
    for group in groups:
        yield from group
```

`yield from group` 的基本含义是：暂时把“逐项产出”的工作委托给 `group` 对应的迭代器，等它结束后再继续当前生成器。

### 17.2 `yield group` 与 `yield from group` 的区别

```python
def yield_groups(groups):
    for group in groups:
        yield group
```

输入：

```python
groups = [[1, 2], [3, 4]]
```

两种行为分别是：

```text
yield group      → 每次产出一个完整列表
yield from group → 依次产出列表内部的 1、2、3、4
```

### 17.3 子生成器的返回值

`yield from` 不只是替代一层 `for`。当委托对象是生成器时，它还能接收子生成器 `return` 携带的结束值：

```python
def child():
    yield 1
    return "child finished"


def parent():
    result = yield from child()
    print(result)
    yield 2
```

消费 `parent()` 时，先得到 `1`；子生成器结束后，`result` 绑定为字符串，再继续产出 `2`。

更完整的委托还涉及 `send()`、`throw()` 和 `close()` 的传递。面试首轮回答通常先说清逐项委托和子生成器返回值即可。

## 18. 用生成器建立处理流水线

### 18.1 去除空白、过滤空行与筛选错误行

假设输入是一组文本行：

```python
lines = [" INFO start ", "ERROR failed", "", " ERROR retry "]
```

可以拆成三个阶段：

```python
def stripped(lines):
    for line in lines:
        yield line.strip()


def nonempty(lines):
    for line in lines:
        if line:
            yield line


def errors(lines):
    for line in lines:
        if line.startswith("ERROR"):
            yield line
```

组合：

```python
def stripped(lines):
    for line in lines:
        yield line.strip()


def nonempty(lines):
    for line in lines:
        if line:
            yield line


def errors(lines):
    for line in lines:
        if line.startswith("ERROR"):
            yield line


lines = [" INFO start ", "ERROR failed", "", " ERROR retry "]
pipeline = errors(nonempty(stripped(lines)))

for line in pipeline:
    print(line)
```

输出是：

```text
ERROR failed
ERROR retry
```

为了得到第一条输出，调用链并不是一次处理完全部列表：

```text
最下游 errors 请求一项
→ nonempty 向 stripped 请求一项
→ stripped 取得 " INFO start "，产出 "INFO start"
→ nonempty 认为它非空，交给 errors
→ errors 发现它不以 "ERROR" 开头，继续向上游请求
→ 上游处理 "ERROR failed"
→ errors 产出第一条结果，整条流水线暂停
```

下游再次请求时，三个生成器都从各自暂停位置继续。每一层只保存自己的局部状态，并只完成得到下一项所必需的工作。

### 18.2 哪些操作会使流水线立即物化

下面这些操作通常会消费全部输入或建立完整结果：

- `list(iterator)`。
- `tuple(iterator)`、`set(iterator)`。
- `sorted(iterator)`。
- 需要完整数据才能得出结果的某些聚合或分组操作。

`sum()`、`min()`、`max()` 也会消费到结束，但它们通常只保留当前汇总状态，而不是保存全部输入。要区分“消费全部输入”和“把全部输入同时保存在内存中”。

## 19. `send()`：把值送回暂停位置

### 19.1 `yield` 也可以是表达式

普通写法：

```text
yield total
```

也可以把恢复时送入的对象绑定给名字：

```text
amount = yield total
```

一个运行中的累计生成器：

```python
def running_total():
    total = 0
    while True:
        amount = yield total
        total += amount
```

使用过程：

```python
def running_total():
    total = 0
    while True:
        amount = yield total
        total += amount


generator = running_total()

print(next(generator))   # 0
print(generator.send(5)) # 5
print(generator.send(2)) # 7
```

### 19.2 `next()` 与 `send()` 的暂停和恢复过程

第一次 `next(generator)`：

```text
total = 0
→ 执行 yield total，向外产出 0
→ 暂停，amount 还没有获得绑定
```

`generator.send(5)`：

```text
数字 5 成为暂停的 yield 表达式结果
→ amount = 5
→ total 变为 5
→ 循环再次到达 yield total
→ 向外产出 5 并暂停
```

### 19.3 为什么启动时不能直接发送普通值

刚创建的生成器还没有运行到任何 `yield`，不存在可以接收普通值的暂停位置。因此通常先使用：

```text
next(generator)
```

或等价地：

```text
generator.send(None)
```

`send()` 适合需要双向交互的状态机式代码，但普通数据遍历优先使用清楚的函数实参、返回值和普通 `yield`。现代异步代码主要使用 `async`/`await`，将在第 10 章学习。

## 20. `throw()` 与 `close()`

### 20.1 `throw()` 在暂停点注入异常

```python
def controlled(events):
    while True:
        try:
            yield "ready"
        except ValueError:
            events.append("handled")
```

在生成器暂停时调用：

```python
def controlled(events):
    while True:
        try:
            yield "ready"
        except ValueError:
            events.append("handled")


events = []
generator = controlled(events)
print(next(generator))                         # ready
print(generator.throw(ValueError("bad input")))  # ready
print(events)                                  # ['handled']
```

第一次 `next()` 让生成器暂停在 `yield "ready"`。调用 `throw()` 时，可以把过程理解为暂停的 `yield` 位置突然发生了 `ValueError`：

```text
ValueError 被当前 except 捕获
→ events 加入 "handled"
→ while 开始下一轮
→ 再次到达 yield "ready"
→ throw() 本次调用得到返回值 "ready"
```

如果生成器内部没有捕获被注入的异常，它会继续传播给 `throw()` 的调用方。

### 20.2 `close()` 请求结束

```python
def resourceful(events):
    try:
        yield "working"
    finally:
        events.append("cleanup")
```

`finally` 表示无论正常结束还是因为某些异常退出，都要尝试执行清理代码。完整语义在第 7 章学习。

```python
def resourceful(events):
    try:
        yield "working"
    finally:
        events.append("cleanup")


events = []
generator = resourceful(events)
next(generator)
generator.close()

print(events)  # ['cleanup']
```

`close()` 会在暂停位置触发内部结束信号 `GeneratorExit`。生成器一般应结束并执行必要清理，不应在收到关闭请求后继续正常产出值。

### 20.3 `send()`、`throw()`、`close()` 的使用场景

面试中知道三个接口的方向即可：

```text
send(value) → 向暂停的生成器送值并恢复
throw(error) → 在暂停位置注入异常
close() → 请求生成器结束并运行清理路径
```

普通业务遍历很少需要手动使用全部接口。不要为了显得高级，把本可用普通循环表达的逻辑改造成难以维护的双向生成器。

## 21. `itertools`：组合迭代过程的标准库

`itertools` 是 Python 标准库中的迭代工具模块。很多函数返回惰性的迭代器，可以像积木一样组合。

### 21.1 `chain()`：依次连接

```python
from itertools import chain

combined = chain([1, 2], (3, 4), [5])
print(list(combined))  # [1, 2, 3, 4, 5]
```

它不会先把所有输入拼成一个新列表，而是先消费第一个可迭代对象，再消费第二个。

### 21.2 `islice()`：对迭代流切片

```python
from itertools import islice

values = (number * number for number in range(100))
selected = islice(values, 2, 8, 2)

print(list(selected))  # [4, 16, 36]
print(next(values))     # 64
```

`islice(iterable, start, stop, step)` 与切片位置概念相似。这里跳过位置 `0、1`，产出位置 `2、4、6` 的平方值，并把上游推进到停止位置 `8`，所以之后 `next(values)` 得到位置 `8` 对应的 `64`。

`islice()` 按顺序消费输入，不支持负位置，也不会让只能向前的迭代器倒退。没有被选进结果的上游项也可能已经被跳过和消费。

### 21.3 `count()` 与无限迭代器

```python
from itertools import count, islice

numbers = count(10, 3)
first_four = islice(numbers, 4)

print(list(first_four))  # [10, 13, 16, 19]
```

`count(10, 3)` 会持续产生 `10、13、16……`，没有自然末尾。必须由 `islice()`、条件判断、`break` 或外部取消机制限制消费。

绝不能对无限迭代器执行：

```python
# list(count())  # 不会自然结束，并会持续消耗内存
```

### 21.4 `repeat()`、`takewhile()` 与 `dropwhile()`

```python
from itertools import dropwhile, repeat, takewhile

print(list(repeat("A", 3)))
print(list(takewhile(lambda value: value < 5, [1, 3, 5, 2])))
print(list(dropwhile(lambda value: value < 5, [1, 3, 5, 2])))
```

输出是：

```text
['A', 'A', 'A']
[1, 3]
[5, 2]
```

`repeat("A", 3)` 依次产生三次同一个字符串对象。

`takewhile()` 先检查 `1、3`，条件都为真，因此产出；检查到 `5` 时第一次为假，于是停止，后面的 `2` 即使满足条件也不会恢复。若输入是一个迭代器，这个让条件失败的 `5` 已经被取出，通常不能再从原迭代器中找回。

`dropwhile()` 的方向相反：它先丢弃开头连续满足条件的 `1、3`；遇到第一个不满足条件的 `5` 后停止检查条件，并直接产出 `5` 及后续所有项，所以后面的 `2` 也会保留。

### 21.5 `tee()` 的多路迭代与内部缓存

```python
from itertools import tee

source = (number for number in range(5))
first, second = tee(source, 2)

print(next(first))       # 0
print(next(first))       # 1
print(next(second))      # 0
print(list(second))      # [1, 2, 3, 4]
print(list(first))       # [2, 3, 4]
```

`first` 先读到 `0、1` 时，`second` 还停在开头。为了让 `second` 以后仍能得到这两项，`tee()` 需要暂存两路之间的进度差。随后 `second` 追上并继续读取源中的 `2、3、4`，这些尚未被 `first` 读取的项又需要为 `first` 保留。

`tee()` 返回的是逻辑上独立的迭代器，不是把全部源数据立即复制两份。若一路走得很快、另一路长期不消费，内部待保留的数据可能不断增长。

因此 `tee()` 解决的是逻辑上的多路消费，不保证固定内存，也通常不是线程安全共享方案。

## 22. 逐行处理文件与数据流

### 22.1 文件对象可以逐行迭代

```python
from io import StringIO


with StringIO("INFO start\nERROR failed\r\n") as file:
    for line in file:
        if "ERROR" in line:
            print(line.rstrip("\r\n"))
```

这里用 `StringIO` 模拟文件内容，使示例无需本地文件也能运行；真实文件可把创建表达式替换为 `open("events.log", encoding="utf-8")`。`with` 用于确保资源最终被关闭，完整上下文管理器机制在第 7 章学习。这里要观察的是：循环每次请求下一行，不要求先把整个文件读成字符串或列表。

`rstrip("\r\n")` 只删除行尾连续的回车和换行字符；无参数的 `rstrip()` 还会删除行尾空格和制表符。需要保留原始行尾空格时，两者不能互换。

### 22.2 与一次性读取比较

```python
from io import StringIO


with StringIO("INFO start\nERROR failed\n") as file:
    content = file.read()
```

`read()` 不带大小限制时通常读取剩余全部内容。若文件很大，内存中会同时保留整段字符串。

逐行处理通常只需要保存当前行和少量累计状态：

```python
from io import StringIO


error_count = 0

with StringIO("INFO start\nERROR failed\n") as file:
    for line in file:
        if "ERROR" in line:
            error_count += 1
```

### 22.3 返回生成器时注意资源生命周期

下面的函数存在隐患：

```python
def read_lines(path):
    file = open(path, encoding="utf-8")
    for line in file:
        yield line
```

文件何时关闭并不清楚。如果调用方只消费一部分后保留或丢弃生成器，资源生命周期容易变得隐蔽。

至少应把打开和关闭放在生成器内部的上下文中：

```python
def read_lines(path):
    with open(path, encoding="utf-8") as file:
        for line in file:
            yield line
```

即使如此，文件会从第一次消费开始保持打开，直到生成器耗尽、关闭或被清理。调用方应明确消费与关闭责任。第 7 章会系统学习资源管理。

### 22.4 文件、数据库、消息队列等数据流来源

数据流表示数据随时间或消费过程逐步到达，不要求一次拥有全部数据。它可以来自：

- 大文件中的行。
- 数据库查询的分批结果。
- 消息队列中的消息。
- 网络连接中的数据块。
- 持续产生的传感器事件。
- 内存中按需计算的序列。

生成器适合表达“得到一项、处理一项、继续等待下一项”的过程。

## 23. 遍历期间修改列表、字典和集合的影响

迭代器可能引用原始可变对象。如果遍历期间修改原对象，行为取决于具体对象和修改方式。

列表例子：

```python
numbers = [1, 2, 3]
visited = []

for number in numbers:
    visited.append(number)
    if number == 1:
        numbers.append(4)

print(visited)
print(numbers)
```

在常见 Python 3 列表迭代行为中，这段代码会继续访问追加到末尾的 `4`，两个列表都显示 `[1, 2, 3, 4]`。原因可以用“迭代器保存下一个位置，而列表长度已经改变”来理解。但边遍历边不断追加也可能让循环意外变长，甚至无法结束。

删除元素更容易造成跳项：

```python
numbers = [1, 2, 3, 4]
visited = []

for number in numbers:
    visited.append(number)
    if number in {1, 3}:
        numbers.remove(number)

print(visited)  # [1, 3]
print(numbers)  # [2, 4]
```

删除 `1` 后，原来的 `2` 左移到已经越过的位置，因此下一次直接看到 `3`；删除 `3` 后同理跳过 `4`。这些结果依赖具体容器及修改方式，不适合作为业务逻辑。

字典和集合在遍历期间改变大小，通常会抛出运行时错误：

```python
mapping = {"a": 1, "b": 2}

# for key in mapping:
#     mapping["c"] = 3  # RuntimeError
```

一般选择是：

- 遍历快照，例如 `for value in numbers.copy()`。
- 先记录待修改项，遍历结束后统一修改。
- 构造新容器，而不是边遍历边改原容器。

第 2 章已经讨论容器遍历期间修改；本章补充原因：迭代器的位置与底层结构变化可能不再一致。

## 24. 常见误解与陷阱

### 24.1 `for` 可用性与迭代器身份的区别

错误。列表能用于 `for`，但 `next(list_object)` 不成立。列表是可迭代对象，不是迭代器。

### 24.2 `iter()` 与数据复制的区别

通常不会。它取得或创建一个遍历对象；迭代器通常仍引用原始数据，而不是复制完整内容。

### 24.3 生成器函数体的开始执行时机

错误。调用生成器函数先创建生成器对象，第一次消费才开始执行函数体。

### 24.4 生成器耗尽后的重复使用

同一个生成器对象会耗尽。要重新遍历，通常需要再次调用生成器函数以创建新生成器。

### 24.5 生成器的内存收益与限制

生成器不保存全部已产生结果，但它可能引用庞大的上游对象、缓存、闭包状态或打开的资源。若最终又执行 `list(generator)`，完整结果仍会进入内存。

### 24.6 惰性计算中的异常延后

错误。实际转换和验证可能在消费时才发生：

```python
values = (int(text) for text in ["10", "bad", "30"])
```

创建 `values` 不会立刻因 `"bad"` 报错；消费到第二项时才会出现 `ValueError`。

### 24.7 `yield from` 的委托与控制传递

对于简单可迭代对象，它确实近似替代一层循环；对于生成器委托，它还处理返回值和双向控制传递，语义更完整。

### 24.8 无限迭代器的消费上限

无限迭代器本身不是问题，没有终止策略才是问题。与 `islice()`、条件、超时或取消机制组合后，它可以自然表达持续编号、轮询或事件流。

## 25. 怎样分析迭代与生成器代码

遇到复杂代码时，按以下顺序分析。

### 第一步：标出哪些是可迭代对象，哪些是迭代器

不要只凭变量名判断。检查对象来自列表、`iter()`、生成器函数调用、生成器表达式还是 `itertools`。

### 第二步：标出每次消费动作

以下操作都可能消费：

- `next()`。
- `for`。
- `list()`、`tuple()`、`set()`。
- `sum()`、`min()`、`max()`。
- `in` 成员测试。
- 消费 `zip()`、`map()`、`filter()` 等下游迭代器。

仅仅创建 `zip(...)`、`map(...)` 或 `filter(...)` 对象通常不会立即读取上游；当 `for`、`list()`、`next()` 等操作开始消费这些下游对象时，请求才会继续传到上游。

### 第三步：逐次记录当前位置

不要一句“生成器被执行了”带过。写成：

```text
第一次 next() 前：尚未开始
第一次 next() 后：暂停在第一个 yield
第二次消费后：局部状态是什么
何时耗尽
```

### 第四步：区分创建时间与执行时间

生成器表达式建立、生成器函数调用和真正的数据转换可能发生在不同时间。

### 第五步：检查是否共享同一个迭代器

两个名字可能指向同一个生成器对象。任何一个消费者推进后，另一个名字看到的也是推进后的状态。

### 第六步：检查终止与资源

确认数据源会自然结束，或调用方提供了明确上限；若涉及文件、连接或锁，还要确认提前停止时怎样清理。

## 26. 面试中怎样回答

### 26.1 可迭代对象与迭代器

首轮可以回答：

> 可迭代对象能够通过 `iter()` 提供迭代器；迭代器保存一次遍历状态，通过 `next()` 返回下一项，结束时发出 `StopIteration`。迭代器本身也是可迭代对象，其 `__iter__()` 必须返回自身。列表可迭代但不是迭代器，同一个列表可以创建多个独立迭代器。

### 26.2 `for` 循环原理

> `for` 先对目标调用 `iter()`，然后反复对得到的迭代器调用 `next()`，把每个结果绑定给循环变量；收到 `StopIteration` 时正常结束。它依赖迭代协议，不要求对象具有整数下标。

### 26.3 生成器

> 生成器是实现迭代器的一种方式。生成器函数包含 `yield`，调用时先得到生成器对象，第一次消费才开始执行。每次 `yield` 产出值并暂停，同时保存局部状态和继续位置；再次消费时从暂停处继续，最终结束后同样会耗尽。

### 26.4 列表推导式与生成器表达式

> 列表推导式立即计算并保存全部结果，适合需要重复遍历、长度或下标的场景；生成器表达式按需计算，适合大数据、流水线或可能提前停止的场景。生成器通常更省中间结果内存，但只能向前消费，耗尽后不能自动重用，错误也可能推迟到消费时出现。

- 第 2 章负责容器、复杂度、`deque`、`heapq` 和遍历修改问题；本章负责统一的迭代协议与消费状态。
- 第 3 章负责函数调用、局部作用域和调用栈；本章说明生成器函数如何暂停并保存本次调用状态。
- 第 4 章介绍 `map()`、`filter()` 的用途；本章解释它们为什么能按需产生结果。
- 第 6 章系统讲类、实例和特殊方法；本章只讲实现迭代协议所需的 `__iter__()`、`__next__()`。
- 第 7 章系统讲异常与资源管理；本章只给出理解 `StopIteration`、`throw()`、`close()` 和文件清理所需的最低解释。
- 第 10 章讲协程与 `async`/`await`；普通生成器可以双向通信，但不应把它与异步任务直接等同。
- 第 12 章系统讲文件和标准库；本章聚焦逐行迭代与惰性数据流。

## 28. 本章总结

1. 可迭代对象通过 `iter()` 提供迭代器。
2. 迭代器通过 `next()` 给出下一项，并保存一次遍历的位置。
3. 没有下一项时，迭代器发出 `StopIteration`。
4. `for` 循环就是对这套协议的自动驱动。
5. 迭代器同时也是可迭代对象，其 `__iter__()` 返回自身；可迭代对象不一定是迭代器。
6. 同一个可重复迭代对象可以创建多个独立迭代器；同一个迭代器会被所有消费者共同推进。
7. 生成器函数调用时先创建生成器，第一次消费才开始执行。
8. `yield` 产出并暂停，`return` 结束生成器。
9. 生成器表达式按需计算，列表推导式立即建立完整列表。
10. 惰性计算可以降低峰值内存并支持提前停止，但会带来单次消费、错误延后和资源生命周期问题。
11. `yield from` 用于委托子迭代对象；`send()`、`throw()`、`close()` 提供双向控制。
12. `itertools` 能组合有限或无限迭代过程，但无限流必须有明确终止策略。
