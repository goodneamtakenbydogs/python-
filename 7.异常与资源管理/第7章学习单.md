# 第 7 章学习单：异常与资源管理

## 1. 为什么学这一章

程序读文件、转换输入或调用外部服务时，失败不一定发生在函数的最后一行。若只处理正常返回路径，失败时可能留下打开的文件、未释放的锁或未回滚的操作。本章同时追踪两条线：**控制流现在走到哪里**，以及**资源现在由谁持有**。

```text
操作失败并产生异常
→ 沿调用栈寻找处理者
→ 需要的清理仍须执行
→ 调用方得到结果，或继续收到异常
```

## 2. 前置知识

- 第 1 章：表达式、条件与运行时对象。
- 第 3 章：函数调用、返回和调用栈。
- 第 5 章：`StopIteration` 作为迭代结束信号，生成器会暂停。
- 第 6 章：实例方法、继承、`__enter__()` 和 `__exit__()` 的最低限度含义。

本章会使用标准库 `io`、`contextlib` 和 `logging` 的小例子；各模块的完整工程用法不作为前置要求。

## 3. 知识点与目标

### 3.1 异常如何运行

- 区分语法错误与已经开始执行后的异常。
- 认识 `BaseException`、`Exception` 和常见具体异常之间的关系。
- 逐层画出异常传播与 traceback，不把“抛出”误当成“程序已经全部结束”。
- 说明 `except` 按顺序匹配类型，为什么具体类型应先于宽泛父类。

### 3.2 控制流与异常信息

- 对正常、被捕获、未被捕获、提前 `return` 四类路径分别分析 `try`、`except`、`else`、`finally`。
- 使用 `raise` 主动抛出，使用单独的 `raise` 在处理异常时重新抛出。
- 对照裸 `raise` 与 `raise error` 的 traceback 帧，说明“保留原位置”具体指什么。
- 区分隐式异常上下文、`raise ... from ...` 的显式原因和 `from None` 的显示抑制。
- 定义有明确语义的自定义异常，并保留有用的原始错误。
- 了解 `traceback`、日志和错误上下文的观察用途。
- 比较 EAFP 与 LBYL，避免过宽捕获和吞错。
- 用检查后状态变化的例子说明“先检查”为什么不是原子保证。

### 3.3 资源管理

- 说明资源的取得、使用、释放与所有权。
- 判断取得多个资源时部分成功、部分失败，由哪一层关闭已取得的部分。
- 使用 `try/finally` 处理正常返回和异常路径上的清理。
- 解释 `finally` 中的 `return`、`break` 或新异常为什么可能盖过原异常。
- 把 `with` 展开为 `__enter__()` 与 `__exit__()` 的调用过程。
- 判断上下文管理器何时传播、何时抑制异常。
- 编写类式和 `@contextmanager` 式上下文管理器。
- 识别文件、锁、事务等资源提前退出时的责任边界。
- 解释返回生成器后资源为何保持打开，以及显式 `close()` 怎样让 `with` 退出。
