# 第 4 章：闭包、装饰器与函数式工具

## 1. 函数对象在闭包与装饰器中的作用

第 3 章已经学过：执行 `def` 会创建函数对象，并把一个名字绑定到它；写出函数名只是在读取这个对象，后面加调用括号才会执行函数体。

```python
def double(number):
    return number * 2


operation = double
print(operation is double)  # True
print(operation(5))         # 10
```

这里发生了两件不同的事：

```text
operation = double
→ 让名字 operation 也指向同一个函数对象，没有调用函数

operation(5)
→ 通过名字 operation 找到函数对象，再使用实参 5 调用它
```

本章会沿着这个事实继续追问：

1. 函数对象能不能像普通数据一样保存、传入和返回？
2. 内层函数被返回后，为什么还能使用外层函数中的名字？
3. 怎样统一给多个函数增加日志、计时或缓存等行为？
4. `map()`、`filter()`、`partial()` 等工具为什么能接收函数？

答案会依次引出一等对象、高阶函数、回调、闭包、装饰器和函数式工具。现在不需要先背这些定义；每个术语会在相应代码已经能够读懂之后再命名。

## 2. 一等对象与高阶函数

### 2.1 一等对象是什么意思

先定义两个函数：

```python
def increase(number):
    return number + 1


def double(number):
    return number * 2
```

执行两条 `def` 后，关系可以画成：

```text
名字 increase ──→ 一个函数对象
名字 double   ──→ 另一个函数对象
```

`increase` 和 `double` 是名字，它们当前指向的才是函数对象。下面四种操作的对象都是函数对象。

第一，函数对象可以绑定给另一个名字：

```python
def double(number):
    return number * 2


saved = double

print(saved is double)  # True
print(saved(10))        # 20
```

`saved = double` 没有调用括号，所以它不会执行 `double`。这条赋值只是让 `saved` 也指向同一个函数对象。`saved(10)` 才是调用表达式。

第二，函数对象可以放入容器：

```python
def increase(number):
    return number + 1


def double(number):
    return number * 2


operations = [increase, double]

for operation in operations:
    print(operation(10))
```

输出是：

```text
11
20
```

`operations` 是列表对象，其中两个元素是函数对象。循环第一次让名字 `operation` 指向 `increase` 所指的函数，第二次让它指向 `double` 所指的函数。每次执行 `operation(10)` 时才真正调用当前函数。

第三，函数对象可以作为实参传给另一个函数。下一节会完整跟踪这个过程。

第四，函数对象可以作为返回值：

```python
def increase(number):
    return number + 1


def double(number):
    return number * 2


def choose_operation(use_double):
    if use_double:
        return double
    return increase


chosen = choose_operation(True)
print(chosen(10))  # 20
```

`return double` 返回的是函数对象，没有调用它。调用者先让 `chosen` 指向这个对象，后面的 `chosen(10)` 才执行函数。

像普通数据一样能够被名字引用、存入容器、作为实参传入并作为返回值交出的对象，常称为**一等对象**。所以准确说法是“Python 中的函数是对象，并且函数对象是一等对象”。这里没有哪个“变量是一等对象”：`double`、`saved`、`operation` 和 `chosen` 都是名字。

### 2.2 高阶函数

现在观察函数对象作为实参传入的过程：

```python
def increase(number):
    return number + 1


def double(number):
    return number * 2


def apply(operation, value):
    return operation(value)


print(apply(double, 6))
```

执行过程是：

```text
调用 apply(double, 6)
→ 实参 double 得到函数对象，形参 operation 绑定到该对象
→ 实参 6 得到整数对象，形参 value 绑定到 6
→ 执行 operation(value)，相当于执行 double(6)
→ double 返回 12，apply 再返回 12
```

换成 `apply(increase, 6)` 时，`operation(value)` 相当于 `increase(6)`，结果是 `7`。`apply` 不需要把“加一”和“乘二”写死，它接收要执行的行为。

**接收函数对象作为实参，或者返回函数对象的函数，称为高阶函数。** `apply` 接收函数对象，所以是高阶函数；上一节的 `choose_operation` 返回函数对象，也是高阶函数。`double` 只接收数字，它不会因为曾被传给 `apply` 就变成高阶函数。

### 2.3 回调函数

在 `apply(double, 6)` 中，`double` 被交给 `apply`，再由 `apply` 的函数体调用。一个函数对象被交给其他代码，并由接收方在需要时调用，它在这次使用中通常称为**回调函数**。

因此，同一次合作可以从两个方向描述：

```text
apply  接收并调用其他函数 → apply 是高阶函数
double 被交给 apply 调用   → double 在这里扮演回调
```

`apply` 和 `double` 是两个不同的函数对象。“高阶函数”说明 `apply` 接收函数对象，“回调”说明 `double` 在这次调用中被交给 `apply` 执行。这两个称呼描述调用关系，不是 Python 将函数划分出的两种互斥类型。

排序的 `key` 是常见实例：

```python
names = ["Li", "Alexander", "Chen"]
ordered = sorted(names, key=len)
print(ordered)  # ['Li', 'Chen', 'Alexander']
```

这里需要分清三样东西：

```text
key → sorted() 的形参名称
len → 传给 key 的函数对象，在这里扮演回调
2、9、4 → sorted() 对三个字符串调用 len 后得到的排序依据
```

`sorted()` 根据这些长度安排元素顺序，返回的仍是原来的字符串。这里写 `key=len` 是传入函数对象；若写 `key=len()`，Python 会在调用 `sorted()` 之前立刻调用 `len`，而且没有提供待计算长度的对象，因此会先抛出 `TypeError`。

## 3. 嵌套函数

### 3.1 函数体内也能定义函数

```python
def outer():
    def inner():
        return "inside"

    return inner()


print(outer())
```

执行过程是：

```text
调用 outer()
→ 执行 def inner，创建内层函数对象
→ outer 本次调用中的局部名字 inner 指向它
→ 执行 inner()，得到字符串 "inside"
→ outer 返回这个字符串
```

这里 `return inner()` 返回的是调用结果。`inner` 函数对象没有被交给外部代码。

### 3.2 内层函数可以使用外层名字

```python
def outer():
    message = "from outer"

    def inner():
        return message

    return inner
```

现在 `return inner` 没有调用括号，返回的是内层函数对象：

```python
def outer():
    message = "from outer"

    def inner():
        return message

    return inner


reader = outer()
print(reader())  # from outer
```

`reader = outer()` 调用外层函数，得到 `inner` 函数对象；`reader()` 才调用这个内层函数。`inner` 自己没有绑定 `message`，读取时按 LEGB 到 Enclosing 外层函数作用域找到它。

对比两种写法：

```text
return inner() → 先调用 inner，返回 inner 的结果
return inner   → 返回 inner 函数对象，交给调用者以后再调用
```

第二种写法产生了新的问题：`outer()` 已经结束，`reader()` 为什么仍能读取原来外层调用中的 `message`？这就是闭包要解释的现象。

## 4. 闭包：内层函数与外层变量绑定

### 4.1 返回内层函数对象

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor

    return multiply


double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))
print(triple(10))
```

输出是 `20` 和 `30`。以 `double = make_multiplier(2)` 为例：

```text
调用 make_multiplier(2)
→ 外层形参 factor 绑定到 2
→ 执行 def multiply，创建内层函数对象
→ return multiply 返回这个函数对象
→ 名字 double 绑定到返回的函数对象

调用 double(10)
→ 内层形参 value 绑定到 10
→ 读取外层 factor 得到 2
→ 返回 10 * 2，也就是 20
```

注意 `return multiply` 没有调用括号。外层函数返回的是内层函数对象，而不是一次乘法结果。

### 4.2 外层函数返回后的变量访问

执行 `double = make_multiplier(2)` 后，`make_multiplier` 本次调用已经返回。普通局部名字通常随调用结束而不可再从外部直接访问，但返回的 `multiply` 仍需要 `factor`。

可以画成：

```text
double ──→ multiply 函数对象
           自由变量 factor ──→ 2

triple ──→ 另一个 multiply 函数对象
           自由变量 factor ──→ 3
```

Python 会让返回函数继续获得运行所需的外层绑定。

### 4.3 自由变量

在 `multiply` 中：

- `value` 是它自己的局部形参。
- `factor` 不是它的局部名字，也不是模块全局名字，而是来自外层函数。

这种被函数使用、但不在该函数局部绑定的外层名字，称为自由变量。更严格的自由变量判断还涉及编译时作用域分析，本章只需能在具体嵌套函数中找出来。

这里的“外层”特指**外层函数的局部作用域**，不是说只要名字写在函数外面就算。先看模块顶层的名字：

```python
global_records = []


def record_global(value):
    global_records.append(value)


record_global("A")
print(global_records)  # ['A']
```

`record_global` 读取 `global_records` 时按 LEGB 到 Global（模块全局作用域）寻找。它确实使用了函数外的列表，但没有捕获任何外层函数的局部名字，因此这个例子不是闭包。

再把列表放进另一个函数的局部作用域：

```python
def make_recorder():
    local_records = []

    def record(value):
        local_records.append(value)
        return local_records.copy()

    return record


recorder = make_recorder()
print(recorder("A"))  # ['A']
print(recorder("B"))  # ['A', 'B']
```

`record` 的 `value` 是自己的局部形参，`local_records` 则要到 Enclosing（外层函数作用域）寻找。`make_recorder()` 返回后，`record` 仍保有访问这次调用中 `local_records` 的能力，所以它形成闭包。两次调用 `recorder()` 继续使用同一个列表。

### 4.4 闭包的定义与成立条件

闭包可以理解为：

> 一个函数，以及它在之后执行时仍然需要访问的外层变量绑定。

仅仅把函数写在另一个函数里面还不够：内层函数要使用外层函数的局部名字，才有需要保留的绑定。**内层函数是否被返回不是闭包的判定条件**；即使它只在外层调用期间执行，也可以形成闭包。前面的例子返回内层函数，是为了更明显地观察外层调用结束后状态依然可用。

## 5. 闭包保存的外层变量绑定

### 5.1 闭包对外层绑定的访问

闭包经常被口语化描述为“记住外层变量”。这有助于入门，但容易误解成定义时把值复制了一份。

观察闭包建立后，原列表又发生变化的情况：

```python
def make_reader(source):
    def read():
        return source.copy()

    return read


values = []
reader = make_reader(values)

values.append("A")
print(reader())  # ['A']
```

调用 `make_reader(values)` 时，外层形参 `source` 与调用处名字 `values` 指向同一个列表。返回的 `read` 需要外层名字 `source`，所以它保留访问这个绑定的能力。后来通过 `values.append("A")` 修改共享列表，再调用 `reader()` 就会看到新内容。

如果闭包只是复制了创建时的空列表值，这里就不应看到 `"A"`。实际结果说明：闭包保留了访问所需绑定和对象的关系，而不是把代码文本旁边的值机械拍成快照。

### 5.2 多个内层函数可以共享状态

```python
def make_box():
    values = []

    def add(value):
        values.append(value)

    def read():
        return values.copy()

    return add, read


add, read = make_box()
add("A")
add("B")
print(read())
```

输出是 `['A', 'B']`。`add` 和 `read` 来自同一次外层调用，共享同一个 `values` 绑定及列表对象：

```text
add  闭包 ─┐
           ├──→ 外层 values ──→ 列表对象
read 闭包 ─┘
```

调用 `add()` 修改列表内容；调用 `read()` 返回当前内容的副本。两个函数分工不同，但状态来自同一次 `make_box()` 调用。

### 5.3 不同外层调用通常建立独立状态

```python
def make_box():
    values = []

    def add(value):
        values.append(value)

    def read():
        return values.copy()

    return add, read


first_add, first_read = make_box()
second_add, second_read = make_box()

first_add("A")
second_add("B")

print(first_read())
print(second_read())
```

输出分别是 `['A']` 和 `['B']`。两次 `make_box()` 调用各自建立新的局部 `values` 绑定和新列表，因此状态互相独立。是否共享状态取决于函数来自同一次还是不同次外层调用，不能只看它们的代码长得是否一样。

## 6. 用函数属性观察闭包

本节用于验证刚才建立的模型，不是理解闭包的前置条件。第一次学习如果只想掌握闭包的使用，可以先读结论，等学完 `nonlocal` 和晚绑定后再回来运行这些观察代码。

### 6.1 `__closure__` 与自由变量名称

函数对象公开了一些用于观察闭包的信息：

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor

    return multiply


double = make_multiplier(2)

print(double.__code__.co_freevars)
print(double.__closure__)
```

第一行会看到自由变量名称 `('factor',)`；第二行会看到包含闭包单元格的元组，具体显示形式带有运行时地址，不需要背诵。

- `double.__code__.co_freevars` 可观察函数代码使用的自由变量名称。
- `double.__closure__` 通常是保存相关单元格对象的元组；没有闭包时可能是 `None`。

代码对象可以先理解为函数所关联的已编译代码及其名称等运行信息。这里看到的都是双下划线特殊属性或代码对象信息。当前只用来验证概念，不要求记忆内部布局，也不应通过修改内部单元格实现业务逻辑。对象数据模型在第 6 章完整学习。

### 6.2 闭包单元格与共享绑定

多个函数可能需要共享同一个外层绑定，因此实现不能只把一个普通值文本塞进每个函数。可以暂时把闭包单元格理解成保存并共享外层绑定的容器。

具体内存布局属于实现细节。面试通常要求解释闭包行为和晚绑定，不要求背 CPython 单元格结构。

## 7. `nonlocal` 与闭包状态

### 7.1 只读取不需要 `nonlocal`

```python
def make_reader(value):
    def read():
        return value

    return read
```

内层函数只读取外层 `value`，按 LEGB 即可。

### 7.2 重新绑定需要 `nonlocal`

先看缺少声明时的问题：

```python
def make_broken_counter():
    count = 0

    def increase():
        count += 1
        return count

    return increase
```

调用返回的 `increase()` 会出现 `UnboundLocalError`。因为函数体中存在对 `count` 的赋值，`count` 被判定为 `increase` 的局部名字；执行 `count += 1` 时需要先读取旧值，但这个局部名字还没有绑定对象。

若目标是重新绑定外层函数中的 `count`，要明确声明：

```python
def make_counter():
    count = 0

    def increase():
        nonlocal count
        count += 1
        return count

    return increase


counter = make_counter()
print(counter())
print(counter())
```

两次输出 `1`、`2`。`nonlocal count` 表示 `increase` 中针对 `count` 的赋值使用最近的已有外层函数绑定；每次调用都更新同一绑定。

### 7.3 修改外层可变对象通常不需要 `nonlocal`

```python
def make_collector():
    values = []

    def collect(value):
        values.append(value)
        return values.copy()

    return collect
```

`append()` 修改列表对象，没有让名字 `values` 重新绑定，因此不需要 `nonlocal values`。

判断方法仍然来自前两章：这一行是在修改对象，还是给名字重新赋值？

## 8. 闭包的晚绑定

### 8.1 循环中创建的函数共享循环变量

```python
def make_late_readers():
    functions = []
    for number in range(3):
        def read():
            return number

        functions.append(read)
    return functions


functions = make_late_readers()
print(functions[0] is functions[1])  # False
for function in functions:
    print(function())
```

输出先是 `False`，然后依次是 `2、2、2`。每轮执行 `def read` 都创建一个新的函数对象；名字 `read` 改为指向新对象，`functions.append(read)` 则把该对象保存到列表，所以三个元素确实是三个不同函数。

但同一次 `make_late_readers()` 调用只有一个局部名字 `number`。普通 `for` 循环每轮重新绑定这个名字，不会为每一轮建立新的函数作用域：

```text
第 1 轮：number → 0，创建函数 A，A 将来读取 number
第 2 轮：number → 1，创建函数 B，B 将来读取同一个 number
第 3 轮：number → 2，创建函数 C，C 将来读取同一个 number
循环结束后：number → 2
之后才调用 A、B、C：每次都读到当前的 2
```

因此，“创建了三个函数对象”与“保存了三个不同的 `number` 值”不是同一件事。外层调用结束后，三个返回的函数仍读取这次调用留下的同一个 `number` 绑定：

```text
函数 A ─┐
函数 B ─┼──→ 同一个外层绑定 number ──→ 2
函数 C ─┘
```

### 8.2 为什么叫晚绑定

自由变量通常在函数被调用时解析当前绑定，而不是创建函数对象时把普通值复制进去，因此称为晚绑定。

上面的例子只使用普通 `def`，说明晚绑定来自外层名字的查找时机。第 18 节学完 `lambda` 后，会看到用简短函数表达式写出的同类代码也遵守这条规则。

### 8.3 用形参默认值固定当前对象

```python
def make_fixed_readers():
    functions = []
    for number in range(3):
        def read(number=number):
            return number

        functions.append(read)
    return functions


functions = make_fixed_readers()
for function in functions:
    print(function())
```

这次依次输出 `0、1、2`。在 `def read(number=number)` 中，等号两侧的 `number` 作用不同：

```text
等号右侧 number → 本轮执行 def 时，读取外层循环名字的当前绑定
等号左侧 number → 新创建函数自己的局部形参
```

三轮创建的函数分别保存 `0、1、2` 作为各自形参的默认对象。以后调用时没有提供实参，就使用对应默认值；函数体读取的是自己的局部形参，不再读取共享的外层 `number`。

这利用了第 3 章“默认值表达式在函数定义时求值”的规则。它不是关闭晚绑定开关，而是改变数据来源。

### 8.4 使用函数工厂建立独立作用域

**函数工厂**是负责创建并返回函数对象的函数。每次调用工厂都可以建立一组新的配置或外层绑定，因此得到的函数可以彼此独立。

```python
def make_reader(value):
    def read():
        return value

    return read


functions = []
for number in range(3):
    functions.append(make_reader(number))

for function in functions:
    print(function())
```

这里依次输出 `0、1、2`。外层循环每轮都会调用一次 `make_reader(number)`；第一次调用建立自己的局部 `value` 并绑定到 `0`，后两次调用分别建立新的局部 `value` 并绑定到 `1`、`2`。返回的三个 `read` 函数因此各自访问不同次调用中的绑定。第 8.1 节则是在**同一次** `make_late_readers()` 调用中创建三个函数，让它们共同读取一个 `number` 绑定。

## 9. 闭包的适用场景与代价

### 9.1 保存少量配置

```python
def make_prefixer(prefix):
    def add_prefix(text):
        return prefix + text

    return add_prefix


add_error_prefix = make_prefixer("ERROR: ")
print(add_error_prefix("disk full"))  # ERROR: disk full
```

`make_prefixer()` 接收一次配置并返回函数；以后每次调用 `add_error_prefix()` 都复用外层 `prefix`。当配置较少、行为单一时，这比每次重复传入前缀更方便。

### 9.2 封装轻量状态

前面的 `make_counter()` 和 `make_box()` 展示了闭包可以保存少量状态。适合的特征通常是：状态项很少、只暴露一两个操作、调用关系容易从局部代码看清。计数器、简单累积器和一次性配置都属于这类场景。

### 9.3 闭包与类的适用场景

如果状态逐渐增加，例如同时保存名称、上限、历史记录和错误状态，还需要重置、暂停、导出等多个操作，多个内层函数会越来越难组织。此时类通常能用属性和方法更清楚地表达结构。类和实例在第 6 章学习。

选择时可以先问：

```text
少量配置或状态 + 少量操作 → 闭包可能清楚
多个状态 + 多个相关操作 + 需要扩展和调试 → 类通常更清楚
完全不需要保存外层状态 → 普通函数通常已经足够
```

### 9.4 生命周期和测试

只要闭包函数仍被引用，它需要的外层对象也可能继续存活。状态隐藏在闭包中还可能增加测试和序列化难度。**序列化**表示把对象或状态转换成适合保存、传输并在之后恢复的形式；闭包捕获的运行状态不一定能被简单序列化。对象生命周期和垃圾回收在第 9 章展开，序列化工具在第 12 章学习。

## 10. 从手工包装到装饰器

### 10.1 给函数增加前后行为

```python
def greet(name):
    return f"Hello, {name}"


def traced_greet(name):
    print("before")
    result = greet(name)
    print("after")
    return result


print(traced_greet("Ming"))
```

输出依次是 `before`、`after`、`Hello, Ming`。调用者先进入 `traced_greet`，它在调用原函数 `greet` 的前后增加动作，再把原结果交还调用者。像这样**接住调用、在原函数调用周围增加行为的函数**，称为包装函数，也常叫包装器（wrapper）。这描述的是函数在这里的作用，不是 Python 新增的一种函数类型。

如果有几十个函数都需要相同日志，手工写几十个 `traced_greet` 式的包装函数会重复。日志可以先理解为程序记录“何时执行了什么、是否成功”等运行事件的信息，第 26 节会给出工程边界。既然函数可以作为实参和返回值，就能把创建包装函数的过程抽出来。

### 10.2 接收原函数，返回包装函数

下面让外层 `trace` 接收原函数，并在内部创建、返回一个包装函数。内层名字写作 `wrapper` 只是常见命名；换成其他名字，包装行为并不会改变。

```python
def greet(name):
    return f"Hello, {name}"


def trace(function):
    def wrapper(*args, **kwargs):
        print("before")
        result = function(*args, **kwargs)
        print("after")
        return result

    return wrapper


decorated_greet = trace(greet)
print(decorated_greet("Ming"))
```

执行 `decorated_greet = trace(greet)` 时：

```text
形参 function 指向原 greet 函数对象
→ 创建 wrapper 函数对象
→ return wrapper 把包装函数交给调用者
→ 名字 decorated_greet 指向 wrapper
```

这一步没有调用原 `greet`。随后执行 `decorated_greet("Ming")` 才进入 `wrapper`，输出顺序是：

```text
before
after
Hello, Ming
```

这里的三个角色分别是：`greet` 是原函数，`trace` 接收原函数并返回替代函数，因此是**装饰器**；`wrapper` 是返回的**包装函数**，以后负责接住调用、执行前后动作和调用原函数。`wrapper` 需要自由变量 `function`，所以又是闭包。`trace` 接收并返回函数，因此也是高阶函数。

### 10.3 装饰器的核心定义

装饰器是接收一个对象并返回替代对象的可调用对象。函数装饰器通常接收原函数，返回包装函数。

装饰器不一定必须返回普通函数，也不一定必须使用闭包；这是最常见、最适合入门的形式。

## 11. `@trace` 与函数名的重新绑定

### 11.1 为什么要重新绑定原名字

上一节把包装后的函数交给新名字 `decorated_greet`，原名字 `greet` 仍指向原函数。如果调用者一直使用 `greet("Ming")`，就不会经过包装器。要让原名字也代表包装后的行为，可以手工重新绑定：

```python
def trace(function):
    def wrapper(*args, **kwargs):
        print("before")
        result = function(*args, **kwargs)
        print("after")
        return result

    return wrapper


def greet(name):
    return f"Hello, {name}"


greet = trace(greet)
print(greet("Ming"))
```

执行 `greet = trace(greet)` 时，右侧的 `greet` 先得到原函数对象，`trace` 接收它并返回 `wrapper`；赋值后，左侧名字 `greet` 改为指向 `wrapper`。此时仍未执行原函数。最后调用 `greet("Ming")`，才依次显示 `before`、`after`、`Hello, Ming`。

### 11.2 `@trace` 是这次重新绑定的简写

Python 允许把 `@trace` 写在函数定义前。这里的 `@` 是装饰器语法，`trace` 是下面先定义好的普通函数名；Python 创建原始 `greet` 函数对象后，会把它交给 `trace`，再让名字 `greet` 指向返回的包装函数：

```python
def trace(function):
    def wrapper(*args, **kwargs):
        print("before")
        result = function(*args, **kwargs)
        print("after")
        return result

    return wrapper


@trace
def greet(name):
    return f"Hello, {name}"


print(greet("Ming"))
```

它与上一完整示例中的 `greet = trace(greet)` 有相同的核心效果和输出。`trace` 必须在执行这条装饰后的函数定义之前已经存在。资料中有时写 `@decorator` 来表示通用形式，其中 `decorator` 只是装饰器位置的占位名称，不是 Python 关键字；当前真正使用的名字是 `trace`。这种方便的书写形式称为**语法糖**，没有创造另一套包装机制。

### 11.3 原名字被重新绑定

装饰前：

```text
greet ──→ 原函数
```

装饰后：

```text
greet ──→ wrapper
          闭包中的 function ──→ 原函数
```

调用者继续写 `greet("Ming")`，实际先进入包装函数。

### 11.4 装饰阶段与调用阶段

前面两个例子中的 `trace` 在装饰阶段确实会执行，但它的外层函数体没有 `print()`，所以此时不会显示 `before` 或 `after`。那两句打印位于返回的 `wrapper` 函数体中，要等以后调用 `greet("Ming")` 才执行。

为了实际观察两个阶段，把打印分别放进外层 `trace` 和内层 `wrapper`：

```python
def trace(function):
    print("decorating")

    def wrapper(*args, **kwargs):
        print("before")
        result = function(*args, **kwargs)
        print("after")
        return result

    return wrapper


@trace
def greet(name):
    return f"Hello, {name}"


print("defined")
print(greet("Ming"))
```

输出顺序是：

```text
decorating
defined
before
after
Hello, Ming
```

执行带 `@trace` 的函数定义时，Python 创建原始 `greet` 函数对象，立即调用外层 `trace`，所以先显示 `decorating`；`trace` 返回 `wrapper` 后，名字 `greet` 指向它，接着显示 `defined`。此时原函数体和 `wrapper` 函数体都还没有执行。调用 `greet("Ming")` 后才进入 `wrapper`，显示 `before`，调用原函数取得结果，显示 `after`，最后由外层 `print` 显示返回值。

```text
定义阶段：创建原函数 → 调用 trace(原函数) → greet 改为指向 wrapper
调用阶段：调用 greet(...) → 进入 wrapper → wrapper 调用原函数
```

## 12. 包装器为什么使用 `*args` 和 `**kwargs`

### 12.1 固定形参会缩小原接口

```python
def trace(function):
    def wrapper(name):
        return function(name)

    return wrapper
```

这个 `wrapper` 只声明了一个名为 `name` 的形参。原函数若需要两个实参、仅限关键字实参，或者调用者使用其他关键字名称，包装后的接口就可能失败。问题不只在“参数数量”，而在于包装器没有接住并转发原函数允许的各种调用形式。

### 12.2 使用 `*args`、`**kwargs` 转发实参

```python
def trace(function):
    def wrapper(*args, **kwargs):
        print("calling", function.__name__)
        return function(*args, **kwargs)

    return wrapper
```

`wrapper` 收集调用者提供的位置实参和关键字实参，再原样展开给原函数。实参最终仍由原函数签名完成绑定和验证。

### 12.3 必须返回原函数结果

```python
def broken_trace(function):
    def wrapper(*args, **kwargs):
        function(*args, **kwargs)

    return wrapper
```

这里原函数虽然执行，但包装器没有返回结果，所以调用者得到 `None`。包装器是否应该修改结果取决于装饰器目的；普通日志和计时装饰器通常应保持返回值语义。

## 13. 包装函数的异常与后置行为

### 13.1 原函数异常时后置代码的执行情况

```python
def trace(function):
    def wrapper(*args, **kwargs):
        print("before")
        result = function(*args, **kwargs)
        print("after")
        return result

    return wrapper
```

如果原函数抛出异常，执行不会正常到达 `print("after")`。异常会沿调用栈继续传播，除非包装器捕获或使用保证清理的结构。

本章只要求识别这个边界。`try` 用于尝试并捕获异常，`finally` 用于无论是否异常都执行清理；上下文管理器是配合 `with` 统一进入和退出资源使用范围的对象。它们会在第 7 章完整学习。

### 13.2 装饰器中的异常传播与记录

日志装饰器如果捕获所有异常后返回 `None`，可能让调用者误以为函数正常完成。除非接口明确规定转换异常，否则记录后通常应继续抛出。

## 14. 为什么需要 `functools.wraps`

### 14.1 包装后函数名称和文档为什么变了

函数对象除了能被调用，还保存着描述自身的信息。例如 `__name__` 是函数名称，`__doc__` 是文档字符串，`__annotations__` 保存注解。这样的描述信息统称**元数据**。它们说明“这是怎样一个函数”，与调用函数后算出的返回值是两回事。

```python
def trace(function):
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


@trace
def add(left, right):
    """返回两个值的和。"""
    return left + right


print(add.__name__)
print(add.__doc__)
print(add(2, 3))
```

三行依次显示 `wrapper`、`None` 和 `5`。前两行是在读取函数的元数据；最后一行是在调用函数，`5` 是计算结果，不是元数据。定义装饰后的 `add` 时，Python 先创建原始 `add` 函数对象，再把它传给 `trace`。在 `trace` 的这次调用中，形参 `function` 指向原始函数；`trace` 返回新创建的包装函数 `wrapper`，名字 `add` 随后改为指向 `wrapper`：

```text
名字 add ──→ wrapper 函数对象
             内部使用外层形参 function ──→ 原始 add 函数对象
```

`trace` 已执行完，但返回的 `wrapper` 以后还要读取外层形参 `function`，Python 因此保留这份绑定。这就是这里说的“闭包保留了原函数”：原始函数不再由名字 `add` 直接指向，却仍能被 `wrapper` 调用。执行 `add(2, 3)` 时先进入 `wrapper`，再通过 `function(2, 3)` 调用原始函数，所以仍得到 `5`。

外部读取 `add.__name__` 和 `add.__doc__` 时，读到的是当前 `wrapper` 的元数据，而不是原始函数的名称和文档。调试器、文档工具和部分框架会受到影响。框架可以先理解为提供应用整体运行结构、并在合适时机反过来调用开发者代码的软件；它可能依赖函数名称、注解等元数据完成注册或配置。

### 14.2 使用 `wraps`

`functools` 是 Python 标准库中集中提供函数相关工具的模块；`from functools import wraps` 表示从该模块取得 `wraps`。完整模块导入机制在第 8 章学习。

```python
from functools import wraps


def trace(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


@trace
def add(left, right):
    """返回两个值的和。"""
    return left + right


print(add.__name__)               # add
print(add.__doc__)                # 返回两个值的和。
print(add(2, 3))                  # 5
print(add is add.__wrapped__)     # False
```

`@wraps(function)` 把原函数常用的名称、文档和注解等元数据更新到 `wrapper`，并设置 `wrapper.__wrapped__` 指向原函数。因此外部看到的名称和文档与原函数相同。最后一行仍为 `False`：名字 `add` 指向的还是包装函数，不是原函数；`wraps` 没有改变谁接收调用，`add(2, 3)` 依然先进入 `wrapper`。元数据相同不代表两个函数对象是同一个。

`@wraps(function)` 本身也是带括号的装饰器写法：这里的 `function` 指向原函数，`wrapper` 接受它的描述信息。下一节会解释这种带配置的装饰器为什么比普通装饰器多一层。

### 14.3 使用 `wraps` 后仍需处理的调用逻辑

它不会自动：

- 转发实参。
- 返回原结果。
- 保证异常处理正确。
- 保证静态类型签名完全精确。
- 修复装饰器的业务副作用。

因此 `wraps` 是必要的元数据维护工具，不是正确装饰器的全部条件。

## 15. 带配置的装饰器为什么有三层

第 11 节的 `@trace` 会直接把原函数交给 `trace`。现在想让“重复调用原函数”的次数由使用者决定，例如写成 `@repeat(3)`。这里的 `3` 是一个普通实参，表示以后每次调用时执行原函数三次；因为它决定包装行为，本节把它称为**配置值**。

Python 处理 `@repeat(3)` 时，先调用 `repeat(3)`，然后把原函数交给这次调用返回的对象。因此 `repeat(3)` 必须返回一个能够接收原函数的装饰器。像 `repeat` 这样**接收配置、创建并返回装饰器的函数**，称为**装饰器工厂**。“工厂”只说明它负责创建另一个函数，不是 Python 的特殊语法。当前版本的 `repeat` 接收的第一个实参必须是次数，所以不能把 `@repeat(3)` 直接改成 `@repeat`；后者会把原函数当作 `times` 传进去。

### 15.1 `repeat`：配置重复调用次数

先只处理一个 `name` 实参，不加入通用转发和 `wraps`，把三层的任务看清楚：

```python
def repeat(times):
    def decorator(function):
        def wrapper(name):
            result = None
            for _ in range(times):
                result = function(name)
            return result

        return wrapper

    return decorator


calls = []


@repeat(3)
def greet(name):
    calls.append(name)
    return f"Hello, {name}"


print(greet("Ming"))
print(calls)
```

输出是：

```text
Hello, Ming
['Ming', 'Ming', 'Ming']
```

原函数执行了三次，每次都向 `calls` 追加一次；包装函数只返回最后一次调用得到的字符串，因此外层的 `print` 只显示一次 `Hello, Ming`。这里的 `3` 在定义 `greet` 时交给 `repeat`，而 `"Ming"` 是以后调用 `greet` 时才交给 `wrapper` 的实参。

### 15.2 装饰器工厂、装饰器与包装函数

回头看刚才完整代码，三层接收的是三个不同时间提供的东西：

```text
定义 greet 时：repeat(3)                → times 绑定到 3，返回 decorator
定义 greet 时：decorator(原始 greet)     → function 指向原函数，返回 wrapper
以后调用时：wrapper("Ming")             → name 绑定到 "Ming"，调用原函数三次
```

`repeat` 是装饰器工厂；它返回的 `decorator` 才直接接收原函数；`decorator` 返回的 `wrapper` 才接收以后调用 `greet` 的实参。这就是需要三层的原因，不是为了符合一个必须背诵的模板。

### 15.3 `@repeat(3)` 的普通调用展开

上面的 `wrapper(name)` 只适用于接收一个位置实参的原函数。第 12 节学过 `*args/**kwargs` 转发，第 14 节学过 `wraps` 保存元数据；把它们加入后，仍是相同的三层关系。下面用普通赋值写出 `@repeat(3)` 的展开过程：

```python
from functools import wraps


def repeat(times):
    def decorator(function):
        @wraps(function)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = function(*args, **kwargs)
            return result

        return wrapper

    return decorator


calls = []


def greet(name):
    calls.append(name)
    return f"Hello, {name}"


decorator = repeat(3)
greet = decorator(greet)
result = greet("Ming")
print(result)
print(calls)
```

输出与第 15.1 节相同。三个阶段仍发生在不同时间：

```text
执行 repeat(3)
→ times 绑定到 3，返回 decorator

执行 decorator(原 greet)
→ function 指向原函数，返回 wrapper

以后调用 greet("Ming")
→ 实际进入 wrapper，位置实参 "Ming" 由 *args 收集并转发
→ wrapper 连续调用原函数三次，calls 记录三次
→ 返回最后一次调用结果
```

`times` 和 `function` 分别由不同层的闭包保留，`*args/**kwargs` 与 `wraps` 没有增加新的时间阶段。看到三层函数时，应标注每一层接收什么、返回什么、何时执行，而不是只数嵌套层数。

## 16. 多个装饰器的顺序

### 16.1 定义时从内到外包装

```python
def inner(function):
    print("decorate inner")

    def inner_wrapper():
        print("call inner")
        return "inner(" + function() + ")"

    return inner_wrapper


def outer(function):
    print("decorate outer")

    def outer_wrapper():
        print("call outer")
        return "outer(" + function() + ")"

    return outer_wrapper


@outer
@inner
def work():
    print("call work")
    return "done"


print("definition complete")
print(work())
```

输出顺序是：

```text
decorate inner
decorate outer
definition complete
call outer
call inner
call work
outer(inner(done))
```

先只看前三行。执行带装饰器的 `def work` 时，Python 创建原始 `work` 函数对象，再从下到上应用装饰器。核心过程可以写成：

```text
原始 work → inner(原始 work) → inner_wrapper
inner_wrapper → outer(inner_wrapper) → outer_wrapper
名字 work 最终指向 outer_wrapper
```

因此定义阶段先打印 `decorate inner`，再打印 `decorate outer`。这时只是创建了两个包装函数；写在 `inner_wrapper`、`outer_wrapper` 和原始 `work` 函数体里的三句 `call ...` 都没有执行。紧接着才显示 `definition complete`。

从表达式角度看，应用过程等价于 `work = outer(inner(原始 work))`；先计算内层调用 `inner(...)`，再把它的返回值交给 `outer(...)`。

### 16.2 调用时从外向内进入

现在看 `definition complete` 后面的输出。名字 `work` 已经指向最外层的 `outer_wrapper`，所以调用 `work()` 的顺序是：

```text
调用 work() → 进入 outer_wrapper，打印 call outer
→ outer_wrapper 调用 inner_wrapper，打印 call inner
→ inner_wrapper 调用原始 work，打印 call work
→ 返回值逐层组合成 outer(inner(done))
```

`inner` 先**接收并包装**原函数，`outer_wrapper` 却先**接收以后的调用**；两句话说的是不同时刻。判断输出时，先标出 `work` 最终指向哪个函数，再沿包装层向内追踪。

### 16.3 带括号装饰器还要先计算工厂表达式

如果写的是 `@make_trace("outer")`，括号中的调用先产生一个装饰器对象。多个这样的表达式会先从上到下求值，得到的装饰器再从下到上应用。下面把三个阶段都打印出来：

```python
from functools import wraps


def make_trace(label):
    print("factory", label)

    def decorator(function):
        print("decorate", label)

        @wraps(function)
        def wrapper(*args, **kwargs):
            print("enter", label)
            result = function(*args, **kwargs)
            print("leave", label)
            return result

        return wrapper

    return decorator


@make_trace("outer")
@make_trace("inner")
def work():
    print("work")


work()
```

输出顺序是：

```text
factory outer
factory inner
decorate inner
decorate outer
enter outer
enter inner
work
leave inner
leave outer
```

先从上到下计算 `make_trace("outer")`、`make_trace("inner")`，所以两个 `factory` 先出现；再从下到上把得到的装饰器应用到原函数，所以先 `decorate inner`。以后调用 `work()` 时，才从最外层包装进入，返回时按相反方向退出。这里共有“工厂表达式求值、装饰器应用、包装函数调用”三个需要分开分析的阶段。

## 17. 类装饰器的基本用法

### 17.1 类定义完成后也得到对象

第 6 章会完整学习类和实例。本章只需要一个前置事实：执行 `class` 定义后会创建类对象并绑定类名，因此类对象也能交给装饰器。

### 17.2 用注册表保存类对象

这里的**注册**表示把类对象保存到一个集合或映射中，让程序以后能按约定发现并使用它，而不是创建该类的实例。

```python
registered_classes = []


def register(class_object):
    registered_classes.append(class_object)
    return class_object


@register
class Report:
    pass


print(registered_classes[0] is Report)  # True
```

核心展开：

```text
class Report:
    pass


Report = register(Report)
```

执行类定义后创建 `Report` 类对象，再调用 `register(Report)`。`register` 把该对象放入列表并原样返回，所以名字 `Report` 和列表中的元素仍指向同一个类对象。类装饰器也可以返回替代对象，但这会更明显地改变类的行为。

### 17.3 本章边界

这里不展开实例化、继承、方法绑定、描述符和元类。描述符是控制属性读取、写入等行为的一类对象协议；元类是参与创建和管理类对象的机制。它们将在第 6 章学习，当前目的只是证明装饰器模型不限于函数。

## 18. `lambda` 是什么

前面用“接收函数并返回包装函数”建立了装饰器。接下来换一个方向：把简短函数交给排序、转换和筛选工具。`lambda` 先解决“只在这里需要一个很短的函数时怎样创建”的问题，随后再学习使用它的 `map()` 和 `filter()`。

### 18.1 创建简短函数对象的表达式

```python
double = lambda number: number * 2
print(double(5))
```

大致对应：

```python
def double(number):
    return number * 2
```

`lambda number: number * 2` 会创建函数对象；名字 `double` 再绑定到它。冒号前的 `number` 是形参，冒号后是调用时要计算的表达式。创建函数时不会计算 `number * 2`，`double(5)` 才让形参绑定到 `5` 并得到 `10`。

`lambda` 常被称为匿名函数，但绑定给 `double` 并不会让它获得与 `def double` 完全相同的定义名称和文档能力。重点不是“没有任何名字”，而是它用一个表达式创建简短函数对象。

### 18.2 只能包含一个表达式

```python
key_function = lambda record: record["score"]
```

调用 `key_function({"score": 95})` 时，形参 `record` 绑定到字典，表达式读取键对应的值，结果 `95` 自动成为返回值。`lambda` 不能直接包含普通赋值语句、`for` 语句、`try` 语句或多步函数体。

### 18.3 `lambda` 与 `def` 的选择

适合：

- 很短的排序 `key`。
- 只在一处使用的简单转换。
- 简短回调。

不适合：

- 多步骤业务逻辑。
- 需要文档字符串和清楚名称。
- 复杂分支或异常处理。

### 18.4 `lambda` 也会晚绑定

第 8 节先用 `def read(): return number` 展示了三个函数共享一个外层 `number` 绑定。现在可以看懂它的简短写法：循环中使用 `lambda: number`，仍然会在调用时读取同一个外层名字，得到相同的晚绑定结果；使用 `lambda number=number: number`，则与第 8.3 节的默认值写法一样，在创建函数时固定每轮的当前对象。`lambda` 与 `def` 创建的函数遵守相同的 LEGB 和闭包规则。

## 19. `map()`：把函数应用到每个元素

### 19.1 基本使用

```python
numbers = [1, 2, 3]
mapped = map(lambda number: number * 2, numbers)
print(list(mapped))
```

输出是 `[2, 4, 6]`。`map(function, iterable)` 保存转换函数和数据来源；消费时依次进行：

```text
取出 1 → 调用函数得到 2
取出 2 → 调用函数得到 4
取出 3 → 调用函数得到 6
```

这里 `map` 是接收函数的高阶函数，传入的 `lambda` 在转换过程中扮演回调。

### 19.2 为什么要转换为列表

Python 3 的 `map` 对象按需产生结果，不会在创建时立刻构造完整结果列表。这里的“按需”是：遍历到某一项时才计算对应结果。完整的可迭代对象、迭代器和惰性计算在第 5 章学习。

为了在示例中一次看到全部结果，使用 `list(mapped)` 消费它并建立列表。`map` 对象通常消费完后不能当作未开始的数据源再次得到同样内容。

### 19.3 与推导式比较

```python
numbers = [1, 2, 3]
doubled = [number * 2 for number in numbers]
print(doubled)  # [2, 4, 6]
```

简单表达式使用推导式通常更直观；已经有清楚命名函数时，`map(existing_function, values)` 也可能自然。选择标准是可读性和是否需要按需处理，不是行数最少。

## 20. `filter()`：按条件保留元素

### 20.1 基本使用

```python
numbers = [1, 2, 3, 4]
filtered = filter(lambda number: number % 2 == 0, numbers)
print(list(filtered))
```

输出是 `[2, 4]`。`filter` 对每个元素调用传入函数：结果为真时保留原元素，结果为假时跳过。它返回的是通过筛选的原元素，并不返回 `True`、`False` 列表。

这种用于回答“当前元素是否满足条件”的函数常称为**谓词函数**。这里的谓词判断数字是否为偶数。

### 20.2 推导式形式

```python
numbers = [1, 2, 3, 4]
even_numbers = [number for number in numbers if number % 2 == 0]
print(even_numbers)  # [2, 4]
```

推导式把“取什么”和“满足什么条件”放在同一结构中，简单过滤往往更清楚。

### 20.3 `filter(None, values)`

当第一个实参是 `None` 时，`filter` 直接使用元素自身的真值：

```python
values = [0, 1, "", "ready", None]
truthy_values = list(filter(None, values))
print(truthy_values)  # [1, 'ready']
```

这会同时移除多种假值。如果业务只想移除 `None`，应明确写条件，不能把所有假值混在一起。

## 21. `reduce()`：把多项逐步合并

### 21.1 `reduce()` 的导入与累积计算

```python
from functools import reduce
```

`reduce(function, iterable, initial)` 使用累计函数逐步把序列合并成一个结果。这里的累计函数每次接收“当前累计值”和“下一个元素”两个输入，因此也常称为二元合并函数；`initial` 是开始累计前的初始值。

```python
from functools import reduce


numbers = [1, 2, 3, 4]
total = reduce(lambda accumulated, value: accumulated + value, numbers, 0)
print(total)
```

状态变化：

```text
初始 accumulated = 0
处理 1 → 1
处理 2 → 3
处理 3 → 6
处理 4 → 10
```

### 21.2 初始值对空输入与累计类型的影响

提供初始值能定义空输入结果，并明确累计类型。没有初始值时，`reduce` 会使用第一个元素作为初始累计值；空输入则会抛出 `TypeError`。

### 21.3 `reduce()` 与 `sum()` 的选择

求和直接使用 `sum(numbers)` 通常比 `reduce` 更清楚。`reduce` 适合确实需要自定义二元合并过程的场景。

## 22. `partial()`：预先固定部分实参

### 22.1 从重复实参到新可调用对象

```python
from functools import partial


def power(base, exponent):
    return base**exponent


square = partial(power, exponent=2)

print(square(5))
print(square(10))
```

`partial` 不会立刻执行 `power`，而是返回一个新的可调用对象。调用 `square(5)` 时：

```text
partial 预存：原函数 power、关键字实参 exponent=2
本次新提供：位置实参 5
合并后调用：power(5, exponent=2)
结果：25
```

`square` 是新的可调用对象，但不一定是用 `def` 创建的普通函数对象；使用者关心的是它支持调用，并把合并后的实参交给原函数。

### 22.2 与闭包比较

闭包也能实现：

```python
def make_power(exponent):
    def calculate(base):
        return base**exponent

    return calculate
```

`partial` 适合预先固定调用已有函数时的一部分实参；闭包适合需要额外逻辑或状态的情况。

### 22.3 实参冲突仍然存在

预设的关键字实参可以在调用时被同名关键字覆盖。沿用上面的 `square`，`square(5, exponent=3)` 返回 `125`。但 `square(5, 3)` 会同时给 `exponent` 提供位置实参和预设关键字实参，抛出 `TypeError`；缺少必需实参也会报错。最终仍要看合并后的实参能否按原函数签名绑定。

## 23. `lru_cache()`：按调用实参缓存结果

### 23.1 为什么缓存

装饰器可以在原函数调用前后增加行为，也可以选择在某些情况下根本不再执行原函数。如果相同输入的计算昂贵且结果稳定，重复计算是浪费；缓存可以记录“调用实参 → 返回结果”，下次遇到相同调用直接复用。

```python
from functools import lru_cache


@lru_cache(maxsize=128)
def square(number):
    print("calculate", number)
    return number * number


print(square(5))
print(square(5))
```

输出顺序是：

```text
calculate 5
25
25
```

第一次没有记录，称为缓存未命中，因此执行函数体并保存结果。第二次使用相同实参时命中缓存，直接返回保存的 `25`，所以没有再次显示 `calculate 5`。

### 23.2 LRU 是什么意思

LRU 是 Least Recently Used，最近最少使用。缓存达到 `maxsize` 后，需要淘汰条目时，优先移除最久没有使用的结果。

例如容量为 `2` 时，依次缓存实参 `1`、`2`，再次访问 `1` 会让它变成最近使用；此后加入 `3`，较久未使用的 `2` 会优先被移除。LRU 管理的是有限缓存满后的淘汰顺序。

`maxsize=None` 表示不按条目数量淘汰，可能持续增长。Python 3.9 起还提供 `functools.cache`，可以理解为不限制大小的简化缓存装饰器。

`lru_cache` 还有 `typed` 配置。`typed=True` 时，数值相等但直接实参类型不同的调用会被要求分别缓存，例如整数实参和浮点实参按不同类型区分；`typed=False` 时不要求按这种方式全面区分，但某些类型仍可能形成不同缓存项。它只观察直接实参，不会递归检查容器内部每个元素类型。

### 23.3 实参必须可哈希

缓存需要用调用实参构成字典式键，因此参与缓存键的实参必须可哈希：

```python
from functools import lru_cache


@lru_cache(maxsize=128)
def total(values):
    return sum(values)


# total([1, 2, 3])  # TypeError：list 不可哈希
total((1, 2, 3))
```

位置实参和关键字实参都可能参与缓存键。相等与哈希协议的完整关系已在第 2 章建立最低直觉，第 6 章会学习自定义实现。

### 23.4 `cache_info()` 与 `cache_clear()`

```python
from functools import lru_cache


@lru_cache(maxsize=128)
def square(number):
    return number * number


square(5)
square(5)
print(square.cache_info())
square.cache_clear()
```

缓存**命中**表示当前调用实参已经有保存结果，可以直接复用；**未命中**表示没有可用记录，需要真正执行函数并保存结果。`cache_info()` 可以观察命中、未命中、最大容量和当前条目数；`cache_clear()` 清空已有缓存。

## 24. 什么函数适合缓存

### 24.1 结果应主要由输入决定

```python
def add(left, right):
    return left + right
```

同样输入得到同样结果，且没有需要重复执行的外部动作，适合考虑缓存。

### 24.2 外部状态会让缓存过期

读取当前时间、随机数、文件、数据库或全局配置的函数，即使调用实参相同，结果也可能变化。直接缓存会返回旧结果，需要明确**过期**和**失效**策略：过期规定结果经过多长时间不再使用，失效规定数据变化或特定事件发生时主动删除哪些缓存记录。

`lru_cache` 自身按容量和最近使用情况淘汰，不提供“保存五分钟后自动过期”的时间策略。需要按时间过期或跟随数据库更新主动失效时，要使用额外设计或其他缓存工具。

### 24.3 副作用函数通常不应跳过执行

发送消息、扣减库存、写日志等函数的意义包括执行动作。如果缓存命中后跳过函数体，副作用也会被跳过。

### 24.4 返回可变对象会共享缓存结果

```python
from functools import lru_cache


@lru_cache(maxsize=8)
def get_values(key):
    return []


first = get_values("A")
first.append("changed")
second = get_values("A")

print(first is second)  # True
print(second)           # ['changed']
```

相同键的调用得到缓存中保存的同一个列表对象。某个调用者修改它，后续调用会看到变化。可以返回不可变对象，或按接口需要复制结果。

### 24.5 缓存会持有对象

缓存保存键和返回对象，会延长它们的生命周期并占用内存。完整内存管理在第 9 章，并发下的缓存一致性和线程行为在第 10 章。

## 25. 缓存与递归

### 25.1 朴素递归的重复子问题

```python
def fibonacci(number):
    if number < 2:
        return number
    return fibonacci(number - 1) + fibonacci(number - 2)
```

`fibonacci(5)` 会多次计算 `fibonacci(3)`、`fibonacci(2)` 等相同子问题，调用数量快速增长。

例如 `fibonacci(5)` 的两个分支会计算 `fibonacci(4)` 和 `fibonacci(3)`，而 `fibonacci(4)` 内部又会计算一次 `fibonacci(3)`。相同输入反复出现，正好符合缓存复用条件。

### 25.2 用 `lru_cache()` 缓存递归子问题

```python
from functools import lru_cache


@lru_cache(maxsize=None)
def fibonacci(number):
    if number < 2:
        return number
    return fibonacci(number - 1) + fibonacci(number - 2)
```

每个不同 `number` 只需真正计算一次，时间可降到与不同子问题数量同阶，通常记作 `O(n)`。缓存保存约 `O(n)` 个结果，递归调用栈仍可能达到 `O(n)`。

缓存减少重复计算，不会自动消除递归深度限制，也不会让任何递归都变高效。

## 26. 日志与计时装饰器

前面已经学完装饰器结构与缓存工具，现在回到两个常见工程场景，检查一个装饰器除了“能运行”之外还应保留哪些接口行为。

### 26.1 日志装饰器

日志是程序按时间和级别记录运行事件的信息，用于排查问题和审计行为。与临时 `print()` 相比，日志系统通常还能统一记录时间、严重程度、来源和输出位置。

```python
from functools import wraps


def log_call(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print("call", function.__name__)
        return function(*args, **kwargs)

    return wrapper


@log_call
def add(left, right):
    return left + right


print(add(2, 3))
```

调用时先输出 `call add`，再输出返回结果 `5`。装饰器记录调用事件，但仍把实参交给原函数并返回原结果。

真实工程通常使用日志系统而不是 `print()`，并考虑密码、令牌、身份证号等敏感实参不能直接记录。日志工具在第 11 章和部署章节继续学习。

### 26.2 计时装饰器

标准库模块 `time` 中的 `perf_counter()` 提供适合测量短时间间隔的高分辨率计时值。先记录开始读数，执行函数后再读取一次，两者相减得到经过时间：

```python
from functools import wraps
from time import perf_counter


def measure_time(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        result = function(*args, **kwargs)
        elapsed = perf_counter() - start
        print(function.__name__, elapsed)
        return result

    return wrapper


@measure_time
def calculate():
    return sum(range(1000))


result = calculate()
```

调用 `calculate()` 时，包装器记录开始读数，执行原函数，计算时间差并返回原结果。打印出的具体秒数每次可能不同。这里的墙钟时间指实际经过了多少秒，它会受机器负载和系统状态影响，只能提供测量证据，不能代替复杂度分析。若原函数抛出异常，上面的后置计时不会执行；完整清理写法留到第 7 章。

## 27. 鉴权与重试装饰器的边界

### 27.1 调用原函数前的身份与权限检查

鉴权在这里表示确认当前调用者身份，并判断它是否具有执行操作所需权限。鉴权装饰器需要明确：从哪里取得当前身份、权限不足抛出什么异常、是否记录审计日志，以及被装饰函数是否允许在检查前执行任何动作。审计日志是专门记录谁在何时执行了什么受控操作的日志。

简化模型：

```python
from functools import wraps


def require_admin(function):
    @wraps(function)
    def wrapper(user, *args, **kwargs):
        if not user["is_admin"]:
            raise PermissionError("admin required")
        return function(user, *args, **kwargs)

    return wrapper


@require_admin
def delete_report(user, report_id):
    return f"deleted {report_id}"
```

调用 `delete_report(user, 10)` 时先进入 `wrapper`。权限不足就抛出异常，原函数不会执行；检查通过后才把 `user` 和其他实参继续交给原函数。异常设计与安全体系会在后续章节展开；当前重点是检查必须发生在原函数之前。

### 27.2 重试必须考虑操作是否可重复

重试表示一次操作失败后，再次执行同一操作以尝试恢复。网络读取失败后重试可能合理；扣款、创建订单或发送消息若没有幂等设计，重复执行可能造成重复副作用。

幂等的最低限度含义是：同一个操作重复执行，最终业务效果与执行一次一致。完整异常和 Web 工程问题分别在第 7 章和第 13 章学习。

### 27.3 重试失败后的异常传播

重试达到上限后通常应继续抛出最后异常，或按照明确接口返回失败对象。静默返回 `None` 会把“失败”混成合法空结果。

## 28. 推导式与函数式工具的选择

### 28.1 函数式工具表达数据流

`map`、`filter`、`reduce`、高阶函数和不可变数据倾向于把程序表达成输入到输出的转换。

### 28.2 嵌套 `map()`、`filter()` 与推导式的可读性对比

假设已有：

```python
values = [-2, 0, 3, 5]
result = list(map(str, filter(lambda value: value > 0, values)))
print(result)  # ['3', '5']
```

上面虽然能写成多层组合，但推导式可能更直接：

```python
values = [-2, 0, 3, 5]
result = [str(value) for value in values if value > 0]
print(result)  # ['3', '5']
```

当转换过程复杂时，拆成命名函数和中间变量更容易测试、调试和解释。

### 28.3 纯函数与副作用

纯函数通常指结果只由输入决定，并且不修改外部可观察状态。它们容易测试、组合和缓存。但实际程序必须进行 I/O 和状态更新；`I/O` 是 Input/Output 的缩写，表示程序与文件、网络、终端等外部环境进行输入输出。目标不是消灭副作用，而是让副作用位置清楚。

## 29. 常见陷阱

### 29.1 混淆名字、函数对象和调用结果

`double` 是当前指向函数对象的名字，`double(5)` 是调用表达式。赋值、放进列表或作为实参传递函数对象时不要误加调用括号。

### 29.2 把所有嵌套函数都叫闭包

应检查内层函数是否需要外层自由变量，以及返回后是否仍依赖这些绑定。

### 29.3 认为闭包复制了循环值

自由变量通常晚绑定，多个函数可能读取同一个最终绑定。

### 29.4 装饰器忘记返回包装函数

装饰结果会成为原名字的新绑定；返回 `None` 会使原函数名不可调用。

### 29.5 包装器忘记返回原结果

原函数执行不等于调用语义被保留。

### 29.6 不使用 `wraps`

名称、文档和检查工具会看到包装函数信息。

### 29.7 混淆应用顺序与调用顺序

先写出 `outer(inner(function))`，再按包装层分析调用。

### 29.8 过度使用 `lambda` 和 `reduce`

短不等于清楚。复杂逻辑使用普通函数和循环。

### 29.9 缓存不稳定或有副作用的函数

命中缓存会跳过函数体，旧结果和缺失副作用可能造成业务错误。

### 29.10 返回可变缓存对象

后续调用可能共享被修改的结果。

### 29.11 重试非幂等操作

一次失败可能已经产生部分外部效果，直接重试会重复操作。

## 30. 怎样分析闭包和装饰器代码

### 第一步：标出每个函数何时创建

先区分名字、函数对象和调用表达式，再标出模块加载、外层调用、装饰阶段和实际调用中分别创建或执行了什么。

### 第二步：为每个函数列出局部名字和自由变量

不要只看缩进。问每个名字最终按 LEGB 从哪里读取。

### 第三步：检查是否共享同一绑定

特别关注循环变量、同一次外层调用返回的多个函数和可变对象。

### 第四步：把装饰器语法展开

```text
@decorator           → function = decorator(function)
@factory(config)     → function = factory(config)(function)
```

### 第五步：分开定义阶段和调用阶段

先执行哪些装饰器表达式，再进入哪些 wrapper，最后原函数是否执行。

### 第六步：检查接口是否保持

- 实参是否转发。
- 返回值是否返回。
- 元数据是否保留。
- 异常和副作用是否符合原接口。

### 第七步：检查状态生命周期

闭包和缓存持有哪些对象，何时清理，是否可能过期或共享。

## 31. 面试中怎样回答

### 31.1 闭包

```text
内层函数使用外层自由变量
→ 即使外层调用结束，函数仍保留访问所需绑定
→ 函数与这些绑定形成闭包
→ 说明 nonlocal、晚绑定和生命周期边界
```

### 31.2 装饰器

```text
装饰器接收原函数并返回替代对象
→ @decorator 等价于重新赋值
→ wrapper 转发调用并附加行为
→ 使用 wraps 保留元数据
→ 区分装饰阶段与调用阶段
```

### 31.3 `lru_cache`

```text
用调用实参构成可哈希缓存键
→ 命中直接复用返回对象
→ 未命中执行函数并保存
→ 检查容量、过期、副作用和可变返回值
```

## 33. 本章总结

1. 名字可以指向函数对象，调用表达式才执行函数；函数是一等对象，高阶函数可以接收或返回函数，传入的函数可在具体场景中扮演回调。
2. 内层函数使用外层自由变量并在之后仍需这些绑定时，会形成闭包。
3. 闭包保存访问绑定的能力，不是机械复制某一时刻的普通值。
4. 重新绑定外层名字需要 `nonlocal`；只修改外层可变对象通常不需要。
5. 循环闭包常出现晚绑定，可通过形参默认值或函数工厂建立当前值来源。
6. `@decorator` 的核心是 `function = decorator(function)`。
7. 通用包装器需要转发实参、返回结果，并通常使用 `wraps` 保留元数据。
8. 带配置的装饰器分为配置、装饰和调用三层；多个装饰器从下到上组合，调用从外向内进入。
9. `lambda` 适合单表达式短函数，复杂逻辑使用 `def`。
10. `map` 和 `filter` 在 Python 3 中按需产生结果，推导式常更直观。
11. `reduce` 逐步累计，`partial` 固定部分实参并返回新可调用对象。
12. `lru_cache` 用可哈希调用实参缓存返回对象，必须考虑容量、过期、副作用和可变结果。
13. 日志、计时、鉴权和重试装饰器必须保留原接口，并明确异常与外部副作用。
