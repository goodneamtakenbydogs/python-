# 第 4 章学习单：闭包、装饰器与函数式工具

## 1. 本章为什么要学

第 3 章已经说明函数也是对象，可以被保存、传递和返回。本章把这个结论用于四类问题：

1. 名字、函数对象和调用结果怎样区分？
2. 一个内层函数被外层函数返回后，为什么还能使用外层函数中的名字？
3. 为什么 `@decorator` 能为函数统一增加日志、计时、权限或缓存行为？
4. `map()`、`filter()`、`partial()` 和缓存工具怎样接收或包装函数？

这些问题不是互不相干的语法技巧：函数是一等对象，所以能成为高阶函数的输入或输出；很多函数装饰器本身就是返回包装函数的高阶函数，包装函数又通过闭包保存原函数和配置。

本章主线是：

```text
名字、函数对象与调用结果
→ 一等对象、高阶函数与回调
→ 内层函数使用外层名字
→ 闭包保存所需绑定
→ 装饰器接收并替换函数
→ 函数式工具与缓存
```

## 2. 学习目标

完成本章后，应当能够：

- 解释一等对象和高阶函数。
- 区分指向函数对象的名字、函数对象本身和函数调用表达式。
- 区分高阶函数与回调在同一次调用关系中的不同角色。
- 区分嵌套函数、自由变量和闭包。
- 说明闭包保存的是变量绑定，而不是机械复制某一时刻的值。
- 使用 `nonlocal` 更新闭包状态。
- 分析循环创建函数时的晚绑定问题。
- 使用形参默认值或函数工厂修复晚绑定。
- 把 `@decorator` 展开为普通函数调用。
- 编写能够转发任意实参并返回原结果的基础装饰器。
- 使用 `functools.wraps` 保留被装饰函数的元数据。
- 分析带配置装饰器的三层调用结构。
- 判断多个装饰器的应用顺序和调用顺序。
- 理解类装饰器接收的是类对象，完整类机制留到第 6 章。
- 正确使用 `lambda`，并知道它只允许一个表达式。
- 比较 `map()`、`filter()` 与推导式。
- 使用 `reduce()`、`partial()` 和 `lru_cache()`。
- 说明缓存对实参可哈希性、返回值共享、内存和副作用的要求。
- 判断日志、计时、鉴权、重试和缓存装饰器应该承担哪些职责。

## 4. 本章知识点清单

### 4.1 函数对象、高阶函数与回调

- `function` 表示读取函数对象，`function()` 表示调用并得到结果。
- 指向函数对象的名字不是函数对象本身。
- 函数对象能够绑定给其他名字、放入容器、作为实参和作为返回值。
- 接收或返回函数对象的函数是高阶函数。
- 被交给其他代码并由接收方调用的函数在该场景中扮演回调。
- 高阶函数描述接收方的能力，回调描述被传入函数的使用角色。

### 4.2 嵌套函数与闭包

- 内层函数和外层函数。
- 局部名字、外层名字和自由变量。
- 闭包由函数行为和所需外层绑定共同构成。
- 外层调用结束后闭包仍可使用相关状态。
- `__closure__` 与 `co_freevars` 只作观察，不依赖内部布局。
- 代码对象、闭包单元格和序列化的最低限度含义。
- 多个闭包是否共享同一外层状态。

### 4.3 `nonlocal` 与状态

- 读取外层绑定不需要 `nonlocal`。
- 重新绑定外层名字需要 `nonlocal`。
- 修改外层可变对象与重新绑定外层名字的区别。
- 闭包状态的用途和可测试性代价。

### 4.4 晚绑定

- 闭包通常在调用时读取自由变量当前绑定。
- 循环结束后多个函数可能看到同一个最终值。
- 使用形参默认值固定当前对象。
- 使用函数工厂为每次调用建立独立作用域。
- 函数工厂是创建并返回配置后函数的函数。
- 晚绑定不是闭包“失效”。

### 4.5 装饰器基础

- 装饰器接收对象并返回替代对象。
- `@decorator` 的普通展开形式。
- 装饰发生在定义阶段，包装函数体发生在调用阶段。
- `wrapper` 为什么通常接收 `*args` 和 `**kwargs`。
- 为什么必须返回原函数结果。
- 装饰器与闭包的关系。

### 4.6 `functools.wraps`

- `functools` 作为标准库函数工具模块的最低限度含义。
- 元数据、框架和 `wraps` 要解决的问题。
- 包装函数为什么会遮蔽原函数元数据。
- `wraps` 保留 `__name__`、`__doc__` 等信息。
- `__wrapped__` 与调试、检查工具。
- `wraps` 不会自动修复装饰器业务逻辑。

### 4.7 带配置与叠加装饰器

- 装饰器工厂、装饰器和包装函数三层结构。
- `@repeat(3)` 的求值过程。
- 多个装饰器从下到上组合。
- 调用时从最外层包装进入。
- 装饰器配置的闭包保存。

### 4.8 类装饰器

- 类在定义完成后也是对象。
- 类装饰器接收类对象并返回类或替代对象。
- 注册类、补充元数据等基础场景。
- 注册、描述符和元类的最低限度含义，完整机制留到第 6 章。
- 类、实例和元类的完整机制属于第 6 章。

### 4.9 `lambda`

- 匿名函数表达式。
- 单表达式限制和隐式返回。
- 常见 `key`、短回调场景。
- 复杂逻辑应使用普通 `def`。
- `lambda` 也遵守 LEGB 和晚绑定。

### 4.10 函数式工具

- `map()` 对元素应用函数。
- `filter()` 按条件保留元素。
- Python 3 中二者按需产生结果，完整迭代机制在第 5 章。
- 推导式与 `map()`、`filter()` 的可读性取舍。
- `functools.reduce()` 累积合并。
- `functools.partial()` 预先固定部分实参。
- 函数组合的基本思路。

### 4.11 缓存工具

- `functools.lru_cache()`。
- 缓存键由调用实参构成，因此参与缓存键的实参需要可哈希。
- `maxsize`、`typed`、`cache_info()` 和 `cache_clear()`。
- 缓存命中、未命中、过期和主动失效。
- `lru_cache` 按容量和最近使用情况淘汰，不自带按时间过期。
- 纯函数与缓存适配性。
- 时间、随机数、外部状态和副作用函数的缓存风险。
- 缓存返回可变对象的共享风险。
- 缓存占用内存和结果过期问题。

### 4.12 装饰器场景与边界

- 日志、计时、鉴权、重试和缓存。
- 日志、墙钟时间、鉴权、审计、重试和幂等的最低限度含义。
- 纯函数、I/O 和 `mock` 的最低限度含义。
- 异常是否传播、被重试或被吞掉。
- 同步函数与异步函数装饰器边界，异步完整内容在第 10 章。
- 装饰器过多造成调用链难以排查。

## 5. 推荐学习顺序

### 第一步：重新确认函数是对象

先分别做函数对象绑定、放入列表、作为实参和作为返回值的小例子。每次都区分“读取函数对象”和“使用括号调用”，再给一等对象、高阶函数和回调命名。

### 第二步：从外层函数作用域理解闭包

画出外层函数调用结束前后的名字关系，理解内层函数为什么还能访问自由变量。

### 第三步：学习闭包状态修改与晚绑定

分别观察 `nonlocal`、可变外层对象和循环创建函数，明确“读取当前绑定”与“复制旧值”的区别。

### 第四步：把装饰器语法完全展开

先手写 `decorated = decorator(original)`，再使用 `@decorator`。如果展开形式不清楚，不进入带配置和叠加装饰器。

### 第五步：学习 `wraps`、装饰器配置与执行顺序

观察元数据丢失、三层调用和多个包装层的进入/退出顺序。

### 第六步：学习函数式工具和缓存

优先理解各工具表达的意图，不以“一行代码”作为更好的唯一标准。

### 第七步：实验与口述

Notebook 先预测再运行；面试题先独立回答，再检查参考回答和复习卡。
