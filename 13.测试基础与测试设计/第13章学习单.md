# 第 13 章学习单：测试基础与测试设计

## 1. 本章为什么要学

会写断言不等于已经知道该测什么。测试需要明确需求、预期来源、代表输入、状态和风险，才能解释一次通过或失败意味着什么。

本章作为 Python 测试应用的前置，用通用需求和虚构模型练习选择与表达，再在第 14 章组织成可维护用例。不预设真实项目经历，也不把框架操作、系统或硬件课程提前放进来。

## 2. 前置知识

- 第 1～3 章：值、类型、真假值、函数接口与异常。
- 第 5～7 章：逐项消费、对象状态、异常传播与清理。
- 第 9～10 章：共享对象、执行交错、超时与副作用。
- 第 11 章：断言、基础测试、替身、隔离和诊断。
- 第 12 章：结构化数据、文件状态与失败保护。

测试层次、等价类、边界、判定表、状态迁移、覆盖率和风险都会在讲义首次需要时解释。代码只依赖标准库，不要求额外测试插件、覆盖工具或真实外部系统。

## 3. 学习目标

能从一条明确或尚有歧义的需求中区分输入、前置、规则、输出和可观察状态，写出需要澄清的问题。能说明每条用例验证什么、预期来自哪里，以及为什么选这些数据。

能运用等价类、边界、判定表、状态转换和组合方法，分析正常、异常、权限、并发与部分成功。能读懂不同覆盖口径，记录未执行和剩余风险，写出可复现的缺陷报告。

客观代码检查与人工设计评审分开完成。通过有限模型检查，不等于需求完整、理由充分或真实系统已经验证。

## 4. 知识点清单

### 4.1 测试目的与需求

- 测试活动、质量证据和结论范围。
- 人的错误、缺陷、失败与预期异常。
- 静态与动态测试，需求、开发、修复中的活动。
- 层次、质量目标、观察依据、执行目的的不同维度。
- 冒烟、确认修复、回归、探索与测试组合。
- 输入、输出、前置、规则、状态和限制。
- 单位、边界、时间起点等歧义与临时假设。
- 测试点、场景、用例、步骤和需求关联。
- 独立预期、可信参考与不变量。

### 4.2 设计方法与失败场景

- 等价类、有效与无效、类型与缺失输入。
- 离散边界、精度、单位、包含关系和去重。
- 单项无效、交互与错误优先级。
- 判定表、条件掩盖、无关项与可行组合。
- 状态、事件、迁移、终止、拒绝与历史序列。
- 两两覆盖、高阶交互、约束和负向场景。
- 依赖失败注入、部分状态变化和清理。
- 主体、对象、权限动作与数据一致性。
- 并发不变量、可控交错和成功数量。
- 超时、重复执行、幂等约定与结果未知。
- 异步完成、最终一致性和有界观察。
- 数据代表性、共享、可重复和隔离。

### 4.3 覆盖、风险与缺陷

- 风险、影响、可能性、执行成本和范围取舍。
- 设计关联、实际执行、通过、阻塞与未执行。
- 语句、分支、业务覆盖与断言质量。
- 用正确与典型错误候选检查测试的区分能力。
- 缺陷标题、版本、前置、最小步骤、预期与实际证据。
- 严重程度、处理优先级和判断依据。
- 失败定位、确认修复和相关回归。
- 测试报告、剩余风险和结论限制。
- 自动化选择、探索和人工评审。

## 5. 推荐顺序与时间

建议 26～34 小时，按四轮完成。时间用于阅读、设计、实验和口述，不是预定完成日期。

| 轮次 | 内容与练习 | 时间 |
|---|---|---:|
| 第一轮 | 讲义第 1～12 节，实验 1、2、6、22；目的、需求与预期 | 6～8 小时 |
| 第二轮 | 讲义第 13～21 节，实验 3～5、7～13、25～27；方法与模型 | 8～10 小时 |
| 第三轮 | 讲义第 22～32 节，实验 14～21、23；失败、风险与覆盖 | 6～8 小时 |
| 第四轮 | 讲义第 33～40 节，实验 24、28，综合人工设计与口述 | 6～8 小时 |

先用一条小规则说清预期，再加入多个条件与状态；不要一开始就堆大量复杂场景或只追求用例数量。

## 7. 实验与人工设计怎样配合

实验 1～24 保留 prediction 与 observation 两份记录。把整个占位字符串替换为值，预测错误时不抹去，实际观察与原因说明分别填写。每题都有自己的 `check_experiment()`，不要求其他题先完成。

实验 25～28 设计整数边界用例、权限判定表，编写状态轨迹模型和验证候选权限实现的测试。检查器可识别若干典型错误，但不能自动评价 purpose 文字是否有道理、需求是否完整。

Notebook 还有一项小型报告导出的综合设计与人工复盘：写需求拆解、问题假设、用例、预期来源、缺陷报告和范围建议，紧跟人工评审清单。它不在 `run_checks()` 的通过范围中，需自己逐项复述或评审。

所有模型、记录编号和版本均为虚构，日志和环境信息不使用真实内部内容。涉及时间和并发的观察使用固定序列或明确交错，不要求精确耗时或偶然调度顺序。

## 8. 分层完成标准

### 8.1 知道

- [ ] 能解释测试目的、层次、分类维度与常见活动。
- [ ] 能认出等价类、边界、判定表、状态迁移和组合覆盖。
- [ ] 知道通过、失败、阻塞、跳过和未执行不是同一状态。

### 8.2 理解

- [ ] 能解释每条用例的独立预期与输入选择理由。
- [ ] 能说明一项条件怎样掩盖另一项错误。
- [ ] 能比较状态、迁移与序列覆盖。
- [ ] 能解释高代码覆盖仍可能漏掉边界或断言错误。
- [ ] 能区分超时、部分成功、异步完成和清理证据。

### 8.3 会用

- [ ] 能拆解需求并记录歧义，而非自行补成标准答案。
- [ ] 能完成 28 道客观实验及逐题检查。
- [ ] 能人工评审一组用例，指出范围、缺口与冗余。
- [ ] 能写可复现缺陷报告并说明严重程度与优先级依据。
- [ ] 能在有限时间中选择范围并记录剩余风险。

### 8.4 能回答

- [ ] 能用 60～90 秒说明为什么测试通过不等于全部正确。
- [ ] 能为一条小需求选择方法并说明局限。
- [ ] 能解释一项测试为何放过错误，以及怎样改进。
- [ ] 能只凭真实学习实验或明确虚构方案完成复述，不伪造项目经历。
