# 第 16 章学习单：Python 测试工具开发

## 1. 本章为什么要学

第十五章把单项任务组织为可靠脚本；本章继续训练可复用接口、多模块职责、工具自身测试和安装交付。目标是让其他使用者在明确环境中也能安装、调用、理解结果并定位失败。

主线是虚构测试记录的本地汇总器，不是岗位平台培训。Linux、服务器、设备、驱动和完整业务背景仍另行成课，当前内容围绕 Python 程序设计。

## 2. 前置知识与环境

- 第 1～6 章：对象、容器、函数、迭代器、类与数据模型。
- 第 7～9 章：异常、资源责任、模块、环境、共享与复制。
- 第 10～12 章：并发边界、测试、文件、JSON、命令行与标准库。
- 第 13～14 章：独立预期、用例组织、替身和生命周期。
- 第 15 章：执行、解析、预算、停止、部分失败与报告。

Notebook 使用仓库 CPython 3.12.13 环境。示例工具在自身目录通过 uv sync 建立独立开发环境，依赖由其 pyproject.toml 和 uv.lock 管理，当前 pytest 9.2.0、Ruff 0.16.10。运行依赖为空，构建通过 Hatchling。声明最低 Python 3.11，不把本机验证与其他平台、版本的 CI 证据混为一谈。

## 3. 学习目标

能从明确小需求写出目标用户、最小功能、输入输出、错误与完成条件；能解释模型、配置、读取、核心、报告和 CLI 的依赖方向。

能验证空输入、坏数据、重复、筛选、资源上限、取消和提交失败；能为公共组件编写有区分能力的测试。能构建分发包，从仓库之外的新环境核对实际导入和命令入口，并解释静态检查、测试、构建、安装和持续集成各自的证据范围。

## 4. 知识点清单

### 4.1 需求与组件

- 目标用户、最小功能、完成条件与非目标。
- 数据流、模块职责、公共接口与依赖方向。
- 类型标注、数据类、运行时校验与规范化。
- frozen、嵌套共享、不可变配置和结构化错误。
- 配置来源、覆盖、空选择、未知字段与来源保护。

### 4.2 数据、资源与结果

- JSONL、UTF-8、物理行号、单行字节上限。
- 验证与筛选顺序、规范化后的唯一编号。
- 输入总数、选中总数、状态计数与耗时范围。
- 一次性迭代、复杂度、记录上限与峰值内存。
- 组合、注入、日志、run_id 和报告结构版本。
- 临时文件、提交点、旧目标、部分失败与取消。
- 运行并发、在途 Future、完成关联与收尾限制。

### 4.3 自身测试与交付

- 模型、解析、核心、文件、CLI 和安装的分层验证。
- 故障注入、清理错误、回归数据与断言质量。
- Python 工具的测量范围、热点和内存指标。
- 发行包、导入包、命令名、src 布局和依赖组。
- 可编辑安装、构建后端、sdist、wheel 与干净安装。
- 自动检查、CI、报告保存、版本兼容与维护成本。

## 5. 推荐顺序与时间

建议 **30～40 小时**，拆成四轮。这里是学习投入，不是预设完成日期。

| 轮次 | 阅读与任务 | 时间 |
|---|---|---:|
| 第一轮 | 讲义 1～10 节，运行示例；实验 1～6 | 8～10 小时 |
| 第二轮 | 讲义 11～18 节，实验 7～14、25～26 | 8～10 小时 |
| 第三轮 | 讲义 19～29 节，实验 15～22、27～28，自身测试 | 7～10 小时 |
| 第四轮 | 讲义 30～41 节，实验 23～24，构建、安装与人工复盘 | 7～10 小时 |

先让一个小功能有清楚接口和测试，再加入其他层。首次学习不要求理解复杂插件系统或搭建完整平台。

## 7. 实验与交付复盘

实验 1～24 保留 prediction、observation 两份记录。先读源码不运行，填写预测；运行后记录实际值，逐题即时检查，再解释原因。替换整个占位字符串，包括引号，保留两位编号。错误预测不抹去。

实验 25～28 分别实现行解析、一次遍历汇总、报告提交和公共组件测试，每题独立。检查会验证正常、边界、错误及必要交互，不判断你是否理解需求或方案是否完整。

最后在个人副本新增一项小规则，完成正反测试，构建 sdist/wheel 并运行 verify_wheel.py。记录新环境、实际导入、命令入口、对应版本与错误结果。CI 配置存在和实际对应提交通过分别记录；该综合任务不计入 run_checks 的通过结论。
