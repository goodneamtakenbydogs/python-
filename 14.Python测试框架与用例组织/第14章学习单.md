# 第 14 章学习单：Python 测试框架与用例组织

## 1. 本章为什么要学

写出一条 assert 只是开始。用例还需要能被找到、能单独运行、能获得独立数据、失败后能清理，并留下足以定位的结果。本章从一条现成 pytest 用例开始，逐步练习修改、组织和扩展。

案例围绕虚构的小型文本报告，不要求真实业务、外部系统或项目经历。Linux、设备与驱动等完整领域继续另行学习；这里聚焦 Python 代码在测试框架中的执行与组织。

## 2. 前置知识与环境

- 第 1～3 章：对象、共享引用、函数形参与实参、作用域。
- 第 4～6 章：装饰器、生成器暂停、类与组合。
- 第 7～9 章：异常、资源责任、导入绑定、嵌套复制。
- 第 10～12 章：并发边界、基础测试、文件与标准库。
- 第 13 章：测试点、独立预期、边界、状态和结果范围。

本章以 CPython 3.12.13、pytest 9.1.1 验证。仓库现有开发环境已声明 pytest，不新增并行、重试、异步或报告插件。Notebook 使用当前内核对应的 Python 启动子进程；若缺少 pytest，先按根 README 同步开发环境并选择对应内核。

## 3. 学习目标

能阅读测试工程，定位入口、配置、收集范围、fixture 依赖和结果输出。能运行一个节点、读失败、修改输入或断言，再补一个有独立预期的边界。

能用参数化组织输入，以 fixture 表达生命周期，用临时目录与独立对象隔离状态，在实际查找位置替换依赖。能区分收集、准备、测试体和退出阶段，解释跳过、预期失败与清理错误；能实现并测试一个简单选项扩展。

## 4. 知识点清单

### 4.1 运行、收集与断言

- 工程源码、用例、数据、配置与报告职责。
- 解释器、`python -m pytest`、节点标识与独立运行。
- 默认命名、模块导入、`--collect-only` 与收集错误。
- 节点、`-k`、`-m`、标记注册与未选中范围。
- 完整业务断言、异常类型、消息匹配与状态保持。
- 参数化、案例编号、组合数量与共享对象。

### 4.2 fixture、依赖与隔离

- 请求、依赖图、作用域、缓存和 autouse。
- 准备顺序、逆序清理、yield 前失败与 finalizer。
- 工厂 fixture、conftest 可见范围、indirect。
- 高成本基础与每项可变状态的分离。
- skip、xfail、严格 XPASS 与维护责任。
- Mock、autospec、patch 查找位置与恢复范围。
- 时间、随机、环境、文件与外部读取的可控边界。

### 4.3 配置、证据与简单扩展

- tmp_path、数据标识与并行资源隔离。
- 配置来源、覆盖约定、转换和校验。
- 数据文件、路径定位与加载阶段。
- capsys、caplog、阶段报告、退出码和 JUnit XML。
- 顺序依赖、不稳定用例、重试限制。
- 帮助函数、断言组件、组合与测试基类。
- hook、命令行选项、插件自身测试及版本边界。

## 7. 怎样完成 Notebook

实验 1～24 为观察题，保持 prediction 与 observation 两份记录。先读源码和命令实参，把整个占位字符串替换成自己的预测，再运行。预测不对时保留原值，只在实际观察和原因解释中修正。每题独立即时检查不要求其他题先完成。

部分子进程故意产生失败、setup 或 teardown 错误，这是要观察的行为。辅助运行器把错误留在返回记录中；需要查看完整错误时读取当前 result 的 output。阶段计数不一定互斥，应结合节点和阶段解释。

实验 25～28 返回自己编写的源码字符串，分别实现参数化测试、独立嵌套数据 fixture、依赖替换测试和有校验的选项。源码会保存到临时工程并由真实 pytest 执行。即时检查可能需要数秒至数十秒；通过有限候选检查不代表设计完整。

最后的示例工程综合任务需记录自己的修改、命令、失败证据、依赖图和范围。它由人工清单复盘，不包含在 `run_checks()` 的通过结论中。原有作答、输出和笔记由学习者保留。
