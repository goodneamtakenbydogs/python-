# 第 8 章复习卡：模块、包与依赖管理

## 1. 导入主线

```text
导入名
→ 查 sys.modules
→ 未命中时找 ModuleSpec 与加载器
→ 创建模块并提前缓存
→ 执行模块顶层
→ 设置父包子模块属性
→ 在当前命名空间绑定名字
```

模块执行前提前缓存解释了循环导入中的“部分初始化对象”。缓存属于当前进程。

## 2. 源文件、导入名与模块对象

| 概念 | 示例 | 作用 |
|---|---|---|
| 源文件 | `pricing.py` | 保存源码文本 |
| 导入名 | `shop.pricing` | 供导入系统解析 |
| 模块对象 | `sys.modules['shop.pricing']` | 保存运行时命名空间 |

导入包名与发行包名也可能不同，例如发行包 `PyYAML` 提供导入包 `yaml`。

## 3. 导入写法与绑定

- `import module`：当前名字指向模块对象，之后读取其当前属性。
- `from module import name`：当前名字绑定导入当时取得的对象，不持续同步模块属性重新绑定。
- `as`：只更改当前名字，不改模块 `__name__` 和身份。
- 共享可变对象的内容修改仍可被多个绑定观察。

## 4. 包与入口

- 普通包常含 `__init__.py`，导入子模块前先初始化父包。
- 相对导入按 `__package__` 解释，不按工作目录拼路径。
- `python -m package.module` 保留包上下文；直接执行包内文件可能失去它。
- `__all__` 主要控制星号导入，不阻止显式访问。
- 命名空间包可由多个目录共同贡献子包，没有统一初始化文件。

## 5. 查找与缓存

- `sys.path`：顶层模块查找位置列表，受入口、环境和配置影响。
- `sys.modules`：进程内导入名到模块对象的缓存。
- `find_spec(name)`：诊断名称能否找到、由谁加载。
- `module.__file__` / `module.__spec__.origin`：确认实际来源。
- 本地同名文件可能遮蔽标准库或第三方模块。
- `reload()` 不会更新所有旧类、旧实例和直接成员绑定。

## 6. 循环导入

```text
A 提前进入缓存但未执行完
→ A 导入 B
→ B 再导入 A，得到部分初始化对象
→ B 读取 A 尚未建立的属性
→ 失败
```

优先提取共同依赖、反转依赖、减少包初始化重导出。局部导入只能推迟读取时点，不自动改善职责耦合。

## 7. 环境诊断

```text
sys.executable   实际解释器
sys.prefix       当前环境前缀
sys.base_prefix  基础 Python 前缀
```

终端、IDE 和 Notebook 可能各用不同解释器。`python -m pip` 明确让当前 `python` 执行 pip，但前提是 `python` 本身选对。

虚拟环境隔离第三方安装目录，不自动锁版本、不隔离网络，也不保证 Notebook 选中它。

## 8. 项目与依赖文件

```text
.python-version → 偏好的 Python 版本
pyproject.toml  → 项目元数据与依赖范围
锁文件          → 一次完整解析结果
.venv           → 当前机器实际环境
```

`requirements.txt` 是 pip 安装需求格式，可能是范围也可能是冻结结果；文件名本身不证明用途。

## 9. 依赖图

- 直接依赖：项目主动使用和声明。
- 传递依赖：上游发行包自身要求。
- 解析器寻找所有版本约束的交集。
- 运行、开发、可选依赖按使用场景分组。
- 锁定提高复现性，不自动保证安全与跨平台完全一致。

## 10. 项目结构

`src` 布局减少“仓库根目录恰好在 `sys.path`”造成的假成功。可编辑安装服务开发；真正发布前仍要构建 wheel，在干净环境安装验证。

## 11. 排查清单

1. `sys.executable` 与 Python 版本是否正确？
2. 项目或发行包是否安装进这个环境？
3. `find_spec()` 找到哪里？
4. `__file__` / `origin` 是否为预期来源？
5. `sys.path` 为什么包含这些位置？
6. 是否有同名本地文件？
7. 是否是部分初始化或循环导入？
8. 声明与锁文件是否同步？

## 12. 高频误区

1. 把 `.py` 文件、导入名和模块对象当成同一东西。
2. 认为 `from ... import ...` 会持续同步重新绑定。
3. 认为重复导入一定重新执行模块。
4. 用修改 `sys.path` 掩盖项目未安装。
5. 把相对导入理解成相对工作目录。
6. 用 `__all__` 当权限控制。
7. 用局部导入掩盖所有循环依赖。
8. 把导入名直接当作发行包名。
9. 认为虚拟环境等于版本锁定。
10. 认为锁定版本就自动安全。

## 13. 一分钟自测

1. 首次导入为什么在执行前缓存模块对象？
2. `import m` 与 `from m import x` 在 `m.x` 重绑后有何差异？
3. 为什么 `python -m package.cli` 有包上下文？
4. 怎样确认实际导入了哪个文件？
5. 循环导入中的“部分初始化”是什么？
6. 虚拟环境和锁文件分别隔离或固定什么？
7. 直接依赖与传递依赖有何区别？
8. 可编辑安装为什么不能代替 wheel 验证？
