# 第 3 章：函数、参数与作用域

## 1. 函数调用中的对象、参数与作用域

你可能已经会写这样的函数：

```python
def add(left, right):
    return left + right
```

但面试不会只问语法。更常见的问题是：

- `left` 和 `right` 在调用时到底绑定到了什么？
- 如果实参表达式得到列表对象，函数内部修改它，为什么调用处也可能观察到变化？
- 默认列表为什么会在多次调用之间保存内容？
- 为什么函数里先读取全局变量、后面给它赋值会报错？
- `*args`、`**kwargs`、`/` 和 `*` 分别控制什么？
- 递归为什么会占用额外空间？

递归可以先理解为函数直接或间接调用自身；真正正确的递归还必须有结束条件并不断接近它，第 24～26 节会从调用栈展开。

这些问题不是互不相关的特殊规则。它们都建立在同一条主线上：

```text
函数对象被调用
→ 实参表达式先得到对象
→ 形参名字绑定到这些对象
→ 函数在自己的局部作用域执行
→ return 把对象交还调用者
```

这条主线会先用到三个术语：函数定义中等待接收对象的名字叫**形参**，调用函数时提供的表达式叫**实参**，形参的名称、顺序、类别和默认值等调用结构称为**函数签名**。第 5 节会再用完整例子区分它们。

本章会把这条主线逐步展开。

---

## 2. 函数解决什么问题

### 2.1 从重复代码到有名字的操作

假设程序多次计算含税价格：

```python
first_total = 100 * 1.13
second_total = 250 * 1.13
third_total = 80 * 1.13
```

把规则写成函数：

```python
def price_with_tax(price):
    return price * 1.13


first_total = price_with_tax(100)
second_total = price_with_tax(250)
third_total = price_with_tax(80)
```

函数至少带来三种价值：

- 给一段规则起名字。
- 让调用者只关心输入和输出。
- 修改规则时集中修改一处。

### 2.2 函数的输入、输出与副作用约定

调用者看到的是：

```text
函数名 + 可以传入什么 + 返回什么 + 是否修改外部状态
```

这构成函数**接口**。接口是使用者能够观察和依赖的调用约定，包括怎样传入数据、返回什么、可能出现什么错误，以及是否修改外部状态。状态可以先理解为程序当前保存的数据和值。函数内部实现可以变化，但接口行为应当清楚、稳定。

例如，`sorted(values)` 返回新列表，而 `values.sort()` 修改原列表并返回 `None`。二者都能得到有序结果，但接口约定不同。调用前必须知道函数会不会修改输入。

## 3. 执行 `def` 时发生了什么

### 3.1 `def` 会创建函数对象

```python
def greet(name):
    return f"Hello, {name}"
```

执行这段定义时，Python 创建一个函数对象，再把名字 `greet` 绑定到它：

```text
greet ─────────→ 函数对象
                 形参：name
                 函数体：返回问候文本
```

执行 `def` 不会立刻运行函数体。只有调用时才执行：

```python
def greet(name):
    return f"Hello, {name}"


message = greet("Lin")
```

### 3.2 函数对象与调用结果不同

```python
def greet(name):
    return f"Hello, {name}"


print(greet)
print(greet("Lin"))
```

- `greet` 表示函数对象本身。
- `greet("Lin")` 表示调用函数后得到的返回值。

这个区别会在“把函数交给其他代码稍后调用”的场景中频繁出现。需要把行为交给其他代码时，通常传 `greet`；需要立刻执行时才写 `greet("Lin")`。这种“稍后由接收方调用”的函数会在本章后面定义为回调函数。

### 3.3 名字可以重新绑定

函数名仍然只是名字：

```python
def greet(name):
    return f"Hello, {name}"


original = greet
greet = "not a function"

print(original("Lin"))
```

函数对象没有因为 `greet` 被重新绑定而自动消失，`original` 仍指向它。这正是第 1 章对象模型在函数上的延伸。

## 4. 一次函数调用怎样进行

### 4.1 函数调用的执行步骤

```python
def multiply(number, factor):
    result = number * factor
    return result


answer = multiply(6, 7)
```

可以按以下顺序理解：

1. 找到名字 `multiply` 指向的函数对象。
2. 从左到右计算实参表达式 `6` 和 `7`。
3. 根据函数签名，把形参 `number` 绑定到 `6`，把 `factor` 绑定到 `7`。
4. 为本次调用建立局部执行环境。
5. 执行函数体，让局部名字 `result` 绑定到 `42`。
6. `return result` 把整数对象 `42` 交还调用位置。
7. 调用结束，调用者的名字 `answer` 绑定到返回对象。

### 4.2 每次调用都有自己的局部名字

```python
def double(number):
    result = number * 2
    return result


first = double(3)
second = double(10)
```

两次调用各自有独立的 `number` 和 `result`。第一次的 `number` 不会被第二次调用直接改成 `10`。

为了理解运行过程，可以先把每次调用想成一张独立工作表。更正式的运行结构叫**栈帧**：它保存本次调用的局部名字、执行位置等状态。递归部分会继续使用这个概念。

### 4.3 实参表达式先求值

```python
def show(left, right):
    print(left, right)


number = 3
show(number + 1, number * 10)
```

形参不是直接绑定到源代码文本 `number + 1`，而是绑定到表达式计算得到的对象。

## 5. 形参与实参

### 5.1 定义中的形参与调用中的实参

```python
def repeat(text, times):
    return text * times


result = repeat("ha", 3)
```

- 定义中的 `text` 和 `times` 是**形参**。
- 调用中的 `"ha"` 和 `3` 是**实参**。

形参是函数定义中声明、在函数内部使用的局部名字。实参是调用时实际提供的表达式；Python 先计算实参表达式，再把得到的对象绑定给相应形参。

为了避免“参数”一词同时指两件事，本讲义需要区分时会明确写“形参”或“实参”。例如，“位置实参”描述调用者怎样提供值，“仅限位置形参”描述函数定义怎样限制调用方式。

### 5.2 函数签名

函数签名描述调用接口中的形参结构：名称、顺序、类别和默认值等。

```python
def connect(host, port=80, *, timeout=5):
    pass
```

这里的裸 `*` 不是形参，它表示后面的 `timeout` 只能由关键字实参绑定；第 11 节会系统解释五类形参。

仅凭签名就能知道：

- `host` 必须提供。
- `port` 有默认值。
- `timeout` 必须按关键字提供。

返回类型是否属于“签名”的严格定义，在不同工具语境中可能表述不同。面试里更重要的是能读懂调用约束，而不是争论术语边界。

## 6. `return` 到底做什么

### 6.1 返回对象并结束当前调用

```python
def absolute(number):
    if number >= 0:
        return number
    return -number
```

执行到 `return` 后，本次函数调用立即结束，后面的语句不会继续执行。

### 6.2 没有显式返回值时返回 `None`

```python
def display(message):
    print(message)


result = display("hello")
print(result)
```

`display()` 会显示文本，但没有显式 `return`，所以调用结果是 `None`。

`print()` 与 `return` 的职责不同：

- `print()` 把内容显示到输出设备。
- `return` 把对象交给调用者继续使用。

### 6.3 返回多个值实际返回元组

```python
def divide_with_remainder(number, divisor):
    quotient = number // divisor
    remainder = number % divisor
    return quotient, remainder


result = divide_with_remainder(17, 5)
print(result)        # (3, 2)
print(type(result))  # <class 'tuple'>
```

调用者可以再解包：

```python
def divide_with_remainder(number, divisor):
    return number // divisor, number % divisor


quotient, remainder = divide_with_remainder(17, 5)
```

### 6.4 返回值与副作用

除了返回值以外，函数还可能修改列表、写文件、更新数据库或输出日志。这些对外部可观察状态的改变通常称为**副作用**。

副作用不等于错误，但接口应该说明它。一个名字叫 `get_sorted_values()` 的函数如果偷偷修改输入，会让调用者难以判断状态。

## 7. 文档字符串与函数信息

### 7.1 文档字符串

函数体第一条字符串字面量可以成为文档字符串：

```python
def area(width, height):
    """返回矩形面积。"""
    return width * height
```

可以通过 `help(area)` 或 `area.__doc__` 查看。文档字符串通常说明用途、参数含义、返回结果、异常和副作用，而不是逐行复述实现。

### 7.2 常见函数属性

```python
def area(width, height):
    """返回矩形面积。"""
    return width * height


print(area.__name__)
print(area.__doc__)
print(area.__annotations__)
```

- `__name__`：函数定义时的名称。
- `__doc__`：文档字符串。
- `__annotations__`：参数和返回值注解。

这些名称开头和结尾各有两个下划线，常被口头称为“双下划线名称”或 `dunder` 名称。Python 为语言协议和对象内部信息预留了许多这类名称：这里的 `__name__`、`__doc__` 和 `__annotations__` 是函数对象的特殊属性；第 1 章预览过的 `__eq__()` 则是可以参与运算协议的特殊方法。属性是对象上可以读取的数据，方法是绑定在对象或类型上、可以调用的行为。

本章不要求背诵所有双下划线名称，也不应随意发明新的双下划线名字。自定义类、特殊属性和特殊方法的完整机制将在第 6 章学习。当前只需知道：它们不是装饰写法，而是 Python 规定或使用的特殊接口名称。

### 7.3 本章中的异常名称怎样阅读

本章会多次看到 `TypeError`、`NameError`、`UnboundLocalError`、`ValueError` 和 `RecursionError`。它们都属于**异常**：程序运行时发现当前操作无法正常继续时，用异常对象表示错误并中断当前路径。

- `TypeError`：对象类型或调用方式不符合当前操作要求。
- `NameError`：读取不到指定名字。
- `UnboundLocalError`：名字已被确定为局部名字，但读取时尚未绑定对象。
- `ValueError`：对象类型可以接受，但具体值不符合要求。
- `RecursionError`：递归调用过深。

实验中的 `try`/`except` 只是为了捕获异常并观察其名称，避免整个 Notebook 在预期错误处停止。异常如何传播、捕获和清理资源将在第 7 章完整学习。本章仍需要知道每个示例为什么产生相应异常，不能只记异常名字。

更完整的函数检查工具属于标准库和工程实践内容。本章只需知道函数是能被观察的对象。

## 8. 位置实参与关键字实参

本节讨论的是**调用函数时提供实参的两种方式**，不是形参的完整类别。位置实参根据出现顺序绑定，关键字实参根据写出的形参名称绑定。

### 8.1 位置实参按顺序绑定

```python
def describe(name, age):
    return f"{name}: {age}"


describe("Ming", 25)
```

调用中的 `"Ming"` 和 `25` 没有写形参名称，所以它们是位置实参。绑定过程是：

```text
第 1 个位置实参 "Ming" → 第 1 个形参 name
第 2 个位置实参 25     → 第 2 个形参 age
```

位置顺序改变，绑定结果也会改变：

```python
def describe(name, age):
    return f"{name}: {age}"


describe(25, "Ming")
```

这时 `name` 绑定到 `25`，`age` 绑定到 `"Ming"`。Python 只遵守绑定规则，不会根据值的业务含义自动纠正顺序。

### 8.2 关键字实参按形参名称绑定

```python
def describe(name, age):
    return f"{name}: {age}"


describe(age=25, name="Ming")
```

调用中的 `age=25` 和 `name="Ming"` 是关键字实参。这里的写法不是普通赋值语句，而是在调用中明确指定目标形参：

```text
age=25       → 形参 age 绑定到 25
name="Ming" → 形参 name 绑定到 "Ming"
```

关键字实参根据名称绑定，所以书写顺序可以不同，调用意图通常也更清楚。

### 8.3 位置实参与关键字实参的混合调用

```python
def describe(name, age):
    return f"{name}: {age}"


describe("Ming", age=25)
```

这里先用位置实参绑定 `name`，再用关键字实参绑定 `age`。普通位置实参必须写在普通关键字实参之前，下面是语法错误：

```python
# describe(name="Ming", 25)
```

### 8.4 同一个形参不能绑定两次

```python
# describe("Ming", name="Hong")
```

位置实参已经把 `name` 绑定为 `"Ming"`，关键字实参又尝试绑定一次，因此调用会抛出 `TypeError`。

下面三种合法调用最终得到相同的形参绑定：

```python
def describe(name, age):
    return f"{name}: {age}"


describe("Ming", 25)
describe("Ming", age=25)
describe(name="Ming", age=25)
```

```text
name → "Ming"
age  → 25
```

当前定义中的 `name` 和 `age` 都属于“位置或关键字形参”，因为调用者可以用任一种方式为它们提供实参。第 11 节会继续区分仅限位置、仅限关键字等五类形参。

## 9. 形参默认值

日常交流中常把“具有默认值的形参”简称为“默认参数”。更准确地说，默认值是形参的一项配置，不是独立的形参类别。

### 9.1 调用者省略实参时才使用默认值

```python
def connect(host, port=80):
    return host, port


print(connect("example.com"))
print(connect("example.com", 443))
```

调用者为 `port` 提供实参时使用该实参对象；省略 `port` 对应的实参时，才使用默认对象。

### 9.2 形参声明顺序

Python 规定：对于能够由位置实参绑定的形参，没有默认值的必填形参不能跟在有默认值的形参后面：

```python
# def connect(port=80, host):
#     pass
```

位置实参只能从左到右连续绑定。Python 不支持用空位置表示“跳过这个形参”：

```python
# connect(, "example.com")  # SyntaxError
```

因此，把必填形参放在前面，调用关系最直接：

```python
def connect(host, port=80):
    return host, port


connect("example.com")
```

这里 `host` 得到位置实参，`port` 因没有对应实参而使用默认值。

这不是所有编程语言都必须遵守的逻辑定律，而是 Python 的语法与绑定设计。如果需要“前面的形参可省略，后面的形参仍然必填”，可以让后者成为仅限关键字形参：

```python
def connect(port=80, *, host):
    return host, port


connect(host="example.com")
```

`host` 必须明确按名称绑定，因此不会产生位置空洞。

### 9.3 默认值表达式在函数定义时求值

这是本章最重要的规则之一：**默认值表达式在执行 `def` 时计算一次。**

```python
def show_default(value=10 + 5):
    return value
```

`10 + 5` 在函数对象创建时计算，结果保存在函数的默认值信息中。后续省略参数时复用该对象。

可以观察：

```python
def show_default(value=10 + 5):
    return value


print(show_default.__defaults__)
```

这条规则对整数通常不显眼，因为整数不可变；遇到可变对象时就非常关键。

## 10. 可变默认值陷阱

### 10.1 默认列表在多次调用之间共享

```python
def collect(value, items=[]):
    items.append(value)
    return items


print(collect("A"))
print(collect("B"))
print(collect("C"))
```

函数定义时只创建一个默认列表：

```text
执行 def：形参 items 的默认值 ──→ 列表对象 []

第一次调用：同一列表变成 ["A"]
第二次调用：同一列表变成 ["A", "B"]
第三次调用：同一列表变成 ["A", "B", "C"]
```

问题不是“列表作为实参不安全”，而是“同一个可变默认对象被多次省略 `items` 实参的调用共享，并且函数修改了它”。

### 10.2 使用 `None` 在调用时创建新列表

```python
def collect(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items
```

`None` 默认对象仍然只保存一次，但 `None` 不会被修改。每次省略 `items` 时，函数体都会新建列表。

### 10.3 显式传入列表仍然会被修改

```python
def collect(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items


external = []
collect("A", external)
print(external)  # ["A"]
```

修复默认值共享，不等于函数变成不修改输入。调用者显式传入列表时，形参仍与调用者共享该对象。

### 10.4 `None` 是合法业务值怎么办

有些接口需要区分：

- 调用者没有为该形参提供实参。
- 调用者明确提供了 `None`。

可以使用专用**哨兵对象**。哨兵是程序专门创建的唯一标记，用来与所有合法业务值区分；这里调用 `object()` 创建一个没有额外业务含义的新对象作为标记：

```python
MISSING = object()


def configure(value=MISSING):
    if value is MISSING:
        return "use default behavior"
    return f"provided: {value!r}"
```

`MISSING` 只用于身份判断。不要用普通字符串当哨兵，因为业务输入可能恰好等于该字符串。

## 11. 五类形参怎样排列

观察一个集中展示形参类别的签名：

```python
def example(pos_only, /, normal, default=0, *args, keyword_only, **kwargs):
    return pos_only, normal, default, args, keyword_only, kwargs
```

从左到右分别是：

1. `/` 之前的 `pos_only`：仅限位置形参。
2. `/` 与 `*args` 之间的 `normal` 和 `default`：位置或关键字形参。
3. `*args`：可变位置形参，收集额外位置实参。
4. `*args` 之后的 `keyword_only`：仅限关键字形参。
5. `**kwargs`：可变关键字形参，收集额外关键字实参。

`default=0` 表示形参 `default` 有默认值，但“有无默认值”不是第六种形参类别。形参类别决定实参可以怎样绑定；默认值决定调用者省略该形参时使用什么对象。这是两个不同维度。

### 11.1 仅限位置形参 `/`

```python
def ratio(numerator, denominator, /):
    return numerator / denominator


ratio(10, 2)
# ratio(numerator=10, denominator=2)  # TypeError
```

`/` 本身不是形参。它表示左侧形参只能由位置实参绑定。

这可以让形参名保留为实现细节，也能允许 `**kwargs` 中出现与仅限位置形参同名的键。许多内置函数也采用位置限定。

### 11.2 仅限关键字形参 `*`

```python
def request(url, *, timeout=5, verify=True):
    return url, timeout, verify


request("https://example.com", timeout=10)
# request("https://example.com", 10)  # TypeError
```

裸 `*` 本身不是形参，它表示后续形参必须由关键字实参绑定。布尔开关、单位不明显的数值等形参要求写出名字，通常更容易阅读。

### 11.3 `*args`：可变位置形参

```python
def collect_all(first, *args):
    print(first)
    print(args)


collect_all(1, 2, 3, 4)
```

`args` 是包含多余位置实参的元组。名字不一定必须叫 `args`，但这是通用约定。

没有额外位置实参时，`args` 是空元组。

### 11.4 `**kwargs`：可变关键字形参

```python
def show_options(**kwargs):
    print(kwargs)


show_options(timeout=5, retry=3)
```

`kwargs` 是保存多余关键字实参的字典。直接写成 `timeout=5` 时，名称需要遵守与变量名相同的书写规则。使用 `**mapping` 展开时，映射的键必须是字符串；与显式形参匹配的键会先绑定相应形参，其余键才由 `kwargs` 收集。

### 11.5 `*args`、`**kwargs` 的使用场景与接口可读性

`*args` 和 `**kwargs` 适合包装器、兼容不同选项或转发调用，但会降低接口明确性。包装器可以先理解为“在另一个函数调用前后增加行为，并把调用继续交给原函数”的函数，第 4 章会完整学习。如果函数真正只需要三个参数，直接写出它们通常更清楚，也更利于类型检查和编辑器提示。

## 12. 调用时的 `*` 与 `**` 展开

### 12.1 `*` 展开位置实参

```python
def volume(length, width, height):
    return length * width * height


dimensions = [2, 3, 4]
result = volume(*dimensions)
```

效果相当于：

```python
def volume(length, width, height):
    return length * width * height


result = volume(2, 3, 4)
```

被展开对象需要**可迭代**，也就是能够依次提供其中元素；列表和元组都是常见可迭代对象。展开后的元素数量还要符合签名要求。迭代协议会在第 5 章完整学习。

### 12.2 `**` 展开关键字实参

```python
def volume(length, width, height):
    return length * width * height


options = {"length": 2, "width": 3, "height": 4}
result = volume(**options)
```

字典键成为形参名，因此键必须是字符串，并且展开后要能与签名匹配。

### 12.3 定义时收集实参与调用时展开实参

在函数定义中，星号把多个实参收集到一个局部形参中：

```text
多个位置实参 → *args   → 一个元组
多个关键字实参 → **kwargs → 一个字典
```

在函数调用中，星号把一个对象展开成多个实参：

```text
一个可迭代对象 → *values  → 多个位置实参
一个映射对象   → **mapping → 多个关键字实参
```

把两个过程放在一次调用中观察：

```python
def show(*args, **kwargs):
    return args, kwargs


values = [10, 20]
options = {"unit": "px"}
result = show(*values, **options)
```

数据依次经历：

```text
调用处展开：
[10, 20] → 位置实参 10、20
{"unit": "px"} → 关键字实参 unit="px"

定义处收集：
位置实参 10、20 → args == (10, 20)
关键字实参 unit="px" → kwargs == {"unit": "px"}
```

所以不是星号本身具有固定的“收集”或“展开”含义，而是要先看它出现在函数定义还是函数调用中。

### 12.4 展开后仍不能重复绑定

```python
options = {"height": 4}
# volume(2, 3, height=5, **options)  # height 被绑定两次
```

看到复杂调用时，先在纸上把所有展开项摊平，再按照签名检查绑定，通常比凭感觉判断可靠。

## 13. Python 的参数传递模型

### 13.1 实参对象与局部形参的绑定

只说“值传递”或“引用传递”都容易产生误解。分析 Python 调用时，直接跟踪下面三个步骤更清楚：

```text
计算实参表达式，得到对象
→ 为本次函数调用建立局部形参名字
→ 让形参绑定到这些对象
```

Python 不会因为调用函数就自动复制实参对象，也不会把调用处的变量名本身交给函数。函数得到的是自己的局部形参名字，只是这些形参最初可能与调用处的名字指向同一个对象。

这种模型通常称为**对象共享传参**。有些资料把它压缩成“对象引用按值传递”，其中“引用按值”想表达的是：函数得到另一个指向同一对象的局部绑定，而不是获得修改调用处名字绑定关系的能力。如果这句简称妨碍理解，直接使用前面的三步过程即可。

### 13.2 修改共享对象

```python
def add_item(items):
    items.append("new")


records = []
add_item(records)
```

`records` 位于执行调用的作用域，`items` 位于 `add_item()` 本次调用的局部作用域。进入函数后：

```text
调用处的名字 records ─┐
                      ├──→ 同一个列表对象 []
局部形参名字 items ────┘
```

`items.append("new")` 修改的是两边共同指向的列表对象：

```text
调用处的名字 records ─┐
                      ├──→ 同一个列表对象 ["new"]
局部形参名字 items ────┘
```

调用结束后，通过 `records` 再访问该列表时可以观察到变化。这里改变的是列表内容，`records` 与列表之间的绑定关系没有改变。

可变对象不会因为被传入函数就自动产生副作用；只有函数确实执行了修改该共享对象的操作，其他位置才可能观察到变化。

### 13.3 重新绑定形参只改变函数的局部绑定

```python
def replace(items):
    items = ["new"]


records = []
replace(records)
print(records)  # []
```

刚进入函数时，`records` 和 `items` 指向同一个原列表。执行 `items = ["new"]` 后：

```text
调用处的名字 records ───→ 原列表 []
局部形参名字 items ──────→ 新列表 ["new"]
```

这条赋值语句改变的是局部名字 `items` 的绑定。调用处的名字 `records` 仍然绑定原列表，所以 `print(records)` 得到 `[]`。

因此，更准确的结论是：

> 重新绑定局部形参，不会让调用处作用域中的名字改为绑定另一个对象。

如果调用处希望使用函数产生的新对象，应通过返回值明确重新绑定：

```python
def replacement():
    return ["new"]


records = []
records = replacement()
```

### 13.4 不可变对象的常见表现

```python
def increase(number):
    number += 1


count = 10
increase(count)
print(count)  # 10
```

整数不可变。`number += 1` 不能原地改变整数 `10`，而是得到整数 `11`，再让局部名字 `number` 绑定到它：

```text
调用处的名字 count ────→ 整数对象 10
局部形参名字 number ────→ 整数对象 11
```

`count` 与整数 `10` 的绑定没有改变，所以调用结束后仍为 `10`。

不可变对象只表示该对象本身不能被原地修改，不表示函数绝对没有其他副作用。函数仍可能输出内容、修改全局状态或修改另外的共享对象。

### 13.5 可变与不可变对象使用同一套传参规则

下面的说法不准确：

```text
可变对象按引用传递
不可变对象按值传递
```

所有函数调用都遵循同一套模型：形参绑定到实参表达式得到的对象。真正需要区分的是后续操作：

```text
修改共享对象
→ 其他指向该对象的位置可能观察到变化

重新绑定局部形参
→ 只改变本次调用中的局部绑定
```

## 14. 函数应不应该修改输入

### 14.1 返回新对象与原地修改输入

返回新对象：

```python
def with_added_item(items, value):
    result = items.copy()
    result.append(value)
    return result
```

原地修改：

```python
def add_item_in_place(items, value):
    items.append(value)
```

前者更容易推理，但需要额外复制；后者可以减少复制，但调用者必须知道输入会变化。

### 14.2 名称和文档应表达副作用

`sort_in_place()`、`update_mapping()` 这样的名字比模糊的 `process()` 更容易提示副作用。接口还应明确返回什么：原地修改函数可以返回 `None`，也可以返回对象以支持**链式使用**，也就是在一个调用结果后继续调用下一个方法，例如 `operation().next_operation()`。是否支持这种写法应由接口明确决定，并在同一项目中保持一致。

### 14.3 浅拷贝不是完全隔离

```python
def add_nested_value(groups):
    copied = groups.copy()
    copied[0].append("new")
    return copied
```

只复制外层列表，内部列表仍可能共享。这里延续第 2 章的浅拷贝结论，深拷贝机制在第 9 章学习。

## 15. 作用域解决什么问题

### 15.1 同一个名字可以存在于不同范围

```python
message = "global"


def show():
    message = "local"
    print(message)


show()
print(message)
```

函数内部的 `message` 与模块顶层的 `message` 是不同作用域中的绑定。

作用域规定名字在哪一部分代码中可见，以及读取名字时到哪里寻找。

这里的**模块**可以先理解为一个被 Python 加载和执行的 `.py` 文件，以及执行该文件时形成的顶层命名空间。命名空间可以暂时理解为“名字到对象绑定关系的集合”。文件顶层绑定的名字称为该模块的全局名字。在 Notebook 中，可以暂时把当前内核会话的顶层区域理解成类似的全局环境。模块怎样导入、缓存和互相引用将在第 8 章完整学习。

### 15.2 函数调用建立局部作用域

函数的形参和函数体内绑定的普通名字通常属于本次调用的局部作用域：

```python
def calculate(price, count):
    total = price * count
    return total
```

`price`、`count` 和 `total` 都是局部名字。调用结束后，调用者不能直接读取 `total`；应使用返回值。

## 16. LEGB 名字查找规则

读取一个名字时，Python 按以下层次寻找：

```text
L：Local，当前函数的局部作用域
→ E：Enclosing，外层函数作用域
→ G：Global，当前模块的全局作用域
→ B：Built-in，内置作用域
```

### 16.1 Local：当前函数的局部作用域

```python
def show():
    value = "local"
    print(value)
```

首先在当前函数局部寻找 `value`。

### 16.2 Enclosing：外层函数作用域

```python
def outer():
    value = "enclosing"

    def inner():
        print(value)

    inner()


outer()
```

`inner()` 局部没有 `value`，于是到外层函数 `outer()` 的作用域找到它。

本章先理解读取规则。若内层函数使用外层名字，并在外层调用结束后仍保留访问这些绑定的能力，函数和相关外层绑定会形成闭包；完整机制会在第 4 章展开。

### 16.3 Global：当前模块的全局作用域

```python
value = "global"


def show():
    print(value)
```

局部和外层函数中都没有时，到模块全局作用域寻找。

“全局”通常是相对于当前模块而言，不是所有 Python 文件自动共享同一个万能命名空间。

### 16.4 Built-in：内置作用域

```python
print(len([1, 2, 3]))
```

如果前面各层没有同名绑定，`print` 和 `len` 会在内置作用域找到。

### 16.5 用 `globals()` 和 `locals()` 观察命名空间

Python 提供两个内置函数帮助观察当前绑定：

- `globals()` 返回当前模块全局命名空间所使用的字典。
- `locals()` 返回表示当前局部命名空间的映射；在函数中修改这个返回对象，不保证能反向改变真实局部名字。

在普通模块顶层调用时，当前局部命名空间就是模块全局命名空间，因此两者看到的是同一组名字。在函数内部调用时，`locals()` 观察本次调用的局部名字，而 `globals()` 仍观察模块顶层的名字：

```python
module_value = "outside"


def inspect_names():
    local_value = "inside"
    print("module_value" in globals())  # True
    print("local_value" in locals())    # True
    print("local_value" in globals())   # False


inspect_names()
```

这里比较的是两张名字表中的条目，并不是说 `globals()` 的“查找范围更大”。函数读取 `module_value` 时仍可按 LEGB 到全局作用域寻找，即使它不在 `locals()` 的映射里。Notebook 的顶层也是类似情况；IPython 还会在其中放入输入历史等辅助名字，所以直接显示整个映射会很长。

本项目的 Notebook 在每道实验后使用 `check_experiment(globals(), 实验编号)` 做即时检查；整章完成后才使用 `run_checks(globals())` 复查。`globals()` 在这里返回当前 Notebook 顶层的名字映射，让检查函数找到本题的 `observation_*` 变量。这是一种教学检查接口，不代表业务函数都应接收完整全局命名空间。

`globals()` 和 `locals()` 适合检查和调试，不应替代清楚的形参、实参和返回值设计。完整模块机制和导入行为仍在第 8 章学习。

### 16.6 名字查找失败与 `NameError`

如果四层都没有该名字，通常抛出 `NameError`。

## 17. 名字读取与局部赋值规则

### 17.1 局部赋值前读取名字的错误

```python
count = 10


def increase():
    print(count)
    count = count + 1
```

很多人以为第一行 `print(count)` 会读全局 `count`，后面再建立局部 `count`。实际调用会出现 `UnboundLocalError`。

### 17.2 函数中的赋值如何决定局部名字

只要函数体中存在对 `count` 的普通赋值，Python 在分析函数代码时通常就把 `count` 视为局部名字。执行到 `print(count)` 时，程序试图读取局部 `count`，但它尚未绑定对象。

```text
函数被分析：count 是局部名字
→ 执行 print(count)
→ 局部 count 尚无对象
→ UnboundLocalError
```

它没有退回全局层继续找，因为这个名字已经被确定为局部名字。

### 17.3 `NameError` 与 `UnboundLocalError`

- `NameError`：按规则没有找到名字。
- `UnboundLocalError`：函数局部名字已经被确定，但当前读取时还没有绑定值。

`UnboundLocalError` 是 `NameError` 的子类，但面试中应能说明它更具体的原因。

## 18. `global`

### 18.1 显式指定模块全局名字

```python
count = 10


def increase():
    global count
    count += 1


increase()
print(count)  # 11
```

`global count` 表示函数中的赋值针对模块全局作用域的 `count`，而不是建立局部 `count`。

### 18.2 `global` 不会让所有模块共享变量

这里的全局是当前函数所属模块的全局命名空间。导入模块、跨模块状态和模块缓存会在第 8 章学习。

### 18.3 用参数和返回值替代全局状态

函数依赖和修改大量全局状态，会使测试、并发和复用变困难。下面通常更清楚：

```python
count = 10


def increased(count):
    return count + 1


count = increased(count)
```

`global` 有配置、缓存或模块级状态等合理场景，但应当是明确选择，而不是为了少写返回值。

## 19. `nonlocal`

### 19.1 修改外层函数中的名字

```python
def outer():
    count = 0

    def increase():
        nonlocal count
        count += 1
        return count

    return increase(), increase()


print(outer())  # (1, 2)
```

`nonlocal count` 让内层函数中的赋值作用于最近的、已经存在 `count` 绑定的外层函数作用域。

### 19.2 `nonlocal` 的边界

- 它不指向当前局部作用域。
- 它不指向模块全局作用域。
- 外层函数作用域中必须已经存在该名字的绑定。

如果目标是模块全局名字，使用的是 `global`，不是 `nonlocal`。

### 19.3 `nonlocal` 与后续闭包知识的联系

`nonlocal` 最常与闭包一起出现。本章先建立名字修改规则；第 4 章会解释函数返回以后，外层状态为什么还能存在。

## 20. Python 没有普通块级作用域

### 20.1 `if` 和 `for` 中的名字通常仍在当前作用域

```python
if True:
    message = "created in if"

print(message)
```

在模块层，这里的 `message` 仍是模块全局名字。

```python
def find_last(values):
    for value in values:
        pass
    return value
```

普通 `for` 不建立独立块级作用域。不过，如果输入为空，`value` 从未绑定，返回时会报错。这也是为什么不应依赖循环结束后的变量作为核心结果。

### 20.2 推导式有自己的作用域行为

现代 Python 中，列表、集合和字典推导式的循环变量不会像普通 `for` 那样泄漏到外围作用域：

```python
number = 100
squares = [number * number for number in range(3)]
print(number)  # 100
```

圆括号形式的生成器表达式，例如 `(number * number for number in range(3))`，会按需逐步产生结果，而不是立刻建立完整列表。它和推导式的更完整执行模型会在第 5 章结合迭代器学习。

## 21. 遮蔽内置名字

### 21.1 名字查找会优先使用前面的层级

```python
list = [1, 2, 3]
# values = list("abc")  # 此时 list 不再指向内置类型
```

局部或全局名字 `list` 遮蔽了内置作用域中的 `list`。类似高风险名字包括：

- `dict`
- `set`
- `str`
- `sum`
- `min`
- `max`
- `id`

### 21.2 删除同名绑定后恢复内置名字查找

只是当前作用域中的名字优先级更高。删除或更换这个绑定后，内置名字仍然存在。但最清楚的做法是从一开始使用 `numbers`、`total`、`maximum` 等表达含义的名字。

## 22. 函数也是普通对象

### 22.1 保存函数

```python
def double(number):
    return number * 2


operation = double
print(operation(5))
```

`operation` 与 `double` 指向同一个函数对象。

### 22.2 函数可以放进容器

```python
def add_one(number):
    return number + 1


def double(number):
    return number * 2


operations = [add_one, double]
for operation in operations:
    print(operation(10))
```

### 22.3 函数可以作为参数

```python
def add_one(number):
    return number + 1


def apply_twice(operation, value):
    return operation(operation(value))


print(apply_twice(add_one, 3))
```

这次调用的绑定关系是：

```text
形参 operation → 函数对象 add_one
形参 value     → 整数对象 3
```

函数体先计算 `operation(3)` 得到 `4`，再计算 `operation(4)` 得到 `5`。

接收函数对象作为实参，或者返回函数对象的函数，称为**高阶函数**。因此 `apply_twice()` 是高阶函数。

返回函数对象也不需要立刻调用它：

```python
def add_one(number):
    return number + 1


def choose_operation():
    return add_one


chosen = choose_operation()
print(chosen(3))  # 4
```

这里沿用上面的 `add_one`。`choose_operation()` 返回的是函数对象，随后 `chosen(3)` 才执行它。第 4 章会继续讨论返回的内层函数如何保留外层状态。

如果一个函数对象被交给其他代码，由接收方稍后在处理过程中调用，这个被交出去的函数通常称为**回调函数**。高阶函数描述接收方的能力，回调函数描述被传入函数在当前场景中的角色；它们不是两种不同的函数对象。

### 22.4 `sorted()` 的 `key` 形参与排序依据

先看 `sorted()` 的简化签名：

```text
sorted(iterable, *, key=None, reverse=False)
```

这里的 `key` 是 `sorted()` 的仅限关键字形参。调用时可以把一个函数对象传给它：

```python
names = ["Li", "Alexander", "Chen"]
ordered = sorted(names, key=len)
```

绑定关系是：

```text
sorted() 的形参 key → 内置函数对象 len
```

排序过程中，`sorted()` 对每个元素调用 `key` 当前指向的函数，得到比较依据：

```text
len("Li")        → 2
len("Alexander") → 9
len("Chen")      → 4
```

于是结果按 `2、4、9` 的顺序排列，但返回的仍是原来的字符串：

```python
names = ["Li", "Alexander", "Chen"]
ordered = sorted(names, key=len)
print(ordered)  # ['Li', 'Chen', 'Alexander']
```

这里需要区分三个概念：

```text
key     → sorted() 的形参名称
len     → 传给 key 的函数对象，也是 sorted() 稍后调用的回调
2、9、4 → 回调结果，也就是各元素的排序依据
```

“`key` 函数”只是“传给 `key` 形参、用于产生排序依据的函数”的简称。它与字典中的键不是同一个概念。

必须写 `key=len`，而不是 `key=len()`：前者传递函数对象，让 `sorted()` 稍后调用；后者会立即调用 `len`，而且没有提供待计算长度的对象，会在进入 `sorted()` 前抛出 `TypeError`。

### 22.5 `callable()`

```python
print(callable(len))      # True
print(callable(42))       # False
```

`callable()` 判断对象是否支持调用语法，但返回 `True` 不保证使用某组具体实参的调用一定成功。

闭包会保留外层绑定；装饰器会接收原函数并返回带附加行为的替代对象；`lambda` 是创建简短函数对象的表达式；`functools` 是标准库中的函数工具模块。它们会在第 4 章系统展开。

## 23. 函数注解

### 23.1 函数形参与返回值的类型标注

```python
def add(left: int, right: int) -> int:
    return left + right
```

注解可以帮助读者、编辑器和静态检查工具理解预期类型。这里的**静态检查**指工具不真正执行这次业务调用，而是分析源代码和注解，提前报告可能不符合约定的位置。它能发现一部分问题，但不能证明程序运行时一定正确。

### 23.2 默认不强制运行时类型

```python
def add(left: int, right: int) -> int:
    return left + right


print(add("a", "b"))
```

普通 Python 调用不会仅因为注解写了 `int` 就自动拒绝字符串。函数体中的 `+` 对字符串有效，所以这个调用可能正常返回 `"ab"`。

注解不是注释文本，它会保存在函数的注解信息中：

```python
def add(left: int, right: int) -> int:
    return left + right


print(add.__annotations__)
```

### 23.3 本章边界

本章只要求能阅读基本参数和返回值注解。联合类型用于表示多个允许类型，泛型用于让同一类型结构适配不同具体类型，协议用于按对象提供的行为描述类型约束；它们连同静态检查器和运行时注解求值差异，会在第 11 章学习。

## 24. 递归是什么

### 24.1 递归调用与阶乘的递推关系

递归函数会直接或间接调用自身。以计算非负整数阶乘为例：

```text
4! = 4 × 3 × 2 × 1
```

可以发现：

```text
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1 × 0!
0! = 1
```

代码：

```python
def factorial(number):
    if number == 0:
        return 1
    return number * factorial(number - 1)
```

### 24.2 终止条件与问题规模的缩小

递归至少需要：

1. **终止条件**：最小问题能够直接返回，不再递归。
2. **规模变化**：每次调用都让问题更接近终止条件。

只有终止条件但永远到不了，也不能结束。

### 24.3 输入范围也是接口的一部分

上面的函数只描述非负整数。如果传入负数，`number - 1` 会离 `0` 越来越远。稳妥的实现应明确检查或文档说明输入约束：

```python
def factorial(number):
    if number < 0:
        raise ValueError("number must be non-negative")
    if number == 0:
        return 1
    return number * factorial(number - 1)
```

异常会在第 7 章系统学习；此处只需看到输入约束与终止性直接相关。

## 25. 递归调用栈怎样变化

调用 `factorial(3)` 时，不是一次得到最终答案：

```text
factorial(3)
等待 3 × factorial(2)

factorial(2)
等待 2 × factorial(1)

factorial(1)
等待 1 × factorial(0)

factorial(0)
直接返回 1
```

随后逐层返回：

```text
factorial(0) 返回 1
factorial(1) 返回 1 × 1 = 1
factorial(2) 返回 2 × 1 = 2
factorial(3) 返回 3 × 2 = 6
```

每一层调用都需要自己的栈帧，保存本层 `number` 和尚未完成的乘法。

可以把栈想成：

```text
栈顶  factorial(0)，number = 0
      factorial(1)，number = 1，等待乘法
      factorial(2)，number = 2，等待乘法
栈底  factorial(3)，number = 3，等待乘法
```

终止层返回后，栈帧按相反顺序退出。

## 26. 递归的复杂度和限制

### 26.1 递归调用次数与时间复杂度

阶乘每一层只调用下一层一次，共约 `n` 层，因此时间复杂度是 `O(n)`。

如果每层产生多个递归分支，调用数可能快速增长。例如朴素斐波那契递归会重复计算大量相同子问题，不能因为代码很短就认为高效。

### 26.2 调用栈占用额外空间

阶乘递归深度约为 `n`，每层栈帧都要保留到下一层返回，所以额外空间通常是 `O(n)`。

对应的迭代版本使用循环逐步计算，而不是让函数调用自身：

```python
def factorial_iterative(number):
    result = 1
    for value in range(2, number + 1):
        result *= value
    return result
```

它的时间仍为 `O(n)`，但只保留少量局部状态，额外空间通常为 `O(1)`。

### 26.3 Python 有递归深度限制

Python 为避免无限递归耗尽底层调用栈，设置递归深度限制。过深调用通常抛出 `RecursionError`。

标准库模块 `sys` 提供与当前 Python 运行环境有关的功能。执行 `import sys` 后，可以通过 `sys.getrecursionlimit()` 观察当前限制。这里的 `import` 表示取得并绑定这个模块对象；模块搜索、首次导入和缓存机制将在第 8 章学习。

具体递归限制数字不是跨环境保证。盲目提高限制也可能造成解释器或进程层面的风险。

### 26.4 CPython 通常不做尾递归优化

如果函数返回前最后一个核心动作就是递归调用，这种形式称为**尾递归**。某些语言或编译器会复用当前调用空间，这称为尾递归优化。CPython 通常不做这种优化，仍为每层保留栈帧。因此不要假设 Python 能自动把深递归变成常量栈空间。

### 26.5 什么时候递归更自然

树是一种由节点和下级子结构组成的层级数据，目录和许多嵌套结构也具有相似递归定义；回溯则会尝试一个选择，在不满足要求时撤销并尝试其他选择。这些问题往往适合递归。线性计数、简单累加或可能极深的数据，更适合迭代。

选择时同时考虑：

- 问题结构是否天然递归。
- 最大深度。
- 是否存在大量重复子问题。
- 代码清晰度。
- 调用栈空间和 Python 限制。

## 27. 常见函数陷阱

### 27.1 把函数对象和调用结果混淆

```python
operations = [str.upper]       # 保存函数对象
# operations = [str.upper()]   # 没有提供调用对象
```

看到括号先问：这里需要现在执行，还是把行为交给之后执行？

### 27.2 用输出代替返回

```python
def add(left, right):
    print(left + right)
```

它显示结果，但调用者拿到的是 `None`，不能继续正常计算。

### 27.3 可变默认值

```python
def append_value(value, values=[]):
    values.append(value)
    return values
```

先问默认对象何时创建，再画出多次调用是否共享。

### 27.4 误以为形参重新绑定会改变调用处的绑定

```python
def reset(values):
    values = []
```

这只让局部形参 `values` 改为绑定新列表，不会让调用处的名字改为绑定该列表。

### 27.5 同一形参被绑定两次

```python
def show(value):
    return value


# show(1, value=2)
```

同一形参不能同时由位置和关键字提供。

### 27.6 遮蔽内置函数

```python
sum = 0
# total = sum([1, 2, 3])
```

问题来自名字绑定，不是内置函数失效。

### 27.7 把注解当成运行时验证

注解默认只表达信息。需要运行时校验时，应显式编写校验或使用清楚约定的工具。

### 27.8 递归不接近终止条件

```python
def countdown(number):
    if number == 0:
        return
    countdown(number + 1)
```

正数输入会远离 `0`，最终触发深度错误。

## 28. 怎样分析一道函数代码题

### 第一步：找函数对象与调用位置

区分只是读取函数名，还是使用括号执行调用。

### 第二步：计算实参表达式

先得到每个实参对象，再处理形参绑定。遇到 `*` 和 `**` 时先展开。

### 第三步：按签名绑定

检查：

- 位置实参数量是否匹配。
- 关键字名称是否存在。
- 是否重复绑定。
- 是否缺少必需形参所需的实参。
- 是否违反位置限定或关键字限定。

### 第四步：建立局部名字表

写出形参和局部赋值分别指向什么。若共享可变对象，画出多个名字指向同一对象。

### 第五步：按 LEGB 分析读取

遇到外部名字时，检查本函数是否存在赋值，再决定从哪一层读取。

### 第六步：区分修改与重新绑定

`append()`、键赋值等可能修改共享对象；普通赋值通常重新绑定名字。

### 第七步：跟踪返回或异常

记录在哪个 `return` 结束、返回哪个对象，或者在哪一步发生绑定错误。

## 29. 面试中怎样回答

### 29.1 回答参数传递

推荐结构：

```text
Python 的形参是本次调用的局部名字
→ 它绑定到实参表达式得到的对象
→ 修改共享对象时，调用处可能通过原有名字观察到变化
→ 重新绑定形参时，只改变函数本次调用中的局部绑定
```

给出一个列表的 `append()` 和 `items = []` 对比，就能说明模型，而不需要争论一个模糊术语。

### 29.2 回答形参默认值

推荐结构：

```text
默认表达式在执行 def 时计算一次
→ 省略对应实参的调用复用默认对象
→ 若默认对象可变且被修改，状态会跨调用积累
→ 通常使用 None，在函数体内新建对象
```

若面试官继续追问 `None` 也是有效输入，再补充专用哨兵。

### 29.3 回答 LEGB

先说读取顺序，再补充赋值规则：函数体中普通赋值通常让名字成为局部名字，所以读后赋值可能产生 `UnboundLocalError`。仅背四个字母不足以应对代码题。

### 29.4 回答递归

先说终止条件和规模变化，再画调用栈，最后分析时间与栈空间。不要只说“自己调用自己”。

## 31. 本章总结

1. `def` 创建函数对象并把名字绑定到它，函数体在调用时才执行。
2. 调用时先计算实参，再按照签名把形参局部名字绑定到对象。
3. `return` 返回对象并结束当前调用；没有显式返回值时返回 `None`。
4. 形参分为仅限位置、位置或关键字、可变位置、仅限关键字和可变关键字五类；默认值不是第六类。
5. 定义中的星号负责收集，调用中的星号负责展开。
6. 默认表达式在函数定义时计算一次，可变默认对象可能跨调用共享。
7. Python 调用时让局部形参绑定到实参表达式得到的对象；修改共享对象与重新绑定局部形参必须分开分析。
8. LEGB 描述名字读取顺序，函数中的普通赋值会影响名字的作用域判定。
9. `global` 指向模块全局名字，`nonlocal` 指向已有的外层函数名字。
10. 函数是普通对象，可以被保存、传递和返回。
11. 函数注解默认不强制运行时类型。
12. 递归必须有可到达的终止条件，并让问题规模不断缩小；调用栈会占用额外空间。
