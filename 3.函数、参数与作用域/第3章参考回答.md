# 第 3 章参考回答：函数、参数与作用域

本文件与 `第3章面试题.md` 的 40 道题逐题对应。参考回答用于学习表达结构，不要求逐字背诵。

## 一、基础概念题

### 第 1 题：定义函数与调用函数

**简短结论：** 执行 `def` 会创建函数对象并把名字绑定到它；只有使用调用语法 `()` 时，函数体才执行。

`calculate` 是当前指向函数对象的名字，`calculate()` 是一次调用表达式，其值是返回对象。`operation = calculate` 让两个名字指向同一个函数对象；`operation = calculate()` 会立刻调用，并把返回结果绑定给 `operation`。

常见误区是说“定义函数时函数内部已经执行”。面试初答说明创建、绑定、调用、返回四步即可；继续追问时可以补充函数名仍能被重新绑定。

### 第 2 题：函数接口与签名

**简短结论：** 签名说明调用者怎样提供参数；函数接口还包括返回结果、异常和副作用等可观察行为。

形参写在函数定义中，是调用期间的局部名字；实参写在调用处，是提供给函数的表达式及其求值结果。签名通常体现参数名称、顺序、类别和默认值。函数通过接口隔离实现，让调用者不必知道内部每一步。

不要把函数只描述成“减少重复”。清晰命名、职责边界、可测试性和稳定接口同样重要。

### 第 3 题：`return`、`print()` 与默认返回值

**简短结论：** `print()` 显示内容，`return` 把对象交还调用者并结束本次调用。

函数执行完而没有显式 `return`，或只执行 `return`，都会返回 `None`。`return first, second` 通过逗号构造并返回元组，调用者可以解包。

常见错误是函数只打印结果，调用者却继续拿调用结果参与计算。面试中应明确“显示”和“返回”是不同数据流。

### 第 4 题：文档字符串与函数属性

**简短结论：** 函数体第一条字符串字面量可以成为文档字符串，用于说明接口；常见属性保存函数的名称、文档、默认值和注解信息。

- `__name__` 保存函数定义名称。
- `__doc__` 保存文档字符串。
- `__defaults__` 保存位置或关键字形参的默认对象元组。
- `__annotations__` 保存参数与返回值注解。

这些开头和结尾各有两个下划线的名称常被称为双下划线或 `dunder` 名称，是 Python 为特殊属性和协议预留的一类接口。这里列出的是函数对象的特殊属性；第 1 章预览的 `__eq__()` 则是特殊方法。仅有注解不会让普通 Python 调用自动执行类型检查。关键字专用参数的默认值还可在 `__kwdefaults__` 中观察。

首轮回答不需要背完属性，但必须知道双下划线不是视觉装饰，也不应随意发明；完整对象数据模型在第 6 章学习。

### 第 5 题：位置实参与关键字实参

**简短结论：** 位置实参按顺序绑定，关键字实参按名称绑定；一个形参只能绑定一次。

普通调用中位置实参写在关键字实参之前，使绑定过程明确。若位置实参已经绑定 `name`，又写 `name="另一个值"`，调用会在进入函数体前抛出 `TypeError`。

关键字实参的优势是表达含义，尤其适合布尔开关、单位不明显的数字和可选配置。

### 第 6 题：五类形参

**简短结论：** Python 形参按照允许的绑定方式分为五类，`/` 限定左侧只能由位置实参绑定，`*` 限定后续只能由关键字实参绑定；默认值是附加配置，不是第六类。

1. 仅限位置形参：位于 `/` 前。
2. 位置或关键字形参：两种实参方式都允许。
3. 可变位置形参：`*args` 收集额外位置实参。
4. 仅限关键字形参：位于裸 `*` 或 `*args` 后。
5. 可变关键字形参：`**kwargs` 收集额外关键字实参。

`/` 与裸 `*` 是签名分隔符，不是普通形参。回答时最好写一个小签名并从左到右标注。

### 第 7 题：`*args` 与 `**kwargs`

**简短结论：** `*args` 得到元组，`**kwargs` 得到字典。

它们适合包装器、转发调用和确实存在可变选项的接口。但全部参数都塞进星号参数，会让必需参数、拼写错误、类型提示和编辑器补全变得不清楚。

名字 `args` 和 `kwargs` 是约定而非语法要求，真正起作用的是一个星号和两个星号。

### 第 8 题：定义中的收集与调用中的展开

**简短结论：** 定义中的星号收集实参，调用中的星号展开对象。

- `def f(*args)` 收集多余位置实参。
- `def f(**kwargs)` 收集多余关键字实参。
- `f(*values)` 把可迭代对象展开为位置实参。
- `f(**mapping)` 把映射展开为关键字实参。

`**mapping` 的键必须是字符串；展开后还必须能与函数签名匹配，或者被 `**kwargs` 收集。字符串键并不在所有情况下都必须是可写成普通标识符的形式，但若要绑定显式形参，必须与形参名一致。

### 第 9 题：形参默认值的计算时机

**简短结论：** 默认表达式在执行 `def`、创建函数对象时计算一次。

省略参数的多次调用会复用保存的默认对象。整数和字符串不可变，函数操作后通常重新绑定局部名字，所以共享不明显；列表或字典能被原地修改，状态便可能跨调用累积。

准确回答应指出问题来自“定义时创建一次 + 后续共享 + 原地修改”，不能简单说“形参默认值不能用列表”。

### 第 10 题：对象共享传参

**简短结论：** Python 使用对象共享传参，也可表述为对象引用按值传递。

调用时，形参这个局部名字绑定到实参表达式得到的对象。`items = []` 只让局部名字改指向新对象，调用者名字不变；`items.append(value)` 修改双方共同指向的列表，调用者能够看到。

不要总结为“可变对象按引用、不可变对象按值”，因为所有参数都遵循同一绑定模型，差别来自后续操作。

### 第 11 题：LEGB 与局部赋值

**简短结论：** 名字读取依次查找 Local、Enclosing、Global、Built-in；普通赋值目标不会沿 LEGB 自动向外寻找。

命名空间可以先理解为一组名字到对象的绑定关系。`globals()` 返回当前模块全局命名空间使用的字典；`locals()` 用于观察当前局部命名空间，在函数内修改其返回结果不保证能反向改变真实局部名字。

若函数体中存在对某名字的普通赋值，Python 通常在分析函数时就把它确定为局部名字。赋值前读取该名字时，读取的是尚未绑定的局部名字，因此出现 `UnboundLocalError`，而不是退回读取全局名字。

只背 LEGB 顺序不够，还必须补充“读取规则与赋值规则不同”。

### 第 12 题：`global` 与 `nonlocal`

**简短结论：** 模块可以先理解为一个被 Python 加载执行的 `.py` 文件及其顶层命名空间；`global` 让赋值针对当前模块的全局名字，`nonlocal` 让赋值针对最近的已有外层函数绑定。

`nonlocal` 必须找到某个外层函数作用域中已经存在的名字，不能凭空创建，也不表示模块全局。模块全局使用 `global`。

两者都应谨慎使用。参数与返回值能表达清楚的数据流，通常更容易测试和复用。

### 第 13 题：普通代码块与作用域

**简短结论：** 普通 `if`、`for` 和 `while` 不创建独立块级作用域；现代 Python 3 的推导式具有自己的循环变量作用域。

普通 `for` 结束后，循环变量通常仍存在于当前作用域；若循环一次都没执行，该名字可能尚未绑定。列表、集合和字典推导式中的循环变量不会覆盖外围同名名字。

这描述现代 Python 3 行为。不要把旧 Python 2 的列表推导式行为混入当前回答。

### 第 14 题：函数对象、高阶函数与注解

**简短结论：** 函数是普通对象，因此可以保存、传递和返回；接收函数或返回函数的函数称为高阶函数。

排序的 `key`、回调和装饰器都利用这一点。函数注解表达接口意图，供读者、编辑器和静态检查工具使用；普通 Python 默认不会仅根据注解阻止调用。

`callable(obj)` 只能说明对象支持调用语法，不保证给定参数一定正确。

### 第 15 题：递归与调用栈

**简短结论：** 正确递归需要可到达的终止条件，并在每次调用中让问题规模接近它。

每层调用都有栈帧，保存局部名字、执行位置和等待中的操作。深度为 `n` 时，通常同时保留约 `n` 层栈帧，所以额外空间是 `O(n)`。

完整分析还应检查调用分支数、重复子问题和最大深度。只说“自己调用自己”没有说明为什么会结束或成本如何。

## 二、代码理解题

### 第 16 题：函数对象还是调用结果

输出：

```text
True
6
10
```

`first = double` 保存函数对象，所以可调用；`second = double(5)` 先调用函数，保存返回的整数 `10`。

常见错误是看到赋值就认为函数已经执行。判断时只需检查是否出现调用括号。

### 第 17 题：返回值和提前结束

输出：

```text
negative
zero
None
positive
```

`-1` 分支直接返回 `"negative"`。输入 `0` 时函数内部先打印 `zero`，随后空 `return` 返回 `None`，外层 `print` 再显示 `None`。输入 `2` 返回 `"positive"`。最后的 `print("finished")` 位于无条件返回之后，不会执行。

### 第 18 题：位置实参、关键字实参与形参默认值

前三次结果：

```text
('a.com', 80, 5)
('b.com', 443, 5)
('c.com', 80, 10)
```

第四次失败并抛出 `TypeError`，因为 `timeout` 位于裸 `*` 后，只能按关键字传入，不能作为第三个位置实参。

回答时应明确错误发生在参数绑定阶段，函数体没有开始执行。

### 第 19 题：仅限位置形参与仅限关键字形参

- `transform(5)` 成功，得到 `(5, False)`。
- `transform(5, factor=2, clamp=True)` 成功，得到 `(10, True)`。
- `transform(value=5, factor=2)` 失败：`value` 是仅限位置形参。
- `transform(5, 2, True)` 失败：`clamp` 是仅限关键字形参。

`factor` 位于 `/` 和 `*` 之间，因此位置或关键字都可以。

### 第 20 题：`*args` 和 `**kwargs`

输出等价于：

```text
(1, (2, 3), 'fast', {'retry': 2})
```

`first` 绑定 `1`，额外位置实参进入元组 `args`；`mode` 是仅限关键字形参；未被显式形参接收的关键字进入字典 `kwargs`。

### 第 21 题：参数展开与重复绑定

第一次输出：

```text
12
```

`*size` 展开为位置实参 `3, 4`。第二次调用中，普通关键字 `height=4` 与展开映射中的 `height=5` 重复提供同一关键字，抛出 `TypeError`，函数体不会执行。

### 第 22 题：默认表达式只计算一次

输出：

```text
['created']
10
10
['created']
```

执行 `def use(value=make_default())` 时会调用一次 `make_default()`，所以第一次打印前列表已有内容。两次省略参数的调用复用默认整数，不会再次调用 `make_default()`。

### 第 23 题：可变默认值

输出：

```text
['A', 'B']
['A', 'B']
True
```

第一次返回的 `first` 与默认列表是同一个对象。第二次调用继续修改该对象，因此最后查看 `first` 时也能看到 `"B"`。`second` 指向同一对象。

若要观察第一次调用刚结束时的内容，需要当时建立快照；保存另一个名字不会复制列表。

### 第 24 题：修改对象与重新绑定形参

输出：

```text
[1, 2, 3]
[99]
False
```

进入函数时 `values` 与 `numbers` 指向同一列表。`append(3)` 修改共享对象；`values = [99]` 只让局部形参重新绑定到新列表。函数返回新列表，外部原列表保留前面的修改。

### 第 25 题：局部名字与 `UnboundLocalError`

调用在执行 `print(count)` 时抛出 `UnboundLocalError`，没有打印 `10`，全局 `count` 仍为 `10`。

原因是函数体存在 `count += 1`。增强赋值包含对 `count` 的赋值，因此 `count` 被确定为局部名字；第一次读取时该局部名字尚未绑定。

### 第 26 题：`global`、`nonlocal` 和遮蔽

输出：

```text
('changed', 'changed')
global
```

模块全局 `value` 保持 `"global"`。`outer()` 建立外层函数名字 `value`，`inner()` 的 `nonlocal value` 修改的就是这个外层绑定，因此返回两次看到的都是 `"changed"`。

### 第 27 题：普通循环与推导式名字

现代 Python 3 输出：

```text
100
2
[0, 1, 4]
```

推导式内部的 `number` 不覆盖外部 `number`。普通 `for` 不创建块级作用域，循环结束后 `item` 保留最后一次绑定 `2`。

若 `range(3)` 为空，`item` 不会因为循环语句自动获得值。

### 第 28 题：函数注解是否强制类型

输出：

```text
3
ab
['left', 'return', 'right']
```

注解保存在 `add.__annotations__` 中。普通调用没有自动强制 `int`；字符串支持 `+`，所以第二次调用能够拼接。

这不表示注解无用。静态检查器可以在运行前指出不符合约定的调用，运行时框架也可能选择读取注解执行额外行为。

### 第 29 题：递归进入与返回顺序

完整输出：

```text
enter 2
enter 1
enter 0
return 0
return 1
return 2
```

进入阶段不断压入新调用；到终止条件后，栈帧按相反顺序退出。`countdown(2)` 必须等待 `countdown(1)` 完成，才能执行自己的 `print("return", 2)`。

## 三、找错与场景题

### 第 30 题：把显示结果误当成返回结果

函数会先显示 `5`，随后隐式返回 `None`。计算 `None * 10` 时抛出 `TypeError`。

应让函数返回结果：

```python
def add(left, right):
    return left + right
```

显示应由调用层决定。若函数业务上既要记录日志又要返回结果，也必须明确二者是不同操作。

### 第 31 题：修复可变默认值并保留接口语义

常见写法：

```python
def add_record(record, records=None):
    if records is None:
        records = []
    records.append(record)
    return records
```

每次省略参数都在函数体创建新列表；显式传入列表时仍原地追加。

如果 `None` 是合法业务值，使用专用哨兵：

```python
MISSING = object()


def add_record(record, records=MISSING):
    if records is MISSING:
        records = []
    if records is None:
        return None  # 示例约定：显式 None 表示不记录
    records.append(record)
    return records
```

这个示例明确规定了显式 `None` 的业务含义；实际接口可以采用其他约定，但必须单独处理。哨兵用身份比较，避免与合法值冲突。

### 第 32 题：函数是否应修改输入

**原地修改**减少外层复制，适合大对象或名称明确的更新操作，但调用者必须知道输入会变化，共享引用会扩大影响范围。

**复制后返回**使数据流更容易推理，调用者可以同时保留旧值，但需要 `O(n)` 复制时间和空间。普通 `.copy()` 只复制外层，嵌套列表或字典仍可能共享。

名称可以使用 `update_in_place()`、`with_defaults()` 等表达语义，文档应写明是否修改输入、复制深度和返回值。

### 第 33 题：滥用 `global`

共享模块变量让函数依赖隐式状态，测试必须重置环境，调用顺序会影响结果，多线程或异步任务还可能发生竞态。函数也难以在其他模块复用。

更清楚的方向是：

```python
def calculate(values):
    return sum(values)


data = [1, 2, 3]
result = calculate(data)
```

确需共享状态时，可以封装到对象或明确的状态容器中，再设计同步和生命周期，而不是散布多个 `global`。

### 第 34 题：回调函数多写了括号

`key` 需要一个稍后由排序过程调用的函数对象。`get_score()` 会在调用 `sorted()` 前立刻执行，而且缺少记录实参，通常当场抛出 `TypeError`；即使碰巧能调用，传入的也是返回结果而非预期函数。

正确形式是：

```python
def get_score(record):
    return record["score"]


records = [{"name": "Ada", "score": 95}]
sorted(records, key=get_score)
```

判断方法是问：接收方需要“行为”还是“已经计算出的值”。

### 第 35 题：递归没有走向终止条件

正整数每次加一会离 `0` 越来越远，终止条件不可达，最终通常出现 `RecursionError`。应根据约束改为 `number - 1`，同时明确负数、非整数和极大输入怎样处理。

线性倒计时的递归时间为 `O(n)`、栈空间为 `O(n)`；极大输入更适合循环，以避免 Python 递归深度限制。

## 四、连续追问题

### 第 36 题：参数传递模型连续追问

1. 形参始终绑定到实参对象。列表能原地修改，整数不能原地改变，因此常见表现不同。
2. 不能总结为两套传递机制；所有参数遵循对象共享模型。
3. 先修改列表会被调用者看到，之后形参重新绑定只影响局部名字。
4. 浅拷贝只复制外层容器，嵌套可变对象仍可能共享，并不永远足够。

首轮回答用列表 `append()` 和 `items = []` 的对比即可；追问时再补充浅拷贝和接口设计。

### 第 37 题：设计清晰函数签名

一种清晰形式是：

```python
def request(url, *, timeout=5, verify=True, headers=None):
    pass
```

URL 是核心必需输入，可以允许位置或关键字；若库明确希望参数名可变，也可设计为仅限位置。`timeout`、`verify` 和 `headers` 适合仅限关键字，因为数值单位和布尔含义需要名字说明。

任意 `**kwargs` 方便转发和兼容扩展，但会隐藏拼写错误和真实接口。只有确实包装下层 API 时才值得使用，并应说明支持范围。

### 第 38 题：作用域综合追问

1. LEGB 描述读取名字的搜索顺序；普通赋值通常在当前局部建立绑定。
2. `NameError` 表示名字找不到；`UnboundLocalError` 表示已确定为局部名字但读取时尚未绑定，后者是前者的子类。
3. `global` 指函数所属模块的全局命名空间，不是所有模块共同空间。
4. `nonlocal` 的含义就是重用已有外层函数绑定，找不到时无法确定修改目标。
5. 当数据可以作为显式输入和输出传递时，返回值通常更易测试、复用和并发控制。

### 第 39 题：递归与迭代综合追问

阶乘递归与迭代都执行线性数量的乘法，时间为 `O(n)`。递归保留 `n` 层左右的栈帧，额外空间 `O(n)`；迭代只保留累计值等少量状态，额外空间 `O(1)`。

CPython 通常不做尾递归优化，所以尾调用仍建立新栈帧。树本身由子树递归组成，递归代码容易对应结构；百万级线性倒计时结构简单且过深，循环更合适。

### 第 40 题：综合执行过程

原代码最终输出：

```text
['A', 'B']
['A', 'local']
['A', 'B']
['A', 'B', 'local']
True
```

默认列表只创建一次。第一次调用把 `"A"` 加入默认列表，`snapshot` 指向它；`records + ["local"]` 创建新列表并只重新绑定局部 `records`。第二次调用继续修改默认列表，因此 `first_snapshot` 最终也看到 `"B"`，而 `first_local` 是第一次创建的独立新列表。

如果改成 `records += ["local"]`，列表的增强赋值会原地修改默认列表。第一次返回的 `snapshot` 和 `records`、第二次返回的二者都会指向同一个默认列表；第二次调用结束后，它们看到的内容都会是：

```text
['A', 'local', 'B', 'local']
```

这个追问的关键不是机械背 `+=`，而是判断当前类型的增强赋值是否修改原对象。
