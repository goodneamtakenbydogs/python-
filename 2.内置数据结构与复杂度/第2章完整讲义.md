# 第 2 章：内置数据结构与复杂度

## 1. 容器操作、存储方式与复杂度

第 1 章已经介绍列表、元组、字典和集合这些基础容器。本章会从它们怎样组织元素继续讲起；如果你还没有使用过 `deque` 或 `heapq`，不需要预先了解，后面会从需求开始解释。

先解释开头会出现的几个词：

- **数据结构**：组织数据以及支持相关操作的方式，容器是 Python 中直接可用的数据结构对象。
- **API**：Application Programming Interface 的缩写，可以先理解为一段代码对使用者公开的函数、方法和调用规则。
- **复杂度**：描述输入规模扩大时，运行时间或占用空间怎样增长的分析方法，`O(1)`、`O(n)` 等写法会从第 2 节开始解释。
- **队列**：通常指先进先出的数据结构，先进入的元素先离开；`deque` 是 Python 标准库提供的双端队列。标准库是常规 Python 安装自带的一组模块和功能。
- **堆**：能高效维护当前最小或最大候选的一种树形数据结构；`heapq` 是标准库提供的最小堆工具模块。

面试通常不会止步于“这个方法怎么调用”，而会继续追问：

- 为什么列表末尾追加通常很快，头部插入却慢？
- 为什么字典查找通常是 `O(1)`，却不能说永远是 `O(1)`？
- 为什么列表不能直接替代队列？
- 为什么求第 `k` 大元素时，常常只保留一个大小为 `k` 的最小堆？
- 为什么复制了外层容器，修改内部列表仍可能影响原数据？

如果只记住 API，这些问题会变成互不关联的结论。本章建立的是一条完整主线：

```text
先学会描述成本
→ 再理解容器怎样组织元素
→ 从组织方式推导操作复杂度
→ 根据问题真正需要的操作选择容器
```

第 1 章已经说明，名字绑定到对象，容器保存的是对象引用。本章在这个基础上继续研究：容器如何组织这些引用，以及这种组织方式带来什么时间和空间代价。

## 2. 复杂度是在描述什么

### 2.1 输入规模 `n` 的含义

**算法**可以先理解为解决一个问题的明确步骤。复杂度用于描述：当输入规模变大时，算法需要的时间或存储资源怎样增长。输入规模通常记作 `n`，但 `n` 的含义必须结合问题说明。

例如：

```python
def contains_zero(numbers):
    for number in numbers:
        if number == 0:
            return True
    return False
```

这里可以令 `n = len(numbers)`。如果列表长度从 100 增长到 10,000，最坏情况下检查次数也会大致增长 100 倍。

对于两个输入，可能需要同时使用两个规模：

```python
def all_pairs(left_values, right_values):
    pairs = []
    for left_value in left_values:
        for right_value in right_values:
            pairs.append((left_value, right_value))
    return pairs
```

若两个列表长度分别为 `n` 和 `m`，产生的结果有 `n * m` 个，更准确的时间和结果空间复杂度是 `O(nm)`，而不是不加说明地写成 `O(n²)`。

### 2.2 大 O 关注增长趋势

大 O 记号描述输入规模趋于很大时，资源使用量的增长上界。它通常忽略固定倍数和较低阶项。

假设某段代码的操作次数近似为：

```text
3n + 10
```

当 `n` 很大时，增长趋势由 `n` 决定，因此记作 `O(n)`。这不表示程序“恰好执行 `n` 次”，也不表示所有 `O(n)` 程序速度完全一样。

类似地：

```text
n² + 5n + 20 → O(n²)
```

大 O 帮助比较规模扩大后的趋势，实际耗时仍会受到常数、对象比较成本、缓存、解释器和硬件等因素影响。

### 2.3 `O(1)`：成本不随 `n` 成比例增长

```python
def first_item(values):
    return values[0]
```

无论列表有 10 个还是 100 万个元素，按下标取得第一个元素所需的主要步骤不会随着列表长度线性增长，因此称为常数时间 `O(1)`。

`O(1)` 不代表“一条机器指令”或“耗时为零”。它只表示成本不随这里定义的输入规模 `n` 增长。

### 2.4 `O(log n)`：每一步排除固定比例

如果每一步都把剩余问题缩小一半，步骤数通常是对数级：

```text
16 → 8 → 4 → 2 → 1
```

规模 16 只需缩小 4 次；规模翻倍到 32，只多一次。因此这种增长记作 `O(log n)`。

二分查找和堆的上浮、下沉经常出现 `O(log n)`。这里通常不必强调对数底数，因为不同固定底数只相差常数倍。

### 2.5 `O(n)`：最多看一遍全部元素

```python
def count_positive(numbers):
    count = 0
    for number in numbers:
        if number > 0:
            count += 1
    return count
```

列表每增加一个元素，循环通常多处理一次，所以时间复杂度为 `O(n)`。

“只有一个循环”常常是 `O(n)`，但不能只数循环层数。例如循环中的 `value in some_list` 本身也可能是 `O(n)`，合在一起就可能达到 `O(n²)`。

### 2.6 `O(n log n)`：排序的常见量级

**比较排序**通过比较元素或排序依据来决定先后关系，高效的通用比较排序常见时间复杂度是 `O(n log n)`。**稳定排序**表示两个元素的排序依据相等时，它们仍保持输入中的原相对顺序。Python 保证 `list.sort()` 和 `sorted()` 的排序稳定性；常见 CPython 实现还能利用输入中已有的有序片段，最坏时间复杂度为 `O(n log n)`，对已经具有较强顺序的数据可能接近 `O(n)`。稳定性可以作为接口行为依赖，具体算法与常数属于实现细节。

现阶段不需要推导排序算法证明，只需先形成量级直觉：排序通常比单次线性扫描贵，但远好于检查所有元素对的 `O(n²)`。

### 2.7 常见增长量级对比

| 复杂度 | 规模翻倍时的直觉 | 常见例子 |
|---|---|---|
| `O(1)` | 主要成本基本不变 | 列表按下标访问、读取堆顶 |
| `O(log n)` | 只增加少量步骤 | 二分查找、堆上浮和下沉 |
| `O(n)` | 工作量大约翻倍 | 遍历列表、线性查找 |
| `O(n log n)` | 略高于翻倍 | 通用高效排序 |
| `O(n²)` | 工作量大约变为四倍 | 检查所有元素对 |

复杂度不是速度排行榜。输入很小时，简单的 `O(n²)` 代码可能足够快；但面试要求你能判断数据规模扩大后是否仍可接受。

## 3. 最好、最坏、平均和摊销复杂度

只说一个大 O 有时会隐藏重要条件。面试中应说明自己说的是哪种情况。

### 3.1 最好情况和最坏情况

继续看线性查找：

```python
def find_index(values, target):
    for index, value in enumerate(values):
        if value == target:
            return index
    return -1
```

- 目标就在第一个位置：检查一次，最好时间是 `O(1)`。
- 目标在最后或不存在：需要看完整个列表，最坏时间是 `O(n)`。

当题目没有特别说明时，算法分析经常重点讨论最坏情况，因为它能给出明确上界。

### 3.2 平均复杂度

平均复杂度讨论某种输入分布下的平均成本。字典查找常说平均 `O(1)`，依赖哈希值分布和哈希表保持足够空余位置等条件。

“平均 `O(1)`”不能简化成“任何一次操作都严格 `O(1)`”。哈希冲突严重或哈希表扩容时，单次操作可能更贵。

### 3.3 摊销复杂度

列表 `append()` 的经典结论是摊销 `O(1)`。

假设底层连续空间已经用满，一次追加可能需要：

1. 申请更大的连续空间。
2. 把原有元素引用搬到新空间。
3. 再放入新元素引用。

这里的**槽位**是底层用于保存一个对象引用的位置。连续空间有多少槽位，就决定当前无需扩容时最多能直接放多少个引用。

这一次可能是 `O(n)`。但 CPython 不会每追加一个元素就只增加一个位置，而是预留额外容量，因此接下来多次追加通常无需搬迁。把偶尔昂贵的扩容成本分摊到一长串追加操作上，每次追加的平均成本保持常数级，这就是摊销 `O(1)`。

```text
多次普通追加：便宜、便宜、便宜……
偶尔一次扩容：较贵
把整段操作总成本平均到每次追加：O(1)
```

“摊销”与“随机输入上的平均”不是同一个概念。摊销分析不要求输入随机，而是把一系列操作的总成本分配到每次操作上。

### 3.4 时间复杂度与空间复杂度

时间复杂度描述运行步骤怎样增长，空间复杂度描述额外占用的存储怎样增长。

```python
def doubled(values):
    return [value * 2 for value in values]
```

它遍历 `n` 个元素，时间为 `O(n)`；新建包含 `n` 个引用的列表，结果空间为 `O(n)`。

```python
def double_in_place(values):
    for index in range(len(values)):
        values[index] *= 2
```

它同样是 `O(n)` 时间，但除输入本身外只使用少量变量，额外空间通常记作 `O(1)`。代价是它会修改输入。

分析空间时要说明是否把返回结果必须占用的空间算入。面试中常讨论“额外空间”，但题目也可能要求总空间。

### 3.5 切片、复制与成员查询的复杂度

下面的代码只有一行，但不是 `O(1)`：

```python
values = [1, 2, 3]
copied = values[:]
```

若切片复制 `n` 个元素引用，时间和新列表空间都是 `O(n)`。

同样：

```python
values = [1, 2, 3]
target = 2

if target in values:
    ...
```

当 `values` 是列表时，最坏需要逐个比较，是 `O(n)`；当它是集合时，平均通常是 `O(1)`。复杂度取决于对象执行了什么操作，而不取决于源代码有几行。

## 4. `list`：有顺序的动态数组

### 4.1 列表的使用特征

Python 列表具有这些语言层面的行为：

- 元素有明确顺序。
- 可以保存重复元素。
- 可以混合保存不同类型的对象引用。
- 支持整数索引和切片。
- 列表本身可变，可以替换、加入或删除元素。

```python
values = [10, "task", 10]
values[1] = "done"
values.append(True)

print(values)  # [10, 'done', 10, True]
```

实际项目中，列表元素类型保持一致通常更容易理解和检查，但语言并不强制这一点。

### 4.2 CPython 列表的连续引用槽位

在 CPython 中，列表通常可以理解为一段连续排列的“对象引用槽位”。列表并不把每个任意 Python 对象本体直接挤在一起，而是按顺序保存指向对象的引用。

```text
values
  │
  ▼
+--------+--------+--------+
| 引用 0 | 引用 1 | 引用 2 |
+---|----+---|----+---|----+
    ▼        ▼        ▼
   10      "task"    10
```

因为槽位连续排列，知道起点和下标后就能快速定位任意位置，所以 `values[index]` 是 `O(1)`。

这是解释常见 CPython 性能的实现直觉，不应扩展成“Python 语言规范要求所有实现都必须用完全相同的内存布局”。语言保证的是列表行为，具体内存组织由实现决定。

### 4.3 为什么中间插入和删除是 `O(n)`

已有列表：

```text
位置：  0    1    2    3
元素： [A]  [B]  [C]  [D]
```

在位置 1 插入 `X` 后，需要给它腾出槽位：

```text
[A]  [X]  [B]  [C]  [D]
          → B、C、D 的引用都向右移动
```

移动数量随列表长度增长，所以 `insert()` 在头部或中间通常是 `O(n)`。删除头部也类似：后面的引用需要整体向左补位。

末尾追加不需要移动已有元素，因此在无需扩容时是 `O(1)`；考虑偶尔扩容后，`append()` 是摊销 `O(1)`。

### 4.4 长度和索引

```python
numbers = [10, 20, 30]

print(len(numbers))  # 3
print(numbers[0])    # 10
print(numbers[-1])   # 30
```

CPython 列表对象会记录当前长度，因此 `len(numbers)` 是 `O(1)`，不需要每次重新遍历计数。按有效下标读写也是 `O(1)`。

越界索引会抛出 `IndexError`：

```python
# numbers[3]
```

### 4.5 `append()`、`extend()` 和 `insert()`

三者都修改原列表，但语义不同：

```python
values = [1, 2]
values.append([3, 4])
print(values)  # [1, 2, [3, 4]]
```

`append(object)` 把实参表达式得到的对象作为一个元素放到末尾。

```python
values = [1, 2]
values.extend([3, 4])
print(values)  # [1, 2, 3, 4]
```

`extend(iterable)` 依次取得实参对象中的元素并追加。若加入 `k` 个元素，操作本身需要 `O(k)` 时间。

```python
values = [1, 3]
values.insert(1, 2)
print(values)  # [1, 2, 3]
```

`insert(index, object)` 在指定位置插入一个元素，通常需要移动后续引用，最坏 `O(n)`。

### 4.6 `pop()`、`remove()`、`del` 和 `clear()`

```python
values = [10, 20, 30]
last = values.pop()

print(last)    # 30
print(values)  # [10, 20]
```

`pop()` 默认删除并返回末尾元素，通常是 `O(1)`。`pop(index)` 按位置删除并返回元素；如果不是末尾，后续引用要移动，最坏 `O(n)`。

```python
values = [10, 20, 10]
values.remove(10)
print(values)  # [20, 10]
```

`remove(value)` 按值删除第一次出现的位置。它先线性查找，再可能移动后续引用，所以最坏 `O(n)`；找不到会抛出 `ValueError`。

`del` 是删除语句，可以按索引或切片删除：

```python
values = [10, 20, 30, 40]
del values[1:3]
print(values)  # [10, 40]
```

`clear()` 删除全部元素并保留同一个列表对象：

```python
values = [1, 2]
alias = values
values.clear()

print(alias)  # []
```

而 `values = []` 只是让名字 `values` 重新绑定到新列表，不会清空 `alias` 仍指向的旧列表。这一差别来自第 1 章的对象与绑定模型。

### 4.7 查找、计数和成员判断

```python
values = [4, 7, 4, 9]

print(7 in values)       # True
print(values.index(4))   # 0
print(values.count(4))   # 2
```

普通列表没有按值直接跳到某个位置的索引结构，因此这些操作通常需要从左向右比较：

- `value in values`：最坏 `O(n)`。
- `values.index(value)`：最坏 `O(n)`，找不到抛出 `ValueError`。
- `values.count(value)`：需要检查全部元素，`O(n)`。

如果程序要进行大量成员判断，集合或字典可能更合适；但它们又不提供同样的按位置访问能力。

### 4.8 切片会构造新列表

```python
numbers = [0, 1, 2, 3, 4]
middle = numbers[1:4]

print(middle)  # [1, 2, 3]
```

假设切片结果含 `k` 个元素引用，创建结果通常需要 `O(k)` 时间和 `O(k)` 新的外层空间。

```text
numbers 的槽位： [→0] [→1] [→2] [→3] [→4]
middle  的槽位：      [→1] [→2] [→3]
```

两个列表的外层槽位独立，但引用仍可能指向同一内部对象：

```python
original = [[1], [2]]
copied = original[:]
copied[0].append(9)

print(original)  # [[1, 9], [2]]
```

这属于浅拷贝边界，本章后面会统一说明。

### 4.9 列表拼接和重复

```python
left = [1, 2]
right = [3, 4]
combined = left + right
```

`+` 创建新列表，并复制两侧元素引用，时间和结果空间是 `O(n + m)`。

```python
values = [0] * 1000
```

创建 `1000` 个槽位需要 `O(n)`。如果被重复的是可变对象，重复的是引用：

```python
rows = [[]] * 3
rows[0].append("x")

print(rows)  # [['x'], ['x'], ['x']]
```

需要独立内部列表时，应让每次循环都创建新列表：

```python
rows = [[] for _ in range(3)]
```

### 4.10 `sort()` 与 `sorted()`

```python
numbers = [3, 1, 2]
result = numbers.sort()

print(numbers)  # [1, 2, 3]
print(result)   # None
```

`list.sort()` 原地重排列表，并返回 `None`。返回 `None` 是为了提醒调用者它修改了原对象，避免误以为得到了一份新列表。

```python
numbers = [3, 1, 2]
ordered = sorted(numbers)

print(numbers)  # [3, 1, 2]
print(ordered)  # [1, 2, 3]
```

`sorted(iterable)` 接受任意可迭代对象，并返回一个新列表。两者都支持 `key` 和 `reverse`。`key` 形参接收一个函数对象，排序会用它为每个元素计算排序依据。下面的 `lambda record: record[1]` 创建一个简短函数：接收当前记录 `record`，返回它的第 2 项分数。`lambda`、高阶函数和回调的完整内容在第 4 章学习；当前只需知道它作为关键字实参交给排序过程调用。

```python
records = [("A", 80), ("B", 95), ("C", 80)]
ordered = sorted(records, key=lambda record: record[1], reverse=True)

print(ordered)
# [('B', 95), ('A', 80), ('C', 80)]
```

Python 排序是稳定的：关键字相等的元素保持原相对顺序，所以两条 80 分记录仍是 A 在 C 前。

对 `n` 个元素排序，最坏时间通常记作 `O(n log n)`。排序还需要一定辅助空间，实际使用量取决于数据顺序和实现；不要把它说成无条件 `O(1)` 额外空间。

### 4.11 遍历列表时修改列表的风险

```python
numbers = [1, 2, 2, 3]

for number in numbers:
    if number == 2:
        numbers.remove(number)

print(numbers)  # 可能与你预期不同
```

第一次删除 `2` 后，后面的元素左移，而循环的内部位置继续前进，第二个 `2` 可能被跳过。问题不在 `remove()` 失效，而在遍历位置和容器结构同时变化。

常见处理方式取决于目标：

- 构造符合条件的新列表。
- 只修改元素值时按索引处理。
- 必须原地删除时，从后向前处理下标。
- 遍历一个浅拷贝，同时修改原列表。

```python
numbers = [1, 2, 2, 3]
numbers = [number for number in numbers if number != 2]
```

选择前还要考虑是否允许重新绑定、是否必须保持原列表身份以及额外空间限制。

### 4.12 列表常见复杂度

令列表长度为 `n`，一次加入或切片涉及的元素数量为 `k`：

| 操作 | 常见时间复杂度 | 原因 |
|---|---:|---|
| `len(values)` | `O(1)` | 容器记录长度 |
| `values[index]` | `O(1)` | 可按起点和下标定位槽位 |
| `values[index] = item` | `O(1)` | 替换一个槽位中的引用 |
| `values.append(item)` | 摊销 `O(1)` | 末尾写入，偶尔扩容 |
| `values.extend(items)` | `O(k)` | 依次追加 `k` 个元素 |
| `values.pop()` | `O(1)` | 删除末尾槽位 |
| `values.insert(index, item)` | `O(n)` | 可能移动大量后续引用 |
| `values.pop(index)` | `O(n)` | 可能移动大量后续引用 |
| `values.remove(item)` | `O(n)` | 先查找，再可能移动 |
| `item in values` | `O(n)` | 最坏逐个比较 |
| `values[start:stop]` | `O(k)` | 创建含 `k` 个引用的新列表 |
| `values.copy()` | `O(n)` | 复制外层全部引用 |
| `values.sort()` | 最坏 `O(n log n)` | 稳定比较排序 |

表格是复习入口，不是背诵终点。面试追问“为什么”时，应回到连续槽位、元素移动、线性扫描和动态扩容来解释。

## 5. `tuple`：结构固定的有序序列

### 5.1 “元组不可变”具体限制什么

元组同样有顺序、允许重复、支持索引和切片。它的不可变性具体表示：元组创建完成后，不能通过普通 Python 操作改变长度，也不能把某个位置改为引用另一个对象。

```python
point = (3, 5)

print(point[0])  # 3
# point[0] = 4   # TypeError
```

元组不提供 `append()`、`insert()`、`remove()` 或 `clear()` 等原地修改结构的方法。

“元组不可变”不表示变量名不能重新绑定：

```python
point = (3, 5)
point = (4, 5)
```

第二行让名字 `point` 改为绑定另一个元组，没有修改旧元组 `(3, 5)`。

### 5.2 元组保存的是固定数量的对象引用

元组并不复制并封存所有元素对象。它保存一组有顺序的对象引用：

```python
record = ("Ada", 95, [80, 90])
```

可以用下面的结构理解：

```text
元组对象 record
├── 长度：3
├── 位置 0 ──→ 字符串对象 "Ada"
├── 位置 1 ──→ 整数对象 95
└── 位置 2 ──→ 列表对象 [80, 90]
```

固定的是元组自身的长度和三个位置所保存的引用。元组不能把位置 `2` 改为指向另一个列表，但原列表对象仍可能通过自己的方法改变内容。

这与列表的核心差异是：列表需要支持追加和删除，因此必须允许引用槽位数量变化；元组创建完成后不需要为这些操作保留修改能力。

### 5.3 CPython 中的固定槽位与列表动态容量

“元组不可变”是 Python 语言行为，所有符合 Python 规范的实现都应向使用者提供这个结果。至于对象具体怎样放在内存中，属于实现细节。

在常见的 CPython 实现中，可以使用下面的简化模型：

```text
tuple
├── 对象管理信息
├── 元素数量
└── 创建时确定数量的引用槽位
    ├── 引用 0
    ├── 引用 1
    └── 引用 2

list
├── 对象管理信息
├── 当前元素数量
├── 已分配容量
└── 指向可调整引用数组的地址
```

列表的“当前长度”和“已分配容量”可以不同。它可能预留额外槽位，使后续 `append()` 不必每次都重新申请空间。元组长度创建后固定，不需要维护用于追加的预留容量。

这只是解释行为和常数开销的结构模型。具体 C 结构字段、对象头大小和分配策略可能随 Python 实现、版本和构建方式变化，业务代码不能依赖它们。更具体的 CPython 结构见[第 2 章拓展讲义](./第2章拓展讲义.md)。

### 5.4 下标赋值为什么会失败

不可变不是说操作系统把元组所在内存设置成只读。它是 `tuple` 类型对 Python 代码提供的操作规则。

执行下标赋值时：

```python
values = (10, 20)
# values[0] = 99
```

Python 会要求对象的类型完成“修改指定下标”这项操作。列表类型提供了这项能力，元组类型没有向普通 Python 代码提供，因此操作会抛出 `TypeError`。

```text
列表下标赋值
→ list 类型支持替换引用槽位
→ 修改成功

元组下标赋值
→ tuple 类型不支持替换引用槽位
→ TypeError
```

特殊方法和类型操作协议会在第 6 章展开。本章只需要理解：不可变性是类型接口保证，不是“对象碰巧没有提供一个方便方法”。

### 5.5 拼接和 `+=` 没有修改旧元组

元组拼接不会修改两侧操作数，而是得到拼接结果。对于下面这种两侧都非空的普通拼接，可以理解为创建一个包含两边引用的新元组：

```python
left = (1, 2)
right = (3, 4)
combined = left + right

print(left)      # (1, 2)
print(combined)  # (1, 2, 3, 4)
```

`+=` 看起来像修改，作用在元组上时仍然是创建结果并重新绑定名字：

```python
values = (1, 2)
alias = values

values += (3,)

print(values)  # (1, 2, 3)
print(alias)   # (1, 2)
print(values is alias)  # False
```

状态变化是：

```text
执行前：values ─┐
                 ├──→ 旧元组 (1, 2)
          alias ─┘

执行后：values ─────→ 新元组 (1, 2, 3)
          alias ─────→ 旧元组 (1, 2)
```

对列表执行 `+=` 通常会原地扩展列表，所以必须根据左侧对象的类型判断增强赋值究竟修改对象还是重新绑定名字。

### 5.6 单元素元组由逗号决定

```python
not_a_tuple = (5)
one_item_tuple = (5,)

print(type(not_a_tuple))      # <class 'int'>
print(type(one_item_tuple))   # <class 'tuple'>
```

括号常用于分组表达式；真正构成单元素元组的是逗号。

### 5.7 元组适合表达固定结构

```python
coordinate = (120.1, 30.2)
name_score = ("Ada", 95)
```

当一组位置具有固定含义、调用者不应增删元素时，元组能表达“结构固定”。例如，可以约定一条学生记录依次保存姓名、分数、城市和考试次数：

```python
record = ("Ada", 95, "深圳", 3)

print(record[0])  # Ada
print(record[3])  # 3
```

Python 的下标从 `0` 开始，因此 `record[3]` 取得第四个元素。不过，只看 `record[3]` 很难判断这个 `3` 表示什么。位置越多，依赖数字下标表达业务含义就越容易读错。

本章后面会介绍带字段名的 `namedtuple`。它可以把访问写成类似 `record.attempt_count` 的形式；第 6 章则会系统学习自定义类。

若数据需要频繁增加、删除或替换元素，列表通常更符合语义。不可变并不自动代表元组比列表更适合当前问题。

### 5.8 元组不可变，但内部对象仍可能可变

```python
record = ("scores", [80, 90])
record[1].append(100)

print(record)  # ('scores', [80, 90, 100])
```

元组位置 `1` 仍然引用原来的列表，变化发生在列表对象内部：

```text
元组位置 1 ─────→ 列表对象 [80, 90]
                              ↓ append(100)
                            [80, 90, 100]
```

因此，“元组不可变”不等于“从元组能够到达的所有对象都不可变”。

### 5.9 元组能否作为字典键

元组的哈希需要结合内部元素的哈希值。只有所有元素都可哈希，整个元组才可能可哈希：

```python
valid_key = ("page", 3)
mapping = {valid_key: "cached"}

invalid_key = ("page", [1, 2])
# mapping = {invalid_key: "cached"}  # TypeError
```

外层引用槽位固定，不能弥补内部列表不可哈希这一事实。为什么键需要稳定哈希值，将在本章第 6 节“从线性查找到哈希查找”和第 7 节“可哈希对象”中解释。

### 5.10 元组的复杂度与内存开销

- `len(values)`：`O(1)`。
- `values[index]`：`O(1)`。
- `item in values`：最坏 `O(n)`。
- 得到含 `k` 个引用的普通切片结果：通常是 `O(k)` 时间和空间。
- 普通非空拼接中，长度分别为 `n` 和 `m` 的元组需要构造结果，通常是 `O(n + m)`。

若在循环中反复使用 `+=` 扩展越来越长的元组，旧引用会被反复复制，总成本可能达到 `O(n²)`。需要持续追加时应先使用列表，完成后再按需要转换成元组。

在 CPython 中，相同元素数量的元组通常比列表少一些管理和预留容量开销，但不能据此声称“元组永远更快”或依赖固定字节数。索引和遍历的增长量级与列表相同，具体常数受实现和版本影响。

这一节需要长期记住的分层结论是：

```text
Python 语言保证：
元组创建后不能通过普通操作改变长度或替换位置引用。

CPython 常见实现：
元组使用创建时确定数量的引用槽位；
列表另外维护可调整数组和容量信息。
```

## 6. 从线性查找到哈希查找

### 6.1 列表查找为什么需要逐个比较

假设列表为：

```text
["cat", "dog", "bird", "fish"]
```

若只知道要找 `"bird"`，普通列表没有记录它在哪个下标。程序通常从头比较，最坏要检查所有元素。

如果我们能根据对象内容先计算出一个整数，再利用这个整数迅速缩小候选位置，查找就可能不必从头扫描。这就是哈希表的核心直觉。

### 6.2 哈希值是什么

Python 可以对可哈希对象调用 `hash()`：

```python
print(hash("cat"))
print(hash((1, 2)))
```

哈希值是由对象计算出的整数，用于帮助选择哈希表中的候选位置。它不是对象在表中的最终下标，也不是对象身份 `id()`。

不同 Python 进程中，同一字符串的具体哈希值可能不同。业务代码不应保存并依赖某次运行得到的字符串哈希值。

### 6.3 哈希查找的简化过程

可以先用一个简化模型理解字典查找：

```text
键
→ 计算哈希值
→ 根据哈希值寻找候选槽位
→ 再比较候选键是否真的相等
→ 找到对应值或确认不存在
```

为什么最后还要比较相等？因为不同对象可能产生相同哈希值，这叫哈希冲突。

这里的“相等”不是 `is` 身份判断，而是第 1 章见过的 `==` 相等性协议。内置类型有自己的相等规则，自定义类型也可以通过与 `__eq__()` 有关的特殊方法定义何时相等。因此，哈希表不是看到两个哈希值一样就认定为同一个键，而是把哈希值当作快速缩小范围的第一步，再用相等性规则确认。

一个不需要自定义类的例子是整数 `1` 和浮点数 `1.0`：

```python
print(1 == 1.0)            # True
print(hash(1) == hash(1.0))  # True

mapping = {1: "stored"}
print(mapping[1.0])        # stored
```

虽然 `1` 和 `1.0` 类型不同，但它们按数值规则相等，并且相等的可哈希对象必须给出相同哈希值，所以字典把查询键 `1.0` 与已有键 `1` 匹配起来。这不是说“哈希相同就相等”；后面的相等确认仍然不可省略。

`__eq__()` 和 `__hash__()` 怎样由自定义类实现、比较无法处理时为什么会返回 `NotImplemented`（表示当前类型无法完成这次比较），将在第 6 章完整学习。本章只需要理解它们分别参与“确认相等”和“产生稳定哈希值”。

### 6.4 哈希冲突与冲突处理

哈希值的可能范围和对象世界都很大，不同键映射到同一候选区域是正常现象。哈希表实现必须处理冲突，而不是假设冲突永远不存在。

可以把它想成多人先被分到同一个候诊区，再核对姓名确认具体对象。冲突增多时，要检查的候选会增多，性能可能下降。

### 6.5 为什么平均 `O(1)`，最坏可能 `O(n)`

正常情况下，哈希值分布较合理，表中保留空余空间，查找只检查少量候选，因此字典和集合的查找、插入、删除平均通常是 `O(1)`。

若出现大量冲突，查找可能需要检查很多候选，理论最坏情况可以退化到 `O(n)`。因此准确表达是：

```text
字典和集合成员查找平均 O(1)，理论最坏 O(n)。
```

不要为了显得严谨而否定哈希表的价值。工程和算法分析中，平均 `O(1)` 仍是选择字典、集合的重要原因；只需避免说成绝对保证。

### 6.6 哈希表为什么也要扩容

哈希表不能一直把所有槽位填满。表越拥挤，寻找空位和处理冲突越困难。常见实现会在装载程度达到一定范围时申请更大的表，并重新安排已有条目。

单次扩容可能需要 `O(n)`，但不是每次插入都扩容。因此字典插入通常仍按平均或摊销 `O(1)` 使用。具体扩容阈值和布局属于 CPython 实现细节，不应在业务逻辑中依赖。

## 7. 可哈希对象：为什么字典键有条件

### 7.1 可哈希需要满足什么

一个对象可哈希，核心要求包括：

1. 在对象参与哈希表期间，它的哈希值保持稳定。
2. 对象可以进行相等比较。
3. 如果两个对象相等，它们的哈希值必须相等。

反方向不成立：哈希值相等的两个对象不一定相等，因为允许冲突。

上面的“对象可以进行相等比较”指对象能够参与 `==` 相等性协议；“哈希值保持稳定”则与 `__hash__()` 提供的结果有关。最低限度可以记成：

```text
__hash__() 帮助缩小候选位置
→ __eq__() 相关协议帮助确认候选键是否相等
```

这里是行为对应关系，不建议业务代码直接调用 `key.__eq__(other)`。正常比较仍写 `key == other`，正常取哈希仍写 `hash(key)`；Python 会负责完整协议。

### 7.2 为什么普通列表不能作为键

列表内容可以原地改变：

```python
numbers = [1, 2]
numbers.append(3)
```

如果一个键放入哈希表后内容改变，按新内容计算出的候选位置可能与插入时不同，表就无法可靠找到它。因此普通 `list`、`dict` 和 `set` 都不可哈希，不能直接作为字典键或集合元素。

```python
# mapping = {[1, 2]: "value"}  # TypeError
```

为什么不直接按照列表的对象身份计算哈希？因为列表的 `==` 按内容判断：两个不同列表可能满足 `[1, 2] == [1, 2]`。哈希协议要求相等对象具有相同哈希值；如果改用各自身份产生不同哈希值，就会违反这条规则。Python 保留列表的内容相等语义，因此把普通列表设为不可哈希。

### 7.3 常见可哈希对象

常见可哈希对象包括：

- `int`、`float`、`bool`。
- `str`、`bytes`。
- `None`。
- 元素全部可哈希的 `tuple`。
- `frozenset`。

“不可变”是重要直觉，但不能把它机械等同于“必然可哈希”。自定义类是否可哈希还会受到其相等与哈希方法设计影响，第 6 章会继续讨论。

### 7.4 字典键的可哈希性与业务唯一性

```python
print(hash((1, 2)))
# hash((1, [2]))  # TypeError
```

小实验可以帮助观察，但选键时还应问：这个对象的值在作为标识期间是否稳定？它的相等语义是否符合业务需要？

例如用用户姓名作为键虽然技术上可哈希，但姓名可能重复；问题不是 Python 能不能接受，而是业务标识是否正确。

## 8. `dict`：键到值的映射

### 8.1 字典解决什么问题

列表擅长“按位置找元素”，字典擅长“按键找值”。

```python
score_by_name = {
    "Ada": 95,
    "Lin": 88,
}

print(score_by_name["Ada"])  # 95
```

字典中的键唯一。如果再次给相同键赋值，会更新对应值，而不是新增第二个相同键：

```python
score_by_name = {"Ada": 95, "Lin": 88}
score_by_name["Ada"] = 99
print(score_by_name)  # {'Ada': 99, 'Lin': 88}
```

“按键找值”的基础就是第 6 节介绍的哈希查找：先计算查询键的哈希值，找到少量候选位置，再用相等比较确认真正的键，最后取得与该键关联的值。

概念上，字典条目保存的是键对象和值对象的引用，不会自动复制它们：

```text
字典条目
├── 键引用 ──→ 字符串对象 "Ada"
└── 值引用 ──→ 整数对象 99
```

具体槽位和索引区域怎样安排属于 CPython 版本相关实现；当前只需掌握哈希负责定位候选，键相等负责确认，字典随后返回保存的值引用。

### 8.2 读取、写入和删除

```python
settings = {"theme": "dark"}

settings["language"] = "zh"
theme = settings["theme"]
del settings["language"]
```

在正常哈希分布下，按键读取、写入和删除平均都是 `O(1)`，理论最坏可能 `O(n)`。

直接读取不存在的键会抛出 `KeyError`：

```python
# settings["font_size"]
```

### 8.3 `get()`：不存在时提供默认值

```python
settings = {"theme": "dark"}

font_size = settings.get("font_size", 14)
print(font_size)  # 14
```

`get()` 不会因为缺失键而抛出 `KeyError`，也不会把默认值自动写进字典。

```python
settings = {"theme": "dark"}
print(settings)  # {'theme': 'dark'}
```

省略第二个实参时，默认返回 `None`。如果字典中本来可能保存 `None`，仅看返回值就无法区分“键不存在”和“键存在但值为 `None`”。

一种直接办法是使用 `key in mapping`。另一种办法是准备一个专门表示“缺失”的独特对象，这种对象称为**哨兵对象**：

```python
settings = {"theme": "dark"}
MISSING = object()
result = settings.get("font_size", MISSING)

if result is MISSING:
    print("font_size 不存在")
```

这里必须先创建一次 `MISSING`，再把同一个对象同时用于 `get()` 和 `is` 判断。哨兵的完整用法、为什么不能分别调用两次 `object()`，以及为什么特殊字符串不够可靠，见[第 2 章拓展讲义](./第2章拓展讲义.md)。

字典也提供按键取出并删除的方法：

```python
settings = {"theme": "dark", "font": 14}

font_size = settings.pop("font")
missing = settings.pop("language", "zh")

print(font_size)  # 14
print(missing)    # zh
```

`pop(key)` 在键不存在且没有提供默认值时抛出 `KeyError`。当前 Python 中，`popitem()` 删除并返回最后插入的键值对；`clear()` 则删除全部条目，但仍保留同一个字典对象。它们都会修改原字典。

### 8.4 计数模式

```python
counts = {}

for character in "banana":
    counts[character] = counts.get(character, 0) + 1

print(counts)  # {'b': 1, 'a': 3, 'n': 2}
```

每一步状态如下：

```text
读 b：以前 0 次 → 写入 1
读 a：以前 0 次 → 写入 1
读 n：以前 0 次 → 写入 1
读 a：以前 1 次 → 写入 2
读 n：以前 1 次 → 写入 2
读 a：以前 2 次 → 写入 3
```

若字符串长度为 `n`，循环 `n` 次，每次字典操作平均 `O(1)`，因此整体平均 `O(n)`。

### 8.5 `setdefault()`：取得已有值或先写入默认值

```python
positions = {}

for index, character in enumerate("banana"):
    positions.setdefault(character, []).append(index)

print(positions)
# {'b': [0], 'a': [1, 3, 5], 'n': [2, 4]}
```

如果键存在，`setdefault()` 返回已有值；如果不存在，它先把默认值写入，再返回该值。

它与 `get()` 的关键区别是：`get()` 不写入缺失键，`setdefault()` 会写入。

还要注意，传给 `setdefault()` 的默认值表达式会在调用前先求值。复杂或昂贵的默认值不应无意识地每轮创建；后面介绍的 `defaultdict` 更适合持续分组。

### 8.6 `update()` 和合并

```python
settings = {"theme": "dark", "font": 14}
settings.update({"font": 16, "language": "zh"})

print(settings)
# {'theme': 'dark', 'font': 16, 'language': 'zh'}
```

已有键的值被覆盖，新键被加入。若更新 `k` 个条目，平均时间通常记作 `O(k)`。

当前 Python 还支持字典合并运算符：

```python
defaults = {"theme": "light", "font": 14}
custom = {"theme": "dark"}
merged = defaults | custom

print(merged)  # {'theme': 'dark', 'font': 14}
```

右侧同名键覆盖左侧，`|` 创建新字典。不要只看写法短就忽略构造结果的 `O(n + m)` 时间和空间。

### 8.7 字典推导式

```python
square_by_number = {
    number: number * number
    for number in range(4)
}

print(square_by_number)
# {0: 0, 1: 1, 2: 4, 3: 9}
```

如果多个输入产生相等的键，后写入的值覆盖先写入的值：

```python
mapping = {number % 2: number for number in range(5)}
print(mapping)  # {0: 4, 1: 3}
```

推导式并没有绕开字典键唯一的规则。

### 8.8 插入顺序

当前 Python 语言保证字典按插入顺序迭代。这个保证从 Python 3.7 起进入语言规范；CPython 3.6 已经把它作为实现特征，但不能把旧版本实现特征倒推为所有旧 Python 的语言保证。

```python
mapping = {}
mapping["b"] = 2
mapping["a"] = 1
mapping["c"] = 3

print(list(mapping))  # ['b', 'a', 'c']
```

这里是插入顺序，不是按键排序。更新已有键的值通常不会改变它的位置；删除后重新插入，该键会出现在末尾：

```python
mapping = {"a": 1, "b": 2, "c": 3}
mapping["a"] = 10
del mapping["b"]
mapping["b"] = 20

print(list(mapping))  # ['a', 'c', 'b']
```

### 8.9 `keys()`、`values()` 和 `items()` 是视图

```python
mapping = {"a": 1, "b": 2}
keys_view = mapping.keys()
items_view = mapping.items()

mapping["c"] = 3

print(keys_view)   # 能观察到新键 c
print(items_view)  # 能观察到新条目
```

这些返回对象叫字典视图。它们与原字典动态关联，不是在调用时自动复制出的普通列表。

需要独立列表时应显式转换：

```python
mapping = {"a": 1, "b": 2, "c": 3}
keys_snapshot = list(mapping.keys())
```

这会遍历并创建 `n` 个元素的列表，因此是 `O(n)` 时间和 `O(n)` 额外空间。

### 8.10 遍历字典

```python
mapping = {"a": 1, "b": 2}

for key in mapping:
    print(key)

for value in mapping.values():
    print(value)

for key, value in mapping.items():
    print(key, value)
```

直接遍历字典得到键。访问键和值时使用 `items()` 比遍历键后再索引更能表达意图。

遍历期间改变字典大小通常会抛出 `RuntimeError`：

```python
mapping = {"a": 1, "b": 2}

# for key in mapping:
#     if mapping[key] == 1:
#         del mapping[key]
```

可以先构造要删除的键列表，或遍历 `list(mapping)` 这个**快照**，也就是在修改前把当时的键复制成一份独立列表，再修改原字典。若只更新已有键对应的值而不改变键集合，通常不会触发“大小改变”错误，但仍应保证业务逻辑易于理解。

### 8.11 字典常见复杂度

| 操作 | 常见时间复杂度 | 说明 |
|---|---:|---|
| `len(mapping)` | `O(1)` | 容器记录条目数 |
| `mapping[key]` | 平均 `O(1)` | 最坏可能 `O(n)` |
| `mapping[key] = value` | 平均或摊销 `O(1)` | 单次扩容可能更贵 |
| `del mapping[key]` | 平均 `O(1)` | 最坏可能 `O(n)` |
| `key in mapping` | 平均 `O(1)` | 检查的是键 |
| `value in mapping.values()` | `O(n)` | 通常逐个比较值 |
| 遍历全部条目 | `O(n)` | 每个条目至少访问一次 |
| `mapping.copy()` | `O(n)` | 浅复制外层条目 |
| `list(mapping)` | `O(n)` | 创建键列表快照 |

字典的优势是按键查找，不是“所有与字典有关的操作都是 `O(1)`”。尤其是按值查找，字典没有反向索引时仍然是线性的。

## 9. `set`：去重与成员查询

### 9.1 集合的核心语义

集合保存互不重复的可哈希元素，主要用于：

- 快速成员判断。
- 去重。
- 计算交集、并集、差集等集合关系。

```python
tags = {"python", "backend", "python"}
print(tags)  # 重复的 python 只保留一个
```

集合不是按位置组织的序列，不支持 `tags[0]`。不要依赖集合迭代顺序来表达业务顺序。

### 9.2 空集合不能写成 `{}`

```python
empty_mapping = {}
empty_set = set()

print(type(empty_mapping))  # <class 'dict'>
print(type(empty_set))      # <class 'set'>
```

花括号空字面量属于字典；空集合必须调用 `set()`。

### 9.3 加入、删除和成员判断

```python
tags = set()
tags.add("python")
tags.add("backend")

print("python" in tags)  # True
```

`add()`、成员判断和按值删除平均通常是 `O(1)`，理论最坏可能 `O(n)`。

删除有两种常用方法：

```python
tags = {"python", "backend"}
tags.remove("python")   # 不存在时抛出 KeyError
tags.discard("missing") # 不存在时不报错
```

`pop()` 会删除并返回某个元素，但集合无位置语义，不能把它理解为“弹出最后一个元素”。

### 9.4 集合去重与保留原始顺序

```python
numbers = [3, 1, 3, 2]
unique = set(numbers)
```

这能去重，平均时间通常为 `O(n)`，并使用 `O(n)` 额外空间。但是普通集合不承诺按原列表顺序返回结果。

如果要求保留首次出现顺序，可以借助字典的插入顺序：

```python
numbers = [3, 1, 3, 2]
unique_in_order = list(dict.fromkeys(numbers))
print(unique_in_order)  # [3, 1, 2]
```

是否选择这种写法，还要考虑可读性和元素是否可哈希。

### 9.5 集合运算

#### 9.5.1 四种运算符会创建新集合

```python
backend = {"Ada", "Lin", "Kai"}
python_users = {"Lin", "Kai", "Mia"}

both = backend & python_users
either = backend | python_users
backend_only = backend - python_users
only_one_side = backend ^ python_users
```

四个结果分别表示：

- `backend & python_users`：**交集**，只保留两边都有的元素。
- `backend | python_users`：**并集**，保留任意一边出现的元素。
- `backend - python_users`：**差集**，只保留 `backend` 有而 `python_users` 没有的元素。差集有方向，交换两边会改变结果。
- `backend ^ python_users`：**对称差**，只保留恰好出现在一边的元素。

可以用集合相等验证结果，而不依赖集合的显示顺序：

```python
backend = {"Ada", "Lin", "Kai"}
python_users = {"Lin", "Kai", "Mia"}
both = backend & python_users
either = backend | python_users
backend_only = backend - python_users
only_one_side = backend ^ python_users

print(both == {"Lin", "Kai"})
print(either == {"Ada", "Lin", "Kai", "Mia"})
print(backend_only == {"Ada"})
print(only_one_side == {"Ada", "Mia"})
```

这些表达式建立了新集合，没有修改原来的两个集合：

```python
backend = {"Ada", "Lin", "Kai"}
python_users = {"Lin", "Kai", "Mia"}

print(backend == {"Ada", "Lin", "Kai"})
print(python_users == {"Lin", "Kai", "Mia"})
```

这里的“新集合”是说结果是另一个集合对象，不是让名字 `backend` 或 `python_users` 改指向结果。若要继续使用结果，需要把它赋给 `both`、`either` 等名字。

#### 9.5.2 集合关系判断返回布尔值

集合还支持子集、超集和不相交判断：

```python
required = {"python", "sql"}
skills = {"python", "sql", "linux"}

print(required <= skills)  # required 是否为 skills 的子集
print(skills >= required)  # skills 是否为 required 的超集
print(required.isdisjoint({"java"}))  # 是否没有共同元素
```

前两个表达式描述的是同一个包含关系，只是观察方向相反：`required <= skills` 表示 `required` 是子集，`skills >= required` 表示 `skills` 是超集。它们在本例中都会得到 `True`。`<=` 和 `>=` 允许两个集合完全相等；要求不能相等的真子集、真超集关系时使用 `<` 和 `>`。

若两个集合规模分别为 `n` 和 `m`，常见实现会尽量从较小集合开始检查交集，因此交集平均与较小一侧规模相关；并集需要处理两侧元素，通常是 `O(n + m)`。准确常数和最坏情况仍受哈希冲突影响。

#### 9.5.3 更新方法会直接修改调用它的集合

普通 `set` 还提供四个原地更新方法。这里的“原地”是指修改已有集合对象，而不是创建结果集合后返回。

- `left.update(right)`：把并集写回 `left`，对应 `left | right`。
- `left.intersection_update(right)`：把交集写回 `left`，对应 `left & right`。
- `left.difference_update(right)`：把差集写回 `left`，对应 `left - right`。
- `left.symmetric_difference_update(right)`：把对称差写回 `left`，对应 `left ^ right`。

“修改左侧集合”指修改点号左边、也就是调用方法的对象。例如 `skills.update(other)` 修改 `skills`，不会修改作为实参传入的 `other`。

先单独观察 `update()`：

```python
skills = {"python", "sql"}
skills.update({"linux", "git"})

print(skills == {"python", "sql", "linux", "git"})  # True
```

它把另一个集合的元素加入 `skills`，效果相当于把并集写回 `skills`。

`intersection_update()` 的含义是“只保留共同元素”。逐步观察：

```python
skills = {"python", "sql", "linux", "git"}
required = {"python", "linux"}

skills.intersection_update(required)

print(skills == {"python", "linux"})  # True
print(required == {"python", "linux"})  # True
```

状态变化是：

```text
skills 原有元素：
{"python", "sql", "linux", "git"}

required 中的元素：
{"python", "linux"}

两边共同拥有：
{"python", "linux"}

intersection_update() 执行后的 skills：
{"python", "linux"}
```

这些更新方法和 `list.sort()` 类似，主要作用是修改原对象，返回值是 `None`：

```python
skills = {"python", "sql"}
result = skills.update({"linux"})

print(result)  # None
print(skills == {"python", "sql", "linux"})  # True
```

对于普通 `set`，`|=`、`&=`、`-=` 和 `^=` 也分别表示相应的原地更新。初学时先把方法名称与四种集合运算对应起来，再阅读这些简写。

#### 9.5.4 新集合与原地更新怎样选择

如果调用方仍然需要旧集合，应创建新结果：

```python
skills = {"python", "sql"}
alias = skills

common = skills & {"python"}

print(common == {"python"})         # True
print(alias == {"python", "sql"})  # True，旧集合没有改变
```

如果确实要更新原集合，可以使用更新方法；所有指向该集合的名字都会观察到变化：

```python
skills = {"python", "sql"}
alias = skills

skills.intersection_update({"python"})

print(skills == {"python"})  # True
print(alias == {"python"})   # True，alias 指向同一个集合
```

因此，选择新集合还是原地更新时，需要依次确认：旧集合是否还要使用、是否有其他名字共享该对象，以及当前代码是否真的希望这些位置一起观察到修改。

### 9.6 `frozenset`：不可变集合

```python
permissions = frozenset({"read", "write"})
```

`frozenset` 创建后不能 `add()` 或 `remove()`，但仍支持成员判断和非原地集合运算。因为它不可变且元素可哈希，它本身可以作为字典键或另一个集合的元素：

```python
routes = {
    frozenset({"read", "write"}): "editor",
    frozenset({"read"}): "viewer",
}
```

当“一个无顺序的元素组合”需要作为键时，`frozenset` 比强行排序成元组更直接地表达集合语义。

### 9.7 集合常见复杂度

| 操作 | 常见时间复杂度 |
|---|---:|
| `value in values_set` | 平均 `O(1)`，最坏 `O(n)` |
| `values_set.add(value)` | 平均或摊销 `O(1)` |
| `values_set.remove(value)` | 平均 `O(1)` |
| 遍历全部元素 | `O(n)` |
| `left | right` | 平均 `O(n + m)` |
| `left & right` | 平均约 `O(min(n, m))` |
| `values_set.copy()` | `O(n)` |

集合适合快速回答“有没有”和“哪些元素共同存在”，不适合回答“第几个是什么”。

## 10. `list`、`tuple`、`dict`、`set` 怎样选择

不要先问“哪种数据结构最快”，而要先问需要支持什么操作。

| 主要需求 | 优先考虑 | 原因 |
|---|---|---|
| 按位置读取、保持顺序、允许重复 | `list` | 支持 `O(1)` 索引，便于末尾追加 |
| 固定位置结构，不希望增删元素 | `tuple` | 不可变，语义上表示固定记录 |
| 根据唯一键快速查找值 | `dict` | 按键平均 `O(1)` 查找 |
| 快速判断元素是否存在、去重 | `set` | 成员判断平均 `O(1)` |
| 不可变的无序元素组合 | `frozenset` | 可用于哈希键和集合元素 |

一个问题可能同时需要多个结构。例如既要保留事件原顺序，又要快速判断事件 ID 是否出现过，可以同时维护列表和集合：

```text
ordered_events = []
seen_ids = set()

for event in events:
    if event.id in seen_ids:
        continue
    seen_ids.add(event.id)
    ordered_events.append(event)
```

这不是“重复存储一定不好”，而是用额外空间换取所需操作效率。代价是必须保证两个结构的状态同步。

## 11. `deque`：两端都要高效操作的队列

### 11.1 为什么普通列表不适合作为高频先进先出队列

队列遵循先进先出：先进入的元素先离开。

```text
进入方向：A → B → C
离开顺序：A → B → C
```

用列表可以写：

```python
queue = []
queue.append("A")
queue.append("B")
first = queue.pop(0)
```

但 `pop(0)` 删除头部后，要把其余所有引用向左移动，是 `O(n)`。如果连续弹出 `n` 次，总成本可能达到 `O(n²)`。

### 11.2 `collections.deque`

`deque` 是双端队列，名称来自 double-ended queue。它专门支持两端高效加入和删除：

`collections` 是标准库中集中提供专用容器工具的模块。`from collections import deque` 表示从该模块取得 `deque` 这个名字，完整导入机制在第 8 章学习。

```python
from collections import deque

queue = deque()
queue.append("A")
queue.append("B")
queue.appendleft("front")

print(queue.popleft())  # front
print(queue.pop())      # B
```

`append()`、`appendleft()`、`pop()` 和 `popleft()` 都是 `O(1)`。

### 11.3 `deque` 与列表的索引性能对比

`deque` 适合两端操作，但访问中间位置需要沿结构移动，最坏 `O(n)`。如果需求是大量按下标随机访问，列表更合适。

```python
from collections import deque


values = deque(range(1000))
middle = values[500]  # 可以访问，但不应误认为和列表一样始终 O(1)
```

容器选型取决于主要操作：

```text
大量末尾追加 + 按下标读取 → list
大量两端加入和删除          → deque
```

### 11.4 有界 `deque`

```python
from collections import deque


recent = deque(maxlen=3)

for value in [10, 20, 30, 40]:
    recent.append(value)

print(recent)  # deque([20, 30, 40], maxlen=3)
```

达到最大长度后，从一端加入新元素会自动丢弃另一端最旧元素。这适合保存最近 `k` 条记录。自动丢弃是设计语义，使用前要确认数据丢失符合需求。

### 11.5 `rotate()`

```python
from collections import deque


values = deque([1, 2, 3, 4])
values.rotate(1)
print(values)  # deque([4, 1, 2, 3])

values.rotate(-2)
print(values)  # deque([2, 3, 4, 1])
```

正数向右旋转，负数向左旋转。旋转多步需要相应的数据调整，不要因为它是一行 API 就默认成本与旋转距离无关。

## 12. `Counter`：元素频次统计

### 12.1 从普通字典计数到 `Counter`

普通字典计数：

```python
counts = {}
for character in "banana":
    counts[character] = counts.get(character, 0) + 1
```

使用 `Counter`：

```python
from collections import Counter

counts = Counter("banana")
print(counts)  # Counter({'a': 3, 'n': 2, 'b': 1})
```

`Counter` 是专门表示“元素到计数”的字典子类。它没有改变计数算法的数量级，仍需读取全部 `n` 个输入，平均时间 `O(n)`；价值在于清楚表达意图并提供计数相关操作。

### 12.2 缺失元素返回零

```python
from collections import Counter


counts = Counter("banana")
print(counts["x"])  # 0
```

普通字典直接访问缺失键会抛出 `KeyError`，`Counter` 则返回整数零。读取不会自动把这个零计数键写入容器。

### 12.3 常用操作

```python
from collections import Counter


counts = Counter("banana")
print(counts.most_common(2))  # [('a', 3), ('n', 2)]
```

`most_common(k)` 返回频次最高的 `k` 项。不要把它想成无成本的查询；实现需要根据计数项数量选择和排列候选。

计数器还支持更新与减法：

```python
from collections import Counter


counts = Counter("banana")
counts.update("band")
counts.subtract("aaa")
```

减法后可以保留零或负计数。这一点与普通集合“存在或不存在”的语义不同，检查结果时不要只看键是否还在。

### 12.4 什么时候不用 `Counter`

如果值并不是次数，例如保存用户资料、下标或复杂状态，普通字典语义更清楚。`Counter` 适用于值确实代表计数的场景，不是所有字典的替代品。

## 13. `defaultdict`：缺失键出现时自动创建默认值

### 13.1 分组代码中的重复判断

普通字典分组常写成：

```python
positions = {}

for index, character in enumerate("banana"):
    if character not in positions:
        positions[character] = []
    positions[character].append(index)
```

`defaultdict` 可以把“缺失时创建什么”放到容器定义处：

```python
from collections import defaultdict

positions = defaultdict(list)

for index, character in enumerate("banana"):
    positions[character].append(index)
```

这里传入的是 `list` 函数本身，而不是 `list()` 创建出的某一个共享列表。这里的**默认工厂**是“需要默认值时负责创建新对象的可调用对象”；`list` 正好能在不提供实参时创建空列表。每当通过下标读取缺失键时，工厂会被调用，创建新的空列表并写入该键。

### 13.2 状态变化

```text
初始：{}
读取 positions['b']：缺失 → 调用 list() → 写入 'b': []
追加 0：{'b': [0]}
读取 positions['a']：缺失 → 再调用 list() → 写入独立空列表
追加 1：{'b': [0], 'a': [1]}
```

不同键得到不同列表，不会共享同一个默认列表对象。

### 13.3 `get()` 不会触发默认工厂

```python
from collections import defaultdict

counts = defaultdict(int)

print(counts.get("missing"))  # None
print(counts)                 # defaultdict(..., {})

print(counts["missing"])     # 0
print(counts)                 # 现在键已被写入
```

默认工厂主要在 `mapping[key]` 读取缺失键时触发。`get()` 仍遵守普通字典的取值方式。这是常见面试追问。

### 13.4 选择 `get()`、`setdefault()` 还是 `defaultdict`

- 偶尔读取缺失键但不想写入：`get()`。
- 在普通字典中偶尔需要“若缺失则写入默认值”：`setdefault()`。
- 整个容器的稳定语义就是“缺失键自动生成默认对象”：`defaultdict`。

选择应让读者一眼看懂数据含义，而不是只比较哪一种少写字符。

## 14. `namedtuple`：带字段名的元组

### 14.1 普通元组的位置含义不直观

```python
record = ("Ada", 95, "Python")
print(record[1])
```

读者必须记住位置 1 表示成绩。`namedtuple` 创建一种带字段名的元组子类：

```python
from collections import namedtuple

Attempt = namedtuple("Attempt", ["name", "score", "language"])
record = Attempt("Ada", 95, "Python")

print(record.name)   # Ada
print(record.score)  # 95
print(record[1])     # 仍可按元组位置读取
```

### 14.2 `namedtuple` 的元组行为与不可变性

`namedtuple` 实例不可变、可迭代，可以解包，并在字段都可哈希时可作为字典键。

尝试为不可重新赋值的命名元组字段赋值时，会出现 `AttributeError`。这个异常表示当前对象不支持所请求的属性读取或写入操作：

```python
record = ("Ada", 95, "Python")
name, score, language = record
# record.score = 100  # AttributeError
```

这里的命名元组字段不可重新赋值，因此修改 `record.score` 会失败。异常体系在第 7 章完整学习。

若只需要少量固定字段和轻量记录，它很方便；若需要复杂验证、方法、继承设计或可变状态，第 6 章的普通类和数据类更合适。数据类可以先理解为 Python 用来简化“主要负责保存字段数据的类”中重复定义工作的一种工具。

本章只把它作为容器工具使用，不提前展开类创建机制和 Python 数据模型。

## 15. 堆的结构与使用场景

### 15.1 反复求最小值时的排序开销

**数据流**表示数据不是一次性全部给出，而是随时间或多次调用持续到来。假设数据流不断到来，每次都要知道当前最小元素。一种做法是每加入一个值就重新排序：

```text
加入一个元素
→ 对全部元素重新排序 O(n log n)
→ 读取第一个元素 O(1)
```

但我们并不总需要知道完整排序，只需要快速取得当前最小值。堆正是为这种“反复加入元素，并反复取得极值”的需求设计的数据结构。

### 15.2 最小堆的规则

堆通常用树形关系解释。树是一种层级结构：最上方节点称为**根节点**；一个节点直接连接的下一层节点称为它的**孩子**，该节点则是孩子的**父节点**。二叉树表示每个节点最多有两个孩子。

最小堆保证每个父节点都不大于它的孩子，因此根节点一定是整个堆的最小值。

```text
        2
      /   \
     5     4
    / \
   8   7
```

它不是完整有序结构。`4` 可以出现在 `5` 的右边，因为堆只要求父子关系满足规则，不要求同一层从左到右有序。

### 15.3 为什么用列表表示堆

堆采用接近**完整二叉树**的形状：除最后一层外各层填满，最后一层从左向右连续填入，不在中间留下空洞。这样的树可以按层依次放入列表：

```text
树：                 列表下标：
        2                0
      /   \            / \
     5     4          1     2
    / \              / \
   8   7            3   4

列表：[2, 5, 4, 8, 7]
```

对下标 `index`：

```text
左孩子：2 * index + 1
右孩子：2 * index + 2
父节点（仅当 index > 0）：(index - 1) // 2
```

根节点下标为 `0`，它没有父节点；不能把公式计算出的 `-1` 当作根节点的父节点下标。

因此不需要为每个节点额外保存左右指针。

### 15.4 上浮和下沉为什么是 `O(log n)`

加入新元素时先放到列表末尾，保持树形没有空洞，再与父节点比较并向上交换：

```text
原堆：[2, 5, 4]
加入 1：[2, 5, 4, 1]
1 与父节点 5 交换：[2, 1, 4, 5]
1 与父节点 2 交换：[1, 2, 4, 5]
```

删除根节点时，先保存根值，把列表末尾元素取出并放到根位置，再不断与较小孩子交换：

```text
原堆：[1, 2, 4, 5]
取出根 1，末尾 5 补到根：[5, 2, 4]
5 与较小孩子 2 交换：[2, 5, 4]
```

使用末尾元素是因为列表末尾删除是 `O(1)`，而且移走最后节点仍能保持完整树没有空洞。若随意从中间取一个元素，删除它还要移动列表元素，或者破坏按层连续存储的树形。

完整二叉树高度约为 `log n`，一个元素最多沿树高移动，因此上浮和下沉是 `O(log n)`。

## 16. `heapq`：用列表维护最小堆

### 16.1 `heapq` 操作的是普通列表

```python
import heapq

heap = []
heapq.heappush(heap, 5)
heapq.heappush(heap, 2)
heapq.heappush(heap, 4)

print(heap[0])  # 2
```

`heapq` 是标准库模块，名称可以理解为 heap queue。它不是一个新的容器类，而是一组把普通列表按堆规则维护的函数。不要绕过这些函数随意修改列表内部，否则可能破坏堆规则。

### 16.2 推入、读取和弹出

```python
import heapq


heap = [2, 5, 4]
heapq.heapify(heap)
heapq.heappush(heap, 1)  # O(log n)
smallest = heap[0]       # O(1)，不删除
removed = heapq.heappop(heap)  # O(log n)，删除并返回最小值
```

不要用 `heap.pop(0)` 删除堆顶。它既要移动所有列表元素，又不会执行正确的下沉恢复过程。

### 16.3 `heapify()` 为什么是 `O(n)`

```python
import heapq


values = [7, 2, 6, 1, 5]
heapq.heapify(values)

print(values[0])  # 1
```

直觉上，把 `n` 个元素逐个 `heappush()` 是 `O(n log n)`。但 `heapify()` 从靠近底部的父节点开始批量下沉；大量底层节点几乎不用移动，只有少数靠近根的节点可能移动很多层。所有工作相加可证明为 `O(n)`。

面试初答不必完整证明，但应知道 `heapify()` 是原地建堆、时间 `O(n)`，而不是机械地把 `n` 次 `O(log n)` 相乘。

### 16.4 堆列表不是完整排序结果

```python
import heapq


values = [7, 2, 6, 1, 5]
heapq.heapify(values)
print(values)
```

只能保证 `values[0]` 是最小值以及父子满足堆规则，不能保证整个列表升序。若要依次得到升序元素，可以反复 `heappop()`，但这会清空堆，并总计花费 `O(n log n)`。

### 16.5 `heappushpop()` 与 `heapreplace()`

固定维护一定数量的候选时，经常需要加入一个新值，同时移走一个最小值。这两个函数的关键区别是操作顺序：

```text
heappushpop(heap, value)
概念上先加入 value，再弹出所有候选中的最小值
→ value 会参与淘汰，可能刚加入就被弹出

heapreplace(heap, value)
先弹出原堆顶，再加入 value
→ 返回的一定是原堆顶，value 一定留在堆中
```

用新值 `1` 可以直接看出区别：

```python
import heapq


first_heap = [3, 5, 8]
heapq.heapify(first_heap)
first_removed = heapq.heappushpop(first_heap, 1)

second_heap = [3, 5, 8]
heapq.heapify(second_heap)
second_removed = heapq.heapreplace(second_heap, 1)

print(first_removed, sorted(first_heap))
# 1 [3, 5, 8]：1 参与比较后立即被淘汰

print(second_removed, sorted(second_heap))
# 3 [1, 5, 8]：先移走原堆顶 3，再让 1 进入堆
```

如果新值是 `6`，两者都会移走 `3` 并保留 `5、6、8`；只有当新值不大于原堆顶时，区别才明显。

| 操作 | 返回值 | 新值是否一定留下 |
|---|---|---|
| `heappushpop()` | 新值和原堆顶中较小的一个 | 不一定 |
| `heapreplace()` | 原堆顶 | 一定 |

维护最大的 `k` 个元素时，通常希望较小的新值自动被淘汰，可以使用：

```text
heapq.heappushpop(heap, value)
```

也可以先判断，再替换已有的最小候选：

```python
import heapq


heap = [3, 5, 8]
heapq.heapify(heap)
value = 6

if value > heap[0]:
    heapq.heapreplace(heap, value)
```

`heapreplace()` 要求堆非空；`heappushpop()` 用于空堆时会返回新值，并让堆保持为空。语义不确定时，先想清楚“新值是否必须留下”，再选择函数。

### 16.6 常用复杂度

| 操作 | 时间复杂度 |
|---|---:|
| `heap[0]` | `O(1)` |
| `heapq.heappush(heap, value)` | `O(log n)` |
| `heapq.heappop(heap)` | `O(log n)` |
| `heapq.heappushpop(heap, value)` | 最坏 `O(log n)` |
| `heapq.heapreplace(heap, value)` | `O(log n)` |
| `heapq.heapify(values)` | `O(n)` |
| 连续弹出全部 `n` 个元素 | `O(n log n)` |

这些结论建立在比较单个元素的成本可视为常数的常规分析上。如果对象的比较本身很昂贵，还要把比较成本计算进去。

## 17. Python 为什么常用负数模拟最大堆

### 17.1 用取负反转数值的比较顺序

`heapq` 的经典接口维护最小堆，因此堆顶是最小元素。但有些问题需要反复取得最大元素。

对于普通数值，可以利用大小关系反转：

```text
原数：  8   7   4
取负： -8  -7  -4

最小负数 -8 对应最大原数 8
```

```python
import heapq

max_heap = []
for value in [8, 7, 4]:
    heapq.heappush(max_heap, -value)

largest = -heapq.heappop(max_heap)
print(largest)  # 8
```

加入时取负，取出后再取负。堆内保存的是转换后的值，变量命名和注释应让这种转换清楚可见。

### 17.2 元组中只反转需要反转的排序字段

堆元素也可以是元组，元组按第一项、第二项依次比较：

```python
import heapq


heap = []
priority = 3
task_id = 10
task_name = "backup"
heapq.heappush(heap, (-priority, task_id, task_name))
```

这里只把优先级取负。如果多个任务优先级相同，接着由 `task_id` 决定顺序。设计元组时要确保可能参与比较的字段彼此可比较；否则平局时可能出现 `TypeError`。

### 17.3 Python 3.14 起的公开最大堆接口

Python 3.14 起，`heapq` 提供 `heapify_max()`、`heappush_max()`、`heappop_max()`、`heappushpop_max()` 和 `heapreplace_max()` 等公开最大堆接口。Python 3.11～3.13 没有这些公开接口，数值场景通常仍使用取负方案。项目应根据目标运行版本选择写法；取负方案兼容较广，但不适用于无法取负的任意对象。

这一节放在最小堆之后，是因为“取负”只是改变比较方向的适配方法，不是另一种独立堆结构。

## 18. Top K：为什么堆的大小往往是 `k`

### 18.1 Top K 与第 `k` 大问题

Top K 指从大量数据中找出最大或最小的 `k` 个元素，或者找第 `k` 大、第 `k` 小元素。

如果只需要第 `k` 大，并不需要保存完整排序结果。关键问题是：哪些元素仍有资格进入最大的 `k` 个？

### 18.2 第 `k` 大：维护大小为 `k` 的最小堆

以数据流 `[4, 5, 8, 2, 10]`，`k = 3` 为例。堆始终保留当前最大的 3 个值：

```text
读 4：保留 [4]
读 5：保留 [4, 5]
读 8：保留 [4, 5, 8]，堆顶是 4
读 2：加入后超过 3 个，移走最小值 2，仍保留 4、5、8
读 10：加入后移走当前最小值 4，保留 5、8、10
```

最后保留的是最大的三个值，其中最小者 `5` 正好是第 3 大。因此：

```text
求第 k 大
→ 保留最大的 k 个
→ 这 k 个中最小的那个就是第 k 大
→ 使用大小为 k 的最小堆
```

```python
import heapq

def kth_largest(values, k):
    if not 1 <= k <= len(values):
        raise ValueError("k must satisfy 1 <= k <= len(values)")

    heap = []

    for value in values:
        heapq.heappush(heap, value)
        if len(heap) > k:
            heapq.heappop(heap)

    return heap[0]
```

这里明确要求 `values` 是可取得长度的非空序列，并满足 `1 <= k <= len(values)`。若 `k == 0`，堆会被清空后再访问 `heap[0]`；若 `k` 大于元素数量，也不存在第 `k` 大，因此不能省略输入约束。

每次堆操作只发生在最多 `k + 1` 个元素上，处理 `n` 个值的时间为 `O(n log k)`，额外空间为 `O(k)`。

### 18.3 为什么不是维护大小为 `k` 的最大堆

保留最大的 `k` 个候选时，每来一个新值，需要快速淘汰候选中最小的那个。最小堆正好把“淘汰边界”放在堆顶。

最大堆会快速告诉你候选中最大的是谁，但这不是需要淘汰的对象。因此容器方向应由“需要快速移走谁”决定，而不是看到“第 `k` 大”就机械使用最大堆。

### 18.4 第 `k` 小的对称关系

求第 `k` 小时，可以保留最小的 `k` 个候选，并快速淘汰其中最大的值，因此使用大小为 `k` 的最大堆。对于数值，可以通过取负模拟。

```text
求第 k 小
→ 保留最小的 k 个
→ 快速淘汰这 k 个中最大的候选
→ 大小为 k 的最大堆
```

### 18.5 Top K 的堆方案与排序方案比较

若数据已经全部在内存中且只查询一次，可以排序后索引；若 `k` 接近 `n`，不同方案的实际表现也可能变化；还有选择算法等其他方案。

本章重点不是宣称堆永远最好，而是理解它的优势：数据可以逐个到来，只保存 `k` 个候选，更新一次通常是 `O(log k)`。

## 19. 容器浅拷贝：外层独立不等于全部独立

### 19.1 常见浅拷贝方法

```text
list_copy = original_list.copy()
list_copy_2 = original_list[:]
dict_copy = original_dict.copy()
set_copy = original_set.copy()
```

这些方法会创建新的外层容器，并把原容器中的元素引用复制过去。

### 19.2 逐步观察嵌套列表

```python
original = [[1], [2]]
copied = original.copy()
```

此时关系是：

```text
original ─→ 外层列表 A ─┬→ 内层列表 X [1]
                         └→ 内层列表 Y [2]

copied   ─→ 外层列表 B ─┬→ 同一个 X
                         └→ 同一个 Y
```

修改外层槽位不会影响另一个外层列表：

```python
original = [[1], [2]]
copied = original.copy()
copied[0] = [99]
print(original)  # [[1], [2]]
```

但修改共享内层对象会被两边观察到：

```python
original = [[1], [2]]
copied = original.copy()
copied[0].append(9)

print(original)  # [[1, 9], [2]]
```

### 19.3 字典浅拷贝也遵守同一模型

```python
original = {"scores": [80, 90]}
copied = original.copy()
copied["scores"].append(100)

print(original)  # {'scores': [80, 90, 100]}
```

字典外层条目独立，值引用仍指向同一个列表。

### 19.4 本章边界

本章只要求理解容器 API 的浅拷贝边界。`copy.copy()`、`copy.deepcopy()`、循环引用、对象生命周期和垃圾回收将在第 9 章系统学习。这里不要把“需要完全独立”机械等同于“任何时候都调用深拷贝”；深拷贝也有时间、空间和语义成本。

## 20. 常见容器陷阱

### 20.1 把方法返回值当成新列表

```python
numbers = [3, 1, 2]
ordered = numbers.sort()

print(ordered)  # None
```

`sort()` 修改原列表。类似地，`append()`、`extend()`、`remove()` 和 `clear()` 主要通过修改对象产生效果，通常返回 `None`。

### 20.2 用列表头部操作实现大队列

```python
queue = list(range(5))

while queue:
    item = queue.pop(0)
```

每次头部删除都可能移动剩余元素。大量先进先出操作优先考虑 `deque.popleft()`。

### 20.3 认为集合会保留输入顺序

```python
values = [3, 1, 3, 2]
unique = list(set(values))
```

它能去重，但不应依赖结果保持首次出现顺序。需要保序去重时应选择具有明确顺序语义的方案。

### 20.4 认为字典按键排序

字典保存插入顺序，不会自动按数值或字母排序。需要排序时应显式使用 `sorted()`，并理解这会引入 `O(n log n)` 时间以及结果容器。

### 20.5 判断字典中是否存在某个值

```python
mapping = {"a": 10, "b": 20}

print("a" in mapping)          # 检查键
print(10 in mapping.values())  # 检查值
```

`in mapping` 检查键，平均 `O(1)`；`in mapping.values()` 通常线性检查，`O(n)`。如果频繁反向查询，需要考虑额外维护值到键的索引，并处理重复值问题。

### 20.6 可变对象不能直接作为哈希键

```python
# visited = {[1, 2]}  # TypeError
visited = {(1, 2)}
```

如果列表表达的是不会变化的位置，可以根据语义转换为元组；不要只为了绕过错误而转换，必须确认不可变键正确代表该状态。

### 20.7 遍历时改变容器结构

列表删除可能跳过元素，字典或集合改变大小通常会抛出运行时错误。先确认是否可以构造新容器、记录待修改项，或遍历快照。

### 20.8 `dict.fromkeys()` 与共享可变默认值

```python
groups = dict.fromkeys(["a", "b"], [])
groups["a"].append(1)

print(groups)  # {'a': [1], 'b': [1]}
```

所有键都获得同一个列表引用。需要每个键独立列表时，使用推导式或 `defaultdict(list)`：

```python
groups = {key: [] for key in ["a", "b"]}
```

### 20.9 堆序与全局排序的区别

`heap[0]` 是最小值，不代表 `heap[1:]` 已排序。需要完整顺序时必须明确付出排序或连续弹出的成本。

### 20.10 平均、摊销与最坏复杂度的限定

“字典查找是 `O(1)`”作为口头简写很常见，但正式回答应补充“平均情况下”，理论最坏可能 `O(n)`；列表追加则应说“摊销 `O(1)`”，偶尔扩容的一次操作可能是 `O(n)`。

## 21. 用操作需求做容器选型

### 21.1 先列出真正高频的操作

面对场景时，按下面顺序思考：

```text
数据是否需要保持顺序？
→ 是否需要按位置访问？
→ 是否允许重复？
→ 主要查询是按位置、按键，还是判断存在？
→ 主要修改发生在末尾、两端，还是任意位置？
→ 是否需要持续取得最小值或最大值？
→ 是否允许额外空间？
```

### 21.2 常见业务场景的容器选择

场景一：保存按到达顺序记录的日志，偶尔按下标查看。

```text
需要顺序 + 允许重复 + 按位置访问
→ list
```

场景二：根据员工 ID 快速找到员工资料。

```text
唯一 ID → 资料
→ dict
```

场景三：判断请求 ID 是否已经处理。

```text
只关心存在性，不需要对应值
→ set
```

场景四：任务先进先出处理。

```text
末尾进入 + 头部离开
→ deque
```

场景五：数据流中持续查询第 10 大元素。

```text
只保留最大的 10 个候选
→ 大小为 10 的最小堆
```

### 21.3 时间、空间和语义一起考虑

集合成员判断通常比列表快，但集合会使用额外哈希表空间，也失去按位置和重复元素语义。字典能快速按键查找，但如果程序只需要顺序遍历一次，建立字典可能没有必要。

好的选型不是看到 `O(1)` 就立即使用，而是在满足正确语义的候选中，选择最符合高频操作和数据规模的结构。

## 22. 如何分析一段容器代码

遇到性能题时，可以逐步进行。

### 第一步：定义规模

```text
n = len(values)
```

若还有另一个独立容器，定义 `m`，不要无条件都写成 `n`。

### 第二步：写出每个内置操作的成本

```text
for value in values:            # n 次
    if value in selected_list:  # 每次最坏 O(m)
        ...
```

因此整体最坏是 `O(nm)`，不是看到一个显式循环就回答 `O(n)`。

### 第三步：确认情况类型

```text
list.append：摊销 O(1)
dict 查找：平均 O(1)，最坏 O(n)
```

### 第四步：检查隐式创建的新容器

```text
for index in range(len(prefix)):
    if target in prefix[:index]:
        ...
```

`prefix[:index]` 每轮都会创建新列表，既有时间成本，也有临时空间成本。不能只分析 `in`。

### 第五步：检查是否能改变主要操作

如果代码反复进行列表成员判断，可以考虑集合；如果反复删除列表头部，可以考虑 `deque`；如果只持续关注少量极值候选，可以考虑固定大小堆。

优化不是机械换容器。换之前必须确认顺序、重复、可哈希性和更新同步等语义仍然正确。

## 23. 面试中怎样回答容器问题

### 23.1 回答复杂度的基本结构

一个完整但不冗长的回答可以按四步组织：

```text
先给结论
→ 说明是平均、最坏还是摊销
→ 用底层组织方式解释原因
→ 补充不适用条件或替代方案
```

例如回答“为什么 `list.pop(0)` 是 `O(n)`”：

```text
在 CPython 的常见实现中，列表按连续引用槽位组织。
删除第一个元素后，后面的引用需要整体左移来填补空位，
移动数量随列表长度增长，所以是 O(n)。
如果需求是频繁从头部弹出，应使用 deque.popleft()，它是 O(1)。
```

### 23.2 回答字典为什么快

只说“因为用了哈希表”还不够。应能继续解释：

```text
键先计算哈希值
→ 哈希值帮助定位少量候选槽位
→ 再用相等比较确认键
→ 正常分布下只检查少量候选，所以平均 O(1)
→ 冲突严重时理论最坏可能 O(n)
```

不必背 CPython 当前版本的具体槽位探测公式或扩容阈值，除非岗位明确要求解释器源码。

### 23.3 回答列表和元组区别

不要只回答“列表可变，元组不可变”。还可以根据追问补充：

- 两者都有顺序、支持索引、允许重复。
- CPython 中可用“元组固定引用槽位、列表维护动态容量”解释结构差异。
- 元组拼接和 `+=` 创建结果并重新绑定名字，不修改旧元组。
- 元组适合表达固定结构。
- 元组是否可哈希取决于所有元素是否可哈希。
- 元组本身不可变，但内部引用的列表仍可能被修改。
- 性能差异不能脱离具体操作随意概括。

### 23.4 回答列表和 `deque` 区别

```text
list 适合按下标随机访问和末尾操作；
deque 适合两端 O(1) 加入删除；
list 的 pop(0) 是 O(n)，deque 的 popleft() 是 O(1)；
deque 中间索引最坏 O(n)，所以它不是通用的更快列表。
```

### 23.5 回答为什么第 `k` 大用最小堆

```text
我只保留当前最大的 k 个元素。
这 k 个候选中最小的元素就是第 k 大，也是新元素到来时的淘汰边界。
最小堆能在 O(1) 读取这个边界，并在 O(log k) 更新，
因此处理 n 个元素是 O(n log k)，额外空间 O(k)。
```

这种回答说明了不变量和选择原因，比只背“Top K 用堆”更可靠。

## 24. 语言规则与 CPython 实现边界

| 结论 | 性质 | 是否适合依赖 |
|---|---|---|
| 列表有顺序、可变并支持索引 | Python 语言行为 | 可以 |
| 元组不可变 | Python 语言行为 | 可以 |
| CPython 元组通常按创建长度分配固定引用槽位 | CPython 实现细节 | 可用于解释行为，不应依赖具体布局 |
| 字典键唯一 | Python 语言行为 | 可以 |
| Python 3.7 起字典按插入顺序迭代 | 当前语言保证 | 可以，需注意目标版本 |
| 集合不提供按位置访问 | Python 语言行为 | 可以 |
| 可哈希对象相等时哈希值必须相等 | 哈希协议要求 | 可以 |
| CPython 列表使用连续的对象引用槽位 | CPython 实现细节 | 可用于解释性能，不应依赖布局 |
| CPython 列表具体预留多少容量 | 版本相关实现细节 | 不应依赖 |
| CPython 字典具体怎样探测冲突槽位 | 版本相关实现细节 | 不应依赖 |
| 字符串哈希值跨进程固定 | 不受语言保证且通常不成立 | 不应依赖 |
| `heapq` 列表整体已经排序 | 错误结论 | 不能依赖 |

稳妥表达方式仍然是：先说容器对使用者保证的行为，再说明 CPython 的常见组织方式如何解释复杂度，最后指出具体布局和阈值可能随版本变化。

## 26. 本章总结

本章最重要的不是孤立背下每个 API，而是能从操作需求推导容器选择和复杂度：

1. 复杂度描述资源随输入规模增长的趋势；分析前必须说明 `n` 代表什么。
2. `O(1)`、`O(log n)`、`O(n)` 和 `O(n log n)` 是增长量级，不是精确耗时。
3. 最坏、平均和摊销是不同分析角度；字典查找通常说平均 `O(1)`，列表追加说摊销 `O(1)`。
4. CPython 列表可用连续引用槽位理解，所以按下标访问是 `O(1)`，头部或中间插删通常是 `O(n)`。
5. 切片、拼接和复制会创建新外层容器，其成本随结果规模增长；浅拷贝仍共享内部对象。
6. 元组表示固定有序结构；CPython 中可用固定引用槽位理解它与动态列表的区别。元组 `+=` 不修改旧对象，外层不可变也不代表内部对象都不可变或任何元组都可哈希。
7. 字典和集合借助哈希值缩小候选位置，再用可自定义的相等性协议确认键；查找平均 `O(1)`，冲突严重时理论最坏可能 `O(n)`。
8. 字典保存键到值的映射并按插入顺序迭代；集合强调唯一元素和成员关系，不提供位置语义。
9. `deque` 适合两端操作，`Counter` 适合计数，`defaultdict` 适合稳定的缺失值工厂，`namedtuple` 适合轻量固定记录。
10. 最小堆只保证堆顶最小，不保证整个列表有序；推入和弹出是 `O(log n)`，读取堆顶是 `O(1)`。
11. 求第 `k` 大时维护大小为 `k` 的最小堆，因为堆顶就是当前候选的淘汰边界。
12. 容器选型应同时考虑顺序、重复、查询方式、修改位置、时间、空间和数据语义。

当你能看到一段容器代码后，先列出高频操作，再解释每个操作为什么是这个复杂度，并能说明换成另一种容器会得到什么、失去什么时，才算真正掌握了这一章。
