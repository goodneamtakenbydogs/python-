# 第 2 章复习卡：内置数据结构与复杂度

这张卡用于完成讲义和实验后的快速回忆，不负责第一次教学。

## 1. 容器选择与复杂度分析步骤

```text
操作需求
→ 顺序和重复约束
→ 查找、索引、更新或两端操作
→ 选择容器
→ 判断单次复杂度
→ 计算整段代码的总复杂度
```

不要只问“哪种数据结构最快”。必须先问：对什么操作快，需要付出什么空间或顺序代价？

## 2. 复杂度关键词

| 术语 | 回忆重点 |
|---|---|
| 数据结构 | 组织数据并支持相关操作的方式 |
| API | 代码对使用者公开的函数、方法和调用规则 |
| 算法 | 解决一个问题的明确步骤 |
| 输入规模 `n` | 描述问题有多大，不一定总是列表长度 |
| 时间复杂度 | 基本操作次数随 `n` 的增长趋势 |
| 空间复杂度 | 额外占用空间随 `n` 的增长趋势 |
| 最坏复杂度 | 最不利输入或状态下的上界 |
| 平均复杂度 | 对输入或内部状态作出合理分布假设后的平均代价 |
| 摊销复杂度 | 一串操作的总代价平均到每次操作 |

常见增长顺序：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
```

## 3. 四种核心容器

| 容器 | 保持顺序 | 允许重复 | 按位置访问 | 典型优势 |
|---|---|---|---|---|
| `list` | 是 | 是 | 是 | 顺序数据、随机索引、末尾追加 |
| `tuple` | 是 | 是 | 是 | 固定结构、不可变外层 |
| `dict` | 保持插入顺序 | 键唯一 | 按键，不按整数位置 | 键到值的平均快速映射 |
| `set` | 不应依赖遍历顺序 | 否 | 否 | 去重和平均快速成员判断 |

## 4. `list` 高频复杂度

| 操作 | 复杂度 | 原因提示 |
|---|---:|---|
| `values[index]` | `O(1)` | 通过位置计算槽位 |
| `values.append(x)` | 摊销 `O(1)` | 偶尔扩容并复制 |
| `values.pop()` | `O(1)` | 删除末尾通常无需搬移后续元素 |
| `values.insert(0, x)` | `O(n)` | 大量已有元素需要移动 |
| `values.pop(0)` | `O(n)` | 后续元素需要前移 |
| `x in values` | `O(n)` | 最坏需要逐个比较 |
| `values[a:b]` | `O(k)` | 建立包含 `k` 个位置的新列表 |
| `values.copy()` | `O(n)` | 复制外层引用槽位 |
| `values.sort()` | `O(n log n)` | 通用比较排序 |

`append()` 是摊销 `O(1)`，不是每一次都保证同样代价。

## 5. 列表方法对比

### 5.1 加入元素

- `append(x)`：把 `x` 作为一个整体放到末尾。
- `extend(items)`：遍历 `items`，把其中元素逐个加入末尾。
- `insert(index, x)`：在指定位置插入，可能移动后续元素。

### 5.2 删除元素

- `remove(x)`：按值删除第一个匹配项，找不到会报错。
- `pop(index)`：按位置删除并返回元素，默认末尾。
- `del values[index]`：删除位置或切片，不返回被删值。
- `clear()`：清空原列表。

### 5.3 排序与反转

- `values.sort()`：原地排序，返回 `None`。
- `sorted(values)`：返回新列表，接受任意可迭代对象。
- `values.reverse()`：原地反转。
- `reversed(values)`：返回反向迭代器。

Python 排序是稳定的：排序键相同的元素保持原相对顺序。

`key` 接收函数来计算排序依据；`lambda record: record[1]` 是创建简短函数的表达式，完整函数式工具在第 4 章学习。

## 6. `tuple` 高频规则

- 单元素元组写成 `(value,)`，关键是逗号。
- 元组不可变，指的是创建完成后不能改变长度，也不能替换位置中的对象引用。
- CPython 中可用“创建时确定数量的引用槽位”理解元组；列表还要维护可调整数组和容量信息。
- 下标赋值失败是 `tuple` 类型不提供修改槽位的操作，不是内存被硬件设置成只读。
- 元组拼接和 `+=` 建立结果元组并重新绑定名字，不修改旧元组。
- 元组内部引用的可变对象仍可能改变。
- 元组不一定可哈希；只有它包含的所有元素都满足可哈希要求时，才可能作为字典键。
- 固定槽位模型属于 CPython 实现解释；元组不可变属于 Python 语言保证。
- 固定字段很多时，普通元组下标可读性不足，可考虑 `namedtuple` 或后续的数据类。

## 7. `dict` 与哈希

核心过程：

```text
键
→ 计算哈希值
→ 定位候选位置
→ 必要时处理冲突并比较相等性
→ 找到值或确认不存在
```

最后一步使用的是 `==` 相关的相等性协议，不是简单判断 `is`。最低限度记忆：`__hash__()` 相关行为负责提供稳定哈希值，`__eq__()` 相关行为负责确认候选是否相等；完整自定义规则在第 6 章学习。

必须带限定词：

- 查找、插入和删除通常是平均 `O(1)`。
- 哈希冲突和极端状态下可能退化，不能说绝对永远 `O(1)`。
- 相等的可哈希对象必须具有相同哈希值。
- 具有相同哈希值的对象不一定相等。
- 字典键在作为键期间，其哈希和相等关系必须保持稳定。
- Python 字典保持插入顺序，但不是按键大小自动排序。

## 8. 字典方法与视图

- `mapping[key]`：键不存在时抛出 `KeyError`。
- `mapping.get(key, default)`：键不存在时返回默认值，不写入字典。
- `setdefault(key, default)`：缺少键时写入默认值并返回对应值。
- `update(other)`：批量加入或覆盖键值。
- `pop(key)`：删除指定键并返回值。
- `keys()`、`values()`、`items()` 返回与字典当前状态关联的视图，不是固定快照。

## 9. `set` 与 `frozenset`

- 集合适合去重、成员判断和集合关系运算。
- `set` 可变，因此本身不能作为普通集合元素或字典键。
- `frozenset` 不可变且可哈希，可用于需要“集合型键”的场景。
- `|` 并集，`&` 交集，`-` 差集，`^` 对称差集。
- 不要通过集合去重后期待仍然自动满足原顺序要求。

## 10. 专用容器

| 工具 | 主要用途 | 高频提醒 |
|---|---|---|
| `deque` | 两端追加和删除 | `popleft()` 为 `O(1)`，中间随机访问不是优势 |
| `Counter` | 频次统计 | 缺失键计数通常表现为 `0` |
| `defaultdict` | 缺失键自动建立默认值 | 默认工厂是可调用对象，不是预先算好的共享值 |
| `namedtuple` | 带字段名的轻量不可变记录 | 本质仍具有元组行为 |

## 11. `heapq` 与 Top K

- 堆用树形关系解释：根节点位于最上方，父节点直接连接下一层孩子；完整二叉树最后一层从左向右连续填入。
- `heapq` 操作普通列表，并维持最小堆规则。
- `heap[0]` 是最小元素，读取为 `O(1)`。
- `heappush()` 和 `heappop()` 通常为 `O(log n)`。
- `heapify()` 可以把已有列表原地建堆，复杂度为 `O(n)`。
- 堆只保证父节点不大于孩子，不保证整个列表完整有序。
- Python 3.11～3.13 的数值最大堆常用取负模拟；Python 3.14+ 已提供公开最大堆接口。取负时必须一致地转换和还原。

维护最大的 `k` 个元素时：

```text
只保留当前最大的 k 个值
→ 使用大小不超过 k 的最小堆
→ 堆顶是这 k 个值中最小者
→ 也就是当前第 k 大的门槛
```

## 12. 容器选型速查

| 需求 | 首先考虑 |
|---|---|
| 保留顺序和重复元素，并按下标访问 | `list` |
| 表达固定且不应改变的顺序结构 | `tuple` |
| 根据键查找、更新对应值 | `dict` |
| 去重或频繁判断成员是否存在 | `set` |
| 从两端频繁加入和删除 | `deque` |
| 统计元素出现次数 | `Counter` |
| 按键分组并自动建立容器 | `defaultdict` |
| 反复取得当前最小值或维护有限候选 | `heapq` |

## 13. 常见陷阱

- 把 `list.pop(0)` 当作 `O(1)` 队列操作。
- 把字典和集合的平均 `O(1)` 说成绝对保证。
- 认为哈希值相同就代表键相等，忽略最终的相等性协议确认。
- 认为所有不可变对象都一定可哈希。
- 认为元组内部的列表也不能修改。
- 认为元组 `+=` 会修改旧元组。
- 因为元组通常管理开销较少，就断言它在所有操作中都比列表快。
- 使用 `append(items)` 却期待逐个加入。
- 使用 `extend(text)` 时忘记字符串会被逐字符迭代。
- 忘记 `sort()` 返回 `None`。
- 把字典视图误认为固定快照。
- 遍历字典或集合时直接改变其大小。
- 依赖集合的显示或遍历顺序。
- 认为浅拷贝会递归复制内部对象。
- 认为堆中的全部元素已经按大小排列。
- 为得到第 `k` 大而无条件保存和排序所有历史数据。
- 在循环内部执行 `x in list`，却只计算了外层循环复杂度。

## 14. 面试回答骨架

回答容器问题时可以按下面顺序组织：

1. 先说明容器保存的数据关系。
2. 说明它是否保持顺序、是否允许重复、是否可变。
3. 说明目标操作的复杂度，并加上平均或摊销限定。
4. 用存储结构或操作过程解释原因。
5. 给出适合场景和不适合场景。

回答复杂度问题时，不要只报一个结果。应明确：

- `n` 代表什么。
- 分析的是单次操作还是整段代码。
- 是否为最坏、平均或摊销复杂度。
- 是否建立了额外容器。
