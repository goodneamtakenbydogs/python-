# 第 15 章复习卡：Python 自动化脚本设计

用于完成讲义和实验后快速回忆，不代替首次教学。

## 1. 一项脚本的处理过程

```text
明确输入、输出、异常、退出状态与副作用
→ 加载、合并并校验配置
→ 在本次剩余预算内执行外部查询
→ 检查退出状态
→ 解析字段与类型
→ 按状态终止或有限等待
→ 检查业务预期
→ 保存结果与证据，完成资源收尾
```

先写约定，再选 API。通过只属于已经执行和实际检查的范围。

## 2. 易混概念

| 对比 | 区别 |
|---|---|
| 执行成功 / 协议成功 / 检查通过 | 退出状态 / 结构与字段 / 满足业务预期 |
| stdout / stderr | 结果通道 / 诊断通道，具体含义看目标协议 |
| 未提供 / 假值 | None 等缺失标记 / 可能合法的 0、False、空文本 |
| 单次 timeout / 总 budget | 一项等待上限 / 多次查询、间隔等累计范围 |
| 轮询 / 重复提交 | 查询同一任务状态 / 再次产生业务动作 |
| 超时 / 未执行 | 没收到及时结果 / 是否执行仍可能未知 |
| 幂等 / 返回相同 | 最终业务效果 / 返回值表现，不是同一性质 |
| 清理 / 补偿 | 释放所持资源 / 按业务约定修复部分效果 |
| 测试体通过 / 报告保存成功 | 业务证据 / 请求的结果保存，也应分别检查 |
| 等待超时 / 取消运行中工作 | 调用方停止等待 / 需要协作或底层终止能力 |

## 3. 输入与调用规则

- 明确配置优先级，逐层检查已提供值，避免高层掩盖错误。
- 不用 `value or default` 处理所有缺失语义；文件 null 与 CLI 未提供可有不同规则。
- 数量若要求精确整数，排除 bool；时间检查有限、正数与单位。
- 路径基准、文件编码和子进程流编码分别规定。
- 程序和实参分列，避免把数据拼成 shell 语句。
- `cwd` 属于子进程，env 通常先从父环境副本调整。
- `check=False` 要有明确的上层退出状态检查，非零结果也要保留。
- 结构合法后才做业务判断；独立 expected 不从 actual 复制。

## 4. 时间与状态控制

```text
deadline = 开始时的单调时刻 + 总预算
remaining = deadline - 当前时刻
本次 timeout = min(单次上限, remaining)
```

启动前检查，返回后再检查；截止点是否接受要写明。本例严格要求结果早于截止点。预算依赖协作者遵守限制，不能强行打断任意阻塞函数，也不保证所有收尾瞬间完成。

pending 才继续观察，ready 进入业务判断，failed 立即结束，未知状态报告协议问题。尝试上限包含第一次；最后一次后不多等。wait 不超过剩余量，晚返回后先判断预算。

只重试已声明的可恢复错误。退避与抖动控制节奏，不能代替预算、次数、状态和幂等约定。TimeoutExpired 的部分输出可能是 bytes，也可能是不完整协议。

## 5. 副作用与清理

超时后业务可能已经提交，不要无条件再次创建。稳定请求标识需要服务端或接口明确去重承诺；客户端自己生成标识不等于获得幂等性。

取得一项资源就建立收尾，部分初始化失败也清理已经取得部分。ExitStack 逆序清理，未知错误保持原因链。资源关闭不自动撤销业务写入。

小输出可以 capture_output，大输出另设受限消费。直接子进程结束不代表任意后代或远端任务结束；手工 Popen 只 wait 不读满管道可能互相等待。

报告先序列化、同目录临时写入、关闭后替换；失败保护旧目标并清理自身临时文件。提交可见性不等于断电持久性、多文件事务或并发仲裁。

## 6. 测试与小批量

- 注入执行器、时钟、等待和随机来源，控制明确边界。
- 检查最终类别，也检查次数、实参、剩余量及不应发生的下一步。
- 测正常、坏输入、非零退出、坏协议、终止状态、迟到结果、次数耗尽和报告失败。
- 保留首次失败与未测范围，不能只保留重试后通过。
- 每项有稳定编号，完成顺序变化时仍能正确关联。
- max_workers 限制运行并发，不自动限制全部已提交 Future 数量。
- cancel 通常仅对未开始项有效，线程池退出仍可能等待运行中工作。

## 7. 一分钟自测

1. 输入、输出和副作用应怎样写成可验证约定？
2. 为什么退出 0、合法 JSON、业务通过要分开？
3. 配置中的 0、False、None 各该怎样处理？
4. 为什么每次查询用完整 timeout 仍可能超过总体预算？
5. ready 恰在截止点返回时，本例怎样处理？
6. 时钟不前进，什么条件能阻止无限循环？
7. 超时前已经创建记录，为什么重试可能重复效果？
8. 报告替换失败后应该保留什么？
9. 等待 Future 超时，正在运行的工作是否已停止？
10. 替身验证与真实本地子进程验证分别提供什么证据？
