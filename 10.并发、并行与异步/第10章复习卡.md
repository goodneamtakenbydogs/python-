# 第 10 章复习卡：并发、并行与异步

学完讲义和实验后使用。每条先用自己的话解释，再举例；想不起原因时返回讲义，不把短句当作首次学习。

## 1. 执行模型

| 概念 | 回忆要点 |
|---|---|
| 并发 | 重叠时间内推进多项工作，可以交错 |
| 并行 | 同一瞬间有多个执行单元实际运行 |
| 同步 / 异步 | 调用与结果取得方式的关系 |
| 阻塞 / 非阻塞 | 条件不满足时当前执行单元是否停下等待 |
| 进程 | 普通地址空间隔离；共享和通信要显式安排 |
| 线程 | 同进程共享对象，各有执行现场，由操作系统调度 |
| 协程任务 | 在循环中协作暂停和恢复，不自动多核 |

先确认任务实际花时间计算还是等待，再检查库接口、共享状态、数据规模与资源容量。任务很少或有顺序依赖时，顺序执行仍可能是正确起点。

## 2. GIL 与版本

常规 CPython 的 GIL 限制同一解释器中多个线程同时执行受保护的 Python 操作。许多 I/O 和部分本地扩展会释放它；纯 Python CPU 工作与释放 GIL 的扩展工作不能混为一类。

GIL 保护解释器运行，不保护“读取、检查、写回”这一整项业务。一次测试没出现丢失更新，不是线程安全证明。

CPython 从 3.13 起提供可选自由线程构建，不等于新版本默认全无 GIL；扩展和实际运行状态也要核对。进程启动默认方式依平台和版本变化，本章用显式 `spawn`，不依赖“Linux 永远 fork”。

## 3. 同步工具的区别

| 工具 | 主要用途 | 容易遗漏的边界 |
|---|---|---|
| `Lock` | 互斥保护完整共享约束 | 所有相关访问者遵守同一锁约定 |
| `RLock` | 同一线程嵌套取得同一锁 | 不能消除多把锁的等待环 |
| `Event` | 表达就绪或停止标志 | 不保存每次通知的数量 |
| `Semaphore` | 限制同时占用名额 | 不等于单位时间请求速率 |
| `Condition` | 锁下检查并等待共享条件 | 等待释放锁，唤醒后重新检查 |
| `Queue` | 传递工作与提供排队背压 | 取出、确认完成和业务成功不同 |

锁范围覆盖需要共同成立的操作，过小留下竞态，过大增加串行等待。统一锁顺序，避免持锁等依赖者、重复取得普通锁和同池任务互等。

线程版与 asyncio 版的工具不能随意替换。异步工具面向同一循环中的任务；`threading.Lock` 的阻塞竞争可能把整个循环卡住。

## 4. 线程池、进程池与结果

- `target=work` 交出函数，`target=work()` 先在调用处执行。
- `start()` 启动，`join()` 等待；普通线程的 `join()` 不返回业务值或自动重抛工作异常。
- Future 代表未来状态；`result()` 返回结果或传播异常，`done()` 不等于成功。
- `map()` 按输入位置提供结果，`as_completed()` 提供已完成 Future；保留用例编号关联。
- `Future.result(timeout)` 超时不自动停止工作；`cancel()` 主要处理尚未开始的工作。
- 线程池上下文退出默认等工作结束；取消排队项不能强制终止运行项。
- 进程池要求可导入工作函数、可传输输入和结果；普通内存不自动共享。
- `spawn` 的启动保护与工作函数可导入性是两项要求；Notebook 实验使用真实临时脚本。
- 进程启动、序列化、传输、汇总和多份内存都要计入成本。

## 5. 协程、任务与等待

```text
async def 定义协程函数
→ 调用得到协程对象
→ await 沿当前任务等待，或 create_task 建立独立调度任务
→ 等待结果，接收异常或取消，确认清理
```

两次依次 `await` 不自动并发。`await` 对象已经完成或无需暂停时，不保证切换任务。循环内同步休眠、同步网络或持续计算仍会阻塞其他任务。

`to_thread()` 可以移出适合的阻塞工作，但不自动使其线程安全，也不保证外层取消停止底层线程。脚本入口用 `asyncio.run()`；已有事件循环的 Notebook 使用顶层 `await`。

## 6. 异常、超时与取消

| 操作 | 重点规则 |
|---|---|
| `gather()` | 成功结果按输入位置；成员普通失败默认不自动取消其余成员 |
| `gather(return_exceptions=True)` | 逐项区分正常结果和异常，不等于全部通过 |
| `TaskGroup` | 普通失败通常取消相关成员，等待收尾后传播异常组 |
| `except*` | 按异常组成员类型处理，Python 3.11 起提供 |
| `wait_for()` | 超时请求取消被等待工作，并等待取消处理 |
| `asyncio.timeout()` | 为当前任务的一段范围设置预算，在范围外捕获超时 |
| `task.cancel()` | 发出请求，随后还要等待任务并接收最终状态 |
| `async with` | 等待异步资源进入和退出，任务应在资源关闭前结束 |

`asyncio.CancelledError` 继承 `BaseException`，普通 `except Exception` 不捕获。清理通常放在 `finally`，捕获取消后一般继续传播，不把取消当作普通可重试失败。异常组和任务取消都不会自动回滚已发生的外部写入。

异步超时可能晚于指定时长结束，取消外层等待也不代表远端操作没有成功。重试要限定异常、次数和总预算，并先确认幂等性。

## 7. 批量任务的上限与清理

并发上限限制同时执行，队列容量限制积压，工作者数量限制任务对象规模。先为全部输入建立 Task、再用信号量等待，不会消除全部任务占用。保存全部结果时，还要计算结果内存。

给账号、目录、端口和业务数据安排隔离，结果保留输入编号。选择收集全部独立结果还是失败后取消相关任务；退出前接收异常、确认工作结束并释放自己拥有的资源。固定随机种子不固定调度，固定休眠不代替状态等待。
