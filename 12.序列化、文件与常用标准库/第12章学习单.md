# 第 12 章学习单：序列化、文件与常用标准库

## 1. 本章为什么要学

测试用例、配置、日志和报告最终都要经过文件、文本、字节或其他程序。会用一个读取函数还不够：必须知道编码、游标、记录边界、字段转换、时间口径和失败清理。

本章把运行时对象与外部表示连接起来，补齐后续 Python 测试应用与工具开发需要的数据与系统交互基础。先声明输入输出约定，再选择格式与工具，不把解析成功当成业务校验完成。

## 2. 前置知识

- 第 1～3 章：字符串、容器、可变性、函数接口与异常。
- 第 4～5 章：回调、缓存、迭代器、生成器与按需消费。
- 第 7 章：文件所有权、上下文管理、失败传播和关闭。
- 第 8 章：模块、解释器、运行入口和环境。
- 第 9～10 章：对象图、复制、共享与进程通信。
- 第 11 章：类型与运行时校验、独立预期、临时数据和替身。

不要求先掌握操作系统文件实现、Unicode 标准细节或完整网络协议。讲义会在需要时解释字节、码点、路径协议、JSON、CSV、时区和子进程接口。

## 3. 学习目标

能区分复制、序列化和文本编码，按明确规则读写数据，解释类型和身份是否保留。能使用文件游标和迭代控制消费，明确正常、失败和提前停止时的关闭责任。

能按具体任务选择路径、数据格式、正则和标准库，使用已知偏移统一时间，构造可验证的子进程调用。能为文件工具设计正常、边界、格式错误与失败清理检查，并保护不应被覆盖的旧报告。

## 4. 知识点清单

### 4.1 文本、字节与文件

- str、bytes、bytearray，码点、字节和显示字符的区别。
- encode、decode、UTF-8、错误策略、乱码与 BOM。
- open 目的、文本/二进制、读写能力、显式编码与换行。
- read、readline、readlines、tell、seek、truncate 与 EOF。
- 缓冲、flush、fsync、关闭与持久化边界。
- 逐行、分块、生成器暂停与资源清理。
- StringIO、BytesIO、Path、纯路径和当前工作目录。
- 目录枚举、路径拼接、检查与使用之间的变化。
- os、os.path、环境变量和路径协议。

### 4.2 数据格式与正则

- JSON 的 Python 映射、文本/流接口与 UTF-8 层次。
- 非字符串键、元组、特殊值、不支持对象与显式转换。
- 重复键、NaN、记录边界与逐行 JSONL。
- pickle 的共享、循环、导入环境和可信边界。
- JSON、pickle、CSV 的选择与约束。
- CSV 引号、字段内换行、表头与显式字段转换。
- re 的模式、转义、字符范围、入口、分组和替换。
- 匹配结果形态、惰性消费与回溯成本意识。

### 4.3 时间与常用标准库

- date、datetime、timedelta、ISO 文本和时间戳。
- naive、aware、UTC、转换与改标签的区别。
- 地区时区、数据来源、夏令时歧义与实际时长。
- 墙上时间、单调时钟与测试中的固定输入。
- collections 统计与分组，functools 配置与缓存。
- itertools 连续分组、上游共享和消费限制。
- random、secrets 与不同随机需求。

### 4.4 系统交互与报告

- subprocess 的程序、实参、输入输出、退出码、环境与目录。
- shell、捕获内存、超时、直接子进程和副作用边界。
- 临时目录、文件句柄与 Windows 关闭顺序。
- gzip、ZIP、命名成员与解压资源范围。
- argparse 的转换、选项、布尔开关与业务验证。
- 同目录临时写入、os.replace、失败清理和提交点。

## 7. 实验环境与记录方式

沿用项目 CPython 3.12.13 和标准库，不要求安装额外地区时区数据。示例使用临时目录、内存流、固定日期和明确偏移，不依赖用户文件、当前目录内容或机器本地时区。

实验 1～30 把 prediction 与 observation 分开。把整个占位字符串替换成实际 Python 值，保留原预测，差异在原因解释区复盘。每题紧随 `check_experiment(globals(), 编号)`，最后 `run_checks(globals())` 只作复查。

实验 31～34 实现逐行 JSONL 读取、CSV 用例加载、UTC 时间转换和 JSON 报告写入。检查器使用自己创建的临时数据，验证按需读取、类型与范围、源文件不变、关闭和失败后旧报告保留，不要求固定随机值或精确耗时。

pickle 仅恢复题目自己生成的可信数据；压缩包只读取已知成员；子进程只运行当前 Python 的固定代码，不执行 shell 拼接。故意观察失败时，记录实际异常，不把代码改成全部成功来作答。
