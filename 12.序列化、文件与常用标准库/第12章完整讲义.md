# 第 12 章完整讲义：序列化、文件与常用标准库

前十一章已经能解释对象、资源、并发和基础测试。本章把程序里的数据与文件、其他进程和外部表示连接起来：一份文本怎样变成字节，文件游标如何推进，结构化数据能保留哪些信息，时间和路径又应该怎样解释。

示例以 **CPython 3.12.13** 为验证基线，主线使用 Python 3.11 及以上语法与标准库。`python` 代码块都能保存为独立脚本运行；文件示例使用临时目录，日期示例使用固定值，不依赖当前日期或机器时区。实验不读取个人文件，不发起网络请求。

## 1. 运行时对象、编码与序列化

第 9 章的复制发生在运行时对象之间；**序列化**把数据状态变成可保存或传输的表示，**反序列化**再按相应规则重建数据。**编码**在本章主要指文本与字节之间的转换规则。它们不是同一个操作。

```text
Python 字典 ── JSON 序列化 ──→ JSON 文本 str
JSON 文本   ── UTF-8 编码 ──→ bytes
bytes       ── UTF-8 解码 ──→ JSON 文本 str
JSON 文本   ── JSON 解析 ───→ 新的 Python 数据
```

文件保存的是字节；文本文件接口会替你处理指定编码和换行。JSON 定义数据表示，UTF-8 定义这些文本如何成为字节，不能把“JSON 编码”与“UTF-8 编码”混成一个选择。

## 2. str、bytes 与长度的单位

`str` 表示 Unicode 文本。**Unicode** 为字符分配码点等标识；Python 字符串按码点组成序列，不承诺一个码点恰好等于屏幕上一个完整文字图形。`bytes` 是不可变字节序列，每个字节的数值范围是 0～255。

```python
text = "中A"
data = text.encode("utf-8")
print(len(text), len(data))  # 2 4
print(type(text[0]).__name__, data[0])  # str 228
print(data.decode("utf-8") == text)  # True
```

字符串下标得到文本，bytes 下标得到整数。UTF-8 对不同码点使用不同字节数量，所以字符数不是传输字节数。组合字符、表情等还可能由多个码点构成，不能把 `len(text)` 直接当作用户看到的字数。

`bytearray` 是可变字节序列，适合需要修改二进制缓冲的场景；它不是另一种文本编码。

## 3. encode 与 decode 的方向

`text.encode(encoding)` 把文本变成字节，`data.decode(encoding)` 按指定规则把字节解释成文本。需要知道数据来源的编码，不能靠函数名自动猜出。

```python
text = "中文"
data = text.encode("utf-8")
wrong = data.decode("latin-1")
print(wrong == text)  # False
print(wrong.encode("latin-1").decode("utf-8") == text)  # True
```

本例的错误解释没有丢失字节信息，因此能沿原步骤反向恢复；不能据此宣称任何乱码都可恢复。若已经忽略字节、替换字符，或拿不到原编码关系，原信息可能已丢失。

UTF-8 能表示 Unicode 文本，不表示任意二进制文件都是合法 UTF-8。图片、压缩包等应先按二进制处理，不能无条件 decode。

## 4. 编码错误、替换策略与 BOM

默认严格模式在不合法数据上抛出编码或解码异常。`errors="ignore"` 丢弃无法处理的部分，`errors="replace"` 用替代内容继续；它们改变了数据，不能作为测试数据损坏时的默认修复。

```python
data = b"A\xffB"
try:
    data.decode("utf-8")
except UnicodeDecodeError:
    print("严格解码失败")
print(data.decode("utf-8", errors="ignore"))  # AB
print(data.decode("utf-8", errors="replace") == "A\ufffdB")  # True
```

**BOM** 是部分文本开头使用的字节顺序标记。在 UTF-8 文件中，它还可能作为编码签名出现。`utf-8-sig` 读取时可处理开头的 UTF-8 BOM，写入时会添加相应标记；普通 `utf-8` 不会因此自动去掉解码后的开头字符。处理带 BOM 的 CSV 表头时，这个差异可能影响字段名。

## 5. open 的模式与编码选择

先按打开目的区分：`r` 读取已有文件，`w` 创建或截断写入，`a` 追加写入，`x` 仅在不存在时创建。再按接口区分文本 `t` 与二进制 `b`；`+` 表示同时允许读写，是附加能力，不是第五种互斥目的。

| 模式 | 核心行为 |
|---|---|
| `r` / `rb` | 文件必须存在，文本读取或字节读取 |
| `w` / `wb` | 打开时就截断已有内容，或创建新文件 |
| `a` / `ab` | 写入追加到末尾；不会自动添加换行 |
| `x` / `xb` | 已存在则抛出 FileExistsError |
| `r+` | 读写已有文件，不自动截断 |

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "report.txt"
    path.write_text("old report", encoding="utf-8")
    with path.open("w", encoding="utf-8") as stream:
        print(path.stat().st_size)  # 0，尚未 write 也已截断
        stream.write("new report")
    print(path.read_text(encoding="utf-8"))  # new report
```

文件不存在、权限不足等属于实际 I/O 异常。文本编码建议明确写出，默认值可能受 Python 版本、UTF-8 模式和系统环境影响。二进制模式传入或返回字节，不再同时指定文本 encoding。

示例的 `path.stat().st_size` 读取文件元数据中的字节大小，用于观察截断，不是文本字符计数。

## 6. 文件游标、读取与定位

**文件游标**表示下一次操作从哪里开始。`read(size)` 读取指定规模的数据，`readline()` 读取一行，`readlines()` 收集剩余行。读到末尾通常得到空字符串或空字节，而不是文件自动从头开始。

下面的 BytesIO 是在内存中提供文件式接口的字节流，不创建磁盘文件；第 10 节会继续比较两类内存流。

```python
import io

stream = io.BytesIO(b"ABCDE")
print(stream.read(2))  # b'AB'
position = stream.tell()
print(position)  # 2
print(stream.read())  # b'CDE'
print(stream.read())  # b''
stream.seek(position)
print(stream.read(1))  # b'C'
stream.close()
```

二进制定位通常按字节偏移理解。文本文件还经过解码和换行处理，`tell()` 的结果应视为可用于恢复位置的标记，不能当作任意字符下标；优先保存 tell 的结果再传回 seek，或使用明确支持的回到开头操作，不在 UTF-8 字符内部随意跳转。

`r+` 覆盖前部内容不自动删除原来后缀。要截短文件需明确 `truncate()`，或选择符合需求的写入方案。

## 7. 文本换行与读写数量

文本 `read(size)` 通常按解码后的字符数读取，字节读取则按字节数。默认 `newline=None` 可在读取时把常见的 `\r\n`、`\r` 统一为 `\n`；指定 `newline=""` 可识别换行但保留原终止符。

`TextIOWrapper` 给底层字节流加上解码与换行处理，下面用同一份字节观察两个文本视图。

```python
import io

data = b"A\r\nB\rC\n"
with io.TextIOWrapper(io.BytesIO(data), encoding="utf-8", newline=None) as stream:
    print(stream.read() == "A\nB\nC\n")  # True
with io.TextIOWrapper(io.BytesIO(data), encoding="utf-8", newline="") as stream:
    print(stream.read() == "A\r\nB\rC\n")  # True
```

`write()` 不自动补换行，返回的数量也按接口单位解释。读取行后直接 `.strip()` 会连业务空白一起删除；只想去换行时应明确去除终止符的规则，不能随意改变字段内容。CSV 还可能在引号内包含换行，需要交给对应解析器。

## 8. 缓冲、flush、关闭与持久化

**缓冲**是先在内存中聚合数据再传给下层，以减少频繁小操作的成本。write 返回不等于数据已永久落到物理介质。flush 把 Python 侧缓冲向下交付，关闭通常会尝试刷新并释放资源；操作仍可能失败。

`os.fsync(stream.fileno())` 可请求同步文件相关的系统缓冲，但系统、文件系统和目录元数据仍有各自保证。flush、文件替换的原子可见性、断电后的持久化是不同性质，不能合并成“调用一个方法就永远不会丢数据”。

`fileno()` 取得底层文件描述符，也就是运行时用于关联某个已打开系统文件资源的编号；内存流不一定提供这种系统资源。

使用第 7 章的 `with` 表达确定的关闭范围。需要提交完整报告时，第 39 节会介绍先写临时文件再替换，避免一开始就用 w 清空旧报告。

## 9. 逐行、分块与大文件处理

直接遍历文本文件可以逐行消费；二进制输入可按固定大小分块，避免一次读入全部内容。**流式处理**强调随消费推进，而不是预先保存全部输入和结果。

下面的 StringIO 是内存文本流，提供与文本文件相似的逐行接口；它的输入本身已经在内存中，当前只用来观察消费规则。

```python
import io

with io.StringIO("ok\nfailed\nok\n") as stream:
    passed = sum(1 for line in stream if line.rstrip("\n") == "ok")
print(passed)  # 2

with io.BytesIO(b"abcdefg") as stream:
    chunks = []
    while True:
        chunk = stream.read(3)
        if not chunk:
            break
        chunks.append(len(chunk))
print(chunks)  # [3, 3, 1]
```

示例只收集块长度。真实程序若把所有块再追加到列表，最终空间仍随文件增长；单行也可能很长，逐行不等于任意输入下固定内存。按字节分块解码时可能切开多字节字符，应使用文本文件层或增量解码器维护跨块状态。

生成器内部打开文件时，函数返回生成器并不表示读取已开始；部分消费后仍可能持有文件。耗尽、异常与显式 close 都应结束自己的资源范围，不能依赖垃圾回收碰巧关闭。

## 10. StringIO、BytesIO 与接口测试

`StringIO` 提供内存文本流，`BytesIO` 提供内存二进制流。它们让测试不用真实磁盘也能观察读取、写入和游标。内存流不是文件编码的自动证明，解码层仍需要另外测试。

```python
import io

with io.StringIO() as stream:
    stream.write("A\n")
    stream.write("B")
    print(stream.getvalue() == "A\nB")  # True
    print(stream.read() == "")  # True，游标仍在末尾
    stream.seek(0)
    print(stream.readline() == "A\n")  # True
```

getvalue 取得全部内容，不依赖当前读取位置；read 从当前游标继续。把两者混用，容易在测试里误以为真实文件读取也会忽略当前位置。

## 11. pathlib 的路径对象与文件操作

`Path` 表达当前平台的路径并提供文件操作，`PureWindowsPath`、`PurePosixPath` 主要处理相应路径语法，不访问真实文件系统。路径对象建立不等于目录或文件已经存在。

```python
from pathlib import Path, PureWindowsPath
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    reports = Path(directory) / "reports"
    reports.mkdir()
    path = reports / "result.json"
    path.write_text("{}", encoding="utf-8")
    print(path.name, path.suffix, path.stem)  # result.json .json result
    print(path.is_file(), path.parent == reports)  # True True
print(PureWindowsPath(r"C:\reports\result.json").name)  # result.json
```

`/` 对路径对象是拼接协议，不是字符串除法。字符串中的反斜线还受 Python 转义规则影响，Windows 路径可合理使用原始字符串或正斜线；原始字符串也不能以奇数个末尾反斜线结束。

## 12. 相对路径、目录遍历与路径边界

相对路径按当前工作目录解释，不自动相对于源文件。Notebook、终端和测试运行器的工作目录不同，可能解释出不同目标。需要时从明确输入目录出发拼接；不要为了读取一个文件随意改变整个进程的工作目录。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    root = Path(directory)
    for name in ["b.txt", "a.txt", "data.json"]:
        (root / name).write_text("x", encoding="utf-8")
    print(sorted(path.name for path in root.glob("*.txt")))  # ['a.txt', 'b.txt']
```

glob、rglob 和目录枚举不应当作天然排序结果。`exists()` 后再打开，也不能保证中间没人删除或替换；按所需操作处理异常，创建时用 x 可表达“必须不存在”。

拼接绝对路径可能覆盖原来的起点，`..` 和符号链接也会影响实际目标。校验允许目录时要区分词法路径与解析后的路径；`resolve()`、`relative_to()` 可辅助判断，但并发替换与平台权限还涉及额外约束，不能只做字符串前缀比较就宣称任意文件操作安全。

## 13. os、os.path 与环境变量

`os` 提供与操作系统环境有关的接口，`os.path` 提供当前平台的路径函数。Path 可通过路径协议交给许多接受文件路径的标准库函数；`os.fspath()` 取得相应文件系统路径表示。

```python
import os
from pathlib import Path

path = Path("reports") / "result.json"
print(os.path.basename(os.fspath(path)))  # result.json
environment = os.environ.copy()
environment["CH12_MODE"] = "brief"
print(environment["CH12_MODE"])  # brief
```

这里修改的是副本，不改变进程的真实环境。`os.environ` 的值是字符串，读取到 `"False"` 不等于布尔假。给子进程传 env 时提供的是它的环境映射，直接只传一个键可能丢失必要的系统变量，通常从副本调整。

## 14. JSON 的值与 Python 类型映射

**JSON** 是一种文本数据格式，定义对象、数组、字符串、数值、布尔值和 null。常规 Python 映射分别是 dict、list、str、int/float、bool 和 None；格式中的 object 不是“任意 Python 对象”的意思。

```python
import json

record = {"name": "中文", "passed": True, "note": None, "scores": [1, 2]}
text = json.dumps(record, ensure_ascii=False)
print(type(text).__name__)  # str
print(json.loads(text) == record)  # True
print("中文" in text)  # True
```

`dumps()` 返回 JSON 文本，`loads()` 解析数据表示；末尾的 s 可帮助记忆字符串接口。`ensure_ascii=False` 保留可直接阅读的非 ASCII 文本，不负责决定文件编码。保存为 UTF-8 仍需文本文件接口或显式 encode。

JSON 能交换数据，但解析成功不等于符合业务字段与类型；第 11 章的运行时校验仍然需要。

## 15. JSON 的键、元组与特殊数值

JSON 对象键是字符串，Python 字典的某些非字符串键会被转换；元组会序列化成数组，读取后得到列表。共享引用、身份和任意循环不属于 JSON 的普通数据模型。

```python
import json

original = {1: ("A", "B")}
restored = json.loads(json.dumps(original))
print(restored)  # {'1': ['A', 'B']}
print(restored == original)  # False
try:
    json.dumps({"value": float("nan")}, allow_nan=False)
except ValueError:
    print("拒绝非标准数值")
```

Python 的 json 默认允许 NaN、Infinity 等扩展数值，严格交换时编码可设置 `allow_nan=False`。读取时该开关不适用，应通过 `parse_constant` 等明确拒绝策略处理这些常量。对象重复键默认通常保留最后一个值；若接口禁止重复键，需要通过 `object_pairs_hook` 等另行验证。

不能用“JSON 往返一次”代替任意数据的深拷贝。它既可能改变类型，也不保留普通 Python 对象图的全部语义。

## 16. JSON 不支持的数据与显式转换

集合、bytes、日期对象和一般自定义实例没有默认通用 JSON 表示。需要先确定交换约定，再选择字段、格式和恢复规则。

这里先用 datetime 表示一个固定日期时刻，以 timezone.utc 明确其 UTC 时间参考，再转成约定文本。第 26～28 节会展开时间字段、偏移与地区规则。

```python
import json
from datetime import datetime, timezone

created = datetime(2024, 1, 2, 3, 4, tzinfo=timezone.utc)
record = {"created": created.isoformat(), "tags": sorted({"slow", "api"})}
text = json.dumps(record)
print(json.loads(text)["created"])  # 2024-01-02T03:04:00+00:00
try:
    json.dumps({"raw": b"abc"})
except TypeError:
    print("需要明确字节的表示规则")
```

这里的 `isoformat()` 生成约定格式文本，第 26 节会解释时间对象。集合转列表还要决定顺序，日期转文本还要决定时区与精度，不能只用 `default=str` 掩盖所有不支持的数据，否则读取端可能不知道如何还原。

## 17. dump、load 与多条记录的边界

`dump(obj, stream)` 写入文本流，`load(stream)` 读取并解析；流的打开、编码和关闭由拥有者负责。JSON 不是自带多记录边界的协议，连续写两份对象不自动形成合法的一份 JSON。

```python
import io
import json

with io.StringIO() as stream:
    json.dump({"id": 1}, stream)
    json.dump({"id": 2}, stream)
    stream.seek(0)
    try:
        json.load(stream)
    except json.JSONDecodeError:
        print("两份相邻对象不是一份完整 JSON")
```

如果需求是记录集合，可以写一个数组；如果需要逐条追加与逐行处理，可选 **JSONL**，即约定每个物理行包含一份 JSON 文本，记录之间用换行分隔。此时每行仍应完整解析并验证结构，不能把任意多行排版 JSON 当作 JSONL。

## 18. pickle 的能力与可信数据边界

`pickle` 是面向 Python 对象的序列化机制，dumps 返回 bytes，loads 恢复对象。一次处理可以保留许多共享与循环关系，但并非任意连接、线程锁或外部资源都可重建。

```python
import pickle

shared = [1]
original = [shared, shared]
original.append(original)
data = pickle.dumps(original)
restored = pickle.loads(data)  # 只恢复本脚本刚生成的可信数据
print(isinstance(data, bytes))  # True
print(restored[0] is restored[1])  # True
print(restored[2] is restored)  # True
```

pickle 恢复过程可能执行代码，不能用于来自不可信文件、请求或可能被篡改的数据。这里不构造任何恶意载荷。它也不是加密或完整性保护；签名等机制另有职责，不能因文件扩展名看起来正确就信任内容。

普通函数与类常通过模块和名字定位，读取环境需满足相应导入与版本条件。这正是第 10 章标准进程池对可导入入口和可传输数据的要求之一。

## 19. JSON、pickle 与 CSV 的选择

选择前先确定跨语言需求、字段结构、可读性、身份关系和可信边界，不只比较能不能调用 dumps。

| 格式 | 常见用途 | 主要边界 |
|---|---|---|
| JSON | 结构化交换、配置和接口数据 | 有限数据模型，仍需字段校验 |
| pickle | 可信环境中的 Python 状态保存 | 恢复可执行代码，依赖 Python 环境 |
| CSV | 表格行与字段交换 | 字段主要是文本，类型与缺失规则另定 |

序列化后的体积、版本兼容和数据迁移也要验证。任何解析器面对超大输入都可能消耗资源；解析成功、内容可信与业务正确是不同判断。

## 20. CSV 的引号、分隔符与换行

**CSV** 表示分隔字段的表格文本，字段中可能包含分隔符、引号甚至换行。直接 `split(",")` 不能正确处理这些情况。

```python
import csv
import io

rows = [["case_id", "note"], ["C-1", 'comma, quote "yes"'], ["C-2", "line1\nline2"]]
with io.StringIO(newline="") as stream:
    writer = csv.writer(stream)
    writer.writerows(rows)
    stream.seek(0)
    restored = list(csv.reader(stream))
print(restored == rows)  # True
```

实际文件通常用 `open(..., newline="", encoding="utf-8")`，让 csv 自己管理换行，避免与文本层重复处理，尤其注意 Windows。writer 的引用与转义规则负责字段边界，不是把每个逗号随便替换掉。

普通 reader 返回文本字段，不自动把 `"False"` 转为布尔值或把数值文本转换为整数。writer 对 None 等值的默认表示也未必可逆，字段缺失和空字符串需要独立约定。

## 21. DictReader、表头与字段校验

`DictReader` 按表头把每行组织成字典，便于按字段名访问；它不自动验证表头唯一、必填列完整或数据类型正确。

```python
import csv
import io

with io.StringIO("case_id,enabled,timeout\nC-1,false,3\n", newline="") as stream:
    row = next(csv.DictReader(stream))
print(row["enabled"], type(row["timeout"]).__name__)  # false str
print(bool(row["enabled"]))  # True，非空文本不是布尔假
```

额外字段默认可能放到特殊键下，缺失字段可能得到 None，重复表头可能覆盖信息。加载测试数据时，先检查原始 fieldnames，再检查每行列数、唯一标识和显式转换规则。带 BOM 的首列表头可按输入约定选择 utf-8-sig。

## 22. re 的模式与原始字符串

标准库 `re` 按**正则表达式**模式匹配文本。`.` 常匹配一个非换行字符，`[]` 表示字符集合，`*`、`+`、`?` 和 `{m,n}` 控制重复，`|` 表示选择。它不是简单的通配字符串替换。

本例的 fullmatch 要求整个目标字符串满足模式，不是只在某处找到一段合法片段。

```python
import re

pattern = re.compile(r"C-[0-9]{2}")
print(pattern.fullmatch("C-12") is not None)  # True
print(pattern.fullmatch("C-1") is not None)  # False
```

这里 `[0-9]` 选择 ASCII 数字，`{2}` 要求重复两次。原始字符串 `r"..."` 减少 Python 字符串层对反斜线的处理，但正则引擎仍会解释模式转义；r 前缀不等于完全取消转义。

正则适合局部格式与提取，不应替代 JSON、CSV 等已有结构化解析器。

## 23. match、search、fullmatch 与字符范围

`match` 从起点尝试，`search` 寻找某处匹配，`fullmatch` 要求整个目标满足模式。结果是匹配对象或 None，取得前要确认是否存在。

```python
import re

text = "prefix C-12 suffix"
print(re.match(r"C-[0-9]+", text) is None)  # True
print(re.search(r"C-[0-9]+", text).group())  # C-12
print(re.fullmatch(r"C-[0-9]+", text) is None)  # True
print(re.fullmatch(r"\d+", "１２") is not None)  # True
print(re.fullmatch(r"\d+", "１２", flags=re.ASCII) is None)  # True
```

`\d`、`\w` 等在普通 Unicode 文本模式下不只表示 ASCII；若协议只允许 ASCII，要明确字符集或相应标志。`^` 与 `$` 的边界还受末尾换行、多行标志影响，校验完整字段时优先明确 fullmatch 的语义，不把 match 当作完整校验。

## 24. 捕获分组、findall 与 finditer

括号可以保存匹配片段，称为**捕获分组**。`(?P<name>...)` 给分组命名，`(?:...)` 只组织结构而不捕获。group、groups 和 groupdict 提取相应内容。

```python
import re

text = "C-12 C-34"
pattern = re.compile(r"(?P<prefix>C)-(?P<number>[0-9]+)")
match = pattern.search(text)
print(match.groupdict())  # {'prefix': 'C', 'number': '12'}
print(pattern.findall(text))  # [('C', '12'), ('C', '34')]
print([item.group() for item in pattern.finditer(text)])  # ['C-12', 'C-34']
```

findall 的结果形态会受捕获组数量影响；finditer 逐个给出匹配对象，适合需要位置与完整分组的处理。结果是否流式还要看后续有没有全部转成列表。

复杂重复与歧义可能使回溯成本激增，处理外部输入要控制规模并选择简单模式。本章不运行可能长时间卡住的病态模式，也不把正则长度直接当作运行成本。

## 25. sub、escape 与替换规则

`sub` 按模式替换匹配；外部文本要按字面意义进入模式时，用 `re.escape()` 转义其中的模式字符。模式字符串与替换字符串有不同规则，不能把 escape 当作所有场合的万能处理。

```python
import re

literal = "a+b"
text = "a+b and aaab"
print(re.sub(re.escape(literal), "X", text))  # X and aaab
print(re.sub(r"C-([0-9]+)", r"ID-\1", "C-12"))  # ID-12
```

替换中的 `\1` 引用捕获组。若替换内容来自任意文本且要原样使用，可以提供返回该文本的替换函数，避免把其中反斜线误当分组引用。**贪婪匹配**通常尽可能多取，非贪婪形式优先少取；这仍是按模式规则搜索，不保证复杂格式都能可靠解析。

## 26. date、datetime、timedelta 与时间戳

`date` 表达日期，`datetime` 表达日期与时刻字段，`timedelta` 表达时长差量。**时间戳**通常是相对于约定起点的数值；Python 常用 POSIX 时间戳以秒表示，与毫秒不能混用。

```python
from datetime import datetime, timedelta, timezone

start = datetime(2024, 1, 1, tzinfo=timezone.utc)
later = start + timedelta(seconds=90)
print((later - start).total_seconds())  # 90.0
print(start.isoformat())  # 2024-01-01T00:00:00+00:00
print(datetime.fromtimestamp(start.timestamp(), timezone.utc) == start)  # True
```

`isoformat` 输出标准化形式文本；`strftime` 按指定格式输出，`strptime` 按格式解析，`fromisoformat` 处理其支持的 ISO 形式。解析成功不等于已知道时区；日期文本也可能缺少时刻信息，需要接口说明。

## 27. naive、aware 与 UTC 转换

**naive** 时间缺少可用的时区偏移信息，**aware** 时间能结合 tzinfo 和 utcoffset 定位相应时刻。UTC 是统一时间参考。naive 并不自动表示 UTC，系统本地时区也不是数据内容天然的一部分。

```python
from datetime import datetime, timedelta, timezone

local = datetime(2024, 1, 1, 8, tzinfo=timezone(timedelta(hours=8)))
converted = local.astimezone(timezone.utc)
relabelled = local.replace(tzinfo=timezone.utc)
print(converted.isoformat())  # 2024-01-01T00:00:00+00:00
print(relabelled.isoformat())  # 2024-01-01T08:00:00+00:00
print(converted == local)  # True
```

astimezone 保持时刻并转换字段；replace 这里只改时区标签，不能当作一般转换。naive 与 aware 的大小比较和相减通常不被允许，相等比较则可能直接为假；别从它们没有抛错就推断已经正确对齐时区。

## 28. 固定偏移、地区时区与夏令时

`timezone(timedelta(hours=8))` 表示固定偏移，不包含某个地区的全部历史变化。`zoneinfo.ZoneInfo` 使用 IANA 地区时区数据库，例如地区进入或退出夏令时的规则；Windows 等环境可能需要另外提供 tzdata 数据，不能默认所有机器都有。

**夏令时**会让当地时钟在某些日期向前或向后调整，所以某些当地时间可能不存在或出现两次。`fold` 可帮助区分重复的当地时间，但简单附加时区不等于已经完整验证任意当地输入。

例如时钟从 01:59 回拨到 01:00，同一天的 01:30 就可能出现两遍。只给当地日期与 01:30，仍不足以唯一选择真实时刻；这不是单靠调整显示格式能消除的问题。

```python
from datetime import datetime, timedelta, timezone

before = datetime(2024, 1, 1, 8, tzinfo=timezone(timedelta(hours=8)))
after = datetime(2024, 1, 1, 9, tzinfo=timezone(timedelta(hours=9)))
print(before.astimezone(timezone.utc) == after.astimezone(timezone.utc))  # True
```

这个固定偏移例子只说明不同当地字段可能是同一时刻，不模拟某地区夏令时。需要地区规则时，明确时区名、数据版本和缺失数据处理。datetime 对同一个 tzinfo 的运算还有墙上时间语义；跨夏令时要求实际经过秒数时，先对齐 UTC 再计算，不机械把当地一天当作总是 24 小时。

## 29. 时间戳、当前时间与耗时测量

带时区的 `datetime.now(timezone.utc)` 可取得当前 UTC 时间，`fromtimestamp(value, timezone.utc)` 可明确解释时间戳。不要把机器本地时区隐式带入跨系统记录，也别把当前时间写成测试的固定答案。

系统墙上时间可能被校准；测量一段操作的耗时通常用 `time.perf_counter()` 或适合的单调时钟。**单调**表示不会因墙上时钟调整而倒退，不意味着能直接转成某个日历日期。

```python
import time

before = time.perf_counter()
sum(range(100))
elapsed = time.perf_counter() - before
print(elapsed >= 0)  # True，不固定具体秒数
```

第 11 章的 timeit 管理重复计时，cProfile 定位调用成本；本节区分它们依赖的时间口径。Unix 时间戳的秒、接口使用的毫秒和业务当地日期，必须在字段约定中说明。

## 30. collections 用于记录汇总

第 2 章已经讲 Counter、defaultdict、deque 等容器工具。本章把它们用到数据处理：Counter 统计频次，defaultdict 为缺失分组创建容器，deque 适合两端消费。

```python
from collections import Counter, defaultdict, deque

records = [("api", "passed"), ("ui", "failed"), ("api", "passed")]
counts = Counter(status for _, status in records)
groups = defaultdict(list)
for kind, status in records:
    groups[kind].append(status)
pending = deque(["A", "B"])
print(counts["passed"], counts["missing"])  # 2 0
print(groups["api"])  # ['passed', 'passed']
print(pending.popleft())  # A
```

defaultdict 的 `mapping[key]` 缺失访问可能创建条目，get 不会因此自动调用工厂。统计不等于保留所有原始数据；若只需要频次，可以边读边更新 Counter，避免先保存全部记录。

## 31. functools 用于配置、包装与缓存

第 4 章的 partial 预先绑定调用信息，wraps 保留被包装函数的常用元信息，lru_cache 根据可哈希实参缓存结果。它们适合减少重复规则，但不能改变函数副作用和资源所有权。

```python
from functools import lru_cache, partial

def render(case_id, *, prefix):
    return prefix + case_id

format_case = partial(render, prefix="case:")
calls = []

@lru_cache(maxsize=2)
def parse_count(text):
    calls.append(text)
    return int(text)

print(format_case("A"))  # case:A
print(parse_count("3"), parse_count("3"), len(calls))  # 3 3 1
parse_count.cache_clear()
```

依赖文件内容、时间或外部状态的函数，不能只按文件名缓存就默认结果永远有效。缓存还会持有实参和结果，第 9 章的生命周期分析仍然适用。选择缓存前先说明失效和容量。

## 32. itertools 与连续分组

chain 连接多个可迭代来源，islice 截取有限消费范围，groupby 把连续相同键分到一组。它们按需工作，但某些组合会共享上游状态。

```python
from itertools import chain, groupby, islice

values = list(islice(chain([1, 2], [3, 4]), 3))
print(values)  # [1, 2, 3]
groups = [(key, len(list(group))) for key, group in groupby("AABA")]
print(groups)  # [('A', 2), ('B', 1), ('A', 1)]
```

groupby 不是无条件汇总全部同值数据：两段 A 仍是不同组。需要按键全局分组时，可先排序再 groupby，或用 defaultdict 按输入组织；排序本身需要时间和存储。当前组还关联同一上游迭代器，不应留着未消费分组又继续推进外层，再假定旧组独立保存。

## 33. random、secrets 与字符串比较

`random` 主要用于模拟和可复现数据，不适合生成安全凭证。`secrets` 使用适合安全随机需求的来源，提供 token_bytes、token_hex、token_urlsafe 等表示接口。它们也不能替代账号权限和生命周期设计。

```python
import random
import secrets

left = random.Random(12)
right = random.Random(12)
print([left.randrange(10) for _ in range(4)] ==
      [right.randrange(10) for _ in range(4)])  # True
token = secrets.token_hex(16)
print(len(token), all(char in "0123456789abcdef" for char in token))  # 32 True
print(secrets.compare_digest(b"same", b"same"))  # True
```

例子不输出生成的 token。token_hex 的实参是随机字节数量，不是最终字符数。compare_digest 用于减少内容相关比较时序泄漏等问题，有输入类型限制；它不是加密，也不意味着整个认证流程就安全。测试安全随机输出时检查接口性质，不要求记住某个随机值。

## 34. subprocess 的程序与实参列表

`subprocess` 启动另一个程序；它与第 10 章的多进程计算模型有关，但重点是外部命令、输入输出和退出结果。`run()` 适合启动并等待一项有限操作。

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-X", "utf8", "-c", "import sys; print(sys.argv[1])", "a b; echo data"],
    capture_output=True, text=True, encoding="utf-8", check=True, timeout=10,
)
print(result.stdout.strip())  # a b; echo data
```

`sys.executable` 是当前解释器路径，列表中的每项是一个实参，带空格和分号的内容在这个示例中仍是一项普通数据。默认 shell=False，不启动 shell 去解释这段字符串。

不要把用户输入拼成 shell 命令。shell=True 时会增加另一层解释规则；Windows 批处理文件等目标还有自己的处理特性，因此也不能把 shell=False 简化为任意程序调用都绝对安全。明确可执行程序、允许实参和运行环境，通常比拼接一长串命令更容易验证。

## 35. 子进程输入、退出码、输出与超时

`CompletedProcess` 保存 args、returncode 和捕获输出。`check=True` 遇非零退出抛 CalledProcessError，标准错误流有文本却不必然表示失败；有的程序把普通诊断写到 stderr。应按程序约定解读退出码和内容。

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-X", "utf8", "-c", "import sys; print(sys.stdin.read().upper())"],
    input="hello", capture_output=True, text=True, encoding="utf-8", check=True, timeout=10,
)
print(result.returncode, result.stdout.strip())  # 0 HELLO
try:
    subprocess.run([sys.executable, "-c", "raise SystemExit(3)"], check=True, timeout=10)
except subprocess.CalledProcessError as error:
    print(error.returncode)  # 3
```

text=True 时按相应编码处理文本，默认二进制接口则用 bytes。`cwd` 指定子进程目录，不改变调用方目录；env 可以基于父环境副本调整。

run 等待超时时会处理自己启动的直接子进程并抛 TimeoutExpired，但不能据此承诺任意后代进程全部停止、外部副作用回滚，或启动过程有严格实时截止。capture_output 将输出收集到内存，海量输出需要设计流式消费；手工 Popen 后只 wait、不消费装满的管道，还可能形成等待问题。

## 36. 临时目录与 Windows 文件句柄

`TemporaryDirectory` 创建唯一临时目录，退出上下文后清理；`TemporaryFile`、`NamedTemporaryFile` 提供临时文件接口。不要用先猜名字再创建的方式竞争共享路径。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    root = Path(directory)
    path = root / "input.txt"
    path.write_text("ready", encoding="utf-8")
    print(path.read_text(encoding="utf-8"))  # ready
print(root.exists())  # False
```

Windows 下打开中的文件可能影响再次打开、删除或替换；需要把路径交给其他程序时，应明确先关闭自己的文件句柄。使用 NamedTemporaryFile 时要按当前版本和删除选项处理，不能照搬只在另一个系统上碰巧成功的写法。清理失败应保留原始错误证据，而不是无条件忽略。

## 37. gzip、zipfile 与压缩数据

gzip 适合压缩一个数据流，ZIP 可组织多个命名成员。压缩不是加密，也不能从压缩体积直接推断解压后占用。gzip 头部可能含时间等信息，不把每次输出字节完全相同当作默认承诺。

```python
import gzip
import io
import zipfile

data = "report 中文".encode("utf-8")
compressed = gzip.compress(data)
print(gzip.decompress(compressed) == data)  # True
with io.BytesIO() as buffer:
    with zipfile.ZipFile(buffer, "w", compression=zipfile.ZIP_DEFLATED) as archive:
        archive.writestr("reports/result.txt", data)
    buffer.seek(0)
    with zipfile.ZipFile(buffer) as archive:
        print(archive.namelist())  # ['reports/result.txt']
        print(archive.read("reports/result.txt") == data)  # True
```

这里按已知成员读取，没有向真实目录提取外来压缩包。处理外部包时还要确认允许成员、目标路径、链接与体积上限，不能因为扩展名是 zip 就无条件解压。库的默认处理并不替代具体任务的文件与资源范围约定。

## 38. argparse 的命令行输入与校验

`argparse` 把命令行文本按接口转换为配置。位置实参按位置提供，选项常用 `--name` 指定；默认值、type、choices 和 action 各有不同职责。

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("input")
parser.add_argument("--limit", type=int, default=10)
parser.add_argument("--format", choices=["json", "csv"], default="json")
parser.add_argument("--verbose", action="store_true")
args = parser.parse_args(["cases.csv", "--limit", "3", "--verbose"])
print(args.input, args.limit, args.format, args.verbose)  # cases.csv 3 json True
```

为了可重复，示例显式传入列表，不读取 Notebook 或外层工具的 sys.argv；真实脚本入口可用 parse_args() 读取实际实参。`type=int` 只转换整数，不自动限制必须为正；需要额外验证或自定义转换函数。

`type=bool` 不适合解析文本真假，因为 bool("False") 为真。布尔开关通常用 store_true、store_false 或合适的布尔选项接口。无效输入通常打印用法并以 SystemExit 结束，测试时应接收退出状态而不是让整个内核退出。

## 39. 报告写入失败与同目录替换

直接用 w 打开正式报告会先清空旧内容。若随后 JSON 序列化或写入失败，旧报告已经失去。常见做法是先在同目录准备临时文件，完整写入并关闭，再通过 os.replace 切换目标。

```python
import json
import os
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory

with TemporaryDirectory() as directory:
    destination = Path(directory) / "report.json"
    destination.write_text('{"version": 1}', encoding="utf-8")
    pending = None
    try:
        with NamedTemporaryFile("w", encoding="utf-8", dir=directory, delete=False) as stream:
            pending = Path(stream.name)
            json.dump({"version": 2}, stream, allow_nan=False)
        os.replace(pending, destination)
    finally:
        if pending is not None:
            pending.unlink(missing_ok=True)
    print(json.loads(destination.read_text(encoding="utf-8")))  # {'version': 2}
```

同目录可避免跨文件系统移动的问题，先关闭临时文件也适应 Windows 句柄限制。序列化、写入或替换失败时，应清理自己的临时文件并保留旧目标；替换完成是提交点。还要单独约定并发写入者、权限和持久化要求。

os.replace 成功的替换可见性与断电持久性不是同一承诺；临时方案也不自动实现多文件事务。这一层次的区分与第 7、10 章的资源和并发约束一致。

## 40. 测试数据与报告工具的完整处理过程

一项小工具可以按顺序声明：输入路径与编码、每条记录的边界、字段类型和缺失规则、转换与汇总方式、时间口径、输出格式、失败结果与清理责任。不要先把各种标准库堆在一起，再猜这些约定。

例如 CSV 用例加载需要真实处理引号和换行，把 enabled 文本按明确集合转为 bool，再验证 timeout 数值范围；JSONL 处理需要逐行解析、记录失败行号，并在停止迭代时关闭文件。报告写入应在失败时保护旧结果，测试覆盖正常、空输入、错误数据和失败清理。

第 13 章继续学习测试设计依据，第 14 章组织框架、数据和 fixture，第 15 章连接接口与页面，第 16 章交付工具与执行流程。本章补齐数据和系统交互基础，不提前假设已有数据库或服务环境。
