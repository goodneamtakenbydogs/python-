# 第 1 章参考回答：Python 基础语法与对象模型

这份文件与《第 1 章面试题》逐题对应。参考回答展示的是组织思路，不是唯一话术，也不建议逐字背诵。面试中应先给一句话结论，再根据追问补充原因和例子。

## 一、基础概念题

### 第 1 题：动态类型与强类型

**一句话结论：**静态/动态关注类型何时确定和检查，强/弱关注隐式转换与绕过类型规则的宽松程度；它们是两个维度，所以 Python 可以同时是动态类型和较强类型。

```python
value = 10
value = "ten"       # 合法：名字重新指向字符串对象

# "10" + 2         # TypeError：不会擅自把其中一方转换类型
```

这两个术语观察的是不同维度，因此并不矛盾。常见错误是把“动态类型”说成对象的类型会随意变化；更准确的说法是名字的绑定可以变化，对象本身有确定的类型。

类型推断不等于动态类型。Rust 的 `let value = 10`、Go 的 `value := 10`、Java 的 `var value = 10` 虽然省略了显式类型名称，但编译器已经推断并静态约束结果，后续不能把字符串赋给该名字。

Python 允许 `1 + 2.5`，是因为语言明确支持整数和浮点数的兼容数值运算；允许某些定义清楚的类型组合，不等于可以任意转换不兼容类型。

JavaScript 示例：

```javascript
1 + "2"   // "12"，string
"5" - 2   // 3，number
```

二元 `+` 同时承担数值加法和字符串拼接，出现字符串时可能转为字符串拼接；`-` 没有字符串拼接含义，普通情况下会把可转换的字符串转成数字再做减法。

可能追问：静态类型检查工具是否会让 Python 变成静态类型语言？不会，类型标注和检查工具能提前发现问题，但 Python 的运行时模型没有因此变成静态类型。强弱类型也没有所有资料统一采用的严格边界，稳妥回答应同时给出具体转换行为。

首轮回答到能准确区分两个维度并给出 Python 示例已经足够；跨语言比较根据追问展开。更完整内容见 `第1章拓展讲义.md`。

### 第 2 题：解释执行与跨平台

**一句话结论：**“解释执行”不等于必然逐行直接执行源码，“跨平台”也不保证所有依赖环境的程序无需修改。

以常见 CPython 为例，源码通常先被编译为字节码，再由虚拟机执行。其他 Python 实现可能采用不同策略，所以不应把 CPython 的具体流程定义成全部 Python 的语言规则。

同一份纯 Python 代码通常能跨系统运行，但文件路径、系统调用、动态库和平台专属接口仍可能需要适配。

常见错误是说“Python 完全不编译”或“跨平台就绝不会有兼容问题”。可能追问：`.pyc` 是什么？可以回答它通常是 CPython 缓存的字节码，目的是减少后续导入时的重复编译工作。

### 第 3 题：标识符、关键字与缩进

**一句话结论：**标识符是程序员定义的名字，关键字具有固定语法含义，注释解释代码意图，而 Python 用缩进划分代码块。

示例中的 `temperature` 是标识符，`if` 是关键字。注释通常用来记录代码为何这样设计，而不应机械复述代码本身；普通注释不参与程序结果。`print` 必须缩进到 `if` 的代码块中：

```python
temperature = 35

if temperature > 30:
    print("hot")
```

原代码会产生 `IndentationError`。常见错误是把缩进只当作 PEP 8 风格；在 Python 中，缩进还直接决定语法结构。面试回答到能说明标识符、关键字和代码块即可，不必背完全部关键字。

### 第 4 题：名字、对象、引用与赋值

**一句话结论：**赋值把名字绑定到对象，名字不是保存固定类型数据的盒子。

执行 `count = 10` 后，运行环境中有一个名字 `count`，它关联到整数对象 `10`。随后执行 `count = "ten"`，是让同一个名字改为关联字符串对象，不是把原整数对象变成字符串。

```text
count ──→ 整数对象 10
重新赋值后：count ──→ 字符串对象 "ten"
```

常见错误是说“变量本身从整数变成字符串”。口语中这样说容易理解，但面试解释对象模型时应说“名字重新绑定”。可能追问：多个名字能否指向同一对象？可以，这正是共享引用现象的来源。

### 第 5 题：对象的身份、类型和值

**一句话结论：**身份回答“是否同一个对象”，类型回答“对象支持什么行为”，值回答“对象表示什么内容”。

- `id(value)` 返回代表对象身份的整数；在对象生命周期内，该身份值保持唯一。
- `type(value)` 返回对象的直接类型。
- `isinstance(value, SomeType)` 判断对象是否属于指定类型或其子类。

常见错误是把 `id()` 直接定义成物理内存地址。Python 语言只保证它表示对象身份；某些实现可能恰好用地址实现。可能追问：比较身份是否应写 `id(a) == id(b)`？通常直接写 `a is b` 更清楚。

### 第 6 题：`type()` 与 `isinstance()`

**一句话结论：**`type(value) is Base` 只接受直接类型就是 `Base` 的对象，`isinstance(value, Base)` 还认可其子类实例。

```python
class Base:
    pass

class Child(Base):
    pass

item = Child()
print(type(item) is Base)       # False
print(isinstance(item, Base))   # True
```

业务代码若希望支持继承和多态，通常使用 `isinstance()`；确实要求“必须是这个直接类型”时才严格比较 `type()`。常见错误是宣称其中一个永远更好。回答边界是说明语义差异和选择依据，不必在本章展开抽象基类。

### 第 7 题：`==` 与 `is`

**一句话结论：**`==` 使用对象类型提供的相等性规则，`is` 判断两个名字是否指向同一个对象。

`==` 的行为可以被自定义类型改变，它大致会进入与 `__eq__()` 有关的相等性协议；`is` 是固定的身份判断，不能由对象重载。`None` 是表示空缺状态的单例对象，所以判断目标正是“它是不是这个唯一对象”，推荐写 `value is None` 或 `value is not None`。

`value == None` 并非语法错误，但它会请求 `value` 的相等性规则，某些自定义类型可能声称自己与 `None` 相等，因此不适合表达身份判断。普通数值比较则关心值，应写 `value == 1000`。整数缓存或字符串驻留可能让某些 `is` 测试偶然为真，但那不是普通值比较可以依赖的规则。

常见错误是说 `is` 等于“更快的 `==`”。回答边界是知道 `__eq__()` 与相等性协议有关，并能解释为什么 `is None` 更准确；`NotImplemented`（表示当前类型无法完成这次比较）、比较回退和自定义类实现留到第 6 章。

### 第 8 题：可变对象与不可变对象

**一句话结论：**可变性描述对象创建后其内部状态能否原地改变，不描述名字能否重新赋值。

常见可变类型有 `list`、`dict`、`set`；常见不可变类型有 `int`、`str`、`tuple`。不可变对象不能原地改变值，但指向它的名字仍可重新绑定：

```python
text = "a"
text = "b"  # 合法；不是把原字符串对象改成了 "b"
```

常见错误是说“不可变变量”。可能追问：元组一定可哈希吗？不一定，其元素也必须满足可哈希要求；这个问题将在容器章节深入。

### 第 9 题：元组中的可变对象

**一句话结论：**元组不能更换自己各位置保存的引用，但它所引用的可变对象仍可改变内部状态。

```python
record = ([1], "A")
record[0].append(2)
print(record)  # ([1, 2], 'A')
```

元组第 0 个位置仍然指向原来那个列表，因此元组结构没有被替换。常见错误是把“元组不可变”扩大解释成对象图中所有后代都不可变。回答到“元组的位置引用没换，内部列表自身变了”即可。

### 第 10 题：`None` 与其他假值

**一句话结论：**这些对象都具有假值表现，但含义、类型和相等关系并不因此相同。

`None` 通常表达缺失或没有结果；`0` 可能是合法数值；空字符串和空列表分别是合法但为空的容器。接口约定用 `None` 表示没有结果时，应写：

```python
result = None

if result is None:
    ...
```

常见错误是用 `if not result` 把所有合法假值一起拒绝。可能追问：`None == False` 吗？结果为 `False`；但不要靠零散比较背答案，应先区分语义。

## 二、代码理解题

### 第 11 题：相等与同一对象

**结论：**输出依次为 `True`、`False`、`True`。

```text
left  ──┐
alias ──┴──→ 列表对象 A：[1, 2]
right ─────→ 列表对象 B：[1, 2]
```

两个列表内容相等，所以 `left == right` 为真；它们由两个列表字面量分别创建，不是同一个对象；`alias = left` 让二者指向同一对象。

常见错误是由“值相等”推出“身份相同”。可能追问：能否通过修改 `alias` 验证共享？可以调用 `alias.append(...)`，然后观察 `left`。

### 第 12 题：修改对象与重新绑定

**结论：**输出是 `[10, 20, 30]` 和 `[99]`。

开始时 `first` 与 `second` 指向同一列表。`second.append(30)` 修改这个列表，因此 `first` 也能看到新内容。`second = [99]` 只让 `second` 改为指向一个新列表，不会修改原列表。

常见错误是把两步都称为“修改变量”。面试时应明确区分 mutation（对象原地变化）和 rebinding（名字重新绑定）。

### 第 13 题：增强赋值 `+=`

**结论：**列表一行输出 `True [1, 2, 3]`；字符串一行通常且按这里的语义应观察到 `False abc`。

列表的 `+=` 会就地扩展该列表，因此 `numbers` 仍与 `numbers_alias` 指向同一对象；字符串不可变，拼接产生字符串结果并把 `text` 重新绑定到结果对象，而 `text_alias` 仍指向原字符串。

需要谨慎的是，关于不可变对象结果身份的微型优化不应成为业务逻辑依据；可靠结论是字符串值不能原地改变。常见错误是把所有 `+=` 一概说成原地修改，或一概说成等价于普通 `+` 后重新赋值。

### 第 14 题：真值判断

**结论：**依次输出 `False`、`False`、`True`、`False`、`True`。

`None`、数值零和空容器是假值；`"False"` 是非空字符串，字符串内容不会被自动解析成布尔值；`[0]` 是含一个元素的非空列表，列表真值看是否为空，而不是递归检查内部元素。

常见错误是认为字符串 `"False"` 为假，或认为 `[0]` 因为包含零而为假。回答到容器真值由是否为空决定即可；自定义对象的真值协议属于后续数据模型内容。

### 第 15 题：`not`、`and`、`or`、优先级与短路

**结论：**依次输出 `True`、`False`、`''`、`'fallback'`、`ready`、`True`、`True`、`True`，除法表达式没有执行。

`not` 先取得对象真值，再返回相反的 `bool`，所以空字符串得到 `True`，非空列表 `[0]` 得到 `False`。`and` 返回第一个假值操作数；若都是真值则返回最后一个。`or` 返回第一个真值操作数；若都是假值则返回最后一个。后两者选择并返回操作数，不保证返回 `bool`。

`True or (1 / 0)` 在左侧已经确定结果，除法不执行。`and` 优先于 `or`，所以：

```python
True or False and False
# 等价分组为 True or (False and False)
```

比较运算优先于 `not`，所以：

```python
not 1 == 2
# 等价分组为 not (1 == 2)
```

常见错误是只回答真假，遗漏实际返回值、分组和副作用是否执行。可能追问：何时应该显式使用 `bool(...)`？当接口确实要求布尔类型而不是某个操作数时。

### 第 16 题：数字类型、整除与取模

**结论：**常见内置数字类型是 `int`、`float`、`bool` 和 `complex`；代码依次输出 `2.5`、`2`、`-3`、`1`、`True 2`。

`bool` 是 `int` 的子类，`False` 和 `True` 在数值上下文中分别表现为 `0` 和 `1`。这解释了最后一行，但业务代码不应为了炫技而滥用布尔值参与算术。

`/` 是真除法；`//` 向负无穷方向取整，所以 `-5 // 2` 是 `-3`，不是向零截断的 `-2`。商和余数满足：

```python
a = -5
b = 2
print(a == (a // b) * b + (a % b))  # True
```

因此 `-5 == (-3) * 2 + 1`。常见错误是把 `//` 一律描述成“去掉小数部分”。可能追问：除数为负时余数符号如何理解？Python 的余数与除数同号或为零，并继续满足上式。

### 第 17 题：比较链与成员运算

**结论：**四个输出依次为 `True`、`True`、`True`、`False`。

第一项可展开为：

```python
value = 2
print(1 < value and value < 3)  # True
```

并且比较链中的中间表达式只求值一次。对字符串而言，第二项可用查找表达意思，例如：

```python
"python".find("th") != -1
```

但实际代码用 `in` 更直接。常见错误是把 `1 < value < 3` 按从左到右先得到布尔值再与 `3` 比较；Python 对比较链有专门语义。

`"java" not in "python"` 为真。`not in` 是完整的成员比较运算符，直接表示“不属于”；虽然 `not value in container` 通常能按 `not (value in container)` 分析，但前者更清楚。

`result is not None` 为假，因为 `result` 就是 `None`。`is not` 是完整的身份比较运算符，不应拆成 `is (not None)`。常见错误是看到其中包含 `not`，就用普通逻辑非的优先级把组合运算符拆开。

### 第 18 题：循环控制与循环 `else`

**结论：**输出 `[1, 3]`。

`number == 2` 时，`continue` 跳过当前轮剩余语句；`number == 4` 时，`break` 立即结束循环。因为循环通过 `break` 退出，循环后的 `else` 不执行，所以没有追加 `"done"`。

常见错误是认为循环 `else` 在循环条件为假时才“一定执行”，却忘了 `break` 会阻止它。可能追问：如果删除 `break` 会怎样？循环正常耗尽，`else` 执行。

### 第 19 题：索引与切片

**结论：**输出依次为 `n`、`yth`、`ython`、`nohtyp`。

负索引 `-1` 表示最后一个元素；`[1:4]` 包含下标 1，不包含下标 4；切片终点超过长度会被截到有效边界；负步长可反向取得元素。左闭右开使长度容易写成 `stop - start`，也方便相邻区间首尾衔接。

若 `text = ""`，`text[-1]` 会引发 `IndexError`，三个切片仍能产生空字符串。常见错误是认为切片越界与单个索引越界一样报错。

### 第 20 题：`range()`、`enumerate()` 与 `zip()`

**结论：**输出为：

```python
[1, 2, 3]
[(1, "a"), (2, "b")]
[(1, "a"), (2, "b")]
```

`range()` 表示整数范围且不含终点；`enumerate()` 同时提供计数位置和元素，`start=1` 只改变计数起点；普通 `zip()` 按位置配对，并在最短输入耗尽时停止，所以数字 `3` 没有配对结果。

常见错误是认为 `enumerate(..., start=1)` 会改变原容器下标，或认为 `zip()` 自动补齐。补齐方案属于标准库工具的后续内容。

### 第 21 题：序列解包

**结论：**输出 `10 20 [30, 40] 50`。

前两个元素分别绑定给 `first`、`second`，最后一个绑定给 `last`，星号目标 `middle` 收集剩余元素并形成列表。如果四个普通名字接收五个元素且没有星号目标，会引发 `ValueError`，因为数量不匹配。

交换写法会先计算右侧并形成待解包的两个值，再分别绑定给左侧名字，所以不需要临时变量。常见错误是以为星号目标只接收一个值，或得到元组。可能追问：一个解包赋值中能否出现两个星号目标？不能。

### 第 22 题：推导式

**结论：**`squares` 是 `[0, 4, 16]`，`mapping` 是 `{"a": 1, "python": 6}`，`labels` 是 `["even", "odd", "even"]`。

等价的清晰循环是：

```python
squares = []
for number in range(6):
    if number % 2 == 0:
        squares.append(number * number)

mapping = {}
for letter in ["a", "python"]:
    mapping[letter] = len(letter)
```

第一个推导式末尾的 `if` 决定元素是否进入结果；第三行的 `A if condition else B` 对每次迭代都产生一个结果，只是根据条件选择结果值。列表、集合和字典推导式分别构造相应容器。

推导式适合单一映射和简单筛选。若包含多层分支、复杂副作用、异常处理或难以命名的中间状态，普通循环更易读。PEP 8 的重点也是可读性和一致性，不是把代码压到最短。常见错误是认为越短就一定越 Pythonic。

## 三、找错与场景题

### 第 23 题：重复引用陷阱

**结论：**输出 `[["x"], ["x"], ["x"]]`；乘法复制了三个对同一个内部列表的引用。

关系可以画成：

```text
rows[0] ──┐
rows[1] ──┼──→ 同一个空列表
rows[2] ──┘
```

需要三个独立列表时，可逐次创建：

```python
rows = [[] for _ in range(3)]
```

常见错误是认为外层有三个位置，就必然存在三个内部对象。可能追问：`[0] * 3` 为什么通常不会出现同类修改问题？整数不可变，位置重新赋值不会原地改变共享整数对象。

### 第 24 题：浮点数比较

**结论：**许多十进制小数不能被有限位二进制浮点数精确表示，计算误差可能使精确相等断言失败。

一般近似计算可写：

```python
import math

result = 0.1 + 0.2
assert math.isclose(result, 0.3, rel_tol=1e-9, abs_tol=0.0)
```

容差不是脱离场景的万能常数：金额、传感器数据和科学计算对误差的要求不同。金额等要求精确十进制语义的场景还可能考虑 `decimal.Decimal`。

常见错误是说“浮点数永远不能用 `==`”。与自身比较、某些可精确表示的值或明确需要精确位级结果时，`==` 仍有意义。回答边界是说明表示误差与按场景选择比较策略。

### 第 25 题：强类型与显式转换

**结论：**`age_text + 1` 会引发 `TypeError`，因为字符串拼接和整数加法不是同一种兼容操作。

如果输入保证表示整数，应先显式转换：

```python
age_text = "18"
age = int(age_text)
next_age = age + 1
```

显式转换能让意图和失败位置清楚，也避免像 `"18" + "1"` 得到 `"181"` 这样的歧义。常见错误是只说“Python 不支持类型转换”；Python支持转换，只是不在这种运算中任意隐式转换。

### 第 26 题：字符串不可变

**结论：**字符串不支持按位置原地赋值，代码会引发 `TypeError`。

一种清晰写法是创建新字符串并重新绑定：

```python
name = "python"
name = "P" + name[1:]
print(name)  # Python
```

结果值为 `"Python"`，`name` 指向结果字符串，而不是原来的字符串对象。常见错误是说“Python 修改了字符串但地址变了”；准确说法是产生结果对象并重新绑定名字。

### 第 27 题：合法假值与缺失结果的区分

**一句话结论：**索引 `0` 是合法结果但为假，`if not position` 会把它误判成未找到。

应按照接口约定精确判断哨兵值：

```python
position = None

if position is None:
    print("not found")
```

常见错误是为了代码短而使用宽泛真值判断。可能追问：如果接口用 `-1` 表示未找到怎么办？就明确比较 `position == -1`；调用代码必须尊重接口定义。

### 第 28 题：共享引用的项目场景

**一句话结论：**`worker_options = default_options` 没有复制字典，只创建了指向同一字典的另一个名字。

因此通过任一名字添加 `timeout`，另一个名字都会观察到。只需要独立外层字典时，可以考虑：

```python
default_options = {"retries": 3, "servers": ["A"]}
worker_options = default_options.copy()
```

但浅层复制后，内部 `servers` 列表仍可能共享。如果嵌套可变对象也必须彼此独立，需要按数据结构明确复制这些层级，或在合适场景考虑深拷贝。

常见错误是把 `.copy()` 宣称为任何层级都独立。回答边界：本题只需识别绑定、外层复制和嵌套共享；浅拷贝、深拷贝及自定义复制行为在第 9 章系统学习。

### 第 29 题：小整数缓存、字符串驻留与身份判断

**一句话结论：**这些结果不能证明 `is` 可以代替值比较；可靠规则只有 `is` 判断身份、`==` 判断值。

CPython 可能缓存一些整数对象，也可能对部分字符串做驻留，因此两个独立写出的字面量有机会复用对象。具体结果还可能受版本、编译方式和运行环境影响。业务代码比较整数或字符串内容时必须用 `==`。

`id()` 在 Python 语言层面是对象生命周期内唯一的身份整数，不保证必须是物理内存地址。CPython 的某些实现中它可能与地址相关，但不能把实现方式写进跨实现业务逻辑。

常见错误包括：背诵一个固定“小整数缓存范围”后把它当语言规范；根据交互式解释器的一次结果推导所有环境；把 `id()` 永久绑定给对象。可能追问：对象销毁后 `id` 能否被复用？可以，因此唯一性只限定在对象生命周期重叠期间。

### 第 30 题：综合执行过程

**结论：**原代码输出：

```python
[0, 3]
[0, 2]
False
False
```

开始时 `values` 和 `alias` 指向同一列表 `[0]`。该列表非空，所以 `alias` 为真；但 `alias[0]` 是整数零，为假，因此整个 `and` 表达式为假并进入 `else`。

`values + [2]` 创建值为 `[0, 2]` 的新列表，`alias` 重新绑定到它；原列表仍由 `values` 指向。随后 `values.append(3)` 只修改原列表，使它成为 `[0, 3]`。两个名字既不指向同一对象，值也不相等。

如果改成 `alias += [2]`，列表的增强赋值会原地扩展二者共同指向的列表。随后 `values.append(3)` 继续修改同一对象，最终两次打印都是 `[0, 2, 3]`，`is` 和 `==` 都为 `True`。

常见错误是只根据 `alias` 这个名字判断对象是否共享，或认为列表 `+` 与 `+=` 必然完全等价。面试回答到逐步说明名字、对象、真值和分支已经足够；不要仅背最终输出。
