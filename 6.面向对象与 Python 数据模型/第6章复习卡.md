# 第 6 章复习卡：面向对象与 Python 数据模型

学完讲义后再用本卡快速回忆。第一次遇到的术语应回到完整讲义学习。

## 1. 类、实例与方法的调用关系

```text
执行 class → 类对象
调用类 → 实例对象
__new__() → 返回实例
__init__() → 设置实例初始状态
实例.方法(...) → 绑定实例给 self，再绑定其余实参
```

实例属性由各实例保存；类属性由类对象保存。修改共享可变类属性指向的对象，不等于给某个实例建立同名属性。

## 2. 实例方法、类方法与静态方法

| 定义方式 | 自动绑定 | 常见用途 |
|---|---|---|
| 普通实例方法 | 实例给 `self` | 读写该实例状态 |
| `@classmethod` | 被调用的类给 `cls` | 替代构造入口 |
| `@staticmethod` | 不自动绑定两者 | 与类语义相关的独立操作 |

`self`、`cls` 是约定名称，不是关键字。`cls(...)` 能保留从子类调用时创建子类的能力。

## 3. 继承与属性

- 继承表达“是一种”，组合表达“有一个”协作者。
- 重写让子类替换同名方法；多态让同一调用作用于不同对象。
- 鸭子类型关注所需行为，不要求每个可用对象都继承同一基类。
- MRO 是多继承中的方法查找顺序，可观察 `Class.__mro__`。
- `super()` 沿当前实例的 MRO 继续，不是固定指向直接父类。
- 普通实例属性可遮蔽普通类属性；`property` 等数据描述符有更高优先级。

菱形例子中，`Combined(Left, Right)` 且两边都继承 `Root` 时，顺序为 `Combined → Left → Right → Root → object`。`Root` 不能抢在 `Right` 前面，也不会重复出现；在 `Combined()` 上运行 `Left.route()` 时，`super()` 继续到 `Right`。

## 4. 属性控制、抽象基类与数据类

- `_name`：内部使用约定，仍可访问。
- `__name`：在类定义中发生名称改写，不是保密措施。
- `@property`：把点号读取和赋值接到 getter、setter。
- `__slots__`：限制普通实例可新增的属性名；已有值仍可改变，内存收益依实现而定。
- `@abstractmethod`：要求继承者实现指定方法，未完成的抽象类不能正常实例化。
- `@dataclass`：按字段生成初始化、表示和相等；可变默认字段用 `field(default_factory=...)`。
- `__post_init__()`：生成的初始化完成后校验字段之间的约束。

## 5. 数据模型速记

| 操作 | 相关方法 | 关键约定 |
|---|---|---|
| `str(obj)`、`print(obj)` | `__str__()` | 面向使用者的文本 |
| `repr(obj)` | `__repr__()` | 易辨认的调试表示 |
| `a == b` | `__eq__()` | 未支持的类型返回 `NotImplemented` |
| `a < b` | `__lt__()` | 一种排序关系，不自动定义全部比较 |
| `hash(obj)` | `__hash__()` | 相等对象哈希必须相同 |
| `len(obj)` | `__len__()` | 返回非负整数 |
| `obj[index]` | `__getitem__()` | 处理索引或切片 |
| `value in obj` | `__contains__()` | 回答成员关系 |
| `obj(...)` | `__call__()` | 使实例可调用 |
| `with obj` | `__enter__()`、`__exit__()` | 进入与退出资源范围 |

特殊语法通常在类型上寻找方法。单给一个实例增加名为 `__len__` 的普通属性，不等于实现 `len(obj)` 协议。

## 6. 相等与哈希

```text
a is b → 是否同一个对象
a == b → 根据相等协议判断值
a == b 为真 → hash(a) 与 hash(b) 必须相同
```

重写 `__eq__()` 却没有提供匹配的 `__hash__()` 时，普通类实例通常变得不可哈希。参与哈希的状态在当作字典键期间必须稳定。`NotImplemented` 是比较协议中的返回值，不是异常 `NotImplementedError`。

```text
插入字典：旧 hash → 保存键所在的候选区域
修改键的哈希字段：对象仍在字典中，hash 却变了
再次查找：新 hash → 可能去另一个候选区域，不能可靠找到旧键
```

`__eq__()` 对不认识的类型返回 `NotImplemented`，Python 才有机会问另一侧；直接返回 `False` 表示已经明确否定。

## 7. 属性查找顺序与访问钩子

```text
数据描述符，例如 property（即使没有 setter）
→ 普通实例属性
→ 类和父类中的普通属性或方法
→ 查找仍失败时 __getattr__()
```

`__getattribute__()` 几乎介入每次普通读取，`__setattr__()` 介入普通赋值；在它们内部直接重复点号操作可能递归。用 `object.__getattribute__()`、`object.__setattr__()` 委托基础操作。描述符与元类只需掌握用途和边界，不要默认用于普通字段。

普通方法属于可被同名实例属性遮蔽的非数据描述符；`property` 即使没有 setter 也属于优先处理属性的数据描述符，只是赋值会报错。描述符由类共享时，每个实例的业务值仍应存在各自的实例上。

## 8. 高频陷阱

1. 把两个内容相同的实例当成同一个对象。
2. 在类顶层放列表，又以为每个实例各有一份。
3. 以为给实例赋值会直接改掉类属性。
4. 把 `super()` 当成固定的直接父类调用。
5. 把双下划线改写当成安全保密。
6. 认为 `__slots__` 或 `frozen=True` 自动递归冻结对象。
7. 重写值相等后继续沿用身份哈希，或修改已入字典的键状态。
8. 把 `NotImplemented` 当成 `False` 或 `NotImplementedError`。
9. 以为普通实例字段永远比 `property` 优先。
10. 重写属性钩子后在内部递归调用自身。

## 9. 一分钟自测

1. 类对象和实例对象分别何时产生？
2. `__new__()` 与 `__init__()` 谁先执行，职责是什么？
3. `obj.method(x)` 怎样得到 `self`？
4. 两个实例为什么会共享可变类属性？
5. 类方法与静态方法有什么区别？
6. `super()` 怎样找到下一层？
7. `property` 为什么能先于实例字典处理赋值？
8. `==`、`is`、`hash()` 分别回答什么？
9. 什么时候返回 `NotImplemented`？
10. `__getattr__()` 何时才会运行？
11. 为什么同一个 `Left.route()` 中的 `super()` 会因实例类型不同走向不同类？
12. 键入字典后改动参与哈希的字段，查找过程哪一步会出问题？
