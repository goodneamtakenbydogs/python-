# 第 6 章参考回答：面向对象与 Python 数据模型

本文件与 `第6章面试题.md` 的 40 道题逐题对应。首轮回答先说结论，再用最小对象图或代码过程解释；更深的实现细节留给追问。

## 一、基础概念题

### 第 1 题：类与实例

执行 `class` 时会执行类体中的普通语句、创建类对象并绑定类名；类体里的 `def __init__` 只是创建函数对象，不会立刻运行它的函数体。调用类通常先得到实例，再执行初始化。两个实例即使属性值相同，身份也可以不同；`is` 判断是否同一对象，`==` 则取决于相等规则。分析输出题时先分开“定义类”和“调用类”两个时刻。

### 第 2 题：`__init__()` 与 `self`

创建实例后，`__init__()` 为其建立初始状态。`self` 是本次方法调用中的实例形参，`self.name = name` 给这个实例设置属性。`obj.method(value)` 通过实例取得绑定方法，通常相当于 `type(obj).method(obj, value)` 的绑定效果。不要说 `self` 是保留关键字，也不要说所有实例共享同一组实例属性。

### 第 3 题：实例属性与类属性

实例属性由各实例分别保存，类属性由类对象保存。读取普通属性时，实例找不到便继续到类及父类查找；`obj.category = "new"` 通常在该实例上建立同名属性，遮蔽普通类属性，不会自动修改类对象。`property` 即使没有 setter 也属于数据描述符，会优先于同名实例字典条目处理点号访问。所以应先判断类中的同名对象是否能接管读写，再使用“实例先于普通类属性”的简化规则。

### 第 4 题：可变类属性

类定义顶层的列表只创建并保存在类对象上。多个实例若没有同名实例属性，读到的是同一个列表。`append()` 修改该共享对象；`obj.items = [x]` 则在该实例上建立新绑定。需要独立列表时，在 `__init__()` 中为每个实例创建。

### 第 5 题：实例方法、类方法与静态方法

实例方法经由实例调用时绑定 `self`；类方法绑定被调用的类到 `cls`；静态方法不自动注入实例或类。若需要从文本等输入创建“当前被调用的类”的对象，`@classmethod` 中使用 `cls(...)` 比写死基类名更能保留子类行为。与类无关的工具函数不必强放进静态方法。

### 第 6 题：`__new__()` 与 `__init__()`

`__new__()` 先负责返回实例，随后通常由 `__init__()` 设置其初始状态，后者应返回 `None`。若前者返回的不是该类实例，通常不会继续调用该类的 `__init__()`。绝大多数普通类只需定义 `__init__()`；为一般字段校验重写 `__new__()` 会增加不必要复杂度。

### 第 7 题：继承与方法重写

继承适合真实的“是一种”关系。子类实例的方法沿类的 MRO 查找；子类定义的同名方法可重写父类实现。成本是父类接口变动会影响子类，子类还可能违背父类的行为承诺。不能只为复用几行代码就随意建立继承。

### 第 8 题：多态与鸭子类型

多态强调同样的调用对不同对象产生各自的行为。鸭子类型强调调用方依赖对象能提供的方法，而不一定依赖指定继承关系。若 `show(item)` 只调用 `item.describe()`，独立类只要提供合适的 `describe()` 也可能工作；调用失败时仍应有清楚的接口约定。

### 第 9 题：组合与继承

报告服务**有一个**打印器，适合把打印器作为协作对象保存；邮件**是一种**消息，可以考虑继承消息接口。选择时还要看替换协作者是否常见，以及子类能否遵守父类行为。组合通常让依赖更显式，继承适合真正稳定的类型关系。

### 第 10 题：MRO

MRO 是类及其父类的方法查找顺序，可读取 `SomeClass.__mro__`。对题目中的菱形结构，`Left` 要在 `Right` 前面，而两个分支都要求先到自身再到 `Root`。合并时不能在处理 `Right` 前提前选 `Root`，共同祖先也只出现一次，所以得到 `Combined → Left → Right → Root → object`。C3 的最低限度直觉是保留各父类已有顺序与直接父类顺序；不要把两个父类链机械拼接。

### 第 11 题：`super()`

零参数 `super()` 按当前类、当前实例对应的 MRO 继续查找，不是固定的“直接父类对象”。在 `Left()` 上执行 `Left.route()`，下一站是 `Root`；在 `Combined()` 上执行同一份方法，下一站是 `Right`。MRO 决定可查找的顺序，但各层仍必须主动调用下一层；协作式方法还要共享相容的参数约定，否则会漏掉或中断调用。

### 第 12 题：名称改写

单下划线是供内部使用的约定，不阻止访问。类定义中的双下划线名会改写成包含类名的形式，主要避免子类无意使用同名属性。它仍可通过实例状态等方式看到，不是安全保密措施；真正敏感信息不能靠它保护。

### 第 13 题：`property`

`property` 允许调用方沿用 `obj.value`，由 getter、setter 集中维护校验与存储约定。它是数据描述符，通常先于实例字典处理属性；即使字典里另有同名 `balance` 条目，`obj.balance` 仍可能运行 getter。没有 setter 时公开赋值会报错；有 setter 时校验应发生在写入内部状态之前，失败时保留旧值。它仍不是安全屏障，直接访问内部存储可能绕过约定。

### 第 14 题：`__slots__`

槽声明普通实例可使用的属性名，常使任意新增属性失败，也可能让实例没有 `__dict__`。已有槽值仍可重新赋值，故不自动不可变。CPython 下可能节省内存，但数值不是语言保证；未相应定义槽的子类可能重新拥有实例字典。

### 第 15 题：抽象基类

`ABC` 与 `@abstractmethod` 用于继承体系中明确要求子类实现方法；未完成要求的类不能正常实例化。鸭子类型则关注使用时是否具有需要的行为，不要求每个可用对象都继承抽象基类。需要强制共同扩展接口时用抽象基类，只需松耦合调用时不必强制继承。

### 第 16 题：`dataclass`

`@dataclass` 常按字段生成初始化、调试表示和相等方法。每实例独立的列表应使用 `field(default_factory=list)`，让工厂在创建实例时建立新列表。`__post_init__()` 适合检查生成的初始化方法设置完字段后，字段之间是否满足共同约束。`frozen=True` 限制字段重新绑定，但字段内部若是可变对象仍可能变化；即使生成了哈希方法，遇到不可哈希字段也可能失败。注解本身不会自动完成运行时类型校验。

### 第 17 题：特殊方法与数据模型

这些语法按照数据模型查找类型上的 `__len__()`、`__getitem__()`、`__call__()` 等方法。只把 `__len__` 塞进某个实例的普通属性字典，通常不能改变 `len(obj)` 的特殊方法查找。回答时要区分“普通点号读取”与“内置语法按类型查找协议”。

### 第 18 题：`__str__()` 与 `__repr__()`

`str()` 与 `print()` 更关注面向使用者的可读文本，`repr()` 更关注可辨认的调试表示。缺少 `__str__()` 时可回退到 `__repr__()`。尽量让 `repr` 清楚，但“必须能交给 `eval()` 重建”不是语言强制规则，也不应随意对不可信文本调用 `eval()`。

## 二、代码理解题

### 第 19 题：两个实例的独立属性

输出 `2 1 False`。`first`、`second` 是两个实例，各自有 `value`。给 `first.value` 赋值不会改动 `second.value`；属性值曾相同也不代表身份相同。

### 第 20 题：类属性遮蔽

输出 `admin member member`。`first.kind = "admin"` 在 `first` 上建立同名实例属性，遮蔽 `Badge.kind`；`second` 没有自己的 `kind`，仍沿类查找。

### 第 21 题：共享列表

两行分别是：

```text
['A']
['B'] ['A'] ['A']
```

`append()` 先改了类属性指向的列表，所以 `second` 看见 `A`。后来 `first.members = ["B"]` 在 `first` 上建立新绑定，类和 `second` 仍指向旧列表。

### 第 22 题：实例、类和静态方法

输出 `SpecialTicket S-4 False`。`SpecialTicket.build(4)` 让 `cls` 绑定到 `SpecialTicket`，`cls(number)` 创建子类实例；实例方法从它的类读取 `prefix`。静态方法只接收显式的 `-1`。

### 第 23 题：创建与初始化

输出 `['new', 'init'] 8`。调用 `Record(8)` 先经 `__new__()` 得到实例，再由 `__init__()` 设置 `value`。不能把 `__init__()` 的职责说成“返回实例”。

### 第 24 题：重写与鸭子类型

输出 `['message', 'email', 'report']`。`Email` 重写父类方法；`Report` 没继承 `Message`，但也提供了 `describe()`，所以 `show()` 的当前调用可正常完成。

### 第 25 题：菱形继承

两行是：

```text
['Combined', 'Left', 'Right', 'Root', 'object']
['Combined', 'Left', 'Right', 'Root']
```

每层沿同一实例的 MRO 调用下一层。特别是 `Left.route()` 的 `super()` 继续找到 `Right.route()`，并非直接固定调用 `Root.route()`。

### 第 26 题：`property` 校验

输出 `10 {'_balance': 10, 'balance': 999}`。初始化中的 `self.balance = 10` 已触发 setter；负值校验先抛异常，没有写 `_balance`。随后手工给实例字典加 `balance: 999`，但点号读取仍由类上的 `property` getter 处理，返回 `_balance` 中的 `10`。不要把 `vars(account)` 里的普通条目与 `account.balance` 的查找结果机械等同。

### 第 27 题：名称改写

输出是 `{'_Vault__code': 'A'}` 与 `False`。类定义中的 `__code` 被改写存储；直接查询字面属性名 `__code` 找不到。数据仍能观察到，说明它并非真正私有。

### 第 28 题：`__slots__`

先显示 `3 False`，随后 `point.z = 4` 抛出 `AttributeError`。`x` 是允许的槽，能改；`z` 不在槽中。`__slots__` 限制可新增名字，不自动冻结已有值。

### 第 29 题：数据类与默认工厂

两行分别是：

```text
True False
False []
```

创建时两个对象字段相同，因此数据类按字段比较为相等，身份仍不同。`default_factory` 为各实例建立独立列表；修改 `first.scores` 后字段值不再相同，`second.scores` 不变。

### 第 30 题：打印与调用

输出 `x3 Multiplier(factor=3) 12`。`str()` 使用 `__str__()`，`repr()` 使用 `__repr__()`，`operation(4)` 调用该类的 `__call__(4)`。`operation` 仍是对象实例，不是普通函数。

## 三、实现与场景题

### 第 31 题：相等与哈希

插入字典时先根据键的哈希找到候选区域，查找时又根据查询键的哈希找到候选区域，再检查相等关系。因此按坐标值相等的对象必须有相同哈希；同哈希但不相等仍可通过相等检查区分。坐标若在入字典后改变，查询可能走向不同候选区域，键会变得不能可靠查找；不要把一次偶然成功当作保证。未知类型应返回 `NotImplemented`，让 Python 有机会采用另一侧规则。普通类重写 `__eq__()` 而不提供匹配 `__hash__()` 时会被设为不可哈希。可用稳定字段和 `@dataclass(frozen=True)` 表达简单值对象，但仍须检查字段本身可哈希。

### 第 32 题：容器协议

`len(obj)` 对应 `__len__()`，索引与切片对应 `__getitem__()`，成员测试优先用 `__contains__()`，必要时还可能有迭代回退。若要求快照，应在初始化时复制输入元素，而不是只保存输入列表引用；否则调用者后续修改会改变对象看到的内容。

### 第 33 题：属性访问钩子

`__getattr__()` 在通常查找失败后处理缺失名字；`__getattribute__()` 几乎接管每次普通属性读取；`__setattr__()` 接管普通赋值。后两者内部若再次用相同点号操作会递归进入自己，通常应委托 `object.__getattribute__()` 或 `object.__setattr__()`。只校验一个字段时先考虑 `property`，不用让所有属性读写都穿过自定义钩子。

### 第 34 题：描述符优先级

`property` 是数据描述符，优先处理相应属性；带 setter 时 `obj.value = ...` 会触发它，没有 setter 时赋值会报错。若一个描述符对象由全类共享，却把每个实例的值都存在描述符对象自身，多个实例可能互相覆盖状态；应把值存到相应实例上。普通实例字段可遮蔽普通类属性；类中的普通函数是没有赋值处理优先级的非数据描述符，实例读取时通常形成带 `self` 的绑定方法，也可能被同名实例属性遮蔽。

### 第 35 题：上下文管理器

进入 `with` 时调用 `__enter__()`，其返回值绑定到 `as value`；离开时调用 `__exit__(exc_type, exc_value, traceback)`，包括异常路径。返回假值不会抑制异常，异常继续传播；完整清理和异常规则属于第 7 章。

### 第 36 题：元类边界

类本身是对象，普通类通常由元类 `type` 创建。登记类可以先考虑类装饰器或 `__init_subclass__()`；校验一般字段也可能由普通类方法或明确的注册函数完成。自定义元类会介入类创建过程，影响面大、调试成本高，不应因名称“高级”就优先使用。

## 四、连续追问题

### 第 37 题：类与对象的完整调用链

执行 `class` 得到类对象并绑定类名；调用类进入创建流程，`__new__()` 返回实例，`__init__()` 为该实例建立状态。之后经实例读取普通方法会形成绑定方法，将该实例绑定给 `self`；实际传入的其他实参再按函数签名绑定。每一步应画出“名字指向类或实例、哪个属性由谁保存”，不要把类名与实例混成一个对象。

### 第 38 题：属性与继承综合追问

普通实例属性由实例保存，可遮蔽普通类属性；修改可变类属性指向的对象会被其他实例看到。`property` 即使没有 setter 也优先介入相应属性访问。继承时类及父类沿 MRO 查找，`super()` 从当前类之后继续。对象只是借用另一个对象的服务时，组合比虚构继承关系更清楚。

### 第 39 题：相等与哈希综合追问

`is` 判断身份，`==` 使用值相等协议。无法处理另一种类型时，`__eq__()` 返回 `NotImplemented`，而不是把它当布尔结果。`a == b` 要求 `hash(a) == hash(b)`，否则字典定位与相等检查会矛盾。`frozen=True` 限制字段重新绑定，不递归冻结字段所指对象，也不保证所有字段都可哈希。

### 第 40 题：练习记录与报告类的设计

单条固定记录可先用 `@dataclass(frozen=True)` 表达按字段比较的值对象；管理一组记录的报告则**包含**这些记录，采用组合而非继承记录类。报告在初始化时复制输入列表，避免调用方后来修改输入影响既有内容；用 `__len__()`、`__getitem__()` 支持数量与索引，用只读 `property` 提供最高分。若每次读取都用 `max()` 扫描，时间随记录数增长；真正需要高频查询时再增加索引或缓存，并同步更新。只有确需统一控制大量属性访问或类创建时，才考虑 `__getattribute__()`、`__setattr__()` 或自定义元类。回答重点是需求范围与机制影响面相称。
