## 1. 使用 `class` 定义类与创建实例

你已经用过列表对象和函数对象。对象有身份、类型和值或状态；名字只是指向对象的绑定。例如两个列表可以内容相等，却仍是两个不同对象。本章要自己定义一种对象，让它同时保存数据和提供相关操作。

```python
class Counter:
    pass


first = Counter()
second = Counter()
print(first is second)  # False
```

执行 `class Counter:` 时，Python 创建一个**类对象**并让名字 `Counter` 指向它。`Counter()` 调用这个类对象，得到一个新的**实例对象**。类描述这一类对象能够拥有哪些属性和行为；实例是某次创建得到的具体对象。`pass` 表示此处暂时没有语句要执行。

```text
Counter ──→ 类对象
             ├── Counter() ──→ 实例 first
             └── Counter() ──→ 实例 second
```

“面向对象”不是一定要把所有函数放进类，而是在数据和操作确实共同构成一个概念时，用类表达它们的关系。

### 1.1 执行类定义与调用类是两个时刻

先不要把 `class` 当作只会被编译器看见的声明。在 Python 中，运行到类定义时会执行类体，然后创建类对象；类体中的 `def` 创建函数对象，但函数体仍要等调用才执行。观察事件顺序：

```python
events = []


class Counter:
    events.append("class body")

    def __init__(self):
        events.append("init")


events.append("after class")
counter = Counter()
print(events)  # ['class body', 'after class', 'init']
```

第一项发生在执行类体时，第二项发生在类对象已经创建之后，第三项才发生在调用 `Counter()` 时。`def __init__` 所在行创建了方法所需的函数对象，并没有立刻执行方法体。以后看到类装饰器、元类或类属性表达式时，这个时间顺序也适用。

### 1.2 类型、类与实例之间的关系

```python
class Counter:
    def __init__(self):
        pass


counter = Counter()
print(type(counter) is Counter)  # True
print(isinstance(counter, Counter))  # True
print(type(Counter) is type)  # True，普通类的常见情形
```

`type(counter)` 返回实例的类型对象，即这里的 `Counter` 类；`isinstance(counter, Counter)` 判断它是否属于该类或其子类。类对象本身也有类型，普通类通常由内置的 `type` 创建。本章末尾才会给“创建类的类”命名为元类；当前只需分清这两个层次，不要说“实例和类是同一个对象”。

## 2. 实例如何保存自己的状态

### 2.1 `__init__()` 初始化实例

只创建空实例还不能表示计数。让每个实例保存自己的当前值：

```python
class Counter:
    def __init__(self, start):
        self.value = start


first = Counter(2)
second = Counter(10)
print(first.value, second.value)  # 2 10
```

`__init__()` 是初始化方法。`Counter(2)` 创建实例后，Python 调用 `__init__()`；`self` 指向正在初始化的这个实例，`start` 绑定到实参 `2`。`self.value = start` 在该实例上保存名为 `value` 的**属性**。属性就是通过 `obj.name` 访问的对象成员，可以是数据，也可以是方法。

两个实例的属性各自保存：

```text
first  ──→ Counter 实例 A ──→ value: 2
second ──→ Counter 实例 B ──→ value: 10
```

这里的 `self` 只是约定俗成的形参名，关键在于它绑定到哪一个实例；改名虽然语法上可行，却会让代码难读。

把 `first = Counter(2)` 拆开看，调用处的 `2` 先成为实参对象，初始化方法的局部形参 `start` 随后绑定到这个对象；`self` 绑定到本次新建的实例。执行 `self.value = start` 时，赋值目标是实例上的 `value`，并没有去修改类名 `Counter` 的绑定，也没有让第二个实例获得同一个普通整数属性槽。

```text
类名 Counter ─────────→ 类对象
实例名 first ─────────→ 实例 A ── value ──→ 2
实例名 second ────────→ 实例 B ── value ──→ 10
```

一个实例属性可以指向列表等可变对象。若两个实例被显式传入同一个列表，虽然它们各有一个属性名，属性仍可能指向同一个列表；“实例属性各自保存”不等于“内部对象必定独立”：

```python
class Folder:
    def __init__(self, items):
        self.items = items


shared = []
first = Folder(shared)
second = Folder(shared)
first.items.append("A")
print(second.items)  # ['A']
```

需要隔离时可在初始化中明确复制，例如 `self.items = list(items)`。是否复制取决于接口约定，不能靠类语法自动猜测。

### 2.2 方法调用如何得到 `self`

```python
class Counter:
    def __init__(self, start):
        self.value = start

    def increase(self, amount):
        self.value += amount
        return self.value


counter = Counter(2)
print(counter.increase(3))  # 5
```

`counter.increase(3)` 在通常情况下相当于 `Counter.increase(counter, 3)`：通过实例取出函数时，Python 形成一个**绑定方法**，把该实例预先绑定给第一个形参 `self`。随后 `self.value += amount` 修改的是 `counter` 的状态，不会自动修改别的实例。

可以观察绑定方法保存的两个关系：

```python
class Counter:
    def __init__(self, start):
        self.value = start

    def increase(self, amount):
        self.value += amount
        return self.value


counter = Counter(2)
method = counter.increase
print(method.__self__ is counter)       # True
print(method.__func__ is Counter.increase)  # True
```

`__self__` 指向预先绑定的实例，`__func__` 指向类中定义的函数。执行 `method(2)` 时只需提供 `amount`；若再写 `method(counter, 2)`，就会多给一个位置实参。通过类直接取 `Counter.increase` 时通常得到原函数，此时可以显式写 `Counter.increase(counter, 2)`。这正是第 3 章形参与实参绑定规则在类上的应用。

`self.value += amount` 对这里的整数会产生新整数并重新绑定该实例的 `value` 属性。若属性指向列表且执行 `self.items.append(x)`，改变的则是共享列表对象。方法名并不会自动决定它是否有副作用。

不要把 `self` 理解成 Python 的保留关键字，也不要在通常的实例方法调用中手动再传一次实例。

## 3. 实例属性、类属性与查找

### 3.1 类属性由类对象保存

```python
class Badge:
    category = "member"

    def __init__(self, name):
        self.name = name


first = Badge("Ada")
second = Badge("Lin")
print(first.name, second.name)      # Ada Lin
print(first.category, second.category)  # member member
```

`name` 由每个实例分别保存。`category` 写在类定义的顶层，由类对象保存。读取普通属性 `first.category` 时，若实例自身没有这个名字，Python 会继续在类及其父类中找。**父类**是被当前类继承、可提供现成行为的类，第 6 节会展开。

### 3.2 给实例赋值可能形成遮蔽

```python
class Badge:
    category = "member"

    def __init__(self, name):
        self.name = name


first = Badge("Ada")
second = Badge("Lin")
first.category = "admin"
print(first.category)   # admin
print(second.category)  # member
print(Badge.category)   # member
```

这次赋值在 `first` 上建立同名实例属性，遮蔽了类属性；没有修改 `Badge.category`。可以用 `vars(first)` 观察该实例当前保存的普通属性映射。

```python
class Badge:
    category = "member"

    def __init__(self, name):
        self.name = name


first = Badge("Ada")
second = Badge("Lin")
first.category = "admin"
print(vars(first))  # {'name': 'Ada', 'category': 'admin'}
print(vars(second)) # {'name': 'Lin'}
```

`vars(instance)` 在这种普通实例上返回其属性字典。第二个字典里没有 `category`，因此读 `second.category` 才继续到类中找到 `"member"`。遮蔽并没有删除类属性；只要读的是另一个没有遮蔽的实例，仍会得到类中的值。

可以按这张状态表手工推导普通属性：

| 读取表达式 | 实例字典中是否有 `category` | 读到哪里 |
|---|---|---|
| `first.category` | 有，值为 `"admin"` | `first` 实例 |
| `second.category` | 没有 | `Badge` 类 |
| `Badge.category` | 不经过实例 | `Badge` 类 |

这个“先实例、后类”的顺序适用于普通属性。后面学习的 `property` 属于更高优先级的**描述符**，也就是能接管点号读取或赋值的类中对象；不能拿这条简化规则解释所有属性访问。

### 3.3 可变类属性可能被所有实例共享

```python
class Team:
    members = []


first = Team()
second = Team()
first.members.append("Ada")
print(second.members)  # ['Ada']
```

两个实例都没有自己的 `members`，因此读到同一个类属性列表。`append()` 修改的是共享列表对象。如果每个实例应有独立列表，应在 `__init__()` 中执行 `self.members = []`。区别来自属性放在哪里，以及后续是修改对象还是重新绑定某个名字。

继续给 `first` 赋新列表后再观察：

```python
class Team:
    members = []


first = Team()
second = Team()
first.members.append("Ada")
first.members = ["Lin"]
print(first.members)  # ['Lin']
print(second.members) # ['Ada']
print(Team.members)   # ['Ada']
```

第一步的 `append()` 通过类属性找到原列表并原地修改；第二步的赋值在 `first` 上建立属性，让它改为指向新列表。对象图从“两个实例沿类找到同一列表”变成“`first` 指向新列表，`second` 仍沿类找到原列表”。如果初始化时写 `self.members = []`，每次创建实例都会执行一次列表字面量，才会得到各自独立的列表。

## 4. 实例方法、类方法与静态方法的绑定

先按调用时自动绑定的对象分类，而不是按“方法重要程度”分类。

```python
class Ticket:
    prefix = "T"

    def __init__(self, number):
        self.number = number

    def label(self):
        return f"{self.prefix}-{self.number}"

    @classmethod
    def from_text(cls, text):
        return cls(int(text))

    @staticmethod
    def valid_number(number):
        return number >= 0
```

- `label` 是实例方法；通过实例调用时，第一个形参 `self` 绑定该实例，适合读写实例状态。
- `from_text` 是类方法；`@classmethod` 使第一个形参 `cls` 绑定被调用的类对象，适合需要按当前类创建实例的替代构造入口。
- `valid_number` 是静态方法；`@staticmethod` 不自动注入实例或类，适合与该类语义相关但无需两者状态的工具函数。

```python
class Ticket:
    prefix = "T"

    def __init__(self, number):
        self.number = number

    def label(self):
        return f"{self.prefix}-{self.number}"

    @classmethod
    def from_text(cls, text):
        return cls(int(text))

    @staticmethod
    def valid_number(number):
        return number >= 0


ticket = Ticket.from_text("12")
print(ticket.label())           # T-12
print(Ticket.valid_number(12))  # True
```

`classmethod` 和 `staticmethod` 都是装饰器。`cls` 也只是约定名称；`cls(int(text))` 保留了“通过哪个类调用，就创建哪个类”的能力。若某工具函数和类无明显语义联系，普通模块函数可能更清楚。

把调用表达式与自动绑定关系并排看：

| 调用表达式 | Python 自动绑定 | 调用者还需提供 |
|---|---|---|
| `ticket.label()` | `self` 绑定 `ticket` | 无 |
| `Ticket.from_text("12")` | `cls` 绑定 `Ticket` | `text="12"` |
| `Ticket.valid_number(12)` | 不自动绑定实例或类 | `number=12` |

静态方法也可以通过实例读取，但仍不会自动得到该实例；`ticket.valid_number(12)` 中的 `12` 依然绑定给唯一形参 `number`。因此判断方法类别时，要看装饰器与绑定规则，不能只看点号左侧写的是类还是实例。

### 4.1 用子类检验 `cls` 的含义

```python
class Ticket:
    prefix = "T"

    def __init__(self, number):
        self.number = number

    def label(self):
        return f"{self.prefix}-{self.number}"

    @classmethod
    def from_text(cls, text):
        return cls(int(text))


class SpecialTicket(Ticket):
    prefix = "S"


special = SpecialTicket.from_text("7")
print(type(special) is SpecialTicket)  # True
print(special.label())                 # S-7
```

`from_text()` 的函数体只写了一次，但通过 `SpecialTicket` 调用时，`cls` 绑定到子类，`cls(7)` 创建子类实例。若把它写成 `return Ticket(int(text))`，得到的将是基类实例，子类扩展能力就丢失了。这是类方法适合替代构造入口的具体原因。

三种调用容易混淆的地方，是“调用者写在点号左侧的对象”和“方法获得的第一个实参”并非总相同：实例方法通常得到实例，类方法得到类，静态方法不自动得到任何一个。不要把静态方法理解成运行速度更快的实例方法。

## 5. 创建与初始化：`__new__()` 在前

`__init__()` 负责给已有实例设置初始状态，本身应返回 `None`。更早一步是 `__new__()`：它接收类对象，负责返回新实例。通常不需要重写它。

```python
class Record:
    def __new__(cls, value):
        print("new")
        return super().__new__(cls)

    def __init__(self, value):
        print("init")
        self.value = value


record = Record(5)
```

创建过程可先按下面的顺序理解：

```text
调用 Record(5)
→ __new__(Record, 5) 返回一个 Record 实例
→ __init__(该实例, 5) 设置 value
→ 调用表达式得到实例
```

输出先是 `new`，后是 `init`。此处 `super().__new__(cls)` 把实例创建交给上层实现；第 7 节会解释 `super()` 如何沿方法查找顺序工作。如果 `__new__()` 返回的不是 `Record` 的实例，`Record.__init__()` 不会按这个通常流程执行。入门时优先使用 `__init__()`，不要为普通校验或赋值重写 `__new__()`。

### 5.1 `__new__()` 创建实例与 `__init__()` 初始化状态

`__new__()` 的结果是一个对象，负责“有没有以及得到哪个实例”；`__init__()` 接收已经得到的实例，负责“它最初保存什么状态”。对普通业务类，继承来的 `__new__()` 已能创建实例，我们只写 `__init__()` 即可。不可变类型的某些子类需要在实例创建阶段确定值，此时才更可能定制 `__new__()`。

初始化方法不应返回另一个业务对象：

```python
class Invalid:
    def __init__(self):
        return 1


# Invalid()  # TypeError：__init__() 必须返回 None
```

如果自定义 `__new__()` 返回的不是当前类实例，当前类的 `__init__()` 不会按通常方式继续。下面只用于观察调用链，不建议用它设计普通构造接口：

```python
events = []


class Substitute:
    def __new__(cls):
        events.append("new")
        return object()

    def __init__(self):
        events.append("init")


result = Substitute()
print(events)                  # ['new']
print(type(result) is object) # True
```

不要从这个例子得出“`__init__()` 可有可无”的结论；它展示的是返回对象类型改变后，正常初始化步骤不再适用。

## 6. 继承、重写与多态

### 6.1 继承表示“是一种”关系

```python
class Message:
    def describe(self):
        return "message"


class Email(Message):
    def describe(self):
        return "email"


print(Email().describe())  # email
```

`Email(Message)` 表示 `Email` 继承 `Message`。实例找不到某属性时，可以继续到父类寻找。子类重新定义同名方法称为**重写**；这里调用的是 `Email.describe()`。

如果暂时删去 `Email.describe()`，`Email()` 实例仍可以调用 `describe()`，这时 Python 沿继承关系在 `Message` 中找到函数，再把当前 `Email` 实例绑定给 `self`。继承并不会把父类代码复制一份放到每个子类实例里；它改变的是属性查找和允许复用的行为。

重写之后仍可明确调用上层行为，例如在子类方法中使用 `super().describe()`。但是否应该调用，取决于父类接口约定：日志类方法可能要先执行上层初始化；完全替换文本的 `describe()` 则未必需要拼接父类结果。不能机械地给每个重写方法都加一次 `super()`。

### 6.2 多态关注相同调用，不同实现

```python
class Message:
    def describe(self):
        return "message"


class Email(Message):
    def describe(self):
        return "email"


def show_description(item):
    return item.describe()


print(show_description(Message()))  # message
print(show_description(Email()))    # email
```

同一段调用代码对不同对象得到不同结果，叫多态的一种表现。Python 还常采用**鸭子类型**：代码关心对象能否提供 `describe()` 行为，而不一定要求它继承某个特定类。例如一个独立的 `Report` 类若也实现此方法，`show_description(Report())` 同样可工作。

把设想中的 `Report` 写完整，更容易看到“可调用”与“继承关系”不是同一个判断：

```python
class Message:
    def describe(self):
        return "message"


def show_description(item):
    return item.describe()


class Report:
    def describe(self):
        return "report"


report = Report()
print(show_description(report))       # report
print(isinstance(report, Message))  # False
```

`show_description()` 的当前实现只要求对象拥有可调用的 `describe()`；`isinstance()` 则是在问它与指定类之间的类型关系。真实接口还需要说明返回值、异常和副作用，不能因为方法同名就假设语义一定相同。

不要因为“两个类都有一个方法”就强制建立继承。继承还意味着子类要接受父类接口约定，修改父类可能影响所有子类。

## 7. 多继承、MRO 与 `super()`

当类有多个父类时，同名方法从哪里找到，需要确定顺序。这个顺序叫 **MRO**（Method Resolution Order，方法解析顺序）。可以读取类的 `__mro__` 观察；Python 使用一套保证顺序一致性的规则计算它，本章重点是会读结果并理解调用链。

```python
class Root:
    def route(self):
        return ["Root"]


class Left(Root):
    def route(self):
        return ["Left"] + super().route()


class Right(Root):
    def route(self):
        return ["Right"] + super().route()


class Combined(Left, Right):
    def route(self):
        return ["Combined"] + super().route()


print([cls.__name__ for cls in Combined.__mro__])
print(Combined().route())
```

两行分别得到 `['Combined', 'Left', 'Right', 'Root', 'object']` 和 `['Combined', 'Left', 'Right', 'Root']`。从 `Left.route()` 中调用的零参数 `super()`，对于 `Combined` 实例会继续找 MRO 中 `Left` 后面的 `Right`，不是固定跳到 `Left` 在定义处写下的父类 `Root`。

### 7.1 为什么共同的祖先只出现一次

`Left` 自己的查找顺序是 `Left → Root → object`，`Right` 则是 `Right → Root → object`。组合类声明 `Combined(Left, Right)` 又要求 `Left` 在 `Right` 前面。Python 使用称为 C3 的线性化规则，合并父类各自已有顺序与直接父类顺序；不能把两条链简单拼起来，否则 `Root` 会重复出现，也可能破坏原有先后约束。

对这个例子，可以把待合并的三列写在纸上：

```text
Left  → Root → object
Right → Root → object
Left  → Right
```

每一步选择一列开头的候选，但它不能还出现在其他未处理列的后面。先选 `Left`。此时 `Root` 仍排在第二列的 `Right` 后面，不能抢先选；于是选 `Right`，然后才选共同的 `Root`，最后是 `object`。再在最前面加上 `Combined`，便得到实际 MRO。

你不必背复杂继承树的手工合并算法，但应能说明这里为什么不是 `Combined → Left → Root → Right`，并且在代码中通过 `Combined.__mro__` 验证结果。若父类给出的顺序互相矛盾，Python 会拒绝创建无法得到一致 MRO 的类，而不是随机选一条路。

### 7.2 `super()` 由当前类和实例的 MRO 共同决定

同一份 `Left.route()` 代码在不同实例上，下一站可能不同：

```python
class Root:
    def route(self):
        return ["Root"]


class Left(Root):
    def route(self):
        return ["Left"] + super().route()


class Right(Root):
    def route(self):
        return ["Right"] + super().route()


class Combined(Left, Right):
    def route(self):
        return ["Combined"] + super().route()


print(Left().route())      # ['Left', 'Root']
print(Combined().route())  # ['Combined', 'Left', 'Right', 'Root']
```

在 `Left()` 实例上，MRO 中 `Left` 后面是 `Root`；在 `Combined()` 实例上，`Left` 后面是 `Right`。零参数 `super()` 不会直接创建父类实例，它给当前方法一个沿 MRO 继续查找的代理入口。

协作链还依赖各层真的调用下一层。如果 `Left.route()` 不调用 `super().route()`，`Right` 与 `Root` 就不会因为 MRO 中有它们而自动运行。各层的形参还必须相容；一个类偷偷吃掉别人的必需实参，也会让后续调用失败。

`super()` 返回一个按当前类与当前实例的 MRO 继续查找的代理对象。协作式多继承要求各层方法能按约定调用下一层，并保持参数接口兼容；随意混合彼此不了解的类可能造成重复执行或漏执行。只需要一个父类时，先使用单继承。

## 8. 组合与继承怎样选择

若一个对象“有一个”协作者，而不是“是一种”协作者，组合通常更直观：

```python
class Printer:
    def print_text(self, text):
        print(text)


class ReportService:
    def __init__(self, printer):
        self.printer = printer

    def publish(self, text):
        self.printer.print_text(text)
```

`ReportService` 保存一个 `printer` 对象，并把输出工作交给它。测试时可以换入提供同样方法的替代对象。若强行让 `ReportService` 继承 `Printer`，就错误地表达了“报告服务是一种打印机”。选择标准是对象关系和接口契约，不是少写几行代码。

观察一次替换协作者的过程：

```python
class Printer:
    def print_text(self, text):
        print(text)


class ReportService:
    def __init__(self, printer):
        self.printer = printer

    def publish(self, text):
        self.printer.print_text(text)


class RecordingPrinter:
    def __init__(self):
        self.messages = []

    def print_text(self, text):
        self.messages.append(text)


recorder = RecordingPrinter()
service = ReportService(recorder)
service.publish("ready")
print(recorder.messages)  # ['ready']
```

`ReportService` 没有变，只有构造时传入的协作者变了。这使测试可以检查“发布了什么”，而无需真的向终端输出。组合的代价是对象之间要有清楚的依赖接口；继承的代价则是把类型关系固定在类层级里。

## 9. 单下划线、双下划线与 `__slots__`

### 9.1 单下划线约定与双下划线名称改写

`_name` 是“供内部使用”的约定，调用者仍能访问。类定义中的 `__name` 会发生**名称改写**，例如 `Vault` 中的 `__code` 通常存为 `_Vault__code`，主要用于避免子类意外覆盖同名属性，不是安全保密机制。

```python
class Vault:
    def __init__(self, code):
        self.__code = code

    def reveal(self):
        return self.__code


vault = Vault("A")
print(vault.reveal())
print(vars(vault))  # {'_Vault__code': 'A'}
```

不要把双下划线用于真正的秘密；对象状态仍存在于程序内存中。

名称改写真正能解决的是父子类不小心撞名。下面两个源码中都写了 `self.__state`，却保存成不同的内部名字：

```python
class Parent:
    def __init__(self):
        self.__state = "parent"

    def parent_state(self):
        return self.__state


class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__state = "child"

    def child_state(self):
        return self.__state


child = Child()
print(child.parent_state(), child.child_state())  # parent child
print(vars(child))  # 同时含 _Parent__state 和 _Child__state
```

这不是“外部访问不了”，而是两个类内部使用相同短名字时不会悄悄覆盖彼此。绝大多数普通内部属性用单下划线约定已足够。

### 9.2 `__slots__` 限制普通实例属性名

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y
```

在这种普通实例中，`x`、`y` 可用，但给实例任意新增 `z` 会报错，且通常没有实例 `__dict__`。这是对动态属性的一种限制。在 CPython 中，大量小对象有时因此减少内存开销，但具体节省量不是跨实现保证。

`__slots__` 并不让对象自动不可变，`point.x = 3` 仍可成功。若子类没有继续适当声明槽，实例可能又有 `__dict__`；也不要在不测量的情况下把它当作通用性能优化。

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y


point = Point(1, 2)
point.x = 3
print(point.x)                    # 3
print(hasattr(point, "__dict__")) # False
# point.z = 4                     # AttributeError


class ColoredPoint(Point):
    pass


colored = ColoredPoint(1, 2)
colored.color = "red"
print(hasattr(colored, "__dict__"))  # True
```

父类声明槽，不等于所有子类实例都永久没有属性字典。这也说明槽不应被当成权限控制。若要回答内存收益，先说“限制普通实例属性布局”，再限定“具体内存开销取决于 CPython 版本、继承布局和实例数量”，不要许诺固定节省比例。

## 10. `property`：在访问属性时执行规则

有时调用者应继续写 `account.balance`，但赋值必须满足约束。`property` 把读取和赋值连接到方法：

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("balance cannot be negative")
        self._balance = value
```

创建 `Account(10)` 时，`self.balance = balance` 触发 setter，校验后保存 `_balance`。读取 `account.balance` 触发 getter。`_balance` 是内部约定名，直接写它仍可能绕过这个接口，因此属性控制不是安全沙箱。

### 10.1 `property` 的赋值校验与实例状态

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("balance cannot be negative")
        self._balance = value


account = Account(10)
print(vars(account))  # {'_balance': 10}

account.balance = 20
print(account.balance)  # 20

try:
    account.balance = -1
except ValueError:
    pass
print(account.balance)  # 20
```

初始化和后来的正常赋值都经过 setter。负值检查发生在写 `_balance` 之前，因此失败后保留旧值。若先写新状态、再检查，就会留下“抛了异常但对象已经改变”的错误接口。调用者应通过公开的 `balance` 使用对象，而不是直接依赖 `_balance` 的存储形式。

### 10.2 `property` 为什么优先于实例字典

为了只观察查找优先级，可以直接往普通实例字典塞入一个同名键。业务代码不应靠这种写法绕过类接口：

```python
class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance


account = Account(20)
account.__dict__["balance"] = 999
print(vars(account))      # 同时含 _balance: 20 与 balance: 999
print(account.balance)    # 20
```

点号读取仍调用 `property` 的 getter，得到 `_balance` 中的 `20`。原因是类上的 `property` 实现了能处理读写的描述符协议，优先于实例字典的同名普通条目。第 20 节会把这条顺序与普通方法绑定放到同一模型中。

即使只定义 getter 而不定义 setter，`property` 对象仍保有处理赋值的协议入口；给它赋值会抛出 `AttributeError`，实例字典中的同名条目也不能靠普通点号读取抢在它前面。因此“有没有 setter”决定可否按公开接口赋值，不决定这类 `property` 是否优先参与查找。

```python
class ReadOnly:
    @property
    def value(self):
        return 5


readonly = ReadOnly()
readonly.__dict__["value"] = 99
print(readonly.value)  # 5
# readonly.value = 7   # AttributeError
```

`@property` 和 `@balance.setter` 是前一章装饰器机制的应用。`property` 也是一种**描述符**：类中的对象可以接管实例属性的读取或赋值。正因它会处理赋值，第 3 节“实例属性先于类属性”的简化模型不适用于这里；更完整的查找顺序放在第 20 节。

## 11. 抽象基类规定必须实现什么

鸭子类型允许只看行为，但有些扩展点需要明确规定子类必须实现某个方法。标准库 `abc` 提供**抽象基类**：

```python
from abc import ABC, abstractmethod


class Storage(ABC):
    @abstractmethod
    def load(self, key):
        pass


class MemoryStorage(Storage):
    def __init__(self):
        self.data = {}

    def load(self, key):
        return self.data.get(key)
```

`Storage()` 不能直接创建实例，因为它仍有未实现的抽象方法。`MemoryStorage` 提供 `load()` 后才可实例化。这是在运行时对继承体系施加的接口约束；它不代表所有能参与 `load()` 调用的对象都必须继承 `Storage`。按结构描述接口的 `typing.Protocol` 在第 11 章学习。

```python
from abc import ABC, abstractmethod


class Storage(ABC):
    @abstractmethod
    def load(self, key):
        pass


class MemoryStorage(Storage):
    def __init__(self):
        self.data = {}

    def load(self, key):
        return self.data.get(key)


# Storage()  # TypeError：抽象方法 load() 尚未实现
storage = MemoryStorage()
print(storage.load("missing"))  # None
```

抽象基类检查的是“子类在类层面是否提供约定的方法”，不自动证明方法的业务结果正确。一个实现了 `load()` 却返回错误数据的类仍能实例化；功能正确性还要靠清楚的接口约定和测试。若只需接受任何具有 `load()` 行为的对象，未必需要让每个实现者都加入同一继承树。

## 12. `dataclass` 减少记录类样板代码

只需要保存几个字段时，反复写 `__init__()`、`__repr__()` 和相等比较容易重复。标准库 `dataclasses.dataclass` 可以按字段声明生成它们：

```python
from dataclasses import dataclass, field


@dataclass
class Task:
    name: str
    scores: list[int] = field(default_factory=list)


first = Task("A")
second = Task("A")
first.scores.append(90)
print(second.scores)  # []
```

字段注解在这里帮助 `dataclass` 确定字段；这不同于普通函数注解默认不做运行时类型验证。`default_factory=list` 在每次创建实例时调用 `list()` 建立独立列表，避免共享可变默认对象。

默认的可变数据类通常生成按字段比较的 `__eq__()`，但实例一般不可哈希。`frozen=True` 限制字段重新赋值，可用于表达固定记录；如果字段指向可变列表，列表内容仍可能变化，所以 `frozen` 不是递归深度的不可变保证。

### 12.1 数据类生成的相等比较与哈希方法

```python
from dataclasses import dataclass, field


@dataclass
class Task:
    name: str
    scores: list[int] = field(default_factory=list)


left = Task("X")
right = Task("X")
print(left == right)          # True
print(left is right)          # False
print(Task.__hash__ is None)  # True

left.scores.append(80)
print(left == right)          # False
```

这里默认生成的相等规则比较字段值，不比较实例身份。因为字段可以改变，而相等关系会随之变化，默认的非冻结数据类不自动提供可安全使用的哈希。`field(default_factory=list)` 解决的是“每个实例独立创建列表”，并不让列表自动不可变或可哈希。

### 12.2 `frozen=True` 与 `__post_init__()` 校验

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class GridCell:
    row: int
    column: int


first_cell = GridCell(1, 2)
second_cell = GridCell(1, 2)
print(first_cell == second_cell)             # True
print(hash(first_cell) == hash(second_cell)) # True
# first_cell.row = 3                        # 冻结字段不能普通赋值
```

这两个字段是整数，因此按字段生成的哈希可用。如果冻结数据类含有列表字段，`frozen=True` 只阻止字段重新绑定，不能使列表内容不可修改，计算哈希时仍可能因为列表不可哈希而失败。

若生成的初始化方法之后还需校验多个字段之间的关系，可以定义 `__post_init__()`：

```python
from dataclasses import dataclass


@dataclass
class Interval:
    start: int
    end: int

    def __post_init__(self):
        if self.start > self.end:
            raise ValueError("start cannot exceed end")
```

`Interval(1, 3)` 先由生成的 `__init__()` 设置字段，再运行 `__post_init__()` 校验关系。注解 `int` 仍不会单独替你拒绝所有运行时错误类型。数据类还支持 `order=True`、`slots=True` 等配置，但应先明确字段是否适合比较、是否需要冻结和是否需要实例字典，不能一口气打开所有选项。

## 13. 数据模型：为什么内置语法会调用对象的方法

数据模型是 Python 对象参与语言行为的一组约定。`len(obj)`、`obj[0]`、`obj == other`、`obj()` 等看起来是不同语法，但各自可以借助类型上的特殊方法完成。我们平时写 `len(obj)`，而不是直接写 `obj.__len__()`；后者只是帮助理解协议的近似表达。

这些双下划线名称不是任意命名风格。Python 会为相应操作在**类型**上查找特殊方法，某些操作甚至不会理会临时塞进单个实例里的同名普通属性。因此判断 `len(obj)` 能否工作，要看类的协议实现，而不是只看 `vars(obj)` 中有没有 `__len__`。

不必为每个类实现所有特殊方法。只实现对象确实需要参与的语法，并让该方法遵守语义约定。

用一个极小例子检验“类型上的协议”与“实例上的普通名字”的区别：

```python
class Empty:
    pass


item = Empty()
item.__len__ = lambda: 10
print(item.__len__())  # 10
# len(item)             # TypeError
```

直接读取 `item.__len__` 能找到实例属性；`len(item)` 则按特殊方法查找规则寻找类上的实现。原因不是这个函数返回类型不对，而是它放错了位置。这个区别会在属性钩子部分再次出现。

## 14. `__str__()` 与 `__repr__()` 的用途

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __str__(self):
        return f"{self.name}: {self.price}"

    def __repr__(self):
        return f"Product(name={self.name!r}, price={self.price!r})"


item = Product("pen", 5)
print(str(item))   # pen: 5
print(repr(item))  # Product(name='pen', price=5)
```

`str(obj)` 和 `print(obj)` 倾向于面向使用者的可读文本；`repr(obj)` 倾向于帮助开发者辨认对象。格式字符串里的 `!r` 使用对应值的 `repr()`，所以字符串名称会显示引号。若没有 `__str__()`，`str()` 可以回退使用 `__repr__()`。

好的 `repr` 应尽量清楚且无歧义，但不保证输出一定是可以直接执行来重建对象的 Python 表达式；不能把这种建议说成语言硬性规定。

## 15. 相等：`is`、`__eq__()` 与 `NotImplemented`

### 15.1 对象身份与自定义相等比较

第 1 章已经区分：`a is b` 判断是否为同一个对象，`a == b` 请求值相等的判断。自定义类若没有有意义的相等实现，两个不同实例通常不会仅因属性内容相同就相等。

```python
class Label:
    def __init__(self, text):
        self.text = text

    def __eq__(self, other):
        if not isinstance(other, Label):
            return NotImplemented
        return self.text == other.text


first = Label("A")
second = Label("A")
print(first == second)  # True
print(first is second)  # False
```

`first == second` 会让 Python 使用相关类型的相等方法。`__eq__()` 返回 `True` 或 `False` 表示已经能判断；返回单例对象 `NotImplemented` 表示“我不支持与这个类型比较”，让 Python 有机会尝试另一侧的比较方法，最终仍无法处理时才按规则得出结果。

`NotImplemented` 不是异常，也不是 `False`；`NotImplementedError` 才是一种可以抛出的异常。比较 `None` 时仍推荐 `is None`，因为它直接表达身份判断，不受自定义相等规则影响。

### 15.2 `NotImplemented` 与另一侧比较方法的尝试

`__eq__()` 的返回值和最终 `==` 表达式的结果不是一回事。看一个专门记录尝试顺序的例子：

```python
class LeftValue:
    def __eq__(self, other):
        print("left tried")
        return NotImplemented


class RightValue:
    def __eq__(self, other):
        print("right tried")
        return True


print(LeftValue() == RightValue())
```

这个例子会先显示 `left tried`，再显示 `right tried`，最后显示 `True`。左侧说“我不知道怎样和它比较”，Python 才继续问右侧；若左侧直接返回 `False`，通常就表达了明确的否定，不会以相同方式给另一侧决定机会。若双方都返回 `NotImplemented`，普通相等比较最后会按身份得到结果：同一个对象与自身相等，不同对象不相等。若右侧类型是左侧的子类，反向比较还有优先处理的细节；分析具体类时不要把“永远先问左侧”背成绝对规则。

这里不能写 `if NotImplemented:` 来代表真假；它是供比较协议识别的特殊对象，不是业务布尔值。第一章推荐 `result is None` 的原因也更清楚了：它不需要向任何对象的 `__eq__()` 询问“你认为自己是否等于 `None`”。

### 15.3 自定义相等比较的对称性与传递性

如果 `A` 与 `B` 对同一业务值有不同判断，`a == b` 和 `b == a` 可能产生令人困惑的行为。尽量让相等关系符合业务上的对称性、传递性和稳定性；不认识的类型返回 `NotImplemented`，不要随意把一切对象都判为相等。

## 16. 排序比较与 `__lt__()`

`<` 可以通过 `__lt__()`（less than）定义对象的顺序：

```python
class Job:
    def __init__(self, priority):
        self.priority = priority

    def __lt__(self, other):
        if not isinstance(other, Job):
            return NotImplemented
        return self.priority < other.priority


jobs = [Job(3), Job(1), Job(2)]
ordered = sorted(jobs)
print([job.priority for job in ordered])  # [1, 2, 3]
```

`__lt__()` 只说明“小于”。`==`、`<=`、`>` 等其他比较不会自动全都拥有相同业务语义；需要时分别实现，或使用标准库装饰器 `functools.total_ordering`：在已提供 `__eq__()` 和一种顺序比较的基础上，它生成其余顺序比较方法。它减少样板代码，但不会替你决定业务顺序是否合理。若顺序只用于一次排序，`sorted(jobs, key=lambda job: job.priority)` 往往更简单；第 3 章已经解释过 `key` 是接收排序依据函数的形参。

## 17. 相等与哈希必须保持一致

### 17.1 为什么字典键需要稳定的哈希

第 2 章已经建立哈希表直觉：字典先根据键的哈希值定位候选位置，再用相等关系判断是不是同一个键。如果 `a == b`，必须有 `hash(a) == hash(b)`；否则相等的两个键可能走向不同候选位置。反方向不成立：哈希相同的不同对象仍可能碰撞。

把插入和查找拆开，可以看到这个约束从何而来：

```text
插入键 a：hash(a) → 某个候选区域 → 保存对键对象和值对象的引用
查找键 b：hash(b) → 候选区域 → 对候选键做相等检查
```

若 `a == b` 却有不同哈希，查找就可能连保存 `a` 的候选区域都不会检查。反过来，两个不同键即使碰巧哈希相同，字典仍可通过相等检查区分它们。哈希值是定位线索，不是对象的唯一身份证。

`Label` 重写了 `__eq__()` 却没有给出匹配的 `__hash__()`。Python 会让这类普通实例不可哈希，以免沿用基于身份的旧哈希与新的值相等规则冲突：

```python
class Label:
    def __init__(self, text):
        self.text = text

    def __eq__(self, other):
        if not isinstance(other, Label):
            return NotImplemented
        return self.text == other.text


print(Label.__hash__)  # None
# hash(Label("A"))     # TypeError
```

### 17.2 只有稳定的字段才适合参与哈希

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class GridCell:
    row: int
    column: int


lookup = {GridCell(1, 2): "occupied"}
print(lookup[GridCell(1, 2)])  # occupied
```

两个字段都是不可变整数，自动生成的相等与哈希按相同字段工作。即使手写 `__hash__()`，也要保证参与哈希的字段在对象作为键的整个期间不改变。不可哈希的字段，例如列表，会让对应实例的哈希计算失败；`frozen=True` 不能改变嵌套列表的性质。

### 17.3 为什么不能先入字典再改哈希字段

下面故意写一个不安全的类，只用于观察错误设计，不要模仿用它作键：

```python
class MutableKey:
    def __init__(self, code):
        self.code = code

    def __eq__(self, other):
        if not isinstance(other, MutableKey):
            return NotImplemented
        return self.code == other.code

    def __hash__(self):
        return hash(self.code)


key = MutableKey(1)
lookup = {key: "saved"}
before = hash(key)
key.code = 2
after = hash(key)
print(before != after)  # True
```

这里检查的是修改前后哈希是否不同，不依赖 `hash(1)`、`hash(2)` 在某个解释器中显示成哪些具体整数。插入时字典根据旧哈希定位；修改后，下一次查找可能根据新哈希去另一个候选区域，因而无法可靠找到已经存放的键。即便某个小例子碰巧还能找到，也不能依赖这种结果：哈希碰撞、表容量和实现布局都会影响现象。关键不是字典“忘记”了键，而是键在表中的定位依据被我们改坏了。保存对象引用而非复制完整对象，也不等于允许它的哈希相关状态随意变化。

实务选择是：让值对象的比较与哈希使用稳定字段；若对象确实需要修改影响相等的字段，通常不要让它可哈希。不要为了通过 `hash()` 测试而写一个与 `__eq__()` 无关的固定哈希值；虽可能满足“相等哈希相同”，却会造成大量冲突且没有解决状态语义。

不要为了“能放入字典”给可变对象随手写一个哈希方法，也不要把相等性和哈希计算建立在不同字段上。

## 18. 容器协议：长度、索引与成员判断

一个轻量对象可以把内部列表作为数据来源，再明确公开需要的容器行为：

```python
class Shelf:
    def __init__(self, values):
        self._values = list(values)

    def __len__(self):
        return len(self._values)

    def __getitem__(self, index):
        return self._values[index]

    def __contains__(self, value):
        return value in self._values


shelf = Shelf(["A", "B"])
print(len(shelf))  # 2
print(shelf[0])   # A
print("B" in shelf)  # True
```

`__len__()` 应返回非负整数；`__getitem__()` 接收索引或切片对象，具体支持哪些方式由接口决定，越界时应使用合适的异常；`__contains__()` 回答成员关系。没有 `__contains__()` 时，`in` 还可能尝试迭代等回退路径，所以“能用 `in`”并不证明类直接实现了该方法。

像这个 `Shelf` 一样，只有 `__getitem__()` 且对越界给出 `IndexError` 的对象，在 Python 中也可能通过旧式序列回退被逐项迭代；第 5 章的主线仍是显式实现 `__iter__()` 的迭代协议。`bool(obj)` 会优先使用 `__bool__()`；没有它时，通常根据 `__len__()` 是否为零判断。

### 18.1 索引、切片、迭代与真值判断的协议

```python
class Shelf:
    def __init__(self, values):
        self._values = list(values)

    def __len__(self):
        return len(self._values)

    def __getitem__(self, index):
        return self._values[index]

    def __contains__(self, value):
        return value in self._values


shelf = Shelf(["A", "B"])
print(shelf[-1])       # B
print(shelf[:1])       # ['A']
print(list(shelf))     # ['A', 'B']
print(bool(Shelf([]))) # False
```

`-1` 和 `slice(None, 1, None)` 都先交给 `__getitem__()`，当前实现直接委托给内部列表，因此分别得到一个元素和一个新列表。`list(shelf)` 在此类中可以沿旧式序列回退依次请求下标 `0、1、2……`，直到内部列表在越界时抛出 `IndexError`。这是 Python 兼容序列的能力；需要一个明确、可控的迭代过程时，仍应实现 `__iter__()`。

成员测试会优先尝试 `__contains__()`；没有它时可能转而逐项迭代。`bool(Shelf([]))` 在未定义 `__bool__()` 时使用长度为零的结果。由此可见，“对象支持某个语法”不总能反推它直接实现了你猜测的同名方法；要按回退规则看实际路径。

## 19. `__call__()` 让实例可以像函数一样调用

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, value):
        return self.factor * value


double = Multiplier(2)
print(double(5))       # 10
print(callable(double))  # True
```

`double` 仍是 `Multiplier` 实例，不是普通函数；调用语法交给类的 `__call__()`。当一个行为需要保留配置状态时，可调用对象是闭包之外的另一种表达。`callable(obj)` 只判断支持调用语法，不保证任何一组实参都会成功。

`double(5)` 可以像实例方法那样拆成“取到 `Multiplier.__call__` → 把 `double` 实例绑定给 `self` → 把 `5` 绑定给 `value` → 执行乘法”。`callable(double)` 为真只说明这个调用入口存在；`double()` 缺少必需实参时仍会报错。选择闭包还是可调用类，常取决于状态是否需要多个清楚命名的操作、是否需要可观察的属性，以及团队是否希望显式表示这个状态对象。

## 20. 属性访问钩子与描述符顺序

本节属于第二轮内容。第一次学习先掌握两个结论即可：`__getattr__()` 只在普通查找失败后介入；`property` 等数据描述符可以先于实例字典处理同名属性。`__getattribute__()`、`__setattr__()` 和手写描述符用于更全面的控制，读懂执行路径比背模板重要。

### 20.1 属性读取与赋值钩子的触发时机

```python
class Settings:
    def __getattr__(self, name):
        if name == "timeout":
            return 5
        raise AttributeError(name)


settings = Settings()
print(settings.timeout)  # 5
```

普通查找找不到 `timeout`，才调用 `__getattr__()`。未知名字仍应抛出 `AttributeError`，否则拼写错误也会被伪装成合法值。

`__getattribute__()` 的介入更早：几乎每次普通点号读取都会经过它。重写时若在方法内部直接写 `self.name`，很可能再次进入同一个方法而无限递归；需要通过 `object.__getattribute__(self, name)` 完成基础读取。`__setattr__(self, name, value)` 可以接管普通点号赋值；内部同理使用 `object.__setattr__()` 保存，避免自我递归。初学时优先用 `property` 完成单个属性的校验。

用最小代码观察“每次读取”与“找不到才补救”：

```python
class TracedSettings:
    def __init__(self):
        self.name = "Ada"

    def __getattribute__(self, name):
        if name == "name":
            print("reading name")
        return object.__getattribute__(self, name)

    def __getattr__(self, name):
        if name == "timeout":
            return 5
        raise AttributeError(name)


settings = TracedSettings()
print(settings.name)     # 先显示 reading name，再显示 Ada
print(settings.timeout)  # 5
```

读 `name` 时前一个钩子通过基础查找找到实例属性；读 `timeout` 时基础查找失败，才进入后一个钩子。两者不是两种任选其一的“读取函数”。若只需给某个缺省配置提供值，优先写 `__getattr__()`；重写每次读取都会经过的 `__getattribute__()` 需要更强的理由。

普通赋值的总入口也能安全地委托给基础实现：

```python
class CheckedValue:
    def __setattr__(self, name, value):
        if name == "value" and value < 0:
            raise ValueError("negative value")
        object.__setattr__(self, name, value)


checked = CheckedValue()
checked.value = 3
print(checked.value)  # 3
```

若写成 `self.value = value`，会再次进入当前 `__setattr__()`，直到递归过深。对单个字段而言，第 10 节的 `property` 通常更清楚。

### 20.2 数据描述符、实例属性与类属性的查找顺序

第 3 节的“实例属性遮蔽类属性”有一个重要例外。**描述符**是放在类中、实现 `__get__()`、`__set__()` 等协议方法的对象，可以参与属性访问。对普通实例的常见查找顺序，可先记成：

```text
类及 MRO 中的数据描述符，例如 property（即使没有 setter）
→ 实例自身保存的普通属性
→ 类及 MRO 中的其他属性，例如普通方法
→ 仍未找到时的 __getattr__()
```

普通方法由函数描述符绑定 `self`；`property` 能把读取和赋值交给方法。这个顺序解释了为什么 `account.balance = ...` 会触发 setter，而普通 `first.category = ...` 会建立遮蔽类属性的实例属性。`__getattribute__()` 包围整个普通读取过程；特殊方法被 `len(obj)` 等语法调用时还可能走类型上的专用查找路径，不能用普通 `obj.__len__` 的规则机械替代。

### 20.3 描述符、实例属性、方法与缺失属性的查找示例

```python
class Lookup:
    category = "class"

    @property
    def controlled(self):
        return "property"

    def run(self):
        return "method"

    def __getattr__(self, name):
        if name == "fallback":
            return "missing-name handler"
        raise AttributeError(name)


item = Lookup()
item.category = "instance"
item.__dict__["controlled"] = "manual entry"
print(item.category)    # instance
print(item.controlled)  # property
print(item.run())       # method
print(item.fallback)    # missing-name handler
```

同是点号读取，四次访问分别在实例普通条目、类上的数据描述符、类中的方法、缺失后的钩子结束。`item.__dict__["controlled"]` 明明存在，却没有遮蔽 `property`。若给实例的 `run` 建立同名普通属性，普通方法可能被遮蔽，因为它没有处理赋值的数据描述符优先级。这样才能同时解释第 3 节的遮蔽和第 10 节的例外。

### 20.4 自定义描述符的读写方法与实例存储

这一小节是第二轮选读。`property` 已经够处理大多数受控字段。下面用一个小描述符看清它为什么能跨实例工作，而不要求你在业务中都手写描述符：

```python
class NonNegative:
    def __set_name__(self, owner, name):
        self.storage_name = "_" + name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return vars(instance)[self.storage_name]

    def __set__(self, instance, value):
        if value < 0:
            raise ValueError("negative value")
        vars(instance)[self.storage_name] = value


class Parcel:
    weight = NonNegative()

    def __init__(self, weight):
        self.weight = weight


first = Parcel(3)
second = Parcel(8)
print(first.weight, second.weight)  # 3 8
print(vars(first))                  # {'_weight': 3}
```

执行 `class Parcel` 时只创建一个 `NonNegative` 描述符并保存在类上；`__set_name__()` 告诉它自己管理的属性名。调用 `Parcel(3)` 后，`self.weight = weight` 进入描述符的 `__set__()`，它把数据存到当前实例的 `_weight`，而不是把 `3` 存在共享的描述符对象里。读取 `first.weight` 再进入 `__get__()`；因此两次创建的实例虽共用一个描述符对象，数值仍然独立。

这类同时处理读取和赋值的对象叫数据描述符。只有读取行为的非数据描述符可以被同名实例属性遮蔽；类中普通函数形成绑定方法，也依赖描述符读取行为。理解这一点即可解释常见行为，不需要背完描述符实现的所有特殊情况。

描述符的完整实现、继承交互和边界较深；面试首轮能解释方法绑定和 `property` 的优先级已足够。

## 21. `with` 与 `__enter__()`、`__exit__()`

第 5 章看到 `with open(...)`，它依赖对象的上下文管理协议：进入时调用 `__enter__()`，离开时调用 `__exit__()`。

```python
class Session:
    def __enter__(self):
        print("open")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("close")
        return False


with Session() as session:
    print("work")
```

正常执行时输出顺序是：

```text
open
work
close
```

先创建 `Session` 实例并调用 `__enter__()`，其返回值绑定给 `session`；然后执行代码块；离开代码块时调用 `__exit__()`。无论正常离开还是代码块抛出异常，`__exit__()` 都有机会执行清理；返回 `False` 不会吞掉原异常。完整的异常传播和清理时序将在第 7 章学习，此处只把 `with` 与对象特殊方法连接起来。

## 22. 元类 `type` 与类对象的创建

本节只建立边界，属于第二轮选读。目标是知道类对象也有类型，以及什么问题才可能涉及元类；本章不要求实现自定义元类。

实例由类创建，而类本身也是对象。普通类默认由内置的 `type` 创建：

```python
class Document:
    pass


print(type(Document))    # <class 'type'>
print(type(Document()))  # <class '__main__.Document'>
```

负责创建类对象的类叫**元类**。`type` 是常见的默认元类。自定义元类能介入类创建过程，例如强制检查类定义或登记类；它影响所有相关类，调试成本高。

若只想在某个父类出现新子类时登记它，可以先考虑父类钩子 `__init_subclass__()`。它在定义子类时触发，不必重写创建所有类的元类：

```python
class Plugin:
    registered = []

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registered.append(cls)


class CsvPlugin(Plugin):
    pass


print([cls.__name__ for cls in Plugin.registered])  # ['CsvPlugin']
```

这里 `registered` 是有意共享的类级登记表，与第 3 节“误把每实例数据放在类上”不同。`class CsvPlugin(Plugin)` 执行时就登记了类对象；不需要先创建 `CsvPlugin()` 实例。多数应用先考虑普通继承、类装饰器、这种子类钩子或清楚的注册函数。本章不要求手写元类，也不把它当成“高级所以更好”的默认方案。

## 23. 实例属性、`property`、继承与特殊方法的选择

面对一个需求，先问它改变的是哪个层次：

1. 每个对象独有的状态：放在实例属性，由实例方法处理。
2. 全体实例共享、语义稳定的配置：考虑类属性；可变共享状态要格外明确。
3. 属性读写需要校验：先考虑 `property`。
4. 一种对象确实是另一种对象：考虑继承；只是使用一个协作者时优先组合。
5. 要支持某种内置语法：实现对应特殊方法并遵守返回值与一致性约束。
6. 需要控制全部属性访问、类创建或复杂多继承：先确认普通机制无法表达，再用钩子或元类。

面试中不必把所有双下划线方法背成一张表。选一个具体调用，说明 Python 查找哪个对象、传入哪个实例、产生什么返回值或副作用，并指出关键边界，通常更有说服力。

## 24. 综合案例：练习记录与报告类的设计

假设要保存一组面试练习记录。每条记录含姓名和分数，建立后不希望改动；记录集合会持续新增记录，支持 `len(report)`、`report[index]` 和读取最高分记录。先不要想着“把所有特殊方法都写上”，逐条把需求映射到对象：

```text
一条记录 → 两个固定字段，适合不可变值对象
一组记录 → 保存记录的列表，适合普通实例属性
新增记录 → 明确会修改集合的实例方法
按下标读取 → __getitem__()
读取数量 → __len__()
读取最高分 → 只读 property
```

先建立值对象：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Attempt:
    name: str
    score: int
```

`Attempt("Ada", 90)` 与另一个同字段对象按值相等。字段类型本身可哈希，且普通字段赋值被禁止，因此它适合充当字典键或集合元素。这里的注解不代表运行时自动拒绝错误类型；若业务输入来自不可信来源，还要在入口验证。

集合对象需要维护会增长的状态，不能把记录列表写成可变类属性：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Attempt:
    name: str
    score: int


class AttemptReport:
    def __init__(self, attempts=()):
        self._attempts = list(attempts)

    def add(self, attempt):
        if not isinstance(attempt, Attempt):
            raise TypeError("expected Attempt")
        self._attempts.append(attempt)

    def __len__(self):
        return len(self._attempts)

    def __getitem__(self, index):
        return self._attempts[index]

    @property
    def best(self):
        if not self._attempts:
            return None
        return max(self._attempts, key=lambda attempt: attempt.score)
```

逐步走一遍：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Attempt:
    name: str
    score: int


class AttemptReport:
    def __init__(self, attempts=()):
        self._attempts = list(attempts)

    def add(self, attempt):
        if not isinstance(attempt, Attempt):
            raise TypeError("expected Attempt")
        self._attempts.append(attempt)

    def __len__(self):
        return len(self._attempts)

    def __getitem__(self, index):
        return self._attempts[index]

    @property
    def best(self):
        if not self._attempts:
            return None
        return max(self._attempts, key=lambda attempt: attempt.score)


source = [Attempt("Ada", 90)]
report = AttemptReport(source)
source.append(Attempt("Ming", 99))
print(len(report))  # 1，构造时复制了输入

report.add(Attempt("Lin", 95))
print(len(report))        # 2
print(report[0])          # Attempt(name='Ada', score=90)
print(report.best.name)   # Lin
```

`AttemptReport` **有一组** `Attempt`，并不是“一种 `Attempt`”，所以它采用组合而非继承。构造时的 `list(attempts)` 建立外层列表快照；输入列表后来增加元素不会自动改变报告。`add()` 明确修改当前报告实例。`best` 没有 setter，调用者不能普通赋值 `report.best = ...`；但这并不妨碍通过 `add()` 改变集合后重新计算最高分。

这个实现也有代价：每次读取 `best` 都要扫描目前的记录，时间随记录数增长。若要频繁读取且记录很多，才考虑维护额外索引或缓存，并处理新增记录时的同步问题。设计对象时，先保证状态关系和接口语义清楚，再根据真实使用规模优化，而不是因为知道 `__slots__`、多继承或元类就把它们全部加入。

## 25. 本章总结

- `class` 创建类对象；调用类创建实例，`__new__()` 在 `__init__()` 之前参与创建。
- 实例属性各自保存；类属性由类保存，实例赋值可能遮蔽普通类属性。
- 实例方法绑定实例，类方法绑定类，静态方法不自动绑定两者。
- 继承和 MRO 决定方法查找，`super()` 沿 MRO 继续；组合适合“有一个”协作者。
- `property`、描述符和属性钩子影响点号访问；名称改写与 `__slots__` 都不是安全保密机制。
- `dataclass` 生成常见样板方法，但可变默认值、嵌套可变字段和哈希约束仍需判断。
- `__str__()`、`__repr__()`、比较、哈希、容器及调用协议让对象参加内置语法。
- 相等对象必须有相同哈希；改变参与哈希的状态会破坏字典键的可靠查找。
- 抽象基类和元类各有用途，普通代码应先用最简单、可解释的机制。
